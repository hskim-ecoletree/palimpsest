## §0 — 앞선 결함 보고 ①은 틀렸다

**대기 문서 §1이 적은 "고유 좌표가 28개다"는 사실이 아니다.**

`label-candidates.toml`을 파싱해 세면 **전체 경로 기준 고유 좌표는 30이고 등록값과 일치한다.**
28은 **파일명만으로 중복 제거**했을 때 나오는 수다. 문제의 두 쌍은 서로 다른 파일이었다:

```
portal-backend/…/config/MultiTenantTransactionManager.kt:166
portal-backend-aa-task/…/config/MultiTenantTransactionManager.kt:166
```

### 그런데 그 밑에 더 큰 것이 있었다

`portal-backend-aa-task/`는 별도 모듈이 아니라 **`portal-backend`의 git worktree**다:

```
$ cat portal-backend-aa-task/.git
gitdir: …/boxwood/portal-backend/.git/worktrees/portal-backend-aa-task
$ git -C portal-backend-aa-task rev-parse --abbrev-ref HEAD
feat/aa-task
```

등록된 범위 문구는 **`worktrees/ 제외`**였다. 이 worktree는 `worktrees/` 디렉터리 **밖**에
놓여 있어 경로 규칙을 빠져나갔다. 실측:

| | 파일 |
|---|---|
| 범위 총계 | 1,036 |
| `portal-backend` | 604 |
| `portal-backend-aa-task` | 415 |
| `boxwood-packages` | 17 |
| 두 worktree가 **상대 경로까지 같은** 파일 | 397 |
| 그중 **바이트 단위로 동일** | **289 — 풀의 27.9%** |
| aa-task 전용(진짜 신규) | 18 |

문제의 두 쌍은 `diff` 결과 **내용이 완전히 같다.** 판정자에게는 구분되지 않는다 —
**좌표는 둘인데 실물 코드는 하나다.** 그래서 앞선 보고의 *결론*("실질 28건")은 맞았고
*원인 설명*("층화 표집이 같은 좌표를 두 번 뽑았다")이 틀렸다.

### 왜 이것이 더 나쁜가

클론의 두 번째 판정은 **이미 읽은 코드**라 부당하게 빨리 끝난다 —
[R-23](../plan/00-risks.md#r-23)이 위험하다고 적은 **과소추정 방향**으로 정확히 작용한다.
그리고 한 브랜치가 이중 계산되어 표본의 대표성이 왜곡된다.

## §1 — T2 판정표: 전면 재표집

**판단: (a) 재추첨 + 재배치.** 다만 §0 때문에 "충돌한 2건 교체"가 아니라 **전면 재표집**이 됐다.

### 갈림길이었던 것 — 사전 등록이 자기모순이었다

문구(`worktrees/ 제외`)와 수치(1,036, worktree 포함)가 **서로 다른 범위를 가리켰다.**
어느 쪽을 택하든 사후 선택이라 선택 자체를 기록해야 했다.

| | 무엇을 하나 | 대가 |
|---|---|---|
| **A ✅** | **문구를 따른다** — worktree 제외, 풀 621, 전면 재표집 | 등록된 풀 수치를 사후에 바꾼다. 층 ②의 등간격이 퇴화한다 |
| B | 수치를 따른다 — 풀 1,036 유지, 클론 2건만 교체 | 풀의 27.9%가 여전히 클론. "충돌한 것만 골라 교체"는 등록 규칙에 없는 사후 개입 |
| C | 무개입 — 클론 쌍도 그대로 | 재질문율에 위양성, 판정 단가에 과소추정 |

**A를 택한 이유**: 수치는 규칙을 돌린 **결과**여야 한다. 규칙이 수치를 따라가면 그것이 사후 조정이다.

### 무엇을 했나

| 커밋 | 무엇 |
|---|---|
| `193bd6b` | **규칙 사전 등록(v2)** — 범위·층·몫·중복 심기 규칙. 추첨 결과 없음 |
| `7a0eaff` | **추첨 확정** — 규칙을 그대로 돌린 결과. **이 시각이 측정 시작 이전이다** |

- v1은 [`label-candidates-v1-retired.toml`](../../corpus/tasks/label-candidates-v1-retired.toml)로 **보존한다.** 무엇을 뽑았다 왜 버렸는지가 감사 대상이다.
- 풀 **621** (①89 · ②10 · ③596). draw 12/6/12는 **바꾸지 않았다.**
- 고정 SHA에서 좌표 대조 — **파일 없음 0 · 줄 불일치 0.** 바이트 동일 클론 **0건**.
- 구현이 v1의 추첨을 **30/30 재현**했다 — 바뀐 것은 범위뿐임이 확인됐다.

### 블라인드를 다시 세운 방법 둘

1. **정답 키를 파일로 분리했다** — [`label-answer-key.toml`](../../corpus/tasks/label-answer-key.toml).
   중복의 정체와 자리는 **씨앗에서 유도**되어 사전 등록 문서 어디에도 실례가 남지 않는다.
   판정 후 씨앗으로 재계산하면 **에이전트가 사후에 자리를 옮기지 않았음이 검증된다.**
2. **판정표에서 후보의 정체를 뺐다.** 33행을 한 화면에 늘어놓은 것이 v1의 실패 경로였다.
   후보는 [`t2-items/`](../../corpus/tasks/t2-items/)에 **한 건에 한 파일**이다.

### 추첨 전에 닫은 명세 구멍 둘

결과를 보고 정한 것이 아니라 **돌리기 전에** 닫았다. 둘 다 커밋에 남아 있다.

- **짝짓기가 없었다** — 중복 대상과 자리를 어떻게 묶는지 등록 명세가 빠뜨렸다 → 얻어진 순서대로 1:1.
- **표집이 끝나지 않는다** — 중복 대상을 0..29에서 고르면, 원본이 33칸에서 최대 `d+4`번째라
  `원본+5`가 33 안에 없는 경우가 생긴다. `d + 4 + 5 ≤ 33` → **d ≤ 24**로 닫았다. 33칸의 산술이다.

### 남은 편향 셋 — 재표집이 고치지 못한 것

1. **층 ②의 등간격이 퇴화했다.** 풀 10에 draw 6이면 `g = 1`이라 사실상 *정렬 앞에서 6개*다.
   `TenantInterceptor` · `WebSecurityConfig` · `MessageResourceDto`가 후보에서 빠진다.
   **draw를 5로 줄이면 퍼지지만 등록된 몫을 사후에 바꾸는 것이라 하지 않았다.**
2. **boxwood는 여전히 편의 표본이다**([R-19](../plan/00-risks.md#r-19)). A는 이것을 고치지 않는다.
3. **층 ③ 596건은 아직 대부분 `@TenantTransactional`이다.**

## §2 — T6 저작 시간: T2와 같은 자리에서, 두 수를 접지 않는다

**판단: (c).** T2에 앉는 김에 개념 저작도 재되 **라벨 판정과 개념 저작을 각각 따로 적는다.**

(b) 기권을 택하지 않은 이유는 **G4가 빈 채로 남기 때문**이다 — G4는 감사(F15)의 생사가 걸린 자리다.

- 시트: [`corpus/tasks/t6-authoring-sheet.md`](../../corpus/tasks/t6-authoring-sheet.md)
- **T2 판정표에 합산하지 않는다.** 개념 저작과 라벨 판정은 다른 노동이고, 한 수로 접으면
  어느 쪽이 값을 냈는지 알 수 없다.

### 이 판단이 뒤집는 것

**G4** — *"사람이 라벨/팩/개념을 저작하지 않는다"*. 무너지면 목표 4(감사)가 전부 `Residual`이 되고
**감사를 산출 목록에서 내린다.** §1의 T2 결과와 **같은 방향을 가리킨다** — 둘 다 나쁘게 나오면
F15·F20이 함께 내려간다.

## §3 — T2는 순수 기준선으로만

**판단: (a).** 장치 없이 33건을 돌린다. T3는 나중에 **별도 표본**으로 분리 측정한다.

(b)를 택하지 않은 이유: 33건에서 층을 또 가르면 층당 n=16이라
[§5 규칙 2](../plan/features/P0-preflight.md)의 n≥5는 넘지만 **순서 효과(뒤로 갈수록 빨라짐)를
통제할 방법이 없다.** 학습 효과와 장치 효과가 섞인 수는 T3의 인수 기준
*"넷 각각이 단가를 얼마나 내리는지 분리해서 기록된다"*를 채우지 못한다.

**분리 측정을 진짜로 하려면 표본이 더 필요하고, 그건 T3의 몫이지 T2에 얹을 것이 아니다.**

판정표에 이 지시를 적어 두었다 — 일괄 승인 같은 절감 장치를 즉흥으로 쓰지 않도록.
