## 2. 정규화 — **해석이다**

### 2.1 끝의 정의

에이전트가 제시하고 소유자가 `U25` 로 받은 끝은 **「설치한 사람이 쓰면서, 도움이 됐는지
스스로 말할 수 있는 상태」**다. 기능이 다 차거나 게이트가 다 초록인 상태가 아니다.

- **내용** — 남의 저장소(TypeScript·Rust)에서 릴리스 바이너리 → `pal install` → 코드를
  만지려는 순간 `pal touch` 가 **걸린 결정과 신선도 · 호출자 자리 · 모르는 것 · 근거**를
  낸다. 다른 디렉터리 이름으로 클론한 팀원도 같은 답을 받는다.
- **판정의 형태** — **사용 기록**이다. 실제 작업마다 *무엇을 하려 했나 · 화면이 무엇을
  말했나 · 무엇이 달라졌나(없음·틀림·시끄러움 포함)*. 기계 게이트로 증명하지 않는다.
- **분할** — 릴리스까지가 회차 `2026-09-14-first-release` 이고, 사용 기록의 판정은 그
  회차가 세우는 이슈가 진다(`U26` 첫 칸). 사용 대상은 ditto 다(둘째 칸).

### 2.2 순서

**첫 릴리스 → 사용 기록 → 품질.** 품질 단계의 첫 자리가 **언어 확장**이다 — Kotlin ·
Java · JavaScript · Python(`U25`). 순서의 정본은 [`docs/plan/03-shortest-path.md`](../plan/03-shortest-path.md) 가 진다.

### 2.3 회차의 무게 — 첫 릴리스까지

`U26` 넷째 칸. 완수 조건은 동작 시험 위주로 10 개 안팎 · 조건 설계 평가와 사전부검은 각
1 라운드 · 독립 리뷰 상한 2 · 결정론 조건만 쓰면 정반합 없음. **앞 지시 「독립 리뷰 상한을
다 쓴다」(2026-08-23 · 2026-09-06)는 첫 릴리스까지 멈춘다.** 근거로 댄 실측: 직전 회차의
커밋 105 중 `crates/` 변경 2,338 줄 · 회차 기록 21,090 줄.

### 2.4 이슈의 처분

열린 64 건을 셋으로 갈랐다(에이전트 분류) — **R1 릴리스 차단 5**(#77 · #127 · #139 · #156 ·
#159) · **R2 릴리스 후 제품 품질 20** · **R3 하네스·측정 장치·문서 39**. R1 은 첫 릴리스
회차가 닫고, R2 는 열린 채 품질 단계의 몫이며, R3 은 **철회 사유 ②**(목표 안이지만 지금
우선순위가 아니다 — 더 먼저인 것은 첫 릴리스)로 닫는다.

### 2.5 사용 기록의 자리와 세는 법 — `U27` 이 `U26` 의 둘째 칸을 바꿨다

- **주 사용처는 palimpsest 자신**(Rust)이다. ditto 는 2026-08-15 이후 커밋이 0 이라 기록이 안 쌓이고, 이 저장소는 같은 기간 약 930 커밋이다.
- **남의 저장소 몇 건**(약 10 건 중 3 건 안팎)을 다른 TypeScript · Rust 저장소에서 **설치부터** 채운다. 둘을 덮는다 —
  R-19(*「자기 적용은 증거가 아니다」*)와, 이 저장소에서는 못 재는 설치 · 훅 경로(설치 짐의 원본이 이 저장소라 같은 이름의 에이전트 정의가 이미 있다).
- **세는 규칙** — 「달라진 것」은 화면이 **그 작업 맥락 밖에서 온 것**(앞 회차 · ADR 에서 온 결정, 몰랐던 호출자 자리)을 보여 줬을 때만 센다.
  같은 작업에서 에이전트가 쓴 결박이 되돌아온 것은 「자기 기록」으로 표시하고 세지 않는다. 이 저장소의 결박 46 중 24 가 회차 메모다.
- **기록 주체** — `pal touch` 를 부른 에이전트가 세 칸을 그 자리에서 적고, **「진짜인가」는 소유자가 판정**한다(자기 보고 치우침을 소유자 판정이 거른다).
