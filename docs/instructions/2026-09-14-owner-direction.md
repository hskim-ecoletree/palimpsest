## 2. 정규화 — **해석이다**

### 2.1 끝의 정의

에이전트가 제시하고 소유자가 `U25` 로 받은 끝은 **「설치한 사람이 쓰면서, 도움이 됐는지
스스로 말할 수 있는 상태」**다. 기능이 다 차거나 게이트가 다 초록인 상태가 아니다.

- **내용** — 남의 저장소(TypeScript·Rust)에서 릴리스 바이너리 → `pal install` → 코드를
  만지려는 순간 `pal touch` 가 **걸린 결정과 신선도 · 호출자 자리 · 모르는 것 · 근거**를
  낸다. 다른 디렉터리 이름으로 클론한 팀원도 같은 답을 받는다.
- **판정의 형태** — **사용 기록**이다. 실제 작업마다 *무엇을 하려 했나 · 화면이 무엇을
  말했나 · 무엇이 달라졌나(없음·틀림·시끄러움 포함)*. 기계 게이트로 증명하지 않는다.
- **분할** — 릴리스까지가 회차 `2026-09-14-first-release` 이고, 사용 기록의 판정은 그
  회차가 세우는 이슈가 진다(`U26` 첫 칸). 사용 대상은 ditto 다(둘째 칸).

### 2.2 순서

**첫 릴리스 → 사용 기록 → 품질.** 품질 단계의 첫 자리가 **언어 확장**이다 — Kotlin ·
Java · JavaScript · Python(`U25`). 순서의 정본은 [`docs/plan/03-shortest-path.md`](../plan/03-shortest-path.md) 가 진다.

### 2.3 회차의 무게 — 첫 릴리스까지

`U26` 넷째 칸. 완수 조건은 동작 시험 위주로 10 개 안팎 · 조건 설계 평가와 사전부검은 각
1 라운드 · 독립 리뷰 상한 2 · 결정론 조건만 쓰면 정반합 없음. **앞 지시 「독립 리뷰 상한을
다 쓴다」(2026-08-23 · 2026-09-06)는 첫 릴리스까지 멈춘다.** 근거로 댄 실측: 직전 회차의
커밋 105 중 `crates/` 변경 2,338 줄 · 회차 기록 21,090 줄.
