## 1. 지시 원문

**받은 순서대로, 손대지 않고 옮긴다.**

### U28 — 제거하면 설치한 적 없던 것처럼

계기는 소유자의 물음 여섯이었다. `pal install` 이 무엇을 하는지 · 사용자가 이 저장소를 받아야 하는지 ·
사용자 PC 에 무엇이 생기고 바뀌는지 · `.claude` 가 프로젝트의 것인지 · 커맨드가 있는데 왜 `PATH` 인지를 물었다:

> install 하면 어떤일이 일어나?

> 그러면 사용자가 본인 프로젝트에 설치하려고 하면 이 프로젝트를 clone 해야해?

> 그럼 설치했을 때 사용자 PC 에 어떤 것들이 설치되는지 무엇이 생기거나 수정되는지 여러 번 설치했을 때 문제 없는지 등을 자세히 알려줘

> .claude 는 이 프로젝트의 클로드 폴더지? 사용자 전역이 아니라?

> 커맨드가 있는데 왜 PATH 를 잡아야 해?

> 그게 사용자 PC 에 환경변수를 등록해야만 하는 일이야?

그 답(릴리스 `v0.1.1` 로 격리 HOME 에서 실측)이 제거 뒤 남는 자리를 보인 뒤 소유자가 쓴 것:

> uninstall 했을 때 정말 깔끔하게 원래 설치된 것이 없었던 것처럼 하고 싶어

에이전트가 물은 문장과 소유자가 고른 칸이다. 칸의 설명문은 에이전트가 쓴 것이다.

| 물음 | 고른 칸 |
|---|---|
| uninstall이 사람이 pal로 쌓은 정본(승인한 결박 intent/*.jsonl, 회차 기록 rounds/)까지 지워야 하나요? 이것은 되돌릴 수 없는 데이터 삭제입니다. | **기본 보존, 플래그로만 삭제** |
| 사용자가 원래 가진 `.claude/settings.json`을 어떻게 다룰까요? | **원래 포맷 유지 최소 편집** |
| CLAUDE.md·.gitignore의 pal 블록을 사용자가 손으로 고쳤을 때 uninstall은 어떻게 할까요? | **거부 유지 + 미리 알림** |
| 프로젝트 밖의 승인 저장소(~/Library/Application Support/palimpsest/approvals 등)에 남은 이 프로젝트 몫도 uninstall이 걷어야 하나요? | **이 프로젝트 몫만 걷기** |
| 프로젝트 밖 승인 저장소의 승인·종료 봉인 파일은 해시 이름만 있어 '어느 프로젝트 몫인지' 가를 수 없습니다(활성화·진행 파일은 가를 수 있음). 어떻게 할까요? | **기록에 프로젝트 식별자 추가** |

칸의 설명문(에이전트가 쓴 것 · 소유자가 고를 때 본 것):

- **기본 보존, 플래그로만 삭제** — `pal uninstall`은 install이 놓은 것과 파생물만 걷고 정본은 남긴 채 '남겼다 + 지우려면 --purge'를
  출력합니다. `--purge`를 주면 정본까지 지워 완전히 없던 상태가 됩니다. 실수로 팀의 승인 기록을 날리는 일을 막습니다.
- **원래 포맷 유지 최소 편집** — install이 파일을 재직렬화하지 않고 필요한 자리에만 텍스트로 끼워 넣습니다. 설치할 때의 diff도 작아지고,
  uninstall 뒤 바이트가 같아집니다. 구현이 가장 무겁습니다(JSON 위치 보존 편집).
- **거부 유지 + 미리 알림** — 지금처럼 uninstall은 거부합니다(사용자가 블록 안에 적은 줄을 보호). 대신 `update`·`doctor --install`이
  수정을 미리 잡아 알립니다. `--force`를 주면 마커 사이를 통째로 지우고 지운 줄을 화면에 출력합니다.
- **이 프로젝트 몫만 걷기** — 이 프로젝트 식별자에 묶인 활성화·진행·승인 파일만 지우고, 저장소 디렉터리가 비면 디렉터리도 지웁니다.
  다른 프로젝트의 승인은 안 건드립니다. 승인 파일이 digest 이름이라 '어느 프로젝트 몫인지'를 가를 수 있는지 먼저 실측해야 합니다.
- **기록에 프로젝트 식별자 추가** — 앞으로 쓰는 승인·봉인 기록에 프로젝트 식별자를 평문으로 함께 적습니다(형식 v2, v1 읽기는 유지).
  digest가 여전히 식별자를 묶으므로 위조 방어는 그대로입니다. 이 변경 뒤 쓴 기록은 uninstall이 완전히 걷고, v0.1.1 이하에서 쓴 옛 기록은
  '가를 수 없는 옛 승인 N개 + 경로'로 출력합니다.

사전부검 1 라운드가 인터뷰 때 몰랐던 사실 셋을 드러낸 뒤 다시 물은 것과 소유자가 고른 칸이다. 칸의 설명문은 에이전트가 쓴 것이다.

| 물음 | 고른 칸 |
|---|---|
| 종료 봉인과 명령 승인 기록은 '회차가 끝났다'는 증거라 지우면 다시 만들 수 없습니다(사전부검 1번: 재설치하면 끝난 회차가 전부 미완료로 읽힘). 기본 uninstall에서 이 둘을 어떻게 할까요? | **정본으로 보고 --purge에서만 걷기** |
| 승인 기록을 프로젝트별로 가르는 방식을 어떻게 할까요? (사전부검 11·16번: v2 형식은 v0.1.1이 '승인 없음'으로 읽고, 종료 봉인은 회차 원장에 이미 목록이 있어 형식을 안 바꿔도 가를 수 있음) | **v1 그대로 + 옆에 표시 파일** |
| 같은 원격(origin)을 가진 클론·git worktree는 외부 기록을 나눠 씁니다(사전부검 2번). --purge가 승인·봉인을 지울 때 어떻게 할까요? | **worktree 있으면 거부, 클론은 경고** |

칸의 설명문:

- **정본으로 보고 --purge에서만 걷기** — 기본 uninstall은 운영 상태(Stop 활성화·진행·잠금 파일)만 걷고, 승인·봉인은 남긴 채
  '무엇이 남았나 + --purge'를 출력합니다. 앞서 고르신 '정본 기본 보존'과 같은 규칙입니다. 회차를 쓴 프로젝트는 기본 uninstall 뒤
  HOME에 그 파일들이 남고, --purge로 지웁니다.
- **v1 그대로 + 옆에 표시 파일** — 승인 파일 형식은 v1 그대로 두고 `<digest>.project`에 프로젝트 식별자를 따로 적습니다.
  v0.1.1(이 저장소의 .palimpsest/bin/pal, PATH에 남은 옛 pal)도 계속 승인으로 읽습니다. 표시 파일을 쓰기 전에 죽은 기록은 옛 기록처럼
  '가를 수 없음'으로 출력됩니다. 봉인은 원장에서 읽어 표시 파일이 필요 없습니다.
- **worktree 있으면 거부, 클론은 경고** — 같은 저장소의 git worktree가 있으면 외부 기록 삭제를 거부하고 이유를 출력합니다(프로젝트 안
  정본은 지움). 따로 클론한 사본은 알 수 없으니 '같은 원격의 다른 클론도 함께 잃는다'를 출력하고 진행합니다. 기본 uninstall의 Stop 해제
  (기존 동작)도 같은 사실을 출력합니다.

이 셋이 앞 표의 다섯째 칸(「기록에 프로젝트 식별자 추가」)을 둘째 칸으로 대신하고, 넷째 칸(「이 프로젝트 몫만 걷기」)을 기본 uninstall 에서는
운영 상태로 좁힌다 — 회차의 `## 승격` 1~3.

조건 설계 평가 두 라운드 뒤 승인 요청과 함께 물은 것과 소유자가 고른 칸이다(설명문 전문은 회차 `approval.md`).

| 물음 | 고른 칸 |
|---|---|
| 사용자가 pal이 놓은 파일(에이전트 정의·커맨드·스킬)을 직접 고친 경우, uninstall은 어떻게 할까요? (기본값 「설치 뒤 사용자가 고친 것은 남긴다」와 「없었던 것처럼」이 부딪히는 자리) | **지우고 경고** |
| 같은 저장소의 다른 git worktree가 있을 때, 기본 uninstall은 프로젝트 밖(HOME)의 Stop 활성화를 어떻게 할까요? (고르신 「worktree 있으면 거부」를 --purge 너머로 넓힐지) | **기본도 밖을 안 건드림** |
| 위 두 판정을 반영해 잠긴 의도(완수 조건 21개)를 승인하시겠어요? 승인하면 구현 루프에 들어갑니다. | **승인** |

인터뷰에서 에이전트가 기본값으로 적고 소유자가 이견을 달지 않은 것:

> 설치 **뒤에** 사용자가 스스로 고친 것(`settings.json` 에 더한 키 · `CLAUDE.md` 의 다른 줄)은 남기고 우리 몫만 걷는다.
> 증인 — 설치 → 실제 사용 → uninstall 뒤 **프로젝트 워킹트리와 HOME 스냅샷이 설치 전과 바이트로 같은가**. 세 OS CI 시험으로 건다.
> 범위 밖 — 사용자가 `PATH` 에 둔 `pal` 바이너리 · Claude Code 가 스스로 만든 파일(`settings.local.json` 등) · git 이력.
> 확대 — `narrative-pending.json` 을 `.gitignore` 블록에 넣는다.
