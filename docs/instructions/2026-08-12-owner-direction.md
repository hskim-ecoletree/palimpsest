## §1 — 지원 언어 넷이 전부 1급이다

> "kotlin 지원은 1급이야. java, javascript, typescript 도 마찬가지로 말이야.
> palimpsest 를 가장 먼저 적용할 프로젝트가 kotlin, java, svelte-5 (js/ts) 사용하고 있어서 그래"

**적용 대상이 boxwood 다.** 그리고 boxwood 는 언어가 저장소별로 갈려 있다
(각 저장소 HEAD 기준 · 고정 SHA 아님):

| 저장소 | Kotlin | Java | TS | Svelte | JS |
|---|---|---|---|---|---|
| `portal-backend` | **751** | 3 | | | |
| `boxwood-packages` | 34 | **431** | 22 | | 3 |
| `automation-engine` | | **346** | | | 3 |
| `external-client` | | **147** | | | |
| `frontend` | | | **721** | **634** | 89 |

**Java 가 세 저장소에 흩어져 있고 Kotlin 과 거의 겹치지 않는다.** 한 언어만 뚫으면
도구가 닿는 저장소가 하나뿐이라는 뜻이다.

### 대가 ① — 설계 문서가 틀렸다. 고쳤다

[stack §3.1](../plan/00-stack.md#31-p0에서-쓰는-것-여기서-늘리지-않는다)이 P0 의 파서를
`tree-sitter-typescript` 하나로 적고 Kotlin 을 §3.2 의 *"P0 후반 · 두 번째 언어"* 로
미뤄 뒀다. **이 지시가 그 순서를 무효화한다.** 같은 것을 두 곳에 다르게 적는 것이 곧
drift 이므로([계획 §7.4](../plan/README.md)) 문서를 이 지시에 맞췄다.

**TypeScript 를 빼는 것이 아니다** — 넷이 같은 층에 서고, 착수 순서만 Kotlin 이 앞선다.
Kotlin 이 앞서는 이유는 선호가 아니라 **거기에만 사전 등록된 대조값이 있기 때문**이다
([T7](../gates/preflight.md#t7--kotlin-파싱-사전-측정)의 94.30%).

### 대가 ② — `Capable<T>` 가 당장 짐을 진다

**이것이 이 지시의 가장 큰 결과다.** 언어가 넷인데 S0 이 하나만 뚫으면 나머지 셋에서
`pal symbols` 가 무엇을 출력해야 하는가. 빈 목록을 내면 **"선언이 없는 파일"과
"이 빌드가 Java 를 모른다"가 같은 출력이 된다** — [stack §5.3](../plan/00-stack.md#53-capablet--점진-구축이-정직함을-깨지-않게)이
*거짓 안전*이라 부른 바로 그것이고, [목표 §3.1](../plan/00-goals.md)의 정면 위반이다.

```
$ pal symbols Foo.kt      →  심볼 목록
$ pal symbols Foo.java    →  (이 빌드에 Java 추출 능력이 없습니다 — F02 미구축)
```

`Capable<T>` 는 [계획 §2](../plan/README.md)가 *"되돌릴 수 없는 것 둘"* 로 지정해
첫 커밋부터 집행하라고 한 것이다. **지시 §1 이 그것을 장식에서 하중 부재로 바꿨다** —
언어가 하나였다면 S0 에서 `Capable<T>` 를 쓸 자리가 없었다.

### 대가 ③ — `.svelte` 는 문법 하나 더 붙이는 일이 아니다

`frontend` 의 **634개**가 Svelte-5 다. Svelte 파일은 `<script>` 블록 안에 js/ts 가
들어 있어 **injection**(바깥 문법으로 파싱한 뒤 그 영역을 다른 문법에 넘기는 것)이 필요하다.
좌표·`body_digest`·스코프 체인이 전부 그 경계를 넘어야 한다.

**S0 에서 손대지 않는다. 기록만 남긴다.** 이것은 "다섯째 언어"가 아니라 **추출기 구조의 문제**이고,
어느 기능이 지는지 아직 배정되지 않았다.

### 무엇이 아직 등록되지 않았나

**Java · JavaScript · TypeScript 에는 대조값이 없다.** T7 은 Kotlin 만 쟀다.
셋의 추출 가능률은 아무도 재본 적이 없으므로, **셋의 게이트는 각각 따로 서야 하고
지금 숫자를 적지 않는다** — 적으면 그것은 근거가 아니라 소원이다([계획 §7.5](../plan/README.md)).

## §2 — S0 의 대조 오라클: 파일별 벡터

### 물어본 것

*"선언 추출이 잘 되었다고 보장할 수 있어? 비교가 큰 의미가 있나?"*

### 답 — 보장할 수 없다. 그리고 그것이 이 대조의 목적도 아니다

**T7 의 94.30% 는 품질이 아니라 이진값의 비율이다** — `선언을 하나라도 뽑을 수 있는 파일
1,058 / 1,122`. 파일에 최상위 선언이 17개 있는데 1개만 뽑아도 성공으로 집계된다.

| | 값 |
|---|---|
| 도구가 뽑은 선언 (전수) | **2,241** |
| 사람이 손으로 세어 본 선언 | **41** — 1.8% |
| 그 표본의 파일 단위 완전 일치 | **17/20 = 85%** |

**나머지 98.2% 는 아무도 검산하지 않았다.**

### 그래서 단일 백분율 대조는 우연히 통과한다

**파일당 첫 선언 하나만 뽑는 고장 난 추출기도 1,058/1,122 를 정확히 재현한다.** 이진값이니까.

그래서 오라클을 **파일별 선언 수 벡터 1,122개**로 바꾼다. T7 은 파일별 값을 남기지 않았으므로
CLI 레퍼런스를 직접 다시 돌려야 하고, **거기에 덤이 붙는다 — T7 자체가 재현되는지가
같은 회차에서 확인된다.** 소유자가 짚은 것이 T7 의 신뢰였으므로 그 검증을 공짜로 얻는 쪽을 택했다.

### 그럼에도 이 대조가 증명하는 것은 좁다

**벡터가 완전히 일치해도 증명되는 것은 "내 Rust 경로 == CLI 경로"까지다.**
둘은 같은 방식으로 틀릴 수 있고 실제로 틀린다 — T7 이 발견한 **조용한 오파싱 17건**은
파서가 오류를 내지 않으므로 양쪽 모두에서 똑같이 사라진다.

**추출 품질은 S0 의 질문이 아니다.** S0 이 판정하는 것은 [R-01](../plan/00-risks.md#r-01)이고,
대조의 일은 그 "완료"가 눈대중이 아니게 만드는 것 하나다. 품질은 [계획 §5](../plan/README.md)의
오라클 *"심볼 리콜 표본 — 손으로 센 선언 수 대 추출 수"* 가 지며, 소유 기능은 아직 미정이다.

## §3 — 허용 불일치 0건

같은 파일에 같은 문법으로 같은 종류의 선언을 뽑는다. **다를 이유가 없으므로 기대값이 0 이고,
0 이 아니면 그 차이는 전부 코드 탓이다** — 그것이 곧 R-01 의 관측이다.

**어긋난 파일 목록을 전부 게이트에 적는다.** 건수만 적고 목록을 생략하는 것은 이 합격선의 위반이다.

## §4 — 기한 2026-08-15

[R-01](../plan/00-risks.md#r-01)의 증상은 *"소유권·수명·트레잇 객체에서 막히면 **며칠이 사라진다**"* 이다.
**기한이 숫자가 아니면 그 증상을 관측할 수 없고, 관측할 수 없으면 판정이 성립하지 않는다.**

이슈 #37 과 [계획 §3](../plan/README.md)이 둘 다 *"며칠 안이다"* 로 적은 것의 **가장 좁은 읽기**를 택했다 — 3일.

**넘기면 [stack §1](../plan/00-stack.md#1-언어--rust-edition-2024)의 Rust 결정이 다시 열린다.**
초과 자체가 R-01 의 관측이므로, 기한을 넘긴 뒤 완성해도 게이트에는 **초과했다는 사실과
어디서 시간이 갔는지**를 적는다.
