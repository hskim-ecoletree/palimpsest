## §1 — Rust 가 다섯째 1급 언어다

**[2026-08-12 §1](2026-08-12-owner-direction.md) 을 갱신한다.** 그 문서의 원문은
그대로 살아 있다 — *"kotlin 지원은 1급이야. java, javascript, typescript 도
마찬가지로 말이야"* 는 **그때 소유자가 실제로 말한 것**이고 지우지 않는다.

### 왜 갱신하나 — 능력 부재가 자기적용을 막았다

[#66](https://github.com/hskim-ecoletree/palimpsest/issues/66) 이 잰 것:

```
palimpsest 에서 결박 가능한 좌표   7 개
그 좌표가 사는 파일               1 개  — corpus/tasks/f03-normalize-seeds.ts
```

**코어가 Rust 인데 추출기에 Rust 가 없다.** 그래서 *"이 도구가 자기 자신을
큐레이션한다"* 가 **코퍼스 픽스처 한 파일 위에서만** 섰다.

[R-19](../plan/00-risks.md) 는 자기적용을 *"**편향된** 표본"* 이라 불렀는데,
여기서는 **편향 이전에 능력 부재**다 — 표본이 치우친 것이 아니라 **잴 대상이 없다.**

### 대가

- `Language` enum 이 넷에서 다섯이 된다. **컴파일러가 안 잡는 자리가 셋** 있고
  (`from_name` 배열 · `const 일급` 배열 · CLI 의 손 목록) 그중 하나는
  **검사가 초록인 채로 안 재는** 형태다
- 「1급은 넷」을 현재형으로 말하는 코드 doc **아홉 자리**가 낡는다
- **동결된 판정 문서와 `corpus/criteria.toml` 은 고칠 수 없다** — 죽은 링크 검사도
  인용 검사도 그 모집단을 뺀다. 그것들은 넷이라고 말하는 채로 남고,
  그 사실을 게이트의 「범위 밖」에 적는다

## §2 — 중첩 순회 + L1

**「중첩 순회」와 「L2 스코프 해소」는 다른 결정이다.** 처음에 하나로 접혀 있었고
사전부검이 그것을 갈랐다.

`impl`·`mod` 안의 표식 25 건을 잡는 데 필요한 것은 **중첩 순회**이지
스코프 체인이 아니다. L2 는 `body_digest` 가 리네임에 안 흔들리게 하는 것이고,
그것은 *낡음의 정밀도* 문제이지 *결박의 존재* 문제가 아니다.

### 대가

- **얻는 것**: Rust 의 shadowing(`let x = 1; let x = f(x);` 가 관용이다)이
  `ScopeChain::resolve` 의 「가장 앞선 것」 팔을 상시 경로로 만드는 문제가
  **구조적으로 사라진다.** `Namespace` 가 둘뿐이라 Rust 의 매크로 이름 공간을
  못 담는 문제도 마찬가지다
- **잃는 것**: Rust 심볼의 `identity` 가 **전부 `Ordinal`** 이 된다.
  그래서 *"선언 순서에 취약한 것"* 과 *"그냥 L1 인 것"* 이 대장에서 같은 글자로
  나온다. **그 수를 여기 안 적는다** — 착수 시점에 적었던 6.1% 는 격리 스파이크의
  값이었고 재현되지 않았다. 세는 자리는 `--example coord_collisions` 다

## §3 — `#[cfg(test)]` 를 건너뛰지 않는다

> **"번복할게 #[cfg(test)] 도 진행해"**

인터뷰에서 *"안 센다"* 를 골랐다가 다음 라운드에 뒤집었다.

**추출기가 `cfg` 를 해석하지 않게 되어 규칙이 단순해진다.** 「소스에 있는 것을
낸다」 하나이고, `cfg(all(test, unix))` 같은 형태를 어떻게 읽을지가 안 생긴다.

### 대가

선언의 **22%**(자기 저장소 2,778 중 629)가 시험 안이라 **분모가 부푼다.**
그래서 합격선에 *"결박은 `#[cfg(test)]` 밖에 선다"* 를 **측정 전에** 걸었다.

그리고 `#[cfg(unix)] fn f` / `#[cfg(not(unix))] fn f` 처럼 갈린 동명 선언이
같은 좌표를 놓고 `ordinal` 을 받아 `identity_ceiling` 이 `Ordinal` 로 내린다.
**설계대로 동작하는 것**이고 판정의 「범위 밖」에 적는다.

## §4 — 손 표본이 정본이다

> **"github 에서 rust project 를 하나 선정해서 대상으로 해보는것은?"**

저장소를 고르는 것은 **모집단**이고, *"무엇이 정답인가"* 는 **오라클**이다.
둘은 다른 물음이라 따로 정했다.

**손 표본이 정본이고 기계 대조군이 음성 대조다.** 손 목록을 **추출기 코드보다 먼저**
커밋하고, 어긋나면 **어긋난 것을 게이트에 적는다** — 표본을 고쳐 맞추지 않는다.
그것을 이 회차의 **금지역**으로 등록했다.

## §5 — 외부 코퍼스는 `rust-lang/cargo`

자기 저장소 117 파일만으로는 [R-19](../plan/00-risks.md) 의 편향을 못 피하고,
**추출기가 palimpsest 의 코딩 습관에만 맞춰질 수** 있다.

핀은 `514c56dd7321eecbfdcf9b6479519cf4edfab906` 이고 모집단은
**`tests/testsuite/` 를 뺀 380** 이다.

### 대가

- `.rs` 1,372 중 **992 가 통합시험**이라 그것을 빼야 했다. 안 빼면 `snapbox` 의
  `str![[r#"…"#]]` 구문 때문에 **992 중 512 가 파싱 오류**를 내고, 「추출이
  정확한가」가 아니라 「그 구문을 읽는가」를 재게 된다
- 남은 380 안에도 **시험지원 24 파일**과 **파싱 오류 6 파일**이 있다.
  **빼지 않는다** — 규칙이 고른 것을 사후에 빼면 그것이 사후 조정이다. 표에 싣는다
- **CI 에 코퍼스 잡을 안 넣는다.** 3,071 파일을 세 OS × 매 커밋 클론하는 비용이
  실질이다. 그래서 이 축의 판정은 **이 기계 하나에서만 재현된다**

## §6 — 회차를 가른다

**초석 변경과 완성 작업이 한 push 에 들어가면 안 된다.**

이 저장소의 CI 는 `cancel-in-progress: true` 라 push 가 한 번이고,
골든 재축복(`--bless`)은 파일을 **통째로 다시 쓴다.** 같은 push 에 회귀 위험이
함께 있으면 **그 재축복이 회귀를 흡수한다** — CI 의 초록이 「회귀 없음」이 아니라
「회귀를 흡수함」이 된다.

**이 회차: 추출기와 오라클.** 다음 회차로 가른 것 다섯은 **넘김이 아니라 분할**이고
이슈로 선다([AGENTS.md](../../AGENTS.md) · `/round` §11③).

### 대가

`GRAMMAR_REV` 이 Kotlin rev 하나뿐이라 TypeScript 핀이 **이미** 캐시 키 밖에 있는
문제([ADR-0004](../adr/0004-cache-key-covers-every-input-that-decides-the-output.md)
위반)가 **한 회차 더 산다.** Rust 핀도 같은 자리에 놓인다.

**알고 두는 것이지 모르고 두는 것이 아니다** — 판정에 적는다.
