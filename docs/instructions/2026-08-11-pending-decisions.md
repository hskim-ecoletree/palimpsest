# 소유자 판단 대기 — 2026-08-11

> 이 문서는 **에이전트 → 소유자** 방향이다. `*-owner-direction.md` 의 반대이며,
> 판단이 내려지면 그쪽 형식으로 기록되고 이 문서는 링크만 남긴다.
>
> **상태는 이슈에 있다**([AGENTS.md §진행 규칙](../../AGENTS.md)). 이 문서는 상태를 복제하지 않고
> **판단에 필요한 사실만** 모은다 — 이슈를 읽고 코드를 뒤지지 않아도 결정할 수 있게.

P0-preflight 열한 작업 중 아홉이 판정됐다. 남은 둘(T2·T6)과 그것에 막힌 하나(T3)가
전부 **사람의 판단 시간**을 재는 것이라 에이전트가 대신할 수 없다 —
대신하는 순간 그 수치가 무효가 된다([R-23](../plan/00-risks.md#r-23)).

| | 판단 | 급한가 |
|---|---|---|
| **§1** | T2 판정표 결함의 처분 | **먼저** — 이것 없이 T2를 시작하면 되돌릴 수 없다 |
| **§2** | T6 저작 시간을 어떻게 얻을까 | T2와 함께 정하면 된다 |
| **§3** | T2를 T3의 기준선으로도 쓸까 | T2에 앉기 전 |

## §1 — T2 판정표에 결함이 둘 있다

**대상**: [이슈 #27](https://github.com/hskim-ecoletree/palimpsest/issues/27) ·
[`corpus/tasks/label-judgment-sheet.md`](../../corpus/tasks/label-judgment-sheet.md) ·
[`corpus/tasks/label-candidates.toml`](../../corpus/tasks/label-candidates.toml)

### 무엇이 잘못됐나

33행을 좌표로 세니 **고유 좌표가 28개다. 등록값 30이 아니다.**

| 중복 쌍 | 시퀀스 자리 | 심은 것인가 |
|---|---|---|
| `PermissionCheckAspect.kt:71#checkResourcePermission` | 5 → 11 | ✅ 설계됨 |
| `TenantInterceptor.kt:25#TenantInterceptor` | 16 → 22 | ✅ 설계됨 |
| `SystemPatController.kt:83#AuthenticationPrincipal` | 27 → 33 | ✅ 설계됨 |
| `MultiTenantTransactionManager.kt:166#validateTenantRegistration` | 4 → 12 | ❌ **사고** |
| `DashboardDto.kt:22#ProcessSummaryDto` | 15 → 19 | ❌ **사고** |

층화 표집이 층을 가로질러 같은 좌표를 두 번 뽑았다. 뒤엣것은 파일이 이미
오탐이라고 적어 둔 그 건이다(층 ②의 `[^{]*`가 줄을 넘어 DTO를 잡았다) —
**오탐을 남긴 것은 의도였으나 같은 좌표를 두 번 뽑은 것은 의도가 아니다.**

### 깨지는 것 셋

1. **`unique = 30`이 사실과 다르다** → 28. 이슈 제목 "라벨 판정 30건"과
   인수 기준 *"후보 목록 30건"* 이 이 표로는 안 채워진다.
2. **재질문율이 오염된다.** 분모는 3인데 판정자가 마주치는 반복은 **5회**다.
   순서가 11(심음) → 12(사고) → 19(사고) → 22 → 33 이라
   **22·33은 이미 반복을 세 번 겪은 뒤**다. 프라이밍이 걸린다.
   그리고 판정표가 33행을 한 화면에 보여주므로 눈으로 훑으면 중복이 그냥 보인다.
3. **블라인드가 이미 깨졌다 — 에이전트의 실수다.**
   결함을 보고하는 과정에서 **심은 중복의 자리(11·22·33)를 소유자에게 공개했다.**
   그 시점에 *이 판정표로* 재질문율을 재는 길이 닫혔다.

> **3번이 선택지를 좁힌다.** "그대로 진행하고 caveat만 단다"가 더 이상 성립하지 않는다 —
> 어디가 중복인지 아는 상태의 판정은 재질문율이 아니라 기억력 시험이다.

### 무엇이 아직 멀쩡한가

- **소요 시간 측정은 유효하다.** 블라인드를 요구하지 않는다.
- **후보 좌표는 살아 있다** — 30/30이 고정 SHA에서 해소된다(2026-08-11 확인).
- **사전 등록의 시각 규율은 지켜졌다** — 후보 고정 커밋 `4d0c97e`가 측정 시작보다 앞선다.
- **판정 대상 자체는 정당하다** — 28건 모두 실재하는 좌표다.

### 선택지

| | 무엇을 하나 | 얻는 것 | 잃는 것 |
|---|---|---|---|
| **(a)** | **재추첨 + 재배치.** 충돌한 2건을 등록된 표집 규칙으로 다시 뽑아 고유 30을 채우고, 심는 중복의 자리를 **새로 정한다(소유자에게 공개하지 않는다)**. 판정표를 한 건씩 여는 형태로 바꿔 눈으로 훑는 것도 막는다 | 인수 기준 넷을 **전부** 채운다. 재질문율이 살아난다 | 사전 등록 커밋 하나 추가. 소유자 시간은 아직 안 듦 |
| **(b)** | **재질문율만 기권.** 표는 그대로, 28건으로 보고, 소요 시간만 잰다. 재질문율은 "대조 불가"로 1급 기록 | 지금 바로 앉을 수 있다. 정직하다 | 인수 기준 하나가 빈다. [T11 M4](../gates/preflight.md#t11--g7-대조-장치-등록)와 같은 처분 |
| **(c)** | **T2 전체를 다시 짠다.** 코퍼스를 ditto로 바꿔 재표집 | boxwood 편의 표본 문제([R-19](../plan/00-risks.md#r-19))도 같이 던다 | 가장 비싸다. T4·T6이 boxwood 위에 서 있어 비교 가능성이 깨진다 |

**에이전트 권고: (a).** 소유자 시간이 아직 안 들어갔고 들어간 뒤엔 못 고친다.
비용은 에이전트 커밋 하나다. (b)는 되돌릴 수 없는 기권이고, (c)는 이 결함에 비해 과하다.

### 이 판단이 뒤집는 것

없다 — 이것은 절차의 판단이다. 뒤집히는 것은 **다음 §의 T2 결과**다.

## §2 — T6의 저작 시간을 어떻게 얻을까

**대상**: [이슈 #31](https://github.com/hskim-ecoletree/palimpsest/issues/31)

### 지금 어디까지 왔나

인수 기준 셋 중 **둘이 충족**됐다([게이트 §T6](../gates/preflight.md#t6--온톨로지-저작-가능성)).

| 기준 | 상태 |
|---|---|
| 개념 20개와 관계가 문서로 고정된다 | ✅ 개념 20 · 관계 16, `7c2f1a7`에 **코드를 찾기 전에** 커밋 |
| 지목 가능률이 기록된다 | ✅ **90%** (문서가 안 도와주면 **83.3%**) |
| 저작에 걸린 시간이 기록된다 (판단 성분만) | ❌ **못 쟀다** |

### 왜 못 쟀나 — 이것이 판단의 핵심이다

**개념 20개를 저작한 것은 에이전트다. 사람이 저작한 적이 없다.**
그러니 잴 사람 시간이 애초에 존재하지 않는다. 에이전트 소요를 그 자리에 적는 것은
[R-23](../plan/00-risks.md#r-23) 위반이라 하지 않았다.

### 선택지

| | 무엇을 하나 | 얻는 것 | 잃는 것 |
|---|---|---|---|
| **(a)** | **소유자가 다시 저작한다.** 다른 코퍼스(ditto 등)에서 개념 20개를 손으로 뽑고 시간을 잰다 | 진짜 측정. G4에 실물 근거가 생긴다 | 소유자 시간. 그리고 코퍼스가 달라 boxwood 지목률과 직접 비교가 안 된다 |
| **(b)** | **기권한다.** *"저작 시간 — 대조 불가. 사람이 저작한 적이 없다"* 로 1급 기록 | 정직하다. 지금 닫힌다 | **G4 판정이 빈 채로 남는다** |
| **(c)** | **T2와 같은 자리에서 잰다.** T2가 '사람의 라벨 판단 단가'를 주므로 개념 저작도 그 세션에서 표본으로 잰다 | 한 번 앉아 둘을 얻는다. 같은 조건이라 비교 가능 | 개념 저작과 라벨 판정은 다른 노동이다 — 한 수로 접으면 안 된다 |

**에이전트 권고: (c), 단 수를 접지 않는 조건.** T2에 앉는 김에 개념 저작도 재되
**두 수를 따로 적는다.** (b)는 G4를 빈 채로 두는데, G4는 감사(F15)의 생사가 걸린 자리다.

### 이 판단이 뒤집는 것

**G4** — *"사람이 라벨/팩/개념을 저작하지 않는다"*.
무너지면 목표 4(감사)가 전부 `Residual`이 되고 **감사를 산출 목록에서 내린다**.
§1의 T2 결과와 **같은 방향을 가리킨다** — 둘 다 나쁘게 나오면 F15·F20이 함께 내려간다.

## §3 — T2를 T3의 기준선으로도 쓸까

**대상**: [이슈 #28](https://github.com/hskim-ecoletree/palimpsest/issues/28) —
`blocked by #27`

### 왜 지금 정해야 하나

T3의 인수 기준이 이렇다:

> 넷 각각이 단가를 얼마나 내리는지 **분리해서** 기록된다 — 묶어서 재면 무엇이 값을 냈는지 모른다

| | 절감 장치 |
|---|---|
| ① | 이미 지불되는 승인에 올라타기 |
| ② | 일괄 승인 |
| ③ | 진척 가시화 |
| ④ | 거부도 기록 |

**분리 측정은 조건을 바꿔 여러 번 재야 한다.** T2를 한 번만 돌리면 기준선 하나만
생기고, 나중에 T3에서 비교할 대조 조건이 없다. **T2에 앉은 뒤에는 소유자가 이미
후보를 다 봤으므로 같은 표로 다시 못 잰다.**

### 선택지

| | 무엇을 하나 | 대가 |
|---|---|---|
| **(a)** | **T2를 순수 기준선으로만 돌린다.** 장치 없이 33건. T3는 나중에 별도 표본으로 | T2가 가볍다. T3가 새 표집을 요구 |
| **(b)** | **T2 안에서 층을 갈라 장치 ②·③을 켠다.** 예: 앞 절반은 건별 승인, 뒤 절반은 일괄 승인 | 한 번에 두 수. 단 순서 효과(뒤로 갈수록 빨라짐)와 장치 효과가 섞인다 |
| **(c)** | **T3를 지금 기권한다.** 넷 중 무엇을 만들지 근거 없이 정하고 그 사실을 적는다 | 가장 싸다. 계획의 논거가 빈다 |

**에이전트 권고: (a).** (b)는 학습 효과와 장치 효과를 못 가른다 — 33건짜리 표본에서
층을 또 가르면 층당 n이 16이라 [§5 규칙 2](../plan/features/P0-preflight.md)의 n≥5는
넘지만 순서 효과를 통제할 방법이 없다. **분리 측정을 진짜로 하려면 표본이 더 필요하고,
그건 T3의 몫이지 T2에 얹을 것이 아니다.**

### 이 판단이 뒤집는 것

직접은 없다. 다만 (c)를 고르면 **"넷 다 만들면 비싸다"는 문제가 근거 없이 결정된다.**

## 판단을 기록하는 법

결정하면 새 세션에서 이렇게 이어진다:

1. 결정을 [`docs/instructions/`](.)에 `YYYY-MM-DD-owner-direction.md`로 적거나, 이슈에 코멘트
2. §1이 (a)면 → 재표집 사전 등록 커밋 → 판정표 갱신 → **그다음에** 소유자가 앉는다
3. §1이 (b)면 → 판정표 상단 경고 블록 제거 → 바로 앉는다
4. 판정 결과는 `docs/gates/preflight.md` §T2에 **통과·반증·대조 불가** 셋 중 하나로

**판정 중 열지 말 것**: `label-candidates.toml`의 `[answer_key]`.
소요 시간만 잴 때도 마찬가지다 — 정답을 보면 판단 시간이 아니라 확인 시간이 된다.
