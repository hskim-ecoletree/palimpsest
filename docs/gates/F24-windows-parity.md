# F24-Windows 게이트 — **라이프사이클이 Windows 에서 같은 결과를 내는가** · **등록 → 판정**

**판정: 통과.** 반증 **0** · **대조 불가 0** · **안 재지는 것 5**(전부 등록됐고 까닭이 붙었다 — 그중 하나는 방어가 아니라 **서술**이 없는 것이다).

> ★ **이 게이트의 §5(다음으로 넘기는 것)는 전부 닫혔다** — [F24-크로스플랫폼](F24-cross-platform.md) 이 그 판정이다(2026-08-17).
> **안 재지는 것 5 → 0.** 그리고 그 다섯 중 **넷은 「못 하는 것」이 아니라 「안 한 것」**이었다.
>
> ⚠ **이 판정의 가장 큰 한계도 그 문서가 냈다: 여기 적힌 모든 측정은 Windows 에서만
> 이뤄졌고, 유닉스 쪽은 이 코드로 한 번도 컴파일된 적이 없었다.** 실제로 돌려 보니
> **Windows 가 가리고 있던 fixture 구멍 둘**이 나왔다 — 둘 다 이 문서가 「통과」로
> 세고 있던 자리다. *"한 플랫폼에서 재고 「선다」고 적지 마라"* 가 이 문서에 대해서도
> 적용된다.

★ **이 게이트는 [F24](F24-install-distribute.md) §5-다-1 「Windows 미검증」을 닫는다.**
그 항목이 적은 것은 이랬다 — *"지원 대상으로 **선언했으나** 빌드 0회 · 시험 0회 · CI 없음.
`#[cfg(unix)]` 로 갈린 자리 셋은 **다른 쪽 분기를 한 번도 안 밟았다**."*

이 회차가 실제로 밟았다. **그리고 그 셋 중 둘이 뚫려 있었다.**

`[f24-win]` 이 물은 것:

> **`pal` 의 라이프사이클과 동작이 Windows 에서 macOS/Linux 와 같은 결과를 내는가.**

⚠ **「같은 결과」의 뜻이 이 회차 중에 한 번 넓어졌다.** 처음에는 *"한 기계에서 유닉스와
같은 산출"* 로 읽었다. 소유자가 그것을 반증했다 (2026-08-17):

> *"동일한 하네스가 서로 다른 플랫폼에서 일관된 방법과 결과를 주지 않는다면 그
> 하네스를 쓰는 프로젝트에서는 품질이 들쭉날쭉할 텐데. 그것을 좋은 하네스라고 볼 수
> 있나? 한의학 의사와 정형외과 의사가 같이 집도를 하는 거잖아? 수술이 잘 되겠어?"*

**이 층의 소비자는 공유되는 프로젝트다.** 그러니 물음은 둘이었다:

| | 물음 |
|---|---|
| (가) | 같은 상황에서 **두 플랫폼이 같은 답**을 내는가 |
| (나) | 한 플랫폼이 낸 산출물을 **다른 플랫폼이 그대로 쓸 수 있는가** |

첫 판정은 (가)만 재고 (나)를 안 쟀다. 그리고 (가)조차 *"축은 달라도 된다"* 로 느슨하게
읽어서 **같은 상황에 rc 가 갈리는 것을 통과로 셌다.** 아래 §1-나·§1-다 가 그 둘을
다시 잰 결과이고, 결정은 [DESIGN §12.9(D34)](../DESIGN.md) · [ADR-0023](../adr/0023-consistent-method-and-result-across-platforms.md) 이다.

## 1. 무엇이 어긋나 있었나

### 가. 진짜 결함 다섯 — **전부 이 플랫폼에서만 다른 결과를 냈다**

| # | 어디 | 무엇이었나 | 왜 위험했나 |
|---|---|---|---|
| **1** | `doctor.rs` 검사 4 | `dir.join("pal")` — 확장자가 없다 | **검사가 뒤집혀 있었다.** `PATH` 에 `pal.exe` 를 둔 정상 설치가 **빨강**이고, 실행조차 안 되는 확장자 없는 사본만 초록이었다. 검사 4~6 은 **침묵하는 훅 실패를 잡는 유일한 문**이라 여기서 신뢰가 통째로 무너진다 |
| **2** | `hooks.rs` `실행할_수_있나` | 실행 가능성 검사가 `#[cfg(unix)]` 안 | 한 겹이 **통째로 빠졌다.** 주석이 그 사실을 적었지만 **적은 주석은 아무것도 안 막는다** |
| **3** | `guard.rs` `제자리에_써도_되나` | `nlink` 검사가 `#[cfg(unix)]` 안 | 실측: **rc=0 · 화면은 정상 설치 · 대상 밖 파일에 우리 블록이 실렸다.** `[f24]` ⑦ 이 이 플랫폼에서 **안 섰다** |
| **4** | `install.rs` `쓸_수_있는가` | 디렉터리의 읽기 전용 속성을 「쓸 수 없다」로 읽는다 | 실측: Windows 에서 그 속성은 **쓰기를 안 막는다**(*"커스터마이즈된 폴더"* 의 뜻이고 흔한 폴더에 흔히 붙는다). **멀쩡한 프로젝트에서 설치가 거부된다** — 1 번과 같은 형태의 뒤집힘 |
| **5** | `settings.rs` | `to_string_pretty` 가 언제나 LF | `core.autocrlf` 워킹트리에서 **되쓸 때마다 파일의 모든 줄이 바뀐다.** 블록에는 있던 규율이 여기만 없었다 |

### 나. 같은 상황에서 두 플랫폼이 다른 답을 내던 자리 — **하드링크**

첫 판정은 이것을 **통과**로 셌다. 유닉스는 `nlink` 를 세어 **rc=1 로 거부**하고 Windows
는 못 세니 **rc=0 으로 끊고 지나갔다** — *"보증(⑦)은 같으니 축이 달라도 된다"* 가 근거.

**그 근거가 반증됐다.** 같은 상황에 rc 가 갈리면 팀에게는 **런북이 둘**이다.
고를 수 있는 것은 셋이었고 둘은 탈락했다:

| 후보 | 판정 |
|---|---|
| 양쪽 다 **거부** | **불가능** — Windows 는 링크 수를 못 센다 |
| 양쪽 다 **끊는다** ← 고른 것 | 가능. 그리고 **첫 판의 거부 문구가 사람에게 적던 처방이 정확히 그것**(`cp` 로 갈아끼우기) |
| 축이 달라도 된다 | 반증됨 |

**산출**: 하드링크 시험이 **`#[cfg]` 없는 한 벌**이 됐다(전에는 유닉스용 둘 + Windows
용 하나 + 외침). 시험 파일의 모양 자체가 *"두 플랫폼이 같은 답을 낸다"* 의 증거다.

남는 비대칭은 **서술 하나** — 유닉스는 볼 수 있으니 *"끊었다"* 를 화면에 내고 Windows
는 못 낸다. 그 외침은 **방어가 아니라 서술이 없다**고 명시한다.

### 다. 한 플랫폼의 산출물을 다른 플랫폼이 못 쓰던 자리 — **커밋되는 절대 경로**

**첫 판정이 아예 안 쟀다.** 측정(2026-08-17 · 같은 저장소를 두 자리에 clone · A 의 pal
자리를 없앰):

| | 고치기 전 |
|---|---|
| 커밋된 파일에 실린 기계 고유 값 | `settings.json`·매니페스트의 훅 `command` = **A 기계의 절대 경로** |
| 받는 쪽 `doctor` 검사 6 | **빨강** |
| 받는 쪽의 훅 | **안 뜬다. 그리고 그 실패는 침묵한다** |
| 받는 쪽이 `install` 로 고치면 | 추적 파일 **둘이 바뀐다** |
| 그것을 커밋하면 | 준 쪽이 다시 빨개진다 — **핑퐁. 매 pull 마다 충돌** |

옛 결정의 근거는 *"PATH 이름은 못 찾으면 침묵한다"* 였는데, **그 근거는 한 기계만 볼 때만
선다** — 절대 경로는 다른 기계에서 **반드시** 없다. 가능한 침묵을 피하려다 **확정적인
침묵**을 모든 협업자에게 안겼다.

**고친 뒤** (같은 시나리오):

```text
A 가 커밋한 command        "pal"
커밋된 파일의 기계 고유 값   0
B: clone 만 하고 doctor     여섯 전부 초록   ← 아무것도 안 하고
B: install · update 뒤      git status 비어 있음
```

줄바꿈도 같은 축이었다 — 매니페스트가 `to_string_pretty` 의 LF 로 되쓰여서
`core.autocrlf` 워킹트리에서 **`pal` 을 돌릴 때마다 파일 전체가 바뀐 것으로 보였다.**
`settings.json`·블록에 이미 있던 규율을 매니페스트에도 세웠다.

### 라. 잡음 열셋 — **결함이 그 안에 묻혀 있었다**

| 어디 | 무엇이었나 |
|---|---|
| `xtask` 파생 문서 대조 | 바이트로 댔다 → CRLF 워킹트리에서 **언제나 실패**. 고쳐도 체크아웃이 되돌린다 |
| `xtask` `WatchEntry` 자리 대조 | `root.join("a/b")` 의 `/` 와 `read_dir` 의 `\` 가 섞여 **「자리가 늘었다」 거짓 실패** |
| 시험 `해시()` · `cmp` | `shasum`·`cmp` 를 `Command::new` → `NotFound`. ★ 게다가 `shasum` 은 **애초에 틀린 오라클**이었다(매니페스트는 **줄바꿈 정규화 뒤의** sha 를 적는다) |
| 시험 스냅샷 키 | 키가 `\` 인데 대조 상수는 `/` → **왕복 동일성 · 기존 파일 불가침 · 매니페스트 대조가 이 플랫폼에서 한 번도 안 재졌다** |
| `PATH` 앞에 붙이기 아홉 자리 | 구분자가 `:` 로 박혀 있었다. Windows 에서는 드라이브 문자에서 쪼개져 **`PATH` 가 통째로 망가진다** |
| `권한을_뺀다` 짝 | `#[cfg(not(unix))]` 에서 **무동작 stub** 인데 뒤의 단언은 *"빨개져야 한다"* — 아무것도 안 바꾸고 빨강을 요구했다 |
| `공백이_든_곳의_pal` | `dir.join("pal")` — 이 플랫폼에서 **애초에 실행 안 되는 파일**로 「정상 설치」를 재고 있었다 |
| `cargo-deny` | 미설치 |

★ **순서가 규율이었다.** 잡음을 먼저 걷었다 — 안 그러면 결함을 고쳐도 **고쳤는지 확인할
수단이 없다.** 첫 커밋이 그것 하나였고, 실패가 15 → 8 로 줄면서 **결함 둘이 드러났다**
(그중 1번은 `PATH` 구분자를 고치기 전까지 **하네스 탓에 가려져 있었다**).

## 2. 안 재지는 것 다섯 — **개수와 이유** (완료 조건 ②)

`cargo xtask test` 가 이것을 **등록**으로 센다. 실패를 「없어야 하는 것」이 아니라
**등록된 집합과 같은가**로 판정한다 — 새 실패도, 승격 뒤 남은 등록도 둘 다 걸린다.

| 시험 | 무엇이 없나 | 왜 |
|---|---|---|
| `모드와_심링크_보존이_…` | **성질** | 모드 비트는 **개념이 없고**, 파일 심링크는 특권이 있어야 만들어진다. ★ 그리고 **D34 가 이 플랫폼의 파일 정체성 보존을 일부러 포기했다** — 하드링크로 밖이 새는 것을 막는 대가다. 「아직 안 쟀다」가 아니라 **「일부는 일부러 안 지킨다」** 다 |
| `쓰기_불가_디렉터리가_…` | **fixture** | 읽기 전용 속성이 디렉터리 쓰기를 안 막는다(실측). 진짜 fixture 는 ACL(`icacls`)이고 std 밖이다. **파일 축은 승격됐다** |
| `파일_심링크_경계가_…` | **fixture** | 파일 심링크에 `SeCreateSymbolicLinkPrivilege` 가 필요하다. **디렉터리 축은 junction 으로 승격됐다** |
| `파이프_방어가_…` | **fixture** | FIFO 가 이 플랫폼에 없다 |
| `끊었다는_말이_…` | ★ **서술** — 방어가 아니다 | 하드링크 방어는 이 플랫폼에서도 **선다**(`설치가_하드링크를_끊고_밖을_안_고친다` 가 잰다). 못 하는 것은 *"끊었다"* 를 화면에 내는 일뿐이다 — 링크 수를 셀 수 없어서 **언제 끊었는지 모른다** |

★ **셋째 칸을 새로 만들었다.** 「방어가 없다」와 「fixture 가 안 선다」와 「말을 못 한다」는
전부 다른 것이고, 하나로 뭉치면 다음 사람이 **없는 방어를 있다고 읽거나 그 반대로 읽는다.**

★ **못 재는 것을 초록으로 안 바꿨다.** 통과로 만들면 그 자리는 *"아무것도 안 재면서
초록"* 이 되고, 그것이 짝 없는 `cfg` 에 대해 이 저장소가 금지한 바로 그 상태다.

★ **하나의 미측정 사실은 한 곳에서만 외친다.** 「쓰기 불가 디렉터리」를 두 자리에서
외치고 있었고, 같은 것을 두 곳에 적는 것이 곧 drift 다(진행 규칙 4) — 하나로 합쳤다.

---

## 3. 승격 셋 — **외침이 시험이 됐다** (완료 조건 ③)

| 축 | 무엇으로 세웠나 | 무엇이 나왔나 |
|---|---|---|
| **하드링크** | `std::fs::hard_link`(이식 가능) · ★ **`#[cfg]` 없는 한 벌** | **뚫려 있었다.** 이제 「끊고 쓰기」로 막고 **두 플랫폼이 같은 답을 낸다**. 네 칸을 잰다 — ① 밖이 안 바뀐다 ② **안에는 실제로 썼다** ③ **링크가 실제로 끊겼다**(안쪽을 또 고쳐도 밖이 안 따라온다) ④ 임시 파일 잔해 0 |
| **읽기 전용 되감기** | `Permissions::set_readonly`(이식 가능) | 파일 축이 **모든 플랫폼에서** 돈다. 실측: 양쪽에서 **쓰기가 실제로 막힌다.** `[f24]` ②(부분 설치 금지)가 이 플랫폼에서 처음 판정한다 |
| **junction 경계** | `cmd /C mklink /J` | 옛 외침이 적은 이유는 **절반만 맞았다** — 심링크는 특권이 필요하지만 **디렉터리 junction 은 일반 사용자가 만든다.** `.claude` 를 밖으로 빼는 형태가 정확히 소유자가 금지한 구조이고, 방어가 **선다** |

⚠ **`cmd` 를 쓰는 것을 정당화한다.** 걷어낸 `shasum`·`cmp` 는 이 플랫폼에 **없는**
도구였고, `cmd.exe` 는 **플랫폼의 일부**이며 여기서 재려는 것이 **플랫폼 기능 그 자체**다.

## 4. 이 게이트가 판정하지 않는 것

- **`claude` 하네스가 실제로 서브에이전트를 막았는가.** [F24](F24-install-distribute.md)
  ⑧-b 가 대조 불가로 남긴 그 칸이고, 이 회차도 안 열었다.
- **배포**(F24 ⑩). 저장소 가시성 결정 대기이고 이 회차의 범위 밖이다.
- **`symbols`·`bind`·`query`… 의 기능 자체.** 범위를 가르는 문장 하나였다 —
  *"이 자리가 플랫폼 때문에 다른 결과를 내는가."*
- ★ **CI 가 실제로 도는가.** `.github/workflows/ci.yml` 이 섰고 그 안의 두 명령은
  이 기계에서 실측했지만, **runner 에서는 아직 한 번도 안 돌았다.**

⚠ **등록 문장이 산출과 어긋난 자리 하나.** 완료 조건 ②③④ 는 *"고친다"* 를 전제로
쓰였는데 이 회차가 한 일의 절반은 **하네스가 거짓말하던 것을 걷어내는 것**이었다.
잡음 열셋 중 넷은 **초록을 내면서 아무것도 안 재고 있었다**(스냅샷 키 · 무동작 stub ·
확장자 없는 fixture · `PATH` 구분자). 그것들은 「고친 것」이 아니라 **「없던 측정을
세운 것」**이다. 다음 회차가 이 구분을 등록에 실을지 정할 일이다.

## 5. 다음으로 넘기는 것

> ★ **아래는 전부 닫혔다** — [F24-크로스플랫폼](F24-cross-platform.md) §6 이 항목별
> 판정을 진다. 이 절은 **그때 무엇이 열려 있었는지의 기록**으로 남긴다(지우면 다음
> 사람이 「무엇이 어떻게 닫혔는지」를 못 읽는다).

**여기가 이 회차 발견의 단일 진실이다.** 이슈로 또 열지 않는다(AGENTS.md 운영 순서 1).

### 가. 외침 다섯 — **영구인 것과 「아직」인 것을 가른다**

⚠ 앞 판정은 이 다섯을 뭉뚱그려 *"전부 fixture 의 한계"* 라고 적었다. **정확하지 않다.**
성질이 셋으로 갈린다:

| 외침 | 성질 | 무엇을 하면 없어지나 |
|---|---|---|
| `모드와_심링크_보존이_…` | **영구 + 일부는 의도** | 모드 비트는 이 플랫폼에 **개념이 없다.** 파일 정체성 보존은 D34 가 **일부러 포기**했다 |
| `끊었다는_말이_…` | **영구(서술만)** | 안정 채널이 링크 수를 열어 주면 없어진다. **방어는 이미 선다** |
| `파이프_방어가_…` | **영구에 가깝다** | FIFO 가 없다. 다만 그 문(`일반_파일이거나_없나`)이 막는 **다른 종류**(디렉터리 등)로 **부분 승격은 가능하다** — 안 했다 |
| `쓰기_불가_디렉터리가_…` | ★ **「아직」이다** | **`icacls` 로 세울 수 있다.** 이 회차가 junction 에 `cmd` 를 쓰면서 *"플랫폼의 일부인 도구는 정당하다"* 를 이미 인정했으므로 **같은 논리가 여기에도 걸린다.** 안 한 이유는 시험이 중간에 죽으면 ACL 이 남아 임시 방을 못 지우기 때문이고, 그 처리를 안 했다 |
| `파일_심링크_경계가_…` | ★ **「아직」이다** | 개발자 모드나 `SeCreateSymbolicLinkPrivilege` 가 있는 기계(예: CI runner)에서는 **선다.** 「되면 재고 안 되면 시끄럽게 실패」 형태로 바꾸면 그 환경에서 실제로 판정한다 |

즉 **다섯 중 둘은 못 고치는 것이 아니라 이 회차가 안 한 것**이다. 그 구분을 여기 적는다 —
안 그러면 다음 사람이 **할 수 있는 것을 못 하는 것으로 읽는다.**

### 나. 측정으로 남은 것

| # | 넘기는 것 | 지금 아는 것 |
|---|---|---|
| 1 | ★ **CI 가 runner 에서 아직 안 돌았다** | 워크플로가 섰고 두 명령은 이 기계에서 실측했다. **첫 회차의 판정은 다음 회차가 본다** — 특히 windows runner 의 `core.autocrlf` 가 우리가 건 `git config --global` 대로 서는지 |
| 2 | **깊은 I/O 오류 문맥의 절대 경로에 `\\?\` 가 남는다** | 55자리다. 화면(설치 배너 · `doctor` 검사 3·4)과 `settings.json` 의 `command` 는 걷었다. 남은 자리들은 **바깥 문장이 이미 상대 경로로 무엇인지 말한다**(실측: 잠긴 파일 제거 화면) |
| 3 | **`settings.json` 의 직렬화 「형태」는 왕복해도 안 돌아온다** | 들여쓰기·키 순서가 우리 것이 된다. **플랫폼 무관**하고 [F24](F24-install-distribute.md) ⑥ 의 값 단위 예외 안이라 이 회차의 범위 밖이었다. 줄바꿈만 고쳤다. 사용자의 JSON 이 이미 `to_string_pretty` 형태면 왕복이 **바이트 동일**이다(실측) |
| 4 | **`x86_64-pc-windows-msvc` 배포 경로** | 빌드는 서지만 [F24](F24-install-distribute.md) ⑩ 이 여전히 대조 불가다. stack §7 의 배포 타깃 목록에 이 타깃이 있는지도 확인 안 했다 |
| 5 | **`cmd` 의존이 시험에 하나 생겼다** | junction fixture. `cmd.exe` 없는 Windows(Nano Server 등)에서는 이 시험이 못 선다 — 그때는 **fixture 가 안 서는 것**이지 방어가 없는 것이 아니다. 그 구분을 시험이 아직 안 낸다 |

### 다. 결정이 필요한 자리

| # | 미결 | 지금 아는 것 |
|---|---|---|
| 1 | **`MAX_PATH` 를 넘는 경로에서 전부 서는가** | `winpath` 가 길면 `\\?\` 를 안 뗀다(시험이 그 분기를 잰다). 그러나 **긴 경로에서 라이프사이클 전체를 돌려 본 적은 없다** |
| 2 | **유닉스도 「끊고 쓰기」로 통일할지** | 지금은 유닉스가 **거부**하고 Windows 가 **끊는다**(D34). 보증은 같고 상호작용이 다르다. 안정 채널에 링크 수를 내는 문이 열리면 **세는 쪽으로 통일한다**고 D34 가 적었다 |
| 3 | **`cargo xtask test` 를 유닉스에서도 CI 진입점으로 쓸지** | 지금 워크플로가 두 플랫폼에서 그것을 부른다. 유닉스 등록은 비어야 하고 시험이 그것을 못 박는다 |
