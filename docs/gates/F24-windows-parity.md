# F24-Windows 게이트 — **라이프사이클이 Windows 에서 같은 결과를 내는가** · **등록 → 판정**

**판정: 통과.** 반증 **0** · **대조 불가 0** · **안 재지는 것 4**(전부 등록됐고 까닭이 붙었다).

★ **이 게이트는 [F24](F24-install-distribute.md) §5-다-1 「Windows 미검증」을 닫는다.**
그 항목이 적은 것은 이랬다 — *"지원 대상으로 **선언했으나** 빌드 0회 · 시험 0회 · CI 없음.
`#[cfg(unix)]` 로 갈린 자리 셋은 **다른 쪽 분기를 한 번도 안 밟았다**."*

이 회차가 실제로 밟았다. **그리고 그 셋 중 둘이 뚫려 있었다.**

`[f24-win]` 이 물은 것:

> **`pal` 의 라이프사이클과 동작이 Windows 에서 macOS/Linux 와 같은 결과를 내는가.**

⚠ **「같은 결과」의 뜻을 먼저 못박는다.** 같은 **코드 경로**가 아니라 같은 **결과**다.
플랫폼이 볼 수 없는 것이 있으면 축을 바꿔서라도 **보증을 같게** 만든다 —
그 결정이 [DESIGN §12.9(D34)](../DESIGN.md) 이고, 이 게이트의 ⑦ 이 그 위에 선다.

## ★ 판정 — 완료 조건 넷에 대해

**어떻게 쟀나.** 아래 전부를 **이 회차가 Windows 11 Pro(10.0.26200) 에서 직접 실행해서**
관측했다. 기준선:

```text
HEAD        c8d13fa1f14b
rustc       1.97.1 · x86_64-pc-windows-msvc
git         2.55.0.windows.3 · core.autocrlf = true
권한        관리자 아님 · 개발자 모드 꺼짐 → 심링크 생성 불가 / junction·하드링크 가능
```

| | 완료 조건 | 판정 | 무엇을 관측했나 |
|---|---|---|---|
| **①** | `cargo xtask check` 가 **Windows 에서 통과한다** | **통과** | **16/16.** `cargo-deny` 포함. 회차 시작 시점에는 「스키마 정합」·「카탈로그 정합」이 **손쓸 수 없는 빨강**이었다 — 체크아웃된 문서가 CRLF 이고 `render_*_doc()` 이 LF 라 `cargo xtask schema-doc` 으로 "고쳐도" 다음 체크아웃이 되돌렸다 |
| **②** | 시험의 실패가 **의도된 외침만** 남는다 | **통과** | **781 통과 · 4 실패 · 1 무시.** 회차 시작은 **539 · 15 · 1**(macOS: 558 · 0 · 1). 남은 넷은 전부 fixture 의 한계이고 **까닭과 함께 `xtask` 에 등록**돼 있다(§2) |
| **③** | 하드링크 · 읽기 전용 되감기 · junction 경계가 **실제로 판정한다** | **통과** | 셋 다 승격됐다. 하드링크는 **뚫려 있었고**(rc=0 으로 대상 밖에 우리 블록이 실렸다) 이제 막힌다 |
| **④** | `%TEMP%` 새 저장소에서 왕복이 **전부 rc=0 · 6검사 초록 · git status 깨끗** | **통과** | 아래 산출 그대로 |

```text
install rc=0 · update rc=0 · uninstall rc=0
doctor --install → 여섯 전부 ok
uninstall 후 git status: (비어 있음)
CLAUDE.md · .gitignore · settings.json  전부 바이트 동일
~/.claude/pal · agents/pal-orchestrator.md · commands/pal  전부 없음   ← ⑦ 의 뒷받침
```

**어긋남 0.** 그러나 **등록 문장 하나가 산출과 어긋난다** — 완료 조건 ②③④ 는 *"고친다"*
를 전제로 쓰였는데, 실제로 이 회차가 한 일의 절반은 **하네스가 거짓말하던 것을 걷어내는
것**이었다. 그 어긋남은 §4 에 남긴다.

## 1. 진짜 결함 다섯 — **전부 이 플랫폼에서만 다른 결과를 냈다**

| # | 어디 | 무엇이었나 | 왜 위험했나 |
|---|---|---|---|
| **1** | `doctor.rs` 검사 4 | `dir.join("pal")` — 확장자가 없다 | **검사가 뒤집혀 있었다.** `PATH` 에 `pal.exe` 를 둔 정상 설치가 **빨강**이고, 실행조차 안 되는 확장자 없는 사본만 초록이었다. 검사 4~6 은 **침묵하는 훅 실패를 잡는 유일한 문**이라 여기서 신뢰가 통째로 무너진다 |
| **2** | `hooks.rs` `실행할_수_있나` | 실행 가능성 검사가 `#[cfg(unix)]` 안 | 한 겹이 **통째로 빠졌다.** 주석이 그 사실을 적었지만 **적은 주석은 아무것도 안 막는다** |
| **3** | `guard.rs` `제자리에_써도_되나` | `nlink` 검사가 `#[cfg(unix)]` 안 | 실측: **rc=0 · 화면은 정상 설치 · 대상 밖 파일에 우리 블록이 실렸다.** `[f24]` ⑦ 이 이 플랫폼에서 **안 섰다** |
| **4** | `install.rs` `쓸_수_있는가` | 디렉터리의 읽기 전용 속성을 「쓸 수 없다」로 읽는다 | 실측: Windows 에서 그 속성은 **쓰기를 안 막는다**(*"커스터마이즈된 폴더"* 의 뜻이고 흔한 폴더에 흔히 붙는다). **멀쩡한 프로젝트에서 설치가 거부된다** — 1 번과 같은 형태의 뒤집힘 |
| **5** | `settings.rs` | `to_string_pretty` 가 언제나 LF | `core.autocrlf` 워킹트리에서 **되쓸 때마다 파일의 모든 줄이 바뀐다.** 블록에는 있던 규율이 여기만 없었다 |

### 그리고 잡음 열셋 — **결함 다섯이 그 안에 묻혀 있었다**

| 어디 | 무엇이었나 |
|---|---|
| `xtask` 파생 문서 대조 | 바이트로 댔다 → CRLF 워킹트리에서 **언제나 실패**. 고쳐도 체크아웃이 되돌린다 |
| `xtask` `WatchEntry` 자리 대조 | `root.join("a/b")` 의 `/` 와 `read_dir` 의 `\` 가 섞여 **「자리가 늘었다」 거짓 실패** |
| 시험 `해시()` · `cmp` | `shasum`·`cmp` 를 `Command::new` → `NotFound`. ★ 게다가 `shasum` 은 **애초에 틀린 오라클**이었다(매니페스트는 **줄바꿈 정규화 뒤의** sha 를 적는다) |
| 시험 스냅샷 키 | 키가 `\` 인데 대조 상수는 `/` → **왕복 동일성 · 기존 파일 불가침 · 매니페스트 대조가 이 플랫폼에서 한 번도 안 재졌다** |
| `PATH` 앞에 붙이기 아홉 자리 | 구분자가 `:` 로 박혀 있었다. Windows 에서는 드라이브 문자에서 쪼개져 **`PATH` 가 통째로 망가진다** |
| `권한을_뺀다` 짝 | `#[cfg(not(unix))]` 에서 **무동작 stub** 인데 뒤의 단언은 *"빨개져야 한다"* — 아무것도 안 바꾸고 빨강을 요구했다 |
| `공백이_든_곳의_pal` | `dir.join("pal")` — 이 플랫폼에서 **애초에 실행 안 되는 파일**로 「정상 설치」를 재고 있었다 |
| `cargo-deny` | 미설치 |

★ **순서가 규율이었다.** 잡음을 먼저 걷었다 — 안 그러면 결함을 고쳐도 **고쳤는지 확인할
수단이 없다.** 첫 커밋이 그것 하나였고, 실패가 15 → 8 로 줄면서 **결함 둘이 드러났다**
(그중 1번은 `PATH` 구분자를 고치기 전까지 **하네스 탓에 가려져 있었다**).

## 2. 안 재지는 것 넷 — **개수와 이유** (완료 조건 ②)

`cargo xtask test` 가 이것을 **등록**으로 센다. 실패를 「없어야 하는 것」이 아니라
**등록된 집합과 같은가**로 판정한다 — 새 실패도, 승격 뒤 남은 등록도 둘 다 걸린다.

| 시험 | 왜 이 플랫폼에서 못 재나 |
|---|---|
| `모드와_심링크_보존이_…` | 모드 비트는 **개념이 없고**, 파일 심링크는 특권이 있어야 만들어진다. ★ 그리고 **D34 가 이 플랫폼의 파일 정체성 보존을 일부러 포기했다** — 하드링크로 밖이 새는 것을 막는 대가다. 「아직 안 쟀다」가 아니라 **「일부는 일부러 안 지킨다」** 다 |
| `쓰기_불가_디렉터리가_…` | 읽기 전용 속성이 디렉터리 쓰기를 안 막는다(실측). 진짜 fixture 는 ACL(`icacls`)이고 std 밖이다. **파일 축은 승격됐다** |
| `파일_심링크_경계가_…` | 파일 심링크에 `SeCreateSymbolicLinkPrivilege` 가 필요하다. **디렉터리 축은 junction 으로 승격됐다** |
| `파이프_방어가_…` | FIFO 가 이 플랫폼에 없다 |

★ **못 재는 것을 초록으로 안 바꿨다.** 통과로 만들면 그 자리는 *"아무것도 안 재면서
초록"* 이 되고, 그것이 짝 없는 `cfg` 에 대해 이 저장소가 금지한 바로 그 상태다.

★ **하나의 미측정 사실은 한 곳에서만 외친다.** 「쓰기 불가 디렉터리」를 두 자리에서
외치고 있었고, 같은 것을 두 곳에 적는 것이 곧 drift 다(진행 규칙 4) — 하나로 합쳤다.

## 3. 승격 셋 — **외침이 시험이 됐다** (완료 조건 ③)

| 축 | 무엇으로 세웠나 | 무엇이 나왔나 |
|---|---|---|
| **하드링크** | `std::fs::hard_link`(이식 가능) | **뚫려 있었다.** 이제 「끊고 쓰기」로 막는다. 네 칸을 잰다 — ① 밖이 안 바뀐다 ② **안에는 실제로 썼다** ③ **링크가 실제로 끊겼다**(안쪽을 또 고쳐도 밖이 안 따라온다) ④ 임시 파일 잔해 0 |
| **읽기 전용 되감기** | `Permissions::set_readonly`(이식 가능) | 파일 축이 **모든 플랫폼에서** 돈다. 실측: 양쪽에서 **쓰기가 실제로 막힌다.** `[f24]` ②(부분 설치 금지)가 이 플랫폼에서 처음 판정한다 |
| **junction 경계** | `cmd /C mklink /J` | 옛 외침이 적은 이유는 **절반만 맞았다** — 심링크는 특권이 필요하지만 **디렉터리 junction 은 일반 사용자가 만든다.** `.claude` 를 밖으로 빼는 형태가 정확히 소유자가 금지한 구조이고, 방어가 **선다** |

⚠ **`cmd` 를 쓰는 것을 정당화한다.** 걷어낸 `shasum`·`cmp` 는 이 플랫폼에 **없는**
도구였고, `cmd.exe` 는 **플랫폼의 일부**이며 여기서 재려는 것이 **플랫폼 기능 그 자체**다.

## 4. 이 게이트가 판정하지 않는 것

- **`claude` 하네스가 실제로 서브에이전트를 막았는가.** [F24](F24-install-distribute.md)
  ⑧-b 가 대조 불가로 남긴 그 칸이고, 이 회차도 안 열었다.
- **배포**(F24 ⑩). 저장소 가시성 결정 대기이고 이 회차의 범위 밖이다.
- **`symbols`·`bind`·`query`… 의 기능 자체.** 범위를 가르는 문장 하나였다 —
  *"이 자리가 플랫폼 때문에 다른 결과를 내는가."*
- ★ **CI 가 실제로 도는가.** `.github/workflows/ci.yml` 이 섰고 그 안의 두 명령은
  이 기계에서 실측했지만, **runner 에서는 아직 한 번도 안 돌았다.**

⚠ **등록 문장이 산출과 어긋난 자리 하나.** 완료 조건 ②③④ 는 *"고친다"* 를 전제로
쓰였는데 이 회차가 한 일의 절반은 **하네스가 거짓말하던 것을 걷어내는 것**이었다.
잡음 열셋 중 넷은 **초록을 내면서 아무것도 안 재고 있었다**(스냅샷 키 · 무동작 stub ·
확장자 없는 fixture · `PATH` 구분자). 그것들은 「고친 것」이 아니라 **「없던 측정을
세운 것」**이다. 다음 회차가 이 구분을 등록에 실을지 정할 일이다.

## 5. 다음으로 넘기는 것

**여기가 이 회차 발견의 단일 진실이다.** 이슈로 또 열지 않는다(AGENTS.md 운영 순서 1).

### 가. 측정으로 남은 것

| # | 넘기는 것 | 지금 아는 것 |
|---|---|---|
| 1 | ★ **CI 가 runner 에서 아직 안 돌았다** | 워크플로가 섰고 두 명령은 이 기계에서 실측했다. **첫 회차의 판정은 다음 회차가 본다** — 특히 windows runner 의 `core.autocrlf` 가 우리가 건 `git config --global` 대로 서는지 |
| 2 | **깊은 I/O 오류 문맥의 절대 경로에 `\\?\` 가 남는다** | 55자리다. 화면(설치 배너 · `doctor` 검사 3·4)과 `settings.json` 의 `command` 는 걷었다. 남은 자리들은 **바깥 문장이 이미 상대 경로로 무엇인지 말한다**(실측: 잠긴 파일 제거 화면) |
| 3 | **`settings.json` 의 직렬화 「형태」는 왕복해도 안 돌아온다** | 들여쓰기·키 순서가 우리 것이 된다. **플랫폼 무관**하고 [F24](F24-install-distribute.md) ⑥ 의 값 단위 예외 안이라 이 회차의 범위 밖이었다. 줄바꿈만 고쳤다. 사용자의 JSON 이 이미 `to_string_pretty` 형태면 왕복이 **바이트 동일**이다(실측) |
| 4 | **`x86_64-pc-windows-msvc` 배포 경로** | 빌드는 서지만 [F24](F24-install-distribute.md) ⑩ 이 여전히 대조 불가다. stack §7 의 배포 타깃 목록에 이 타깃이 있는지도 확인 안 했다 |
| 5 | **`cmd` 의존이 시험에 하나 생겼다** | junction fixture. `cmd.exe` 없는 Windows(Nano Server 등)에서는 이 시험이 못 선다 — 그때는 **fixture 가 안 서는 것**이지 방어가 없는 것이 아니다. 그 구분을 시험이 아직 안 낸다 |

### 나. 결정이 필요한 자리

| # | 미결 | 지금 아는 것 |
|---|---|---|
| 1 | **`MAX_PATH` 를 넘는 경로에서 전부 서는가** | `winpath` 가 길면 `\\?\` 를 안 뗀다(시험이 그 분기를 잰다). 그러나 **긴 경로에서 라이프사이클 전체를 돌려 본 적은 없다** |
| 2 | **유닉스도 「끊고 쓰기」로 통일할지** | 지금은 유닉스가 **거부**하고 Windows 가 **끊는다**(D34). 보증은 같고 상호작용이 다르다. 안정 채널에 링크 수를 내는 문이 열리면 **세는 쪽으로 통일한다**고 D34 가 적었다 |
| 3 | **`cargo xtask test` 를 유닉스에서도 CI 진입점으로 쓸지** | 지금 워크플로가 두 플랫폼에서 그것을 부른다. 유닉스 등록은 비어야 하고 시험이 그것을 못 박는다 |
