# F22-3 게이트 — 사슬의 마디 · 판정 기록

**판정: 대조 불가 (2026-08-12).**

**등록된 오라클을 이 빌드로 잴 수 없다.** [T10](preflight.md#t10--여정결함의-올라탈-곳)이
잰 표본은 ditto 의 커밋 5 건이고 ditto 는 **TypeScript** 다. 이 빌드의 추출기는
**Kotlin 하나**다(`pal_extract::capability` — Java · JavaScript · TypeScript 는 전부
`NotBuilt{F02}`). 그래서 발현 좌표를 하나도 세울 수 없고, 등록값
**발현 4/5 · 도입 4/5 · 엄격 하한 2/5** 는 재어지지 않는다.

| ④ 담기지 않는 결함 계수 | **1** | **대조 불가** — T10 표본에서는 5/5 가 `NoExtractor` 다 |
| ⑤ `NotBuilt` 경로 | 빈 목록이 아님 | **통과** — `Journey` 거주 불가 · `NoExtractor` 가 `CapabilityId` 를 싣는다 |

## 대조 불가가 드러낸 것 — **계획의 두 자리가 겹치지 않는다**

이것이 이 게이트에서 가장 중요한 산출이다.

> **P0-preflight 의 오라클(ditto · TypeScript)과 P0 가 실제로 만든 능력(Kotlin 추출기)이
> 겹치지 않는다.**

T10 은 코드 없이 손으로 측정했으므로 언어가 상관없었다. 그런데 [stack §3.1 의 착수
순서 변경](../plan/00-stack.md)(2026-08-12)이 **Kotlin 을 첫 언어로** 세웠고, 그 결정은
적용 대상(boxwood)을 보고 내려진 것이다. 두 결정 다 옳았고 **아무도 그 둘이 만나는
자리를 보지 않았다.**

결과: **T10 이 등록한 수치는 F02 가 TypeScript 추출기를 세울 때까지 재어질 수 없다.**
이것은 F22-3 의 실패가 아니라 계획의 사실이고, 그래서 판정이 반증이 아니라 대조 불가다.

같은 종류의 자리가 더 있는지는 세어 보지 않았다 — **P0-preflight 의 다른 오라클들이
어느 언어의 저장소에서 측정됐는지**를 확인하는 것은 이 게이트 밖이고, 빚으로 남긴다.

## 첫 구현이 이 도구가 고발한 문제를 저질렀다

**음성 대조가 아니라 실행 자체가 잡았다.** 첫 실행에서 다섯 건이 전부 이렇게 나왔다:

```
■ **담기지 않았다** — 세어서 표시한다
    코드는 변했는데 의미가 변한 심볼이 없다 (포매팅·주석·신규 파일)
```

**거짓이다.** 코드는 의미까지 변했고, 우리가 **읽지 못했을** 뿐이다.
`digests_at` 이 `Capable::NotBuilt` 를 받아 빈 표로 바꾸고 있었고, 그 빈 표가
*"변한 심볼 0 개"* 로 세어졌다 — **`Finding 0` 과 "감사를 안 만들었음"이 같은 출력이
되는 것**([목표 §3.1](../plan/00-goals.md) · S2 합격선 ②)의 정확한 재현이다.

고친 형태는 [`Uncapturable::NoExtractor`](../../crates/pal-core/src/chain.rs) 이고
**능력 부재가 값으로 실린다**:

```
■ **담기지 않았다** — 세어서 표시한다
    이 빌드에 그 언어의 추출기가 없습니다 — F02 미구축 (typescript-extraction)
    **변한 것이 없다는 뜻이 아닙니다.** 읽지 못했다는 뜻입니다.
```

그리고 `DefectReport.not_extracted` 가 **읽지 못한 파일을 산출에 남긴다** — 일부만 읽은
답이 전부 읽은 답처럼 보이지 않게.

## 기계가 도는가 — Kotlin 에서의 비판정 관측

**이 값은 합격선이 아니다.** 등록된 오라클이 대조 불가여서, *"경로 자체가 서 있는가"* 를
따로 봤다. 모집단이 다르므로 T10 의 표와 비교하지 않는다.

선정 규칙은 **T10 의 것을 그대로 옮겼다** — 시각 오름차순 등간격 5.
모집단은 `boxwood/portal-backend` 의 `^fix` 커밋 **477 건**.

```
4ad79de7  bound               발현   1 · 도입 f370960d (1/1 = 100%)
cb7fc927  bound               발현   8 · 도입 c7ecdbdb (7/8 = 87%) · 나머지 후보 1
d79a0c5a  no_semantic_change
f2aa232f  outside_code
91445143  bound               발현   1 · 도입 86610001 (1/1 = 100%)

발현 좌표 3/5 · 도입(과반) 3/5 · 도입(엄격) 3/5 · 담기지 않음 2/5
```

`cb7fc927` 이 이 표에서 가장 값진 줄이다 — 발현 좌표 8 개 중 7 개가 한 커밋을 가리키고
**하나는 다른 커밋을 가리킨다.** 그 하나가 `others` 에 남았다. 최빈만 저장했다면 그것이
곧 조용한 절단이었을 것이다(stack §5.4).

## 줄이 아니라 심볼 위에서 결박한다 — **T10 과 방법이 다르다**

T10 은 **삭제된 줄을 blame** 했다. 이 구현은 **`body_digest` 가 마지막으로 변한 조상**을
본다. 그래서 두 측정은 같은 질문에 다른 도구로 답하고, 그 사실을 여기 적는다.

| | T10 (손) | 이 구현 |
|---|---|---|
| 단위 | 삭제된 줄 | **심볼(`symbol_id`)** |
| 신뢰도 | 최빈 줄의 비율 | 최빈 커밋에 동의한 **좌표**의 비율 |
| 포매팅 커밋 | 도입 커밋으로 지목될 수 있다 | **지목되지 않는다** — 정규화가 이미 지웠다 |

**바꾼 이유는 좌표계다.** [`Coord`](../DESIGN.md#21-d1--3축-좌표)에 `span` 이 없고 줄
번호는 포매팅으로 움직인다. 줄 위에서 결박하면 [R-07](../plan/00-risks.md#r-07)의 거짓
양성이 결함 계보 안에서 재생산된다.

### 그리고 이 방법이 못 하는 것 하나

T10 은 `afcfefab` 을 *"발현 좌표 ✗"* 로 적었다 — `src/**` 변경이 0 줄이고 결함이 에이전트
지시 문서에 있었기 때문이다. 그런데 그 커밋은 **테스트 파일(`.ts`) 하나를 함께 바꿨고**,
이 구현은 **테스트와 실코드를 구별하지 않는다.** TypeScript 추출기가 서면 그 커밋은
*"테스트 심볼이 발현 좌표"* 로 결박될 것이고 그것은 **틀린 결박이다.**

지금은 재어지지 않아 드러나지 않았다. **F02 가 서는 날 이 자리가 다시 열린다** — 빚으로 적는다.

## 코드를 스키마에 맞춘 자리와 설계를 정정한 자리

### J2. `Actor` 의 `종류(human|agent|tool)` 를 노드에서 뺐다

[DESIGN §1.1](../DESIGN.md)은 `Actor` 를 `{종류, 안정 식별자, 표시 이름}` 으로 적고
출처를 `asserted`(등록)라 했다. **그 셋은 한 노드에 설 수 없다.**

- git 커밋의 이름·이메일 → `(재현 입력, 추출기 버전)` 만으로 재현된다 → 배정 규칙 1 →
  **`extracted`**
- *"이 식별자는 사람이 아니라 에이전트다"* → 코드에서 나오지 않는다 → **`asserted`**

[§3.4](../DESIGN.md)의 속성 출처 동질성이 깨지고, 그 규칙의 처방은
*"섞으려면 노드를 쪼개고 엣지로 잇는다"* 이다. 그래서 `Actor` 는 **git 정체성만** 진다.
종류를 싣는 등록 노드는 **저작할 기능이 없어 만들지 않았다** — 없는 것을 미리 선언하면
스키마가 만들 수 없는 것을 실은 채 자란다.

**[DESIGN §1.1](../DESIGN.md)의 `Actor` 행을 정정했다.**

### J3. `Defect` 의 `원인 좌표[]` 를 두지 않았다

소급 결박에서 **원인은 발현과 구별되지 않는다.** 우리가 아는 것은 *"이 심볼이 수정
커밋에서 변했다"* 와 *"그 전에 마지막으로 변한 커밋이 이것이다"* 뿐이고 둘 다 같은
좌표를 가리킨다. 구별하려면 인과 판정이 필요하고 그것은 F15 다.

지금 넣으면 발현의 복사본이 되고, [§3.1](../DESIGN.md)이 금지한
*"이 시스템은 이것을 다룬다는 거짓 신호"* 가 된다.

### J4. `Defect` 의 출처가 `extracted` 다

F22 §2.2 는 `asserted`(사람) 또는 `observed`(도구)라 적었다. **그것은 인입(F16)으로
들어오는 결함**을 두고 쓴 것이고, 여기 있는 것은 git 이력에서 결정론적으로 나온다
(배정 규칙 1 · 재현 입력이 `History`). 같은 결함을 도구가 다시 보고해도
**파생 id 규칙에 따라 다른 노드로 선다**([F22-2](F22-2-derived-id.md)) — 붕괴하지 않는다.

**한 라벨이 여러 출처에 서는 문제는 열린 채 남는다.** 지금 스키마는 노드마다 출처
하나이고, F16 이 `observed` 결함을 들일 때 그 자리가 다시 열린다.

### `blame` 을 켜지 않았다 — 검토하고 기각

`gix` 의 `blame` 기능을 켜면 `gix-diff/blob` → `gix-filter` → **`encoding_rs`
(BSD-3-Clause)** 가 트리에 돌아온다. S1 이 정확히 그 크레이트를 features 를 좁혀
몰아냈고 [`deny.toml`](../../deny.toml)은 *"예외를 늘리기 전에 의존을 줄이는 것이
순서다 — 정책은 느슨해지면 되돌아오지 않는다"* 라고 적었다.

줄여 보려 했으나 `gix-diff/blob` 이 `gix-filter` 를 무조건 끌고 온다(직접 `gix-blame` 을
써도 같다). **그리고 위에서 적은 대로 줄 단위 blame 은 애초에 이 좌표계가 아니다.**
그래서 예외를 늘리지 않고 방법을 바꿨다. `cargo deny` 는 그대로 통과한다.

## 이 게이트가 판정하지 않는 것

- **T10 의 수치가 반증된 것이 아니다.** 재지 못했을 뿐이다. 반증하려면 TypeScript
  추출기가 있어야 한다.
- **결함 인입(F16)이 아니다.** `observed` 결함을 도구에서 받는 경로는 없다.
- **`Journey` 저작이 아니다.** T10ⓑ 가 진입점 좌표 0/3 으로 반증했고, 여기서는
  **자리와 거주 불가능성**뿐이다.
- **`pal defect` 가 `Envelope` 를 돌려주지 않는다.** `pal touch` 만 그렇다.
  커버리지의 구멍은 `not_extracted` 가 대신 싣는다 — 임시 형태다.
- **테스트와 실코드가 구별되지 않는다.** 위 참조.
