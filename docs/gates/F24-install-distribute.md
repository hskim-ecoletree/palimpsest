일**이고, 전부 §5 에 있다.

## 0. 등록된 합격선 열

**판정은 통과 · 반증 · 대조 불가 셋 중 하나다.** 모집단이 0 인 자리는 통과로도 반증으로도
세지 않고 **대조 불가**로 적는다([ADR-0002] · F05 §라 가 이미 그 형태를 썼다).

| | 합격선 | 무엇을 재서 가르나 | 반증되면 |
|---|---|---|---|
| **①** | `install` 은 **대상에 없는 것만** 쓴다 | 트리 전체의 (경로, sha256) 스냅샷 전후 비교 | 기존 파일이 밟혔다 |
| **②** | 대상 `settings.json` 파싱 실패 시 **아무것도 안 쓴다** | 실패 fixture 에서 전후 스냅샷이 **바이트 동일** | 부분 설치가 남았다 |
| **③** | 매니페스트에 **파일 목록 · 각 sha256 · 버전** | 매니페스트 ↔ 실물의 **양방향 차집합 둘 다 0** | 매니페스트가 실물과 다르다 |
| **④** | `update` 는 안 고친 것만 교체하고 고친 것은 **보고** | sha256 3분기(같음 → 교체 · 다름 → 보존 + 보고) | 사용자 수정이 밟혔다 |
| **⑤** | `doctor` 검사 **다섯** | 고장 fixture 다섯 각각을 지목 + 정상 fixture 는 전부 초록 | 못 지목하거나 항상 빨갛다 |
| **⑥** | `uninstall` 은 **매니페스트에 적힌 것만** 되돌린다 | 설치 전 스냅샷 = 제거 후 스냅샷 | 밖의 것이 사라졌다 |
| **⑥-b** | 리소스를 **하나도 못 찾으면 실패** | 그 fixture 의 종료 코드 ≠ 0 | 0 을 냈다(거짓 성공) |
| **★ ⑦** | 세 경로 어디서도 **대상 바깥에 안 쓴다** | 격리 HOME + 감시 뿌리 스냅샷 · 차이 **0** | 밖에 하나라도 생겼다·바뀌었다·사라졌다 |
| **⑧** | 등록된 **훅 명령이 발화**하고 **차단 결정이 전달**된다 | 사건을 실제로 일으켜 흔적과 차단을 각각 확인 | 안 불렸거나 차단이 안 먹었다 |
| **⑨** | 최신인지 판단할 근거가 **바이너리 안에** | 서로 다른 두 빌드의 `--version` 이 **갈리는가** | 두 빌드가 같은 값을 냈다 |
| **⑩** | **Rust 툴체인 없이** 받아서 설치된다 | `cargo`·`rustc` 를 실패 shim 으로 막고 설치 완주 | 툴체인 없이는 못 선다 |

## 1. 소유자가 쓴 요구사항 — **원문 그대로**

요약하면 근거가 사라진다. 네 문장이 이 게이트의 전부다.

> palimpsest 는 어떤 사용자 환경에서도 어느 정도 일관된 방법과 성능을 내야하는데 지금
> 설정은 이 PC에서만 동작하잖아

> palimpsest 역시 ditto 처럼 사용자 프로젝트에 설치될거야. 그러면 그때 사용자 프로젝트에
> settings.json 및 agents/commands/hooks 와 CLAUDE.md/AGENTS.md 가 설치 되어야 해.
> 그래서 `~/.claude/` 하위에 기대는 구조는 절대 있어서는 안 돼

> 수시로 사용할 수 있는 최신 palimpsest 버전으로 업데이트 하기 위한 update, 설치 상태를
> 확인하고 수정할 수 있는 doctor, 삭제할 수 있는 uninstall 같은게 있어야 하지

> 그러려면 당연히 우리가 만든 palimpsest 를 받아서 설치하거나 업데이트할 수 있도록
> 배포도 해야겠고

**둘째 문장의 마지막 절이 ⑦ 을 낳았다.** *"`~/.claude/` 하위에 기대는 구조는 절대 있어서는
안 돼"* — 「기대지 않는다」는 코드를 읽어서도 말할 수 있지만, **안 기댄다는 주장과 안 쓴다는
사실은 다르다.** ⑦ 은 주장이 아니라 사실을 잰다.

## 2. 합격선 각각 — **판정 방법까지**

### ① `install` 은 대상에 없는 것만 쓴다

**fixture 셋** — (a) 빈 프로젝트 (b) 사용자 키가 든 `settings.json` 이 이미 있는 프로젝트
(c) 이미 palimpsest 리소스가 깔린 프로젝트.

**재는 법**: 설치 직전 대상 트리 전체의 `(상대경로, sha256)` 집합을 뜬다. 설치 후 다시 뜬다.

- **새로 생긴 경로**만 있고 **기존 경로의 sha256 이 하나도 안 바뀌면** 통과.
- **예외는 `settings.json` 하나다.** 병합이 일어나므로 바뀐다. 그때는 값 단위로 잰다 —
  **설치 전의 모든 키·값이 설치 후에도 그대로 있는가**(부분집합 검사). 하나라도 없어지거나
  값이 달라지면 **반증**.
- fixture (c) 에서 **두 번째 설치가 첫 번째와 같은 상태를 낸다**(멱등). 다르면 반증.

**★ 이름으로 세지 않는다.** F04 게이트가 같은 자리에서 이미 적었다 —
*"`intent.redb` 를 이름으로 적으면 다음에 생기는 파일이 빠지고, **낡은 검사는 통과한다**"*
([F04.md](F04.md)). 그래서 집합은 트리 전체를 훑어서 뜬다.

### ② 파싱 실패 시 아무것도 안 쓴다 — **부분 설치 금지**

**fixture**: `settings.json` 이 깨진 JSON 인 프로젝트(끝 중괄호 누락 · 후행 쉼표 · 빈 파일 셋).

**재는 법**: 실행 전후 스냅샷이 **바이트 동일**해야 한다. 그리고 —

- 종료 코드 ≠ 0
- 표준오류에 **어느 파일의 몇 번째 줄이 왜 안 읽혔는지**가 나온다
- 새 파일 0 · 바뀐 파일 0 · 지워진 파일 0

**하나라도 안 서면 반증.** 특히 *"일부는 쓰고 실패했다"* 는 이 합격선이 잡으려는 바로 그
형태다 — 실패한 설치가 사용자 프로젝트를 반쯤 오염시키면 `doctor` 도 `uninstall` 도 그
상태를 모른다.

### ③ 매니페스트 — 목록 · sha256 · 버전

**재는 법**: 설치 후 매니페스트를 읽고 실물과 **양방향**으로 뺀다.

- `매니페스트 − 실물 = ∅` (적혔는데 없는 것 0)
- `실물 − 매니페스트 = ∅` (생겼는데 안 적힌 것 0)
- 각 항목의 `sha256` 이 실물의 sha256 과 일치
- 매니페스트의 버전 문자열 = 설치한 `pal --version` 의 출력

넷 중 하나라도 안 서면 **반증**. 셋째·넷째는 ④⑥⑨ 가 전부 그 위에 서므로 여기서 깨지면
아래가 전부 무의미해진다.

### ④ `update` — 사람이 고친 것은 밟지 않는다

**fixture**: 설치된 리소스 셋 중 **하나를 손으로 고친다**. 모집단 조건 — 안 고친 것 ≥ 1 ·
고친 것 ≥ 1. **둘 중 하나라도 0 이면 대조 불가**(그 회차는 통과로 안 센다).

**재는 법**: `update` 후 셋을 동시에 본다.

| 대상 | 기대 | 안 서면 |
|---|---|---|
| 매니페스트 sha256 **= 실물** | 새 버전으로 **교체됐다** | 반증 |
| 매니페스트 sha256 **≠ 실물** | 사람이 고친 그 sha256 이 **그대로** | 반증 |
| 위 둘째 | 보고에 그 경로가 **「사용자 수정 — 건너뜀」**으로 나온다 | 반증 |

셋째가 없으면 *"조용히 안 밟는 것"*이 되고, 사용자는 자기 파일이 낡았다는 사실을 모른다.
**밟지 않는 것과 말하지 않는 것은 다르다.**

### ⑤ `doctor` — 검사 다섯

| # | 검사 | 고장 fixture |
|---|---|---|
| 1 | 대상 `settings.json` 이 **유효한 JSON 인가** | 깨진 JSON |
| 2 | **매니페스트 대조** — 적힌 것이 있고 sha256 이 맞는가 | 파일 하나를 지운다 · 하나를 고친다 |
| 3 | **현재 위치가 설치 루트인가** | 하위 디렉터리에서 실행 |
| 4 | **`pal` 실행 파일을 찾을 수 있는가** | `PATH` 에서 뺀 셸 |
| 5 | **`.gitignore` 등재 여부** | 등재를 지운 프로젝트 |

**재는 법**: 고장 fixture 다섯을 하나씩 만들고 `doctor` 가 **그 항목을 지목**하는지 본다.
검사할 수 없는 것은 `Residual` 로 낸다 — `pal doctor` 가 이미 쓰는 어휘이고 새로 만들지
않는다.

**★ 그런데 정상 fixture 에서는 다섯이 전부 초록인가.** 이 줄이 없으면 **항상 빨간
`doctor`** 가 위 다섯을 공짜로 통과한다. F04 가 `prune` 에서 쓴 것과 같은 형태의 대칭
검사다(*"★ 그런데 실제로 지우기는 했는가"*).

### ⑥ `uninstall` — 매니페스트에 적힌 것만

**재는 법**: 스냅샷 셋을 뜬다 — 설치 전 `S0` · 설치 후 `S1` · 제거 후 `S2`.

- **`S2` 와 `S0` 이 같다.** 다르면 반증. (⚠ `settings.json` 은 ① 과 같은 규칙으로 값
  단위로 비교한다 — 설치가 더한 키만 빠지고 사용자 키는 전부 살아 있어야 한다)
- **매니페스트 밖 경로가 하나라도 사라지면 반증.** `S1 − S2` 가 매니페스트 항목 집합의
  부분집합이어야 한다.

**⑥-b — 거짓 성공 금지**: 매니페스트가 가리키는 리소스를 **하나도 못 찾은** fixture(설치
디렉터리를 통째로 지운 뒤 `uninstall`)에서 **종료 코드 ≠ 0**. 0 을 내면 반증. *"지울 게
없었으니 성공"*은 사용자에게 **지웠다는 거짓말**이다.

### ★ ⑦ 대상 프로젝트 바깥에 아무것도 쓰지 않는다 — **어떻게 재는가**

이 게이트에서 가장 센 줄이고, **어떻게 잴 것인지를 여기 못박는다.**

**실행 격리** — 세 경로(`install`·`update`·`uninstall`)를 각각 **격리 HOME** 아래에서
돌린다:

```
HOME=$(mktemp -d)  XDG_CONFIG_HOME=$HOME/.config  XDG_DATA_HOME=$HOME/.local/share
TMPDIR=$(mktemp -d)
```

★ 격리 HOME 을 쓰면 재는 문장이 *"진짜 사용자 홈이 안 변했다"* 가 아니라 **"홈이 무엇이든
그 아래에 안 쓴다"** 가 된다. **후자가 더 센 문장이고**, 동시에 이 측정이 실제 사용자 홈을
건드릴 위험을 0 으로 만든다.

**감시 뿌리** — 실행 직전에 아래 각각을 재귀로 훑어 `(경로, size, mtime, sha256)` 집합을
뜬다:

- 격리 `$HOME` 전체 (`~/.claude/` · `~/.config/` · `~/.local/` ·
  `~/Library/Application Support/` 를 포함한다)
- 격리 `$TMPDIR`
- 대상 프로젝트의 **부모 디렉터리**(형제 경로에 새는지)

**판정** — 실행 후 다시 떠서 **집합 차이가 0**. 생긴 것·바뀐 것·사라진 것을 각각 센다.
**셋 중 어느 것이든 ≥ 1 이면 반증**이고, 그때 **어느 경로가 무엇을 건드렸는지**를 게이트에
그대로 적는다.

**구조로 한 겹 더** — 설치 경로의 소스에 홈을 유도하는 형태(`home_dir` · `$HOME` 읽기 ·
`~` 전개 · `dirs::` 계열)가 **0** 인지 `cargo xtask check` 의 문자열 스캔으로 센다.

**⚠ 그러나 문자열 스캔만으로는 부족하다.** F04 가 이미 같은 말을 했다 —
*"그것은 문자열 스캔이라 「소스에 그 낱말이 없다」만 말한다 — 낱말 없이도 상위 디렉터리를
지울 수 있고 `..` 하나면 경계가 사라진다."* **실물 하중은 스냅샷이 진다.**

**⚠ 이 측정의 한계를 미리 적는다.** 스냅샷 비교는 **실행 중에 생겼다가 지워진 것을 못
잡는다.** 그것까지 잡으려면 syscall 추적(`dtruss`·`strace`)이 필요하고 **이 회차는 하지
않는다.** 나중에 *"쟀는데 못 잡았다"* 가 아니라 **처음부터 안 잰 범위**로 남긴다.

### ⑧ 훅 — **메커니즘을 안 박는다**

합격선은 두 문장뿐이다:

> **등록된 훅 명령이 발화한다. 그리고 차단 결정이 하네스에 전달된다.**

**재는 법**: 대상 프로젝트에 설치한 뒤 훅이 걸린 사건을 **실제로 일으킨다.**

- (a) **발화** — 훅 명령이 실행된 흔적이 남는다(훅이 남기는 산출물 ≥ 1). 0 이면 반증.
- (b) **전달** — 훅이 「차단」을 반환한 회차에서 **하네스가 실제로 그 동작을 막았다.**
  막지 못했으면 반증.
- 사건을 일으킬 수 없으면 **대조 불가.** 통과로도 반증으로도 안 센다.

**★ 등록 형태를 합격선에 안 박는다.** 셸 스크립트든 `pal <hook-name>` 서브커맨드든 그 밖의
무엇이든, 위 (a)(b) 만 서면 된다. **형태는 아직 측정 중이다** — 지금 박으면 측정이 답을
정하는 것이 아니라 **등록이 답을 정한다.** G50 이 *"고르기보다 먼저 오라클이 있었다"* 로
얻은 것의 반대 형태이고, 여기서는 **오라클이 형태를 고르지 않는 것**이 그 값이다.

### ⑨ 버전 — 최신인지 판단할 근거가 **바이너리 안에**

**지금**: `pal --version` 이 **`0.0.0` 고정**이다(§3 에서 실행으로 확인). 워크스페이스
`Cargo.toml:15` 의 `version = "0.0.0"` 이 그대로 나오고 `build.rs` 가 없어 커밋·태그가 안
실린다. **이 상태에서는 「설치된 것이 최신인가」를 물을 수 없다.**

**재는 법**: 서로 다른 두 커밋에서 빌드해 `pal --version` 을 각각 뜬다.

- **두 값이 같으면 반증.** 갈리면 통과.
- 그리고 `update` 가 「이미 최신」과 「낡음」을 **그 값만으로** 가르는지 fixture 둘로 각각
  한 번씩 확인한다.

**★ 이 합격선은 버전이 무엇이어야 하는지 안 정한다.** 태그든 커밋 SHA 든 `build.rs` 든
빌드 시각이든, **가르는가**만 잰다. 형태를 정하는 것은 구현의 일이고 등록의 일이 아니다.

### ⑩ 배포 — **Rust 툴체인 없이**

**재는 법**: `cargo` 와 `rustc` 를 **부르면 실패하는 shim** 으로 `PATH` 앞에 놓고, 공개된
설치 경로 **하나만으로** `pal` 을 세운다.

- 설치 종료 코드 0 · 이어서 `pal --version` 이 돈다 → 통과
- shim 이 **한 번이라도 불렸으면** 반증(shim 이 호출을 기록한다)
- 대상 플랫폼 둘을 각각 잰다 — `aarch64-apple-darwin` · `x86_64-unknown-linux-musl`
  (stack §7 이 고정한 타깃). 한쪽만 되면 그 한쪽만 통과로 적고 나머지는 대조 불가.

**⚠ 대조 불가 조건을 미리 적는다.** 저장소가 **private** 인 동안 인증 없는 제3자는 저장소·
릴리스·tarball·clone 에서 전부 **404** 를 받는다(§3 에서 실측). **그 상태에서 이 합격선은
대조 불가이고 통과로 세지 않는다.** 가시성을 어떻게 할지는 이 게이트가 결정하지 않는다(§5).

## 4. 이 게이트가 판정하지 않는 것

- **훅의 등록 형태**를 고르지 않는다(⑧). 셸 스크립트인지 바이너리 서브커맨드인지는 측정이
  정한다.
- **버전 문자열의 형태**를 고르지 않는다(⑨). 가르는가만 잰다.
- **저장소 가시성**을 정하지 않는다(⑩ · §5). 배포의 선행 결정이지만 이 문서의 것이 아니다.
- **성능을 안 잰다.** 소유자의 첫 문장 *"어느 정도 일관된 방법과 성능"* 중 **방법**만 이
  게이트가 진다. 성능의 일관성은 이미 F04 의 캐시 지표가 자기 자리를 갖고 있고, 여기서
  또 재면 같은 것이 두 곳에 적힌다.
- **다중 하네스를 안 잰다.** 대상은 `settings.json` + `agents`/`commands`/`hooks` +
  `CLAUDE.md`/`AGENTS.md` 하나의 형태다. 다른 도구로의 이식은 범위 밖이다.
- **`pal init` 이 없다는 사실**을 판정하지 않는다. [how-it-works §2.1](../how-it-works.md)
  이 `pal init` 의 화면을 그리지만 이 빌드에 그 서브커맨드가 없다 — 관측으로만 적고 §5 로
  넘긴다.
