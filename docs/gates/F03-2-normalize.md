## 3. §3.1 표가 다섯 줄 모자랐다 — **실물이 채웠다**

등록 시점에 표는 여섯 행이었고 **그중 둘이 안 서 있었다**. 세우고 나니 실물이 다섯을
더 요구했다. **넷은 ①이, 하나는 ②가 찾았다.**

| | 무엇이 | 어떻게 드러났나 | 누가 찾았나 |
|---|---|---|---|
| **후행 쉼표** | `,` 가 리프 토큰이라 그대로 실렸다 | 등록 시점 실측 | 등록 |
| **리터럴 따옴표 종류** | 따옴표 토큰이 그대로 실렸다. **이스케이프까지 풀어야 한다** — `prettier` 가 `"a\"b"` 를 `'a"b'` 로 바꾼다 | 등록 시점 실측 | 등록 |
| **불필요한 그룹 괄호** | `prettier` 한 번에 심볼 **58**(파일 40)이 움직였고 **원인이 그것 하나**였다 | ① prettier | ① |
| **합집합 타입의 선행 `\|`** | `\| A \| B` ↔ `A \| B`. 줄 폭에 따라 포매터가 넣었다 뺐다 한다. 마지막 **16** 건 | ① prettier | ① |
| **중첩 심볼이 바깥 지역을 안 지웠다** | `outer` 의 지역을 `walk` 가 이름 그대로 실었다. **10** 건, 전부 중첩 함수 | ① 리네임 | ① |
| **`import` 이름이 지워졌다** | 위 규칙을 넓히다 **밖에서 온 계약까지 지웠다.** `f(readFile)` 과 `f(readdir)` 이 같은 요약이 된다 | ② `7b571cb3` | **②** |
| **보간 없는 템플릿이 문자열과 갈렸다** | `` `x` `` ↔ `'x'`. 린터가 코드베이스마다 한쪽으로 몬다 | ② `0d0f4aab` | **②** |

### 그룹 괄호가 이 조각의 설계를 바꿨다

**평평한 토큰 열에서 괄호만 지우면 서로 다른 코드가 같아진다** — `(a+b)*c` 와 `a+b*c`
가 한 바이트열이 되고, 그것이 [R-22](../plan/00-risks.md#r-22)가 경고한 충돌 그 자체다.
**괄호가 지우던 일을 다른 것이 대신해야 괄호를 지울 수 있고**, 그 다른 것은 트리 모양이다.

그래서 정규형이 **토큰 열이 아니라 트리의 직렬화**가 됐다 — 마디마다 여닫는 표식을
싣고 `parenthesized_expression` 을 벗긴다. F03 §2 가 이미 *"**구문 트리에서** 주석·
공백·포매팅을 제거한 정규형"* 이라고 적었으니 문서와 어긋나지 않는다. §3.1 에 그 사실을
적었다.

### `import` 은 ①이 못 잡았고 ②가 잡았다 — **두 측정을 가른 값**

F03 §6.2 는 ①과 ②를 가르며 *"이 구별이 없으면 이 계획은 F03 에서 영구히 멈춘다"*
라고 적었다. 그 구별이 **다른 방향으로도** 값을 냈다:

> **우리가 통제한 변형은 우리가 생각한 것만 잡는다.**

리네임 변형은 `exact` 심볼 **안**의 바인딩만 건드리므로 `import` 를 건드릴 일이 없었다.
그리고 변형 목록에 「템플릿 ↔ 문자열」이 없었다. **①은 일곱 변형에서 100% 였는데 그
상태로 결함 둘을 품고 있었다.** 그것을 꺼낸 것이 실 이력의 손 검토다.

## 4. ③ De Bruijn — **낱말의 문제다. 문서를 고쳤다**

`[f03.2.pass]` ③ 이 판정 기준을 *"낱말이 아니라 불변식"* 으로 등록했다:

> 두 치환 방식이 §6.1 의 양방향 속성에서 **다른 답을 내는 입력이 존재하는가.**

### 판정: 존재하지 않는다

**두 번호 매김은 같은 동치 관계를 만든다.** 근거는 이렇다 — 이름 아닌 토큰이 같으면
바인더의 **자리도 같고**, 그러면 「선언 순서 순위」와 「스코프 중첩 깊이」는 **둘 다
그 자리들의 함수**다. 즉 두 번호는 고정된 전단사로 이어지고, 어느 쪽을 써도 *"어떤 두
소스가 같은 요약을 갖는가"* 가 바뀌지 않는다. 구조가 다르면 이름 아닌 토큰이 이미
다르므로 두 방식 모두 갈라 낸다.

### 그러므로 문서를 고쳤다 — 코드가 아니라

F03 **§3.1 은 이미 옳게 적혀 있었다**: *"선언 순서 기반 **De Bruijn 유사** 색인"*.
느슨했던 것은 **§7 체크리스트의 「De Bruijn 색인」** 이라는 줄이고, 그것은 규범이 아니라
줄임말이다. 실물은 §3.1 을 따른다.

**그리고 §3.1 의 예시가 자기 표와 어긋나 있었다.** 예시의 정규형에 `;` 가 남아 있는데
바로 위 표는 *"선택적 세미콜론은 지운다"* 라고 적는다. **예시를 고쳤다** — 표가 규범이다.

`정규형이_문서에_적힌_그대로다` 가 그 예시를 붙든다. **문서의 예시가 시험의 오라클이므로
어긋나면 둘 중 하나가 반드시 고쳐진다** — 조용히 갈라지지 않는다.

```
원본:   function add(a: number, b: number) { const s = a + b; return s }
정규형: function add(#0: number, #1: number){const #2=#0+#1 return #2}
```

### 다만 두 방식이 **정말 다른** 자리 하나는 적어 둔다

De Bruijn 색인은 **쓰는 자리 기준**이라 심볼 **밖**의 바인더에도 번호가 붙는다.
우리 자리 번호는 이 심볼이 **가리키는** 바인딩만 센다 — 그리고 **모듈 스코프는 뺀다**
(§3 의 `import`). 그 차이는 의도된 것이고, 뺀 이유가 곧 R-22 다.

## 5. ② 실 이력 표본 — **거짓 양성 0 / 9. 합격선은 아니다**

`[f03.2.selection]` 이 **측정보다 먼저** 등록한 조작적 정의를 그대로 돌렸다.
축 A(커밋 제목의 어휘)에서 **26 건**, sha 중복 제거 후 **22**, 앞의 **20** 을 본다.

**축 B(git 의 공백 무시 diff 가 비는 커밋)는 등록 시점에 이미 0 이었다** —
ditto 1,188 커밋 중 `.ts` 를 건드리며 공백만 바뀐 커밋이 **하나도 없다.**
**「포매팅 전용 커밋」은 이 코퍼스에 존재하지 않는다.** F03 §6.2 가 *"실제 커밋은
순수하지 않다"* 라고 예상한 그대로이고, **②에 0 을 걸 수 없다는 문장이 실측으로 선다.**

### 손 검토 — 켜진 `stale` 아홉을 하나씩

| 커밋 | 켜진 것 | 그 커밋이 무엇을 했나 | 거짓 양성인가 |
|---|---|---|---|
| `a0db9e1a` | 4 (+ 사라짐 45) | 구 2계층 스토어 **제거** · 소비처 재배선 | **아니다** — 코드가 없어졌다 |
| `c81f23d0` | 2 | env 리더가 비교 **전에 `trim()`** 을 한다 | **아니다** — 동작이 변했다 |
| `47388f26` | 1 | warm-start cap 을 **가치순 정렬**로 | **아니다** — 동작이 변했다 |
| `895f6ea5` | 1 | `.map { it.trim() }` **추가** | **아니다** — 동작이 변했다 |
| `8828285b` | 1 | `new RegExp('…','g')` → `/…/g` | **경계다 — 아래** |

**나머지 열다섯 커밋은 `stale` 0 이다.** 그중 여덟이 `style(...)` · `chore(format)` ·
`biome lint:fix` 로, **린터가 손댄 커밋에서 결박이 하나도 안 켜졌다.**

### `8828285b` — 경계 사례를 숨기지 않는다

`new RegExp('[ -…]', 'g')` 가 정규식 리터럴 `/[ -…]/g` 로 바뀌었다.
사람 눈에는 *"같은 정규식"* 이고 커밋 제목은 `fix(lint)` 다.

**그런데 우리는 이것을 거짓 양성으로 세지 않는다.** F03 §4.2 가 이 기능이 거르는 것을
*"텍스트만 변했다"* 까지로 못박았고, **생성자 호출과 리터럴은 다른 구문 구조**다 —
컴파일 시점도 이스케이프 규칙도 다르다. 여기까지 같다고 적으려면 *"이 두 표현식이 같은
값을 만든다"* 를 알아야 하고, 그것은 이 기능이 보증하지 않는다고 문서가 스스로 적은
자리다.

**그러나 이 한 건이 「린트 커밋에서 결박이 켜지는」 실물 사례라는 사실은 기록한다.**
F09 가 합격선을 그을 때 이 형태를 세어야 한다.

### 그래서 기록하는 값

| | |
|---|---|
| 표본 | **20** (모집단 22 · 목표 20) |
| 켜진 `stale` | **9** |
| 손 검토상 **거짓 양성** | **0** (경계 1 건 포함해도 1) |
| 거짓 양성률 | **0 / 9** — 경계를 세면 **1 / 9 = 11.1%** |

**합격선은 F09 에서 확정된다.** 여기 적은 값은 그 선을 그을 때의 입력이지 판정이 아니다.

## 6. ⑥ 두 언어 — 규칙은 하나인데 하중이 다르다

정규형은 `pal-extract::parse` 하나가 만든다. **언어마다 따로 쓰면 두 언어의
`body_digest` 가 서로 다른 규칙 위에 서게 되고, 그러면 같은 리팩터가 한 언어에서만
결박을 `stale` 로 만든다.** 그 규율은 지켜졌다 — 다만 **규칙마다 하중이 다르다**:

| 규칙 | TypeScript | Kotlin |
|---|---|---|
| 공백 · 주석 · 세미콜론 | ✅ | ✅ |
| **후행 쉼표** | ✅ | ✅ — 실측으로 확인했다(`fun g(a,b,)` = `fun g(a,b)`) |
| 마디 표식 · 그룹 괄호 | ✅ | ✅ (`parenthesized_expression` 이름이 같다) |
| **리터럴 따옴표 종류** | ✅ | **하중 0** — Kotlin 에 교체 가능한 따옴표가 없다 |
| **지역 이름 지우기** | ✅ (`exact` 심볼) | **하중 0** — L1 이라 전부 `ordinal` 이다 |

**Kotlin 요약 1,296 개가 전부 움직였다.** 규칙이 공통 자리에 섰다는 증거다.

## 7. 대조가 **자기를 여섯 번 속였다** — 그리고 다섯이 같은 병이었다

F03-1 에서 셋, 여기서 여섯. **아홉 중 다섯이 「어디가 코드이고 어디가 아닌가」였다.**

| | 무엇이 꺼졌나 | 어떻게 드러났나 |
|---|---|---|
| 열쇠에 **자리(byte)** 를 넣었다 | 포매팅이 자리를 밀어내 4,578 중 **136** 만 짝지어졌다 | 「안 움직였다」가 아니라 **「아무것도 안 봤다」** |
| 의미 변형을 **주석 안**에 놓았다 | 정규화는 주석을 지운다 — **설계대로 동작한 것**을 결함으로 셌다 | 가시율 85% |
| **템플릿 안**을 들여썼다 | 문자열의 **값**이 바뀐다. `prettier` 도 안 건드리는 자리다 | 17 건, 전부 여러 줄 템플릿 상수 |
| 주석의 **아포스트로피**를 문자열 시작으로 봤다 | 그 뒤가 통째로 어긋나 파일이 깨졌고 **심볼 134 개가 사라졌다** | 사라진 심볼은 어긋남을 못 낸다 |
| **정규식 리터럴**을 안 갈랐다 | `/"""/g` 의 따옴표가 문자열 시작이 됐다 | 17 건 |
| 후행 쉼표를 **붙이려** 했다 | 씨앗이 이미 `prettier` 를 거쳐 붙일 자리가 없었다 → **아무것도 안 바꿨다** · 억지로 붙이니 `if (a \|\| b,)` 가 됐다 | 61 건 |

**그래서 스캐너를 하나로 모았다** — 주석 · 문자열 · 템플릿 · 정규식을 한 번에 훑고
모든 변형기가 그것을 쓴다. 따로 세면 그 여섯이 각각 다시 난다.

**그리고 대조가 안 물면 실패로 적는다**: 변형이 어느 파일도 안 바꾸면 실패,
`proptest` 에는 *"모든 변형이 적어도 한 씨앗을 바꾼다"* 는 시험이 따로 있다.

## 8. 이 조각이 **찾은 실물 결함** 하나 — 주석이 선언이 됐다

tree-sitter 에서 **주석은 이름 있는 노드**라 `named_children` 에 섞여 나온다.
`declare_parameters` 가 그것을 거르지 않아서 — 파라미터 목록 안의 주석 한 줄이
**통째로 「선언된 이름」**이 되고 있었다.

```
이름: "// #36 (wi_260713u4k): the run's `started_untracked_baseline` — untracked (`??`) dirt"
```

ditto 실측 **32 개**(파일 5 — `memory.ts` · `autopilot-dispatch.ts` ·
`interview-driver.ts` · `question-context.ts` · `work-item-handoff.ts`).
전체 바인딩 27,777 중이므로 비율은 작지만, **그 「이름」이 참조와 우연히 맞으면 해소가
조용히 틀린다.** 고쳤고 시험을 붙였다.

## 9. 이 조각이 **증명하지 않는 것** — 등록된 그대로

| | 관측 |
|---|---|
| **R-07 이 안 닫힌다** | ① 의 100% 는 **우리가 가한 변형**에 대한 값이다. 실 이력의 선은 **F09** |
| **의미 등가를 보증하지 않는다** | `foo(CONST)` 에서 `CONST` 값만 바뀌면 안 움직인다. 그리고 `new RegExp('x')` 와 `/x/` 도 다르다고 적는다(§5) |
| **Kotlin 에서 지역 이름이 안 지워진다** | L1 · `ordinal`. ① 의 리네임 변형은 TypeScript 에서만 재어졌다 |
| **`.tsx` 는 여전히 잘못된 문법으로 읽힌다** | F02 가 넘긴 빚. 두 코퍼스에 0 개 |
| **정규형이 문법 버전에 묶였다** | 마디 표식이 **tree-sitter 의 노드 이름**이다. 문법을 올리면 요약이 움직인다 — `GRAMMAR_REV` 가 이미 좌표 축이므로 표현은 되지만, **묶임이 세졌다는 사실**은 새것이다 |

## 10. 넘기는 빚

| 빚 | 자리 |
|---|---|
| 정규형이 **문법 노드 이름**에 묶였다 (§9) | 문법 승급 때 좌표가 통째로 움직인다. [#50](https://github.com/hskim-ecoletree/palimpsest/issues/50) 의 순서 판단에 걸린다 |

이 기능에서 **세 번째로** 관측됐다 — F03-1 은 반대 방향(좌표만 움직이고 요약은 안
움직였다)이었다.

**요약이 전부 움직인 것은 마디 표식 때문이다.** 심볼의 뿌리 마디에 표식이 붙으므로
예외가 없다. `EXTRACTOR_REV` `f03-1` → `f03-2`.
