## 등록된 합격선 — 결과보다 먼저

**측정값은 실측만 적는다. 재지 못한 것은 대표값으로 채우지 않고 "못 쟀다"고 적는다.**

| | 값 |
|---|---|
| **오라클** | `git ls-tree -r --name-only a29cad0bf6a8` — **997 파일의 경로 집합** |
| **코퍼스** | `boxwood-portal-kotlin @ a29cad0bf6a8` (S0 이 이미 검증한 핀) |
| **① 경로 집합 불일치** | **0건** (양방향 — git에만 0 · 대장에만 0) |
| **② 상태 분할** | **전수 분할** — 모든 파일이 정확히 한 상태, 합이 997 |
| **③ 캐시 2회차 미스** | **0건** · 두 회차 산출이 **바이트 단위로 동일** |

### 합격선을 누가 정했는가 — S0 과 다르다. 숨기지 않는다

**S0 의 합격선은 소유자가 정했고 이것은 아니다.** 소유자가 *"끝까지 이어서 하라"* 고
위임한 자리에서 에이전트가 정했다. [R-18](../plan/00-risks.md#r-18)(게이트를 스스로
판정한다 · 구조적·영구)이 S0 보다 **한 단계 더 세게** 걸린다 — 거기서는 판정만 자기
것이었고 여기서는 **합격선도 자기 것**이다.

그 대응 셋을 합격선 안에 넣었다:

1. **오라클을 우리가 만들지 않은 것으로 잡는다** — `git ls-tree`. git 이 정본이고 우리
   코드가 그것을 재현하는지만 본다
2. **음성 대조를 합격선 ④ 로 넣는다** — 캐시가 "항상 적중"을 보고하는 고장이 아님을
   보이는 절차. 없으면 캐시 검사는 자기 신고다
3. **소유자가 이 값을 뒤집을 수 있다.** 뒤집히면 그 사실이 여기 적힌다

## 이 게이트가 판정하지 않는 것

- **F01 의 완료가 아니다.** 워킹트리 머클 · 언어 인식 4단계 · `detector_freshness` ·
  골든 스냅샷 · 벤치는 F01 완료 체크리스트의 것이다. 슬라이스는 순서를 정하고 체크리스트가
  완결을 정한다([계획 §3](../plan/README.md)).
- **분류가 옳은지가 아니라 전수 분할인지만 본다.** `.sql` 을 `unrecognized` 로 둘지
  `unsupported{SQL}` 로 둘지는 우리가 정하는 규칙이고 그 규칙의 오라클은 없다.
- **R-06 이 닫히지 않는다.** `TreeRef` 가 타입으로 서고 커밋 축이 도는 것까지다.
- **저장소 하나다.** 멀티레포 스티칭은 F14 이고, "선언된 저장소 N개"는 여기서 항상 1 이다.
