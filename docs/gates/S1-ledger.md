## 등록된 합격선 — 결과보다 먼저

**측정값은 실측만 적는다. 재지 못한 것은 대표값으로 채우지 않고 "못 쟀다"고 적는다.**

| | 값 |
|---|---|
| **오라클** | `git ls-tree -r --name-only a29cad0bf6a8` — **997 파일의 경로 집합** |
| **코퍼스** | `boxwood-portal-kotlin @ a29cad0bf6a8` (S0 이 이미 검증한 핀) |
| 기한 | **없다** — 계획 §7.2 가 기본값이다 |

### 합격선을 누가 정했는가 — S0 과 다르다. 숨기지 않는다

**S0 의 합격선은 소유자가 정했고 이것은 아니다.** 소유자가 *"끝까지 이어서 하라"* 고
위임한 자리에서 에이전트가 정했다. [R-18](../plan/00-risks.md#r-18)이 S0 보다 **한 단계
더 세게** 걸린다 — 거기서는 판정만 자기 것이었고 여기서는 **합격선도 자기 것**이다.

그 대응 셋을 합격선 안에 넣었고, 셋 다 실제로 하중을 졌다:

1. **오라클을 우리가 만들지 않은 것으로 잡았다** — `git ls-tree`. git 이 정본이다
2. **음성 대조를 합격선 ④ 로 넣었다** — 아래 §음성 대조가 그 결과다
3. **소유자가 이 값을 뒤집을 수 있다.** 뒤집히면 그 사실이 여기 적힌다

## 대조 회차 — 2026-08-12

### 환경 — 재현 좌표

```
코퍼스   ~/dev/projects/boxwood/portal-backend @ a29cad0bf6a8  (997 파일)
바이너리 target/release/pal · rustc 1.94.1
gix      0.86 · default-features = false · features = ["sha1", "revision"]
대조     ./scripts/s1-verify.py --repo <저장소> --at a29cad0bf6a8
구조     cargo xtask check  (검사 6/6)
```

### 결과

```
1회차   파일 997 · 적중 1 · 빗나감 996
① 경로  git 997 · 대장 997 · git에만 0 · 대장에만 0
② 분할  합 997 / 파일 997  ·  parsed 641 · partial 30 · unsupported 311 ·
                              unrecognized 7 · binary 8   (excluded 0 · generated 0)
③ 캐시  2회차 적중 997 · 빗나감 0 · 산출 동일 예
④ 음성  최초 5 · 재실행 0 · 1파일 변경 후 1   (기대 5 · 0 · 1)
```

### 음성 대조 — 캐시가 눈이 멀지 않았음을 보인 것

**③ 만 보면 "언제나 적중"이라고 거짓 보고하는 캐시가 만점을 받는다.** S0 에서 대조
도구가 아무것도 안 하는 도구일 수 있다는 것이 문제였고, 캐시에서는 같은 문제가 더
조용하게 일어난다 — 2회차가 빨라진 것처럼 보이면서 값은 1회차의 것이다.

그래서 임시 저장소를 만들어 파일 다섯을 커밋하고, 하나만 고쳐 다시 커밋한 뒤 같은
캐시로 돌렸다. **미스가 정확히 1건이었다.** 0 이면 캐시가 변경을 못 보는 것이고,
2 이상이면 키가 파일 경계를 넘는 것이다([R-05](../plan/00-risks.md#r-05)의 조기 신호).

### 1회차에 적중이 1건 있었던 이유 — 캐시가 옳게 동작한 증거다

빈 캐시에서 시작했는데 적중이 0 이 아니라 1 이었다. **같은 내용의 파일이 두 개 있다:**

```
V073__Create_Connector_Meta_Version_Tables.sql
V075__Create_Connector_Meta_Version_Tables.sql      ← blob 3dd3c105… 로 동일
```

키가 경로가 아니라 **blob** 이므로 두 번째 파일은 계산 없이 답을 얻는다. 캐시 키를
`(blob, 추출기 버전)` 으로 잡은 설계가 그대로 관측된 자리다(stack §5.1 · [R-06]).

## 부차 관측 — 판정에 쓰지 않고 기록만 한다

### S0 의 자산과 교차했다 — **두 경로가 같은 파일을 같게 본다**

| | S1 대장 | S0 레퍼런스 (같은 671 파일) |
|---|---|---|
| `.kt` 파일 | 671 | 671 |
| 정상 파싱 | `parsed` **641** | `parse=ok` **641** |
| 오류 회복 | `partial` **30** | `parse=fail` **30** |
| **어느 파일인지** | — | **30개가 완전히 같은 집합** (차집합 양방향 0) |

두 판정은 **독립적인 경로로 나왔다** — S1 은 Rust tree-sitter 의 `ERROR`/`MISSING`
노드를 세고, S0 레퍼런스는 tree-sitter CLI 의 `parse --quiet` 가 실패로 보고한 것이다.
그 둘이 같은 30개 파일을 지목했다.

### 시간 — **합격선이 아니다**

| | |
|---|---|
| 1회차 (빈 캐시) | **6.90초** / 997 파일 |
| 2회차 (전량 적중) | **0.02초** |
| 캐시 크기 | 3.9 MB |

예산 회귀는 F05 의 것이고 여기 숫자를 박으면 그것이 굳는다([`criteria.toml`](../../corpus/criteria.toml) `[s1.secondary]`).

### S0 이 회귀하지 않았다

`extract` 를 `extract_detailed` 위로 얹는 리팩터링을 했으므로 S0 대조를 다시 돌렸다 —
**1,122 파일 불일치 0건 유지.** 대장이 `partial` 을 가르려면 파싱 건강 정보가 필요했고,
그것을 S0 이 대조한 함수의 산출을 바꾸지 않는 방식으로 얻었다.

## R-01 두 번째 관측 — **이번에는 수명이 실제로 물었다**

S0 의 판정은 *"이 규모에서는 막히지 않았다"* 였고, 그때 적은 단서가 있었다 —
**위험이 겨눈 난소(소유권·수명·트레잇 객체)가 그 슬라이스에 거의 등장하지 않았다.**
S1 에서 등장했고, 결과는 이렇다.

**막힌 자리 하나 · 몇 분.** `Snapshot` 을 `Copy` 로 만들려고 `repo: &'static str` 로
뒀다가 `Deserialize<'de>` 에서 컴파일이 거부했다 — `'de` 가 `'static` 을 넘어 산다고
요구할 수 없다. **수명 파라미터를 피하려는 선택이 곧 R-01 의 회피 동작이었고, 타입이
그것을 거부한 것이다.**

소유(`RepoId`)로 바꾸는 것이 답이었고 **그 답이 설계적으로도 옳았다** — 대장은 기계
사이를 오가는 산출이라 되읽을 수 있어야 하고, `&'static str` 은 되읽을 수 없는 것을
타입으로 선언한 셈이었다. 근거는 `pal-core/src/repo.rs` 의 `Snapshot` 문서 주석에 남겼다.

**막히지 않은 자리도 적는다.** `GitAccess` 트레잇은 트레잇 객체(`dyn`) 없이 제네릭
없이 섰고, gix 의 빌림은 `GixRepo` 안에서 닫혔다. 첫 컴파일이 한 번에 통과했다.

**여전히 R-01 은 닫히지 않는다.** 본래 판정 시점은 F01~F03 이고, `EdgeCursor`(수명
파라미터가 실제로 등장하는 유일한 자리, P0 후반)는 아직 오지 않았다.

## 이 회차가 드러낸 것 — 켜자마자 검사가 일을 했다

**`cargo-deny` 를 S0 의 빚으로 갚은 직후 S1 의 의존이 들어왔고, 셋을 잡았다:**

| 잡힌 것 | 처분 |
|---|---|
| `postcard` → `heapless` → **`atomic-polyfill`(유지보수 중단)** | `default-features = false` 로 끊었다. std 위에서 `alloc` 만 쓰므로 heapless 가 필요 없다 |
| `gix` → **`uluru`(MPL-2.0 · copyleft)** · `encoding_rs`(BSD-3) | gix 를 `features = ["sha1", "revision"]` 로 좁히자 **트리에서 빠졌다** |
| `foldhash`(Zlib) · `arrayref`(BSD-2, **blake3** 가 들여옴) | 줄일 수 없다. 둘 다 permissive 이고 copyleft 가 아니다 — 예외로 적었다 |

**예외를 늘리기 전에 의존을 줄였다.** 정책은 느슨해지면 되돌아오지 않는다.

### stack §3.4 와 실제가 달라졌다 — 그 사실을 여기 적는다

stack §3.4 는 *"라이선스: MIT/Apache-2.0만"* 이라고 적었고, **이번이 그 문장의 첫
예외다**(`Zlib` · `BSD-2-Clause`). 그 문장은 P0 착수 전에 쓰였고 `gix`·`blake3` 를
고른 순간 결과가 정해졌다. 배포 제약은 늘지 않는다(둘 다 고지만 요구한다).
**소유자가 뒤집으면 대체 크레이트를 찾는 일이 되고, gix 는 팩 읽기를 포기할 수 없으므로
git 접근 방식 자체가 바뀐다.** 근거는 `deny.toml` 의 예외 2·3 주석에 있다.

## 이 게이트가 판정하지 않는 것

- **F01 의 완료가 아니다.** 슬라이스는 순서를 정하고 체크리스트가 완결을 정한다.
- **분류가 옳은지가 아니라 전수 분할인지만 봤다.** `.sql` 을 `unsupported{SQL}` 로 둔 것은
  우리가 정한 규칙이고 그 규칙의 오라클은 없다.
- **R-06 이 닫히지 않는다.** `TreeRef::Worktree` 는 **타입으로만 서 있다.** S1 은 커밋
  축만 돌았고 머클 계산·git 인덱스 캐시는 F01 §3.2 다.
- **저장소 하나다.** "선언된 저장소 N개"는 여기서 항상 1 이다.
- **선언의 이름도, 심볼 수도 대장에 없다.** 대장 스키마는 상태를 싣지 파생 수치를 싣지
  않는다(DESIGN §4.1). 부차 관측을 위해 스키마를 늘리지 않았다.
