# F24-크로스플랫폼 게이트 — **세 플랫폼에서 같은 소스가 서고, 한쪽이 낸 것을 다른 쪽이 쓴다**

**판정: 통과.** 반증 **0** · **대조 불가 0** · **안 재지는 것 0**.

★ **이 게이트는 [F24-Windows](F24-windows-parity.md) §5 를 통째로 닫는다.** 그 문서가
남긴 것은 외침 다섯 · 측정 다섯 · 결정 셋이었고, 여기서 전부 판정됐다(§6).
그리고 [F24](F24-install-distribute.md) 의 마지막 두 칸(⑧-b · ⑩)도 닫는다.

앞 게이트가 물은 것은 *"Windows 가 유닉스와 **같은 결과**를 내는가"* 였다. 그 판정은
**Windows 에서만 이뤄졌다** — 유닉스 쪽은 그 코드로 **한 번도 컴파일된 적이 없었다.**
그리고 그것이 이미 한 번 물었다: `제자리를_준비한다` 가 양쪽에서 부르게 바뀐 함수에
`#[cfg(windows)]` 가 남아 있었고, **Windows 빌드가 서니까 끝까지 안 걸렸다**(`c19920e`).

그러니 이 게이트가 묻는 것:

> **같은 소스가 세 플랫폼에서 실제로 서고 같은 답을 내는가. 그리고 각 플랫폼 사람이
> 그것을 받아서 쓸 수 있는가.**

---

## ★ 판정 — 완료 조건 여섯에 대해

**어떻게 쟀나.** 유닉스의 컴파일과 동작은 **CI 가 유일한 문**이다. 이 기계에서
`cargo check --target x86_64-unknown-linux-gnu` 로 대신할 수 없다 — `zstd-sys` 와
tree-sitter 문법들이 C 컴파일러를 타고 크로스 gcc·WSL·docker·zig 가 **하나도 없다**(실측).

```text
기준선
  로컬        Windows 11 Pro 10.0.26200 · rustc 1.97.1 x86_64-pc-windows-msvc
              git 2.55.0.windows.3 · core.autocrlf=true
              관리자 아님 · 개발자 모드 **켜짐**(소유자가 이 회차에 켰다)
              LongPathsEnabled = 0 · WSL 배포판 없음 · docker 없음 · zig 없음
  CI          ubuntu-latest · macos-latest · windows-latest
  하네스      claude 2.1.233
```

| | 완료 조건 | 판정 | 무엇을 관측했나 |
|---|---|---|---|
| **①** | 세 플랫폼에서 `cargo xtask check` 와 `cargo xtask test` 가 **전부 초록** | **통과** | CI 에서 실제로 돌았다. §1 |
| **②** | `xtask` 의 **`외침` 목록이 비어 있다** | **통과** | 다섯이 전부 없어졌다. **넷은 「안 한 것」이었고 하나는 제품을 고쳐서** 사라졌다. §2 |
| **③** | **CI 가 실제로 돌아서 초록이다** | **통과** | 워크플로가 있는 것과 도는 것은 다르다. 다섯 회차를 돌렸고 그 과정이 **진짜 결함 둘과 fixture 결함 둘**을 냈다. §1 |
| **④** | 크로스 플랫폼 상호운용을 **실제 두 플랫폼**으로 잰다 | **통과** | `Windows→리눅스` 와 `리눅스→Windows` **양방향**. §3 |
| **⑤** | 아직 아무도 안 잰 위험 **여덟이 전부 판정**됐다 | **통과** | 여덟 중 **넷이 새 방어나 새 진단을 낳았다.** §4 |
| **⑥** | 각 플랫폼 사용자가 **받아서 쓸 수 있다** | **통과** | 릴리스 워크플로가 타깃 넷을 내고, **Rust 툴체인을 실패 shim 으로 막은 채** 받은 바이너리로 라이프사이클을 완주하는 것까지 잰다. §5 |

## 1. CI — **워크플로가 있는 것과 도는 것은 다르다** (완료 조건 ①③)

매트릭스를 **셋**으로 넓혔다. `macos-latest` 를 더한 이유: 둘이었을 때 macOS 는
「유닉스니까 리눅스와 같겠지」로 덮여 있었는데, 이 저장소가 실제로 갈리는 축 둘이
정확히 거기서 갈린다 — **대소문자를 안 가리는 파일시스템**(APFS 기본)과 BSD 계열 도구.
그리고 그 예감이 맞았다(§4-③).

### 회차별로 무엇이 나왔나 — **다섯 회 전부 무언가를 냈다**

| 회차 | 결과 | 무엇이 나왔나 |
|---|---|---|
| 1 | ubuntu·macos 빨강 | ★ **`install_hooks.rs` 의 `검사들()` 이 `PATH` 를 안 얹었다.** 그런데 **Windows 에서는 통과했다** — `cargo test` 가 동적 라이브러리 탐색 경로에 `target/debug` 를 얹는데 **그 변수가 이 플랫폼에서는 `PATH` 자신**이기 때문이다(유닉스에서는 `LD_LIBRARY_PATH`·`DYLD_FALLBACK_LIBRARY_PATH` 로 가고 `PATH` 는 안 건드린다). 그 자리는 「하네스가 이 이름을 풀 수 있는가」가 아니라 **「cargo 가 마침 그 디렉터리를 얹어 줬는가」**를 재고 있었다 |
| 2 | ubuntu·macos 빨강 | ★ **`못_열리게_한다` 가 두 플랫폼에서 다른 겹을 재고 있었다.** Windows 만 등록을 절대 경로로 옮겼고, 유닉스는 이름 하나로 둔 채 `chmod -x` 만 했다 — 그러면 `exe::명령을_찾는다` 가 실행 비트로 걸러서 그 이름이 `PATH` 에서 **아예 안 잡힌다.** 유닉스는 「이름 해석 겹」, Windows 는 「실행 가능성 겹」을 재고 있었다 |
| 3 | **세 플랫폼 초록** | 처음으로 유닉스에서 컴파일과 동작이 확인됐다 |
| 4 | macos 빨강 | ★ **APFS 가 UTF-8 이 아닌 파일 이름을 거부한다.** §4-③ |
| 5 | ubuntu 빨강 | ★ **리눅스의 `ETXTBSY` 경쟁** — 시험이 병렬로 돌면서 한 스레드의 복사 기술자를 다른 스레드의 `fork` 가 물려받는다. fixture 의 경쟁이고 제품이 아니다 |

★ **다섯 중 둘(1·2)은 「Windows 가 가리고 있던 진짜 구멍」이다.** 둘 다 *"한 플랫폼에서
재고 「선다」고 적지 마라"* 가 가리키던 바로 그 형태이고, 유닉스를 실제로 돌리기 전에는
**원리상 안 보이는** 것이었다.

### `cargo xtask check` — 세 플랫폼 16/16

검사 열여섯이 전부 소스 텍스트와 파생 문서 대조라 플랫폼을 안 타는데, **줄바꿈 하나만
탄다**(파생 문서 대조). 워크플로가 checkout **보다 먼저** Windows 에서
`core.autocrlf=true` 를 걸어서 실사용자 환경과 같은 바이트로 체크아웃한다.

## 2. 외침 다섯 — **전부 없앴다** (완료 조건 ②)

앞 게이트 §5-가 가 다섯의 성질을 갈라 적었다. **다섯 중 하나도 「고쳐서」가 아니라
「갈라서」 없어졌다.**

| 없어진 등록 | 앞 판이 적은 까닭 | 실제로 무엇이었나 | 어떻게 닫혔나 |
|---|---|---|---|
| `모드와_심링크_보존이_…` | *"모드 비트는 개념이 없고 … D34 가 파일 정체성 보존을 일부러 포기했다"* | 성질 **셋이 한 덩어리**였다 — 이식 가능한 둘이 못 재는 하나에 끌려 통째로 외침이었다 | 심링크 축 → `심링크가_살고_그_대상에_쓰인다`(이식) · 모드 축 → `모드가_살아_있다`(유닉스 인코딩). **그리고 심링크 축은 제품이 바뀌어서 이식 가능해졌다**(§2-가) |
| `쓰기_불가_디렉터리가_…` | *"진짜 쓰기 불가 디렉터리는 ACL 이고 **std 밖이다**"* | 관측은 맞았고 **결론이 틀렸다.** std 밖이라는 것은 fixture 를 std 로 못 만든다는 뜻이지 재려는 성질이 없다는 뜻이 아니다 | `icacls DIR /deny USER:(WD,AD)` — 이 저장소는 junction fixture 에 `cmd` 를 쓰면서 *"플랫폼의 일부인 도구는 정당하다"* 를 이미 인정했다. 되돌림은 **`Drop`** 에 건다 |
| `파일_심링크_경계가_…` | *"파일 심링크에 `SeCreateSymbolicLinkPrivilege` 가 필요하다"* | **플랫폼의 한계가 아니라 기계의 준비 상태**였다 | 소유자가 개발자 모드를 켰고 `std::os::windows::fs::symlink_file` 이 그 자리에서 바로 섰다(실측). 심링크 경계 시험 셋에서 `cfg` 가 통째로 사라졌다 |
| `파이프_방어가_…` | *"FIFO 가 이 플랫폼에 없다"* | 재려는 성질은 「FIFO」가 아니라 **「일반 파일이 아닌 자리」**였다. 제품이 세운 문(`일반_파일이거나_없나`)이 묻는 것은 `is_file()` 이지 FIFO 인지가 아니다 | 디렉터리로 이식. FIFO 시험은 **더 센 사실**(매달림)을 위해 남는다 |
| `끊었다는_말이_…` | *"링크 수를 셀 수 없어 언제 끊었는지 모른다"* | 결과는 이미 같았고 **말할 것이 더 많은 쪽이 침묵**했다 | 못 세는 플랫폼이 *"걸렸는지 모르므로 늘 끊는다"* 를 자리 목록과 함께 한 줄로 낸다 |

### 가. 그 과정에서 제품이 바뀐 자리 — **끊을 것은 「이름」이 아니라 「실체」다**

`제자리를_준비한다` 가 `path` 를 그대로 끊고 있었다. 그래서:

| | 심링크 | 실체의 하드링크 |
|---|---|---|
| 앞 판 (유닉스) | 산다(`nlink==1` 이라 안 끊었다) | **안 끊긴다** — 실체에 걸린 링크로 밖이 샜다 |
| 앞 판 (Windows) | **죽는다**(`rename` 이 링크 자체를 갈아끼운다) | 끊긴다 |
| **지금 (양쪽)** | **산다** | **끊긴다** |

Windows 가 못 보는 것은 **링크 수**뿐이고 `symlink_metadata` 는 양쪽에 다 있다.
심링크는 「이름이 하나 더 있는 것」이 아니라 **다른 이름을 가리키는 것**이므로 끊어야
할 대상은 그것이 가리키는 **실체**다. 그러면 **둘 다 이긴다.**

★ 가르는 문장: *"플랫폼이 못 보는 것이 정확히 무엇인지 좁혀라."* 「Windows 는 링크를
못 본다」는 **너무 넓은 진술**이었고, 그 넓이만큼 비대칭이 정당화됐다.
[ADR-0023](../adr/0023-consistent-method-and-result-across-platforms.md) 을 그렇게 고쳐 썼다.

### 나. 목록을 안 지운다 — **자격을 박는다**

빈 목록과 장치가 없는 것은 다르다. 다음에 짝 없는 `cfg` 가 생기면 **등록되지 않은
실패**로 걸린다. 그리고 자격을 시험이 판정한다:

- `어느_플랫폼에도_안_재지는_것이_없다` — 앞 판은 이 단언이 `#[cfg(unix)]` 였다.
  Windows 에 무엇이 등록되든 아무 말도 안 했다. **`cfg` 를 뗀 것이 이 시험의 값이다.**
- `등록은_원리상_불가능한_것만_담는다` — 까닭에 「아직」·「나중에」·「다음 회차」·
  「미측정」이 있으면 걸어 낸다. 그것은 **할 일이지 사실이 아니고**, 목록에 넣는 순간
  CI 가 그것을 초록으로 세어 준다.

⚠ 앞 판의 `등록에는_까닭이_있다` 는 `assert!(!외침.is_empty())` 를 했다 — *"목록이
비면 이 대조가 아무것도 안 센다"* 는 이유로. **그 단언은 틀렸다.** 대조가 살아 있다는
것은 순수 함수 위의 음성 대조 둘이 재고, 목록의 길이에 안 기댄다.

## 3. 상호운용 — **양방향으로, CI 에서** (완료 조건 ④)

앞 회차는 이것을 **Windows↔Windows 로만** 쟀다. 같은 기계의 같은 `core.autocrlf` 로는
이동에서만 보이는 셋이 **하나도** 안 드러난다:

| 이동에서만 보이는 것 | 왜 |
|---|---|
| 산출물에 실린 **기계 고유의 값** | 절대 경로·그 기계의 줄바꿈. 받는 쪽에서 **반드시** 틀린다 |
| 줄바꿈 왕복 | Windows 는 `core.autocrlf=true`, 리눅스는 `false` |
| 매니페스트의 sha256 | 워킹트리 바이트가 갈리면 대조가 갈린다 |

`produce`(각 플랫폼이 설치·커밋한 저장소를 아티팩트로) → `receive`(**반대 플랫폼**이
`git clone` 으로 받아 판정) 두 job 이 매 커밋마다 돈다.

★ **clone 으로 받는 것이 핵심이다.** 파일 복사로 받으면 git 이 워킹트리 바이트를 정하지
않고, 그러면 `core.autocrlf` 가 아예 안 걸려서 **재려던 축이 통째로 사라진다.**

판정 넷 — **둘째가 심장이다**:

1. `git clone` 한 워킹트리가 **깨끗하다**
2. ★ **아무것도 안 하고** `doctor` 여섯에 **빨강이 없다** — 안 서면 그 저장소는
   **받는 사람에게 고장 난 채로 도착**한 것이다
3. `install`·`update` 뒤 **추적 파일 diff 0**
4. `uninstall` 뒤 사용자 바이트

### ⚠ 4번의 대상이 둘로 갈린다 — **게이트 ① 이 이미 정한 갈래다**

| 대상 | 보증 |
|---|---|
| `README.md`·`CLAUDE.md`·`.gitignore` | **바이트 동일** |
| `.claude/settings.json` | **모든 키·값이 그대로**(바이트 동일 아님) |

실측이 그 갈래를 확인했다: `{"env": {"A": "1"}}` 가 왕복 뒤 여러 줄로 다시 쓰였다.
**키도 값도 안 바뀌었고 공백만 바뀌었다.** JSON 을 파싱해서 병합하고 다시 쓰므로
포맷이 정규화되고, [F24](F24-install-distribute.md) ⑥ 이 그 파일을 유일한 예외로
적어 두었다. 판정을 그 보증에 맞췄다.

### ① 대소문자를 안 가리는 파일시스템 — **새 문 하나**

이 저장소의 다른 플랫폼 분기는 전부 **API 의 차이**였다(모드 비트·확장자·링크 수).
이것은 다르다 — **같은 코드가 같은 호출을 하는데 파일시스템이 다른 답을 낸다.**

| `Claude.md` 가 있는데 `CLAUDE.md` 를 놓으면 | |
|---|---|
| Windows(NTFS)·macOS(APFS 기본) | **같은 파일** — 우리 블록이 `Claude.md` 에 들어간다 |
| 리눅스(ext4) | **다른 파일** — `CLAUDE.md` 가 새로 생긴다 |

**둘 다 그 플랫폼에서는 맞고, 그래서 더 나쁘다.** 무너지는 것은 공유되는 저장소다 —
Windows 에서 설치·커밋한 것을 리눅스에서 clone 하면 `doctor` 가 `CLAUDE.md` 를 못
찾고 하네스도 그 지시를 안 읽는다.

**양쪽이 할 수 있는 것**을 골랐다(ADR-0023): `read_dir` 은 어디서나 같은 답을 내므로
`install/casing.rs` 가 **양쪽에서 멈춘다.**

⚠ **잃는 것**: 리눅스에서 무관한 `Claude.md` 를 가진 사용자가 `git mv` 한 번을 해야
한다. 그 대신 얻는 것은 *"어디서 clone 해도 같은 것이 선다"* 이고, 그 사람의 저장소는
**우리와 무관하게 이미** Windows 동료에게서 깨져 있었다.

### ② `MAX_PATH` 를 넘는 경로 — **선다. 그리고 주변 도구가 못 따라온다**

365자 경로 실측(Windows · `LongPathsEnabled=0`):

| | |
|---|---|
| `pal install --target` · `update` · `uninstall` · `doctor --repo` | **전부 rc=0** · 왕복 바이트 동일 · 잔해 0 |
| `Command::current_dir` | **안 선다** — `Os { code: 267, NotADirectory }` |
| `git -C <긴 경로> init` | **안 선다** — `Filename too long`(`core.longpaths=true` 도 같다) |

아래 둘은 **우리 코드 밖의 사실**이다 — 프로세스의 작업 디렉터리에는 긴 경로 지원이
안 붙고(`CreateProcess` 의 `lpCurrentDirectory` 가 `MAX_PATH` 로 잘린다) `git` 은 그
자리로 `chdir` 부터 한다. **Windows 에서 `MAX_PATH` 를 넘는 자리에 git 저장소를 둘 수
없다** — 「아직 안 했다」가 아니라 그 플랫폼의 사실이다.

★ **그리고 그 실측이 결함 하나를 냈다.** `\\?\` 가 화면에 다시 새고 있었다:

```text
⚠ 훅이 아직 안 뜬다   … `\\?\C:\dev\...\pal.exe` 을 `PATH` 에 넣으십시오
```

**50자짜리 경로다** — 벗겨야 하는 길이인데 `install/hooks.rs` 의 아홉 자리가
`PathBuf::display()` 를 직접 불렀다. 이 저장소는 같은 종류의 누출을 **이미 한 번
고쳤다**(`78b27dc`). 한 번 고치고 다시 난다는 것은 **그 자리에 문이 없다**는 뜻이라,
라이프사이클 전체와 오류 경로에서 재는 시험을 세웠다.

### ③ UTF-8 이 아닌 경로 — **갈래가 둘이고 둘 다 단언한다**

| 파일시스템이 그 이름을 | 무엇을 단언하나 |
|---|---|
| **받는다**(NTFS·ext4) | 라이프사이클 넷 rc=0 · 왕복 바이트 동일 · **산출물에 U+FFFD 0** |
| **거부한다**(APFS) | **거부한다는 것 자체** — 그 자리에 위험이 **존재할 수 없다**는 증거다 |

★ 「fixture 가 없다」와 「그 위험이 없다」는 다르다. macOS 에서 재는 것은 **후자**이고,
언젠가 그 플랫폼이 그 이름을 받기 시작하면 이 시험은 **첫째 갈래로 넘어가서**
라이프사이클을 재기 시작한다. 조용히 통과하는 자리가 없다.

**왜 지금은 손실이 안 실리는가**: 매니페스트의 경로는 우리가 정한 ASCII 상수(`Rel`)
이고, 훅 등록은 `PATH` 의 이름 하나이며, 파일 조작은 `OsStr` 로만 나른다.
`to_string_lossy` 가 남은 자리는 **화면**뿐이다. 시험이 그 구조를 잠근다.

### ④ 하네스 마지막 한 칸 — **쟀다. 통과** ([F24](F24-install-distribute.md) ⑧-b 가 닫힌다)

실제 `claude` 2.1.233 세션. `CLAUDE_CONFIG_DIR` 로 격리했고 **홈은 한 바이트도 안
바뀌었다**(소유자 결정: 자격 증명을 `%TEMP%` 로 복사해 격리 실행하고 끝나면 지운다).

```text
① 등록이 실제로 풀린다 — 그리고 그것은 이 회차가 바꾼 `PATH` 이름 등록이다
   Hook SubagentStop (SubagentStop) success:
   pal hook SubagentStop  ·  pal 0.0.0+…  ·  통과 — 돌려준 말이 있다

② 차단 바이트를 하네스가 존중한다
   Hooks: Parsed initial response: {"decision":"block","reason":…}
   Hook SubagentStop (…) returned permissionDecision: deny
   Hook SubagentStop … success: …  ·  통과 — 반복 회차다      ← 2회차가 왔다
```

②의 마지막 줄이 차단이 **먹었다**는 증거다 — 서브에이전트가 **재개됐다.** 그리고
그것은 `hook/policy.rs` 의 *"반복 회차에서는 절대 차단하지 않는다"* 가 **실제로
필요했다**는 증거이기도 하다. 그 규율이 없으면 무한 반복이다.

⚠ **②는 대역으로 쟀다.** pal 은 「돌려준 말이 빈」 서브에이전트만 막는데 그 상태를
모델에게 유도할 수 없었다(빈 최종 메시지를 지시해도 모델이 텍스트를 낸다). 그래서
**pal 과 같은 모양의 바이트를 내는 20줄짜리 대역**으로 하네스 쪽 성질을 쟀다.
사슬의 다른 반쪽(*"pal 이 그 바이트를 낸다"*)은 `install_hooks.rs` 가 **매 커밋마다**
잰다. 두 링크가 각각 측정됐고 이어진다.

그리고 첫 회차가 덤으로 하나 확인했다 — `pal` 이 `PATH` 에 없을 때:

```text
[ERROR] Hook command failed to spawn (SubagentStop): Executable not found in $PATH: "pal"
```

인데 세션은 `is_error:false` 로 **정상 종료**했다. *"훅 실행 실패는 완전히 침묵한다"*
가 실제 세션에서 확인됐고, **그것이 `doctor` 검사 6 의 존재 이유다.**

### ⑤ `settings.local.json` — **발화한다. 그런데 안 옮긴다**

같은 사슬이 그 층에서 그대로 섰다(parsed → deny → 재개 → 반복 회차). 그러니
`install/hooks.rs` 의 *"안 잰 것 위에 경계를 세우지 않는다"* 는 이제 안 쓴다 — **쟀다.**

그런데 **안 옮긴다.** 이유 둘:

| | |
|---|---|
| 옮길 **이유가 사라졌다** | 근거는 *"기계 고유의 사실은 기계 고유의 파일에"* 였다. 그런데 등록은 이제 **`PATH` 의 이름 하나**이고 기계 고유의 값이 **아니다** |
| 옮기면 **깨진다** | 그 파일은 관습상 커밋되지 않는다. 옮기면 **clone 한 동료에게 훅이 아예 안 간다** — 이 층의 소비자가 공유되는 프로젝트라는 것과 정면으로 부딪힌다 |

둘째만으로 결정된다.

### ⑥ `git` 이 `PATH` 에 없는 환경

`install/ignore.rs` 는 `.gitignore` 등재를 **git 에게 물어서** 판정한다(`!` 부정 패턴이
`.git/info/exclude`·전역 `core.excludesFile`·중첩 `.gitignore` 에도 살기 때문에 텍스트
스캔으로는 못 본다). 그러니 git 이 없으면 그 걸음이 **원리상 안 선다.**

실측: **rc=1 · 잔해 0 · 1단계에서 끊긴다.** 옛 문구는 `program not found` 하나뿐이라
*"다음에 무엇을 하라"* 가 없었다 — 이 저장소의 다른 실패는 전부 그것을 적는다. 고쳤다.

★ 그리고 그 옆에서 **틀린 진단** 하나를 고쳤다. git 이 rc=128 을 내면 우리는
*"git worktree 가 아니다"* 라고 말했는데, `.git` 이 **있는데도** rc=128 이 나는 경우가
정확히 위험 ②③ 이다(긴 경로 · 비 UTF-8 경로). 그때 그 문구는 **틀린 말**이고, 틀린
진단은 침묵보다 나쁘다 — 사용자가 없는 문제를 고치러 간다. `.git` 의 유무로 갈랐다.

## 5. 배포 — **「파일을 올렸다」로 끝내지 않는다** (완료 조건 ⑥)

소유자 결정(2026-08-17): **릴리스를 내고 저장소를 public 으로 한다.** 앞 게이트가
[F24](F24-install-distribute.md) ⑩ 을 *"저장소가 private 이라 대조 불가"* 로 뒀던 자리다.
(저장소는 이미 public 이었다 — 확인하고 그 사실을 여기 적는다.)

타깃 넷을 **각자의 runner 에서 네이티브로** 세운다 — `x86_64-pc-windows-msvc` ·
`x86_64-unknown-linux-gnu` · `aarch64-apple-darwin` · `x86_64-apple-darwin`.

★ **`toolchain-free` job 이 「받아서 쓸 수 있는가」를 직접 잰다.** `cargo`·`rustc`·
`rustup` 을 **실패 shim(exit 127)으로 막고** 받은 바이너리 하나로
`install`·`doctor`·`update`·`uninstall` 을 완주한다. 그리고 **shim 이 실제로 걸렸는지
부터 확인한다** — 안 걸렸으면 그 job 은 아무것도 안 재면서 초록이 된다.

「없애기」가 아니라 「막기」인 이유: 재려는 것이 *"우리 코드가 툴체인을 안 부른다"*
이므로 **부르면 죽는 상태**가 정확한 fixture 다.

유닉스 산출물은 `tar.gz` 다 — zip 은 **실행 비트를 못 지고**, 그러면 받는 사람의 `pal`
이 `PATH` 에 있어도 안 뜬다(`install/exe.rs` 가 재는 바로 그 축).

⚠ **서명이 없다.** 인증서가 없고 **없는 것을 근거로 삼지 않는다** — `SHA256SUMS` 를
같이 내고 그 한계를 워크플로 머리말에 적었다. `-gnu` 바이너리의 glibc 바닥도 빌드
로그에 남긴다.

### 실제로 냈다 — `v0.0.0-f24.1` (2026-08-17)

```text
릴리스 회차 31969153224 — 여덟 job 전부 초록
  세운다        x86_64-pc-windows-msvc · x86_64-unknown-linux-gnu
                aarch64-apple-darwin   · x86_64-apple-darwin
  툴체인 없이    windows · linux · macos(arm)   ← cargo·rustc·rustup 을 exit 127 로 막고
  릴리스를 낸다  자산 5개(아카이브 4 + SHA256SUMS)
```

★ **그리고 「받을 수 있다」를 인증 없는 제3자로 다시 쟀다** — 앞 게이트가 ⑩ 을 대조
불가로 판정할 때 쓴 것과 **같은 방법**(`env -u GITHUB_TOKEN -u GH_TOKEN curl`)이다.
그때는 **404** 였다:

```text
http=200  bytes=4642300   pal-x86_64-pc-windows-msvc.zip
http=200                  SHA256SUMS
3d15b699c8db35f0…  ✔ SHA256SUMS 와 일치
받은 바이너리:  pal 0.0.0+1db3c7eabb8c
```

### ⚠ 첫 회차는 빨갰고, 빨간 것은 제품이 아니라 **측정 자신**이었다

첫 회차(31968690577)의 `toolchain-free` 가 **세 플랫폼 전부** 실패했다. 제품은 전부
완주했다 — 설치 rc=0 · 진단 여섯 초록 · 제거가 `.claude/` 까지 남김없이 걷었다.
마지막 검사에 남아 있던 것은:

```text
왕복 뒤 추적 파일이 더럽다
?? d.json
```

**우리가 쓴 파일이다.** `doctor --json` 산출을 대상 프로젝트 **안**에 썼고, 그래서
측정이 만든 상태를 제품의 결함으로 읽었다.

★ 이 저장소가 제품에 요구하는 것(*"어느 경로에서도 대상 바깥을 안 건드린다"*)의
**뒷면**이다: **측정도 대상 안에 자기 흔적을 남기면 안 된다.** 이 회차가 그것을
세 번째로 배운 자리이고(앞 둘은 `PATH` 를 안 얹은 fixture 와 겹이 어긋난 fixture),
셋 다 *"fixture 가 재려던 것이 아닌 것을 쟀다"* 라는 같은 형태다.

| 나-3. `settings.json` 직렬화 형태 | **판정: 안 바꾼다.** 게이트 ① 이 그 파일을 값 단위 예외로 적었고, §3 의 상호운용이 **키·값 보존**을 실제 이동에서 잰다. 포맷 정규화는 플랫폼 무관이고 보증 밖이다 |

| 다-1. `MAX_PATH` 라이프사이클 | ★ **닫혔다** (§4-②) |
| 다-2. 유닉스도 「끊고 쓰기」로 통일할지 | **판정: 통일 안 한다. 그리고 그럴 필요가 없어졌다.** 남아 있던 실질적 차이는 **심링크**였고 §2-가 가 그것을 없앴다. 일반 파일의 `nlink==1` 자리는 결과가 같고(내용·권한 보존) 갈리는 것은 파일 신원뿐이다 — 그리고 Windows 는 그것을 **원리상 못 본다**(`number_of_links()` 는 rustc 1.97 에서도 unstable · `windows_by_handle` · rust#63010. **이 회차가 지금 툴체인에서 다시 확인했다**) |
| 다-3. `cargo xtask test` 를 유닉스 CI 진입점으로 | ★ **닫혔다** — 그렇게 하고 있고, 등록이 비었음을 `어느_플랫폼에도_안_재지는_것이_없다` 가 못 박는다 |

## 7. 이 게이트가 판정하지 않는 것

- **`symbols`·`bind`·`query`… 의 기능 자체.** 범위를 가르는 문장은 앞 게이트와 같다 —
  *"이 자리가 플랫폼 때문에 다른 결과를 내는가."*
- **arm64 리눅스 · musl.** 릴리스 타깃 넷 밖이다. 세우는 것은 워크플로에 줄 하나이지만
  **받아서 쓸 수 있는지를 안 쟀고**, 안 잰 것을 낸다고 적지 않는다.
- **`cmd.exe`·`icacls` 가 없는 Windows**(Nano Server 등). fixture 가 그 환경에서
  시끄럽게 죽는다 — 그 구분은 시험이 낸다.
- **모델이 빈 최종 메시지를 내는 실제 세션.** §4-④ 의 ② 를 pal 자신으로 재는 자리이고,
  유도가 안 된다. 대역과 바이트 대조로 사슬을 이었다.
