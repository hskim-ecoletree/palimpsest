## 1. 이 조각에서 가장 값진 것 — **실물이 규칙 넷을 고쳤다**

스코프 해소를 처음 세워 ditto 496 파일에 대 보니 「선언 전 참조(TDZ)」가 **14 건** 나왔다.
**전부 거짓 양성이었다.** 그리고 그 14 건이 그대로 심볼을 `ordinal` 로 떨어뜨리고 있었다 —
정규화가 지울 수 있는 것을 안 지우고 있었다는 뜻이다.

| 고친 것 | 무엇이 틀렸나 |
|---|---|
| **함수 경계를 지나면 자리를 비교하지 않는다** | `function f(){ return LATER }` 뒤에 `const LATER` 가 오는 것은 **정상이고 흔하다.** 그 본문은 나중에 실행된다. TDZ 는 *참조가 선언보다 먼저 **실행**될 때*의 규칙이지 *먼저 **쓰일** 때*의 규칙이 아니다 |
| `for (const x of xs)` 의 루프 바인딩 | `lexical_declaration` 이 아니라 `left` 필드다. 그리고 그 노드는 스코프를 **여는** 쪽이라 선언을 모으는 다른 가지에 있었다 — 안 잡히면 `x` 의 참조가 **뒤에 선 같은 이름**으로 해소된다 |
| `import { a as b }` 의 `a` | **저쪽 모듈의 export 이름**이지 이 파일의 스코프 참조가 아니다. 참조로 세면 이 파일 어딘가의 같은 이름으로 해소된다 |
| 인덱스 시그니처의 파라미터 | `{ [k: number]: string }` 의 `k` 는 어떤 선언도 가리키지 않는다 |

고친 뒤: **선언 전 참조 0 · 파일 안 참조 76,048 전부 해소.**

**이것이 코퍼스 실물을 오라클로 쓰는 이유다.** 단위 시험 여덟은 넷을 고치기 전에도 전부
통과했다 — 픽스처에는 *"함수 안에서 뒤에 선 모듈 상수를 부르는"* 코드가 없었기 때문이다.

## 2. `exact` 의 조건 — **`OutsideFile` 을 실패로 세지 않는 것이 판단이다**

합격선은 *"스코프 해소에 실패한 심볼은 `ordinal` 로 떨어진다"* 라고만 적는다. **무엇이
실패인가**는 적혀 있지 않고, 그 선택이 이 조각의 값을 정한다.

| 참조가 | 실패인가 | 왜 |
|---|---|---|
| 이 파일의 선언으로 해소됨 | 아니다 | |
| **import · 전역**(`console`) | **아니다** | 파일 하나만 보는 연산에서 **정확한 답**이다. 푸는 것은 F07(L2b) |
| 선언 전 참조(TDZ) | **그렇다** | 우리가 해소하지 못한 자리다 |
| 이름을 못 잡은 바인딩이 안에 있음 | **그렇다** | 본문의 어떤 이름이 그것을 가리키는지 모른다 → **지우면 안 된다** |

**`OutsideFile` 을 실패로 셌으면 거의 모든 심볼이 `ordinal` 이 된다** — 실물에서 파일 밖
참조가 9,862 건이다. 그러면 이 등급이 *"이 심볼이 얼마나 자족적인가"* 를 재게 되고,
그것은 **지우기의 안전성과 무관한 값**이다. R-22 가 묻는 것은 *"이 이름이 지역인지 아는가"*
이지 *"이 이름이 어느 파일에 있는지 아는가"* 가 아니다.

**이 해석은 합격선 문면에 없다. 여기 적어 판정에 싣는다.**

## 3. 불변식 넷 — **B 가 다섯째이고, C 는 기대 방향이 뒤집혀 있었다**

전부 **코퍼스 실물**(고정 SHA · 실재 식별자)에서 잰다. 대상이 소스에 없으면 멈춘다.

```
✓ A · exact 에서 지역 이름을 바꾼다      요약이 같다      (exact · rebuild/memory/query.ts)
✓ B · ordinal 에서 지역 이름을 바꾼다     요약이 바뀌었다   (ordinal · src/cli/commands/impact.ts)
✓ C · 안쪽 지역을 바깥 이름과 같게 바꾼다   요약이 같다      (exact · rebuild/memory/query.ts)
✓ C · 안팎이 다른 선언으로 해소된다       서로 다른 선언 2 개
✓ D · exact 에서 의미를 바꾼다          요약이 바뀌었다   (exact)
✓ D · ordinal 에서 의미를 바꾼다        요약이 바뀌었다   (ordinal)
```

**B 가 왜 다섯째인가**: A·C·D 만 재면 *"항상 지운다"* 가 **만점을 받는다.** 그것이 R-22 가
경고한 **"서로 다른 코드가 같은 digest"** 의 정확한 형태다. B 는 `ordinal` 심볼
(`impactCommand` — `run: async ({ args }) => …` 의 구조 분해 때문에 `ordinal` 이다)에서
지역 이름을 바꾸면 **요약이 반드시 바뀌는지**를 묻는다.

### ⚠ C 를 처음에 반대로 적었고, 실행이 그것을 잡았다

초안은 *"안쪽 지역을 바깥 이름으로 덮으면 요약이 **바뀐다**"* 로 적었고 **실패했다.**
파고든 결과 **기대가 틀렸다:**

- 안쪽 콜백의 `const body` 를 `const events`(바깥 파라미터와 같은 이름)로 바꾸는 것은
  **이름만 바꾼 것**이다 — 그 콜백 안에서 바깥 `events` 를 쓰지 않는다. 의미가 같으므로
  요약도 같아야 한다
- **그리고 「같다」가 바로 이 검사의 discriminating power 다.** *이름 표*였으면 안쪽
  `events` 가 파라미터 `events` 의 자리를 물려받고, 그 자리는 `body` 의 자리와 다르다 →
  **요약이 움직인다.** 스코프 체인이라서 움직이지 않는다

기대를 뒤집고 **구조적 절반**(안팎의 참조가 실제로 다른 선언으로 해소되는가)을 함께
넣었다. 둘 다 있어야 C 가 선다.

**초안의 기대가 틀렸다는 사실 자체를 여기 적는다** — 합격선을 고친 것이 아니라 그 합격선을
재는 **방법**이 틀렸던 것이고, 그 구별이 규율 7 의 자리다.

### 자리 번호가 이름을 대신한다

전부 같은 바이트로 지우면 `f(a, b)` 와 `f(a, a)` 가 같아진다. **선언 순서의 자리 번호**를
실어 *어느 지역인지*는 남기고 *그 이름*만 지운다. 참조 순서로 매기면 본문에서 쓰는 순서만
바꿔도 요약이 바뀐다.

**심볼인 이름은 지우지 않는다.** `class C { m() {} }` 의 `m` 은 C 안에서 선언되지만 그
자체가 심볼이다 — 지우면 메서드 이름을 바꿔도 클래스 요약이 안 바뀌고, 그것은 정규화가
아니라 정보 손실이다.

### ⚠ ④ 는 이 코퍼스에서 켜지지 않는다

`interface Foo` 와 `const Foo` 가 **같은 스코프에 서로 다른 자리로** 공존하는 경우가

그 사실이 기록이다 — F01 이 언어 인식 ③(`linguist-language` · 실물 하중 0)에 대해 적은
것과 같은 형태다.

**그렇다고 뭉개도 된다는 뜻이 아니다.** 뭉개면 타입 자리의 참조가 값 선언으로 해소되고,
틀린 해소는 틀린 정규화이며 틀린 정규화는 서로 다른 코드가 같은 digest 다. 하중이 0 인
것은 *"이 코퍼스가 그것을 시험하지 못한다"* 이지 *"안 일어난다"* 가 아니다.

### 해소율은 합격선이 아니다

`[f02.3.secondary]` 가 그렇게 등록했다. **아무도 이 값을 재본 적이 없었으므로 지금 숫자를
박으면 그것이 굳는다.** 100.00% 는 *"파일 밖을 분모에서 뺀"* 값이고, 넣으면 88.5% 다 —
**어느 쪽도 하한이 아니다.** 하한이 정해지는 것은 F07 의 게이트다(R-02).

## 5. `export_digest` 의 소유 — **핸드오프가 미배정으로 남긴 것을 여기로 정한다**

> *"`export_digest` (R-05) — **#48 아니면 #49 — 소유가 명시되지 않았다. 판단하고 적어라**"*

**#48 이다.** 근거 셋:

1. **#49 의 합격선은 *"같은 입력이 같은 산출을 낸다"* 다.** 거기서 새 필드를 더하면 그
   조각의 음성 대조가 **등록 시점에 없던 모양**을 비교하게 된다 — 결정성 검사가 자기가
   방금 만든 필드를 자기가 확인하는 꼴이다
2. **값의 정확성 조건은 이미 섰다.** *"집합 순서에 의존하지 않는다"* 는 #46 이
   `ExportSet` 을 정렬·중복 제거로 세우면서 성립했고, 여기서는 그 위에서 요약만 잰다
3. **쓰는 쪽은 여기가 아니다.** 무효화 전파는 **F05 · F07** 이고 이 조각이 지는 것은
   *"값이 있고, 집합이 같으면 같고 다르면 다르다"* 까지다. **그 사실을 적는다**

Kotlin 에서는 `exports` 가 `NotBuilt` 이므로 `export_digest` 도 `NotBuilt` 다 — 안 만든
집합의 요약은 값이 아니다.

## 6. Kotlin 이 안 움직였다 — **팔을 갈라 둔 이유가 여기서 실현됐다**

```
S0 전수 대조     1,122 파일 · 불일치 0
골든 대장        997 항목 — **상태 이동 0**
grade_of(Kotlin) L1 · 심볼 등급 ordinal · scopes = NotBuilt · export_digest = NotBuilt
```

#46 이 `grade_of` 의 Kotlin 팔과 TypeScript 팔을 `#[allow(clippy::match_same_arms)]` 와
함께 **일부러 갈라 두었다**. 이 커밋이 TypeScript 팔만 L2 로 올렸다 — 합쳤으면 Kotlin 이
딸려 올라가 `f01-verify` 의 등급 음성 대조(Kotlin 팔 하나를 L0 으로 떨어뜨려 골든이
잡는지 보는 것)가 **무의미해졌을 것이다.**

### 골든이 한 줄 움직였다 — `EXTRACTOR_REV`

`s2` → `f02-3`. 추출 산출이 바뀌었으므로(`Symbol.identity` · 지우는 정규형) 올려야 한다 —
올리지 않으면 **옛 캐시가 옛 요약을 새 스키마로 되돌려 주고**, 같은 커밋이 캐시 상태에
따라 다른 답을 낸다. 움직인 것은 `detector.extractor` **한 줄**이고 **997 항목의 상태는
하나도 안 움직였다.**
