## 등록된 합격선 — 결과보다 먼저

합격선은 코드보다 먼저 커밋됐다(`3c39e80`). **오라클을 값이 아니라 불변식으로 잡았다** —
`body_digest` 가 옳은 값인지 말해 줄 바깥의 표가 존재하지 않기 때문이다. S1 에는
`git ls-tree` 라는 외부 정본이 있었지만 여기에는 없다.

**합격선을 누가 정했는가** — S1 과 같다. 소유자 위임 하에 에이전트가 정했고
[R-18](../plan/00-risks.md#r-18)이 세게 걸린다. 소유자가 뒤집으면 그 사실이 여기 적힌다.

### ③ 정규화가 양방향으로 섰다 — R-07 이 사는 자리

| 입력 변화 | `body_digest` | 왜 중요한가 |
|---|---|---|
| 공백 · 줄바꿈 · 들여쓰기 | **불변** | 포매터 커밋 하나에 결박이 무더기로 `stale` 이 되면 사람이 표시를 무시한다 |
| 주석 추가 | **불변** | 문서 수정이 코드 변경이 아니다 |
| 선택적 세미콜론 | **불변** | Kotlin 에서 스타일이다 |
| 반환값 변경 | **가변** | |
| 파라미터 타입 변경 | **가변** | |
| 본문에 호출 추가 | **가변** | |
| **지역 변수명 변경** | **가변 — 지우지 않는다** | [R-22]. 스코프 해소(L2)가 없는데 지우면 서로 다른 코드가 같은 요약을 갖는다 |

**앞의 셋만 보면 상수를 돌려주는 요약이 만점을 받고, 뒤의 셋만 보면 원문 해시가 통과한다.**
원문 해시는 R-07 의 거짓 양성 그 자체다. 그래서 양방향을 함께 요구했다 —
S1 의 캐시 음성 대조와 같은 형태의 방어이고, 세 슬라이스 연속으로 같은 함정을 막았다.

토큰 사이에 `\x1f` 를 넣는다. 넣지 않으면 `fun f` 와 `funf` 가 같은 바이트열이 된다.

### ④ 두 축이 실제로 분리돼 있다

`symbol_id 3b24ed45c5f2` ≠ `body_digest b9fd0caa81de`. 경로가 `symbol_id` 의 성분이고
`body_digest` 의 성분이 아니므로, **파일을 옮기면 정체성은 끊기고 본문 요약은 남는다** —
그것이 [R-08](../plan/00-risks.md#r-08)의 재결박 제안을 가능하게 하는 유일한 근거다.

`identity ordinal` 로 나오는 것도 옳다. 이 추출기는 **L1(구조)** 이라 스코프가 없고,
심볼의 정체성 등급은 `min(판별자 상한, 언어 등급)` 이다. 언어 단위가 아니라 **심볼
단위**로 계산한다([R-22]).

## 이 회차가 드러낸 것 — 캐시 키 설계가 관측됐다

`Symbol` 에 `body_digest` 가 붙어 추출 산출이 바뀌었는데 `EXTRACTOR_REV` 가 `"s0"` 그대로였다.
**옛 캐시를 새 스키마로 읽으려다 실패했다.**

이것은 사고가 아니라 **설계가 작동한 자리**다. stack §5.1 이 추출기 버전을 1층 캐시 키에
넣은 이유가 정확히 이 경우이고, 값을 `"s2"` 로 올리자 키가 달라져 옛 항목이 조회되지
않는다 — **삭제 없이 무효화된다.** 문법 rev 는 그대로다. 축이 둘인 이유가 이것이다.

`pal-store` 의 캐시가 *"깨진 캐시를 조용히 미스로 만들지 않는다"* 는 규칙을 지킨 덕에
오류로 드러났다. 미스로 처리했다면 성능 저하로만 보이고 영원히 발견되지 않았을 것이다.

## R-01 세 번째 관측 — 수명이 세 번 물었고, 두 번은 타입이 옳았다

| 자리 | 무슨 일 | 처분 |
|---|---|---|
| `Snapshot.repo: &'static str` (S1) | `Deserialize<'de>` 가 거부 | **소유로 바꿨다.** 대장은 되읽어야 하는 산출이므로 타입이 옳았다 |
| `Coord.extractor` · `Envelope.capabilities` | 같은 거부 | **되읽기를 포기했다.** 밖에서 온 좌표의 추출기 버전을 이 빌드의 상수로 읽으면 서로 다른 추출기의 산출이 같은 좌표계에 있는 것처럼 보인다 — **타입이 옳은 말을 하고 있었다** |
| tree-sitter 커서를 재귀에 넘김 | 커서 수명이 자식 노드 수명과 얽힘 | 각 층에서 만들었다. 빌림 하나를 아끼려던 것 |

**셋 다 몇 분이다.** 그리고 두 번째가 이 회차에서 가장 값진 관측이다 — 수명 오류를
*"컴파일러와 싸우는 일"* 로 읽고 소유로 바꿨다면, **버전 대조 없이 외부 좌표를 받는
경로가 생겼을 것이다.** 타입이 막은 것이 설계 결함이었다.

R-01 은 여전히 닫히지 않는다. 본래 판정 시점은 F01~F03 이고 `EdgeCursor` 는 아직 없다.

## 이 게이트가 판정하지 않는 것

- **정규화가 "옳은지"** — 불변식 둘까지다. 어디까지 지워야 의미 보존인가는 F03 의 표본이 진다.
  **후행 쉼표와 리터럴 따옴표 종류는 아직 지우지 않는다**([F03 §3.1]의 표에 있으나 S2 범위 밖).
- **참조 해소(F07)** · **결박(F09~F12)** · **효과(F13)** · **판정(F15)** — 전부 `NotBuilt` 이고
  그것이 ② 가 시험한 자리다.
- **예산 절단** — `Elision` 은 타입으로 서고 값은 언제나 `none()` 이다. 자를 만큼의 답이 없다.
- **R-07 이 닫히지 않는다.** 거짓 양성률은 실제 커밋 이력에 대고 재야 하고 그것은 F03 의 오라클이다.
