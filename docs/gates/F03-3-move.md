# F03-3 게이트 — 이동과 골든: 좌표가 움직인 것이 보이는가 · 판정 기록

**판정: 통과 (2026-08-13).** 합격선 넷이 선다. **그리고 하나는 기권이다** — 등록할 때
이미 기권으로 적었고(`[f03.3.abstain]`), 그 기권이 이 게이트의 1급 기록이다.

`[f03.3]` 이 물은 것:

> **좌표가 움직인 것이 관측 가능한 사건이 되는가 — 그리고 조용히 흡수되지 않는가.**

**둘 다 선다.** 이 조각의 산출은 새 능력이 아니라 **막아 둔 것 셋**이다 — 자동으로
흡수하지 않고, 제안을 적용하는 경로가 없고, 축복이 목록보다 앞서지 않는다.

## 2. ① 별칭 — **빈 방에 자물쇠를 걸지 않았다**

`cargo xtask check` 의 「의도 저장소 폐기 경로 부재」가 정적으로 지키지만, 그것이 말하는
것은 *"`pal-store` 소스가 그 경로를 언급하지 않는다"* 까지다. S3 게이트가 결박에 대해
같은 지적을 했다 — *"의도 저장소가 비어 있었으므로 그것은 **빈 방에 자물쇠를 건 것**"*.

**그래서 실제로 넣고, 파생층을 지우고, 남아 있는지 봤다.**

```
<임시>/derived/index.redb   ← 만들고, 통째로 지운다 (`pal doctor --rebuild` 가 하는 일)
<임시>/intent/intent.redb   ← 별칭이 여기 산다
```

| | 관측 |
|---|---|
| 파생층 삭제 후 별칭 | **남는다** — `order-svc → order` |
| **★ 선언 안 된 이름** | **그대로다** — 자동으로 흡수하지 않는다 |
| **★ `a → b → a` 사슬** | **멈춘다** — 선언 수만큼만 따라간다 |

**★ 둘째가 이 조각의 반대 방향이다.** 흡수만 재면 *"무엇이든 흡수한다"* 가 만점을 받고,
그것은 F03 §5 가 기각한 *"파일 이동 시 자동 재결박 — **의미가 다른 동일 코드에 잘못
붙는다**"* 그 자체다.

**셋째는 우리가 고칠 수 없는 것을 대하는 방식이다.** `a → b → a` 는 사람이 만들 수
있는 선언이고 여기서 막지 않는다 — 다만 **좌표를 만드는 쪽이 멈추지 않는 것**은
우리 몫이다. F03-1 의 `container_chains` 가 포함 관계의 순환에 한 것과 같은 처분이다.

## 3. ② 재결박 — **신호까지다. 적용하는 함수가 없다**

F03 §7 이 *"재결박 제안(자동 아님) — **소유는 F09**, 여기서는 **제안 신호 계산만**"*
이라고 적었다.

### 없는 것을 시험한다

대조가 `pal-intent` 의 소스에 `RebindProposal` 이 **없다**는 것을 센다. 있으면
제안을 받아 결박을 고쳐 쓰는 경로가 서 버리고, 그 순간 §5 의 기각이 무너진다.
**막아 둔 것은 시험하지 않으면 다음 사람이 연다.**

### 신호를 한 숫자로 접지 않는다

| 신호 | 뜻 |
|---|---|
| `body` | 본문 요약이 같다 — **후보의 필요조건.** 거짓이면 후보가 아니다 |
| `name` | 이름이 같다 |
| `container` | 컨테이너 체인이 같다 |

*"믿을 만하다 0.87"* 같은 한 값으로 접으면 **사람이 무엇을 승인하는지 모른다.**
승인이 사람의 일이라는 §5 의 결정은 사람이 근거를 볼 수 있을 때만 성립한다.

### 요약이 다르면 후보가 아니다 ★

이름 유사도로 후보를 **만들지 않는다.** 만들면 그것이 §5 가 기각한 *"잘못 붙는"*
자리다. 후보가 없으면 **빈 목록**이고, 그것이 정확한 답이다 — 흡수 안 된 재배치는
`orphaned` 라는 관측 가능한 사건이 되고 F03 §4.2 가 그것을 *"조용한 정체성 유실보다
낫다"* 로 판단했다.

**그리고 살아 있는 좌표는 제안하지 않는다.** 그 확인이 없으면 이 함수는
*"같은 요약을 가진 심볼 쌍"* 을 세는 것이지 재결박 제안이 아니다.

## 4. ③ 골든 — **축복이 목록보다 앞서지 않는다**

| 파일 | 줄 | 무엇을 본다 |
|---|---|---|
| `corpus/golden/ditto.symbols.tsv` | **4,578** | TypeScript — `(경로, 컨테이너, 이름, 종류, 등급, symbol_id, body_digest)` |
| `corpus/golden/portal-backend.symbols.tsv` | **1,296** | Kotlin — 같은 열 |

**줄 단위이고 대장의 순서 그대로다.** 다시 정렬하지 않는다 — 대장의 순서가 결정적이라는
사실이 이 파일에서도 보여야 한다. `diff` 가 곧 움직인 것의 목록이다.

`--bless` 는 **움직인 것을 넷으로 갈라 찍은 뒤에만** 축복한다: 사라짐 · 새로 ·
좌표 이동 · 요약 이동. 축복이 먼저면 이 골든은 검사가 아니라 산출의 복사본이다.

### F02 지붕이 남긴 구멍과 겹치는가 — **절반 덮는다**

F02 지붕 §2 는 *"TypeScript 496 파일 중 20 만 손 목록이 덮고 나머지 476 은 「안 변했다」
를 지키는 장치가 없다"* 를 구멍으로 적고 **F04·F05 로 넘겼다.** 근거는 *"지금 세우면
축복 대상이 아직 자주 바뀌는 산출이고, 그런 골든은 매 커밋 재축복되어 검사가 아니라
잡음이 된다"* 였다.

**그 「자주 바뀌는」 원인이 F03 이었다.** 이 기능이 좌표와 요약을 한 번씩 통째로 옮겼고,
그것이 끝났으므로 지금이 세울 때다. 그래서 **덮는다** — 476 을 포함한 496 파일 전부의
심볼 목록이 골든에 들어간다.

**다만 덮는 것은 「안 변했음」뿐이다.** *"빠뜨리지 않았음"* 은 여전히 손 목록
(`f02-recall-sample.tsv` · 20 파일 172 개)이 지고, **골든은 그것을 대신하지 못한다**
(F02 §6 이 적은 그대로). **그 빚은 남는다.**

## 5. 기권 — **대조 불가는 1급 판정이다**

`[f03.3.abstain]` 이 **등록 시점에** 적은 그대로다.

| | |
|---|---|
| 지표 | 대규모 이동 커밋에서 재결박 제안 정확도 **≥ 90%** (F03 §6.2) |
| 판정 | **대조 불가** |
| 근거 | 이름 변경 3 건 이상인 커밋: **ditto 0 · portal-backend 1**. `[outcome.procedure].abstention_rule` 의 `n < 5` |
| 덤 | 유일한 1 건은 **Kotlin** 이라 컨테이너 체인이 없다 — 그 코퍼스에서 재는 제안은 F03 이 만든 신호를 시험하지 않는다 |

**90% 를 채우려고 모집단을 넓히지 않았다.** 넓히면 결과를 보고 선정을 고친 것이고
그것이 R-18 이다. 대신 **합성 이동**은 잰다 — 우리가 파일을 옮기고 제안이 그 심볼을
정확히 가리키는지(§3). 그것은 정확도 지표가 아니라 불변식이다.

**기권을 등록에서 빼지 않고 남기는 이유는 R-29 §대응3 이다** — *"대조 불가"는 1급
판정이고, 생략하고 통과로 처리하는 것이 가장 조용한 실패 경로다. `[[outcome.metric]]`
M4 · F22-3 이 같은 형태로 기권했다.

## 6. ④ 선택 필드 금지 — **셋을 잡았고 코드를 고쳤다**

[stack §4.3](../plan/00-stack.md#43-검사를-언제-켜는가--전부-첫-커밋에-켜지-않는다)이 이
검사의 소유를 **F03** 으로, 1 단계의 범위를 *"`pal-core` 의 `pub struct` 필드 문자열
스캔"* 으로 적었다. `cargo xtask check` 가 **7 → 8** 이 됐다.

등록할 때 *"지금 워크스페이스가 통과하는지는 모른다"* 라고 적었고, **셋이 걸렸다.**

| 걸린 것 | `None` 이 무엇을 뭉갰나 | 처분 |
|---|---|---|
| `FileAttributes.text: Option<bool>` | *"`-text` 라 꺼져 있다"* 와 *"미지정이라 `core.autocrlf` 가 정한다"* | `Declared<bool>` |
| `FileAttributes.language: Option<String>` | 위와 같음 | `Declared<String>` |
| `EdgeDecl.carried_by: Option<Carrier>` | *"실린 자리가 없다"* 는 곧 **「별도 자리다」** 라는 사실이다 | `Carried { Standalone, By(_) }` |

**`Declared<T>` 가 `Option<T>` 과 구조가 같다는 것이 요점이 아니다.** 요점은
`Unspecified` 라는 **이름이 코드와 산출에 남는 것**이고, 그것이
[ADR-0005](../adr/0005-absence-carries-its-kind.md)(*"부재는 종류를 싣는다"*)가
정본화한 규율이다. `Capable::NotBuilt{capability}` 가 빈 `Vec` 을 대신한 것과 같은 자리다.

### ★ 음성 대조

`pal-core` 의 `pub struct` 에 `Option<u32>` 필드를 하나 넣었더니 검사가 **잡았다**.
되돌렸다. 없으면 이 검사는 아무것도 안 세는 검사이고, F22 가 *"음성 대조가 없으면
아무것도 세지 않는 검사가 만점을 받는다"* 라고 적은 그 자리다.

### 이 검사가 **못 보는 것** — 적어 두지 않으면 1 단계가 2 단계인 척한다

| 못 보는 것 | 실물에 있는가 |
|---|---|
| `enum` 변형 안의 필드 | **있다** — `Resolution::Candidates { demoted_to: Option<NodeKey> }` |
| 여러 줄에 걸친 필드 선언 | 지금은 없다 |
| 타입 별칭 뒤에 숨은 `Option` | 지금은 없다 |
| `pub` 이 아닌 필드 | **일부러 안 본다** — stack §5.4 가 구현 내부 자료구조를 허용 열에 뒀다 |

**첫 줄이 실물에 있다는 사실을 그대로 적는다.** 2 단계(`syn` AST)가 그것을 볼 것이고,
그때까지 이 검사는 *"`pub struct` 의 필드"* 만 말한다.
