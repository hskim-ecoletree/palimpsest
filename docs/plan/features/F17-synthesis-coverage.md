# F17 — 합성물과 검증자 커버리지

| 우선순위 | 의존 | 규모 | 크레이트 |
|---|---|---|---|
| **P3** | F11 · F15 | L | `pal-core::narrative` |

---

## 1. 왜

이 도구의 소비자는 사람만이 아니라 **생성형 에이전트**다. 에이전트가 만든 요약·설명·제안은 1급 산출이되, **근거 없이 저장되면 안 된다.** 그리고 검증자가 "충분히 봤다"고 **신고하는 것**과 실제로 본 것은 다르다.

두 장치가 여기 산다.

---

## 2. 합성물 — 근거 없이 저장되지 않는다

```rust
pub struct Synthesis {
    body: String,
    provenance: Inferred,
    evidence_refs: NonEmpty<Coord>,   // 비면 생성 불가 — 타입으로 강제
    gaps: Gaps,                       // 기계가 채운다. 못 채우면 쓰기 실패
    confidence: Confidence,
    produced_by: ProducedBy,          // {모델, 프롬프트 해시, Snapshot}
}

pub struct Narration {
    synthesis: Synthesis,
    coverage: Coverage,
    unresolved_refs: Vec<UnresolvedRef>,
    narration_basis: NarrationBasis,  // GraphOnly | GraphPlusDirectRead
    direct_reads: Vec<Coord>,         // basis=GraphPlusDirectRead 인데 비면 저장 거부
}
```

**`gaps`를 기계가 채우는 이유**: 사람/에이전트가 "빠진 것 없음"이라고 쓰면 그것이 곧 거짓 안전이다. 기계가 `evidence_refs`의 커버리지에서 계산하고, 계산하지 못하면 **쓰기 자체가 실패한다.**

**생산자 분리**: 산출을 만든 주체와 그것을 검증하는 주체를 `produced_by`로 사후 관측 가능하게 한다. 설명·출제도 생성 경로 밖에 둔다.

---

## 3. 커버리지 — 신고받지 않고 계산한다

**질의 로그에서 계산한다.** F05에서 **처음부터** 질의 로그를 켠 이유가 이것이다 — 이 기능이 착수될 때 새 장치를 만드는 게 아니라 이미 쌓인 로그를 읽는다.

```
미조회 하한 = (판정 대상 좌표 집합) − (질의 로그가 접근한 좌표 집합)
```

- **하한이다** — 로그에 없는 접근(직접 파일 읽기)이 있을 수 있다. 그래서 `narration_basis`를 선언받고, 호스트 도구 로그를 조달할 수 있으면 미신고 접근 건수를 산출에 넣는다.
- **비대칭 처분**: 커버리지가 임계(미조회 50%)를 넘으면 → **`Finding`은 등급을 달고 그대로 선다**(존재 주장이므로 하한 위에서 참) / **완결성 주장과 후속 판정 입력 자격은 잃는다.**

## 4. 승인 큐

| 장치 | 내용 |
|---|---|
| 일괄 승인 | 같은 규칙이 파생한 N건을 한 번에 |
| **거부도 기록** | 재질문 제거가 승인 비용 절감의 대부분이다 |
| 진척 가시화 | 남은 건수·예상 시간 |

P0-preflight T3에서 어느 장치가 실제로 단가를 내리는지 이미 측정했다. **그 결과에 따라 여기서 만들 것이 정해진다.**

---

## 5. 이슈와 대응

| 이슈 | 왜 | 대응 | 안 되면 |
|---|---|---|---|
| **커버리지가 실제 사각을 반영 못 함** | 직접 파일 읽기가 로그에 없음 | `narration_basis` 선언 + 호스트 로그 조달 | 하한임을 명시하고 "약한 이름"으로만 부른다 |
| **`gaps` 계산 불가** | 판정 대상 집합이 정의 안 됨 | 질의 종류마다 대상 집합을 정의. 못 하면 그 종류는 `Narration`을 못 만든다 | 쓰기 실패가 옳다 |
| **`evidence_refs`가 형식적** | 아무 좌표나 넣기 | 커버리지 계산이 실제 접근과 대조하므로 드러난다 | — |
| **승인 노동** | [R-10](../00-risks.md#r-10) | 일괄 + 거부 기록 | P0-preflight가 이미 판정 |

---

## 6. 고려한 대안

| 대안 | 기각 이유 |
|---|---|
| **커버리지를 자기 신고로** | 신고와 실제의 차이가 이 기능의 존재 이유다 |
| **`evidence_refs`를 선택 필드로** | 선택 필드는 비게 된다 |
| **커버리지 미달 시 `Finding` 억제** | 존재 주장은 하한 위에서도 참이다. 억제하면 실제 위반을 숨긴다 |
| **`gaps`를 사람이 작성** | "빠진 것 없음"이 거짓 안전을 만든다 |

---

## 7. 검증

- **신고 대 계산의 차이 측정** — 실제로 벌어지는가.
- **`graph-only` vs `graph+direct-read` 산출 품질 대조** — 그래프만으로 서술한 것과 직접 읽기를 섞은 것의 차이.
- **승인 큐 실사용 단가** — P0-preflight 측정과 대조.
