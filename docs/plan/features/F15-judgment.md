# F15 — 지배관계(C5)와 3분할 판정

| 우선순위 | 의존 | 규모 | 크레이트 |
|---|---|---|---|
| **P2 — 가장 큰 단일 베팅** | F13 · F14 | **XL** | `pal-core::judgment` · `pal-query::audit` |

---

## 1. 왜

서사적 결함의 공통 형태:

> 진입점 E에서 지점 S로 가는 경로 중, 술어 P로 **지배되지 않는** 것이 존재하는가?

"이 엔드포인트에 닿는 모든 경로가 인가 검사를 통과하는가"가 이 형태다. 단위 테스트로 안 잡히고, 대부분의 코드 검색 도구가 제공하지 않는다.

**그리고 이 기능의 정체성은 `clean`을 출력하지 않는 것이다.**

```rust
pub enum Judgment { Finding(Finding), Residual(Residual), OutOfScope(OutOfScope) }
//     ^ 넷째 변형이 없고 #[non_exhaustive] 도 아니다
```

271개 엔드포인트에 **"전부 위험"도 "이상 없음"도** 말하지 않는다. "위반 없음"은 **빈 `Finding` 목록 + 비지 않은 `Residual` 목록**으로만 표현된다.

---

## 2. 3분할

| | 뜻 | 필수 필드 | 성질 |
|---|---|---|---|
| **`Finding`** | 위반이 존재한다 | **반례 경로 `Site`** | 존재 주장. 하한 위에서도 참이다. 커버리지가 낮아도 **그대로 선다**(등급을 달고) |
| **`Residual`** | 판정할 수 없었다 | `{사유, 술어, 결박 좌표[], 발생 Snapshot, 해소 조건}` | **목록이 아니라 결박물** |
| **`OutOfScope`** | 범위 밖이다 | 대장 참조 | 대장이 근거 |

### 2.1 `Residual`이 결박물인 이유

잔여를 "이번에 못 본 것들의 목록"으로 두면 다음 실행에서 조용히 사라진다. 그러면 **판정되어 사라진 것과 범위가 줄어 사라진 것이 구별되지 않는다.**

`Residual`을 좌표에 결박하면:
- `touch`(F11)로 **사람이 있는 곳에 온다**
- 좌표가 변하면 `stale`이 되어 **재판정 큐**에 들어간다
- 소멸의 원인이 3분해된다: **판정됨 / 좌표 소멸 / 범위 축소**

### 2.2 잔여 사유

`미해소 참조 경유` · `candidate 집합 과다` · `경로 곱 예산 초과` · `언어 등급 미달` · `라벨 없음` · `라벨 낡음` · `관측 낡음` · `범위 밖 경유` · `제어흐름 미지원`

---

## 3. 구현

### 3.1 제어흐름(L4)과 경로

- tree-sitter 트리에서 함수별 **CFG(기본 블록 + 분기)** 를 만든다. 조건·루프·early return·throw/catch.
- 지배관계는 **함수 내부에서는 지배자 트리(Lengauer-Tarjan 또는 단순 반복법)** 로, **함수 간에는 호출 그래프 위의 경로**로 계산한다.
- `petgraph`를 부분 그래프 알고리즘에 사용한다(도달성·SCC·지배자).

### 3.2 판정 술어

```
가드 지배:  entry E → sink S 의 모든 경로가 guard 라벨이 붙은 심볼을 통과하는가
효과 비대칭: writes(P1) ⊋ writes(P2)              ← F13
```

**가드 라벨은 사람이 승인한 `asserted`다**([R-10](../00-risks.md#r-10)). 라벨이 없으면 판정할 것이 없고 전부 `Residual{라벨 없음}`이 된다 — **이것이 이 기능의 최대 위험이다.**

### 3.3 예산과 절단

경로 탐색은 F05의 예산을 그대로 진다. `candidate` 경유 경로는 `Finding`이 아니라 **`Residual`** 이다 — 후보 집합을 통과한 경로는 실재를 보증하지 않으므로 존재 주장을 세울 수 없다.

### 3.4 범위 축소를 판정에 동반시킨다

```rust
pub struct ScopeReduction {
    handle: ReductionHandle,      // 제외 규칙 · 언어 등급 · 팩 규칙 삭제 · 라벨 삭제 · 범위 설정 · 예산
    before: ScopeSnapshot, after: ScopeSnapshot,
    vanished: Vec<Coord>,         // 판정 대상에서 사라진 좌표
    at: Snapshot,
    rule_id: RuleId,
}
```

**판정 산출에 `ScopeReduction` 동반이 필수다.** 빠지면 "잔여가 줄었다"가 "판정이 진전됐다"로 읽힌다 — 그것이 게이트 오염의 형태다. 그리고 `ScopeReduction`은 사라진 좌표에 결박되어 `touch`로 **사람이 있는 곳으로 온다.**

## 4. 이슈와 대응

| 이슈 | 왜 | 대응 | 안 되면 |
|---|---|---|---|
| **잔여가 90%다** | 라벨 없음 + 미해소 경유 | ① 사유별 분해로 무엇이 지배적인지 보인다 ② 라벨 저작 단가를 P0-preflight가 이미 쟀다 | **감사를 산출 목록에서 내린다.** 큐레이션·컨설팅만 남긴다 |
| **경로 폭발** | 분기 × 후보 | 예산 B + `Residual{예산 초과}` | 함수 내부 지배관계만 하고 함수 간은 포기 |
| **가드 라벨 부재** | 사람 노동 | 팩 규칙(F18)이 파생 | 규칙도 안 써지면 이 기능이 빈다 |
| **거짓 `Finding`** | 반례 경로가 실제로 불가능한 경로 | **반례 경로를 `Site`로 첨부해 검증 가능하게.** 사람이 즉시 반박할 수 있어야 한다 | 표본 검토로 정밀도 측정 |
| **CFG 구축 비용** | 함수마다 | 필요한 함수만 지연 계산(질의 시점) | 캐시 |
| **기존 도구와 겹침** | 정적 분석 lint가 이미 있다 | **이길 지점은 정밀도가 아니라 셋** — 결박된 기준 / 3분할 / 적시 제시. 이 셋이 사람 행동을 안 바꾸면 기성 도구가 낫다 | 이 기능을 내린다 |

---

## 5. 고려한 대안

| 대안 | 기각 이유 |
|---|---|
| **`clean` 출력 허용** | 이 제품의 정반대. "이상 없음"이 거짓 안전을 만든다 |
| **`Residual`을 로그로** | 다음 실행에서 조용히 사라진다. 결박물이어야 한다 |
| **위험 점수로 순위** | 점수는 근거가 없다. 3분할이 근거 기반 |
| **가드를 자동 인식(휴리스틱)** | 거짓 라벨이 판정 전체를 오염시킨다. 규칙 파생(팩)은 가능하되 `asserted_via=rule`로 추적 |
| **범위 축소를 별도 보고서로** | 판정과 함께 안 나오면 아무도 안 본다. 동반 필수 |

---

## 6. 검증 — 반증되면 내린다

| 측정 | 게이트 |
|---|---|
| **잔여 비율과 사유 분포** | 90% 이상이면 산출이 무의미 |
| 과거 결함 재현 검출 | 코퍼스의 실제 가드 누락을 잡는가 |
| `Finding` 정밀도 | 표본 손 검토. 거짓 양성이 많으면 신뢰를 잃는다 |
| `Residual`이 `touch`로 되돌아오는가 | F11 재사용 검사 |
| **기성 도구 대비 행동 변화** | 결박된 기준·3분할·적시 제시 중 어느 것도 행동을 안 바꾸면 **이 산출을 내린다** |
