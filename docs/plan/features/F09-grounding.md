# F09 — 결박과 낡음 (C6)

| 우선순위 | 의존 | 규모 | 크레이트 |
|---|---|---|---|
| **P1 — 제품의 심장** | F03 · F05 | L | `pal-core::binding` |

---

## 1. 왜

**문서가 낡는 것은 막을 수 없다. 낡았다는 사실의 감지는 기계적으로 가능하다.**

> 의도층의 모든 항목은 사실층의 좌표에 결박된다. 그 좌표의 코드가 변하면 기계는 그 결박이 낡았음을 안다.

"이 결정은 어느 커밋 기준으로 쓰였고, 그 커밋 이후 결박된 코드가 바뀌었는가" — 결정론적으로 답할 수 있다. **낡음이 조용한 거짓 신호가 아니라 표시된 상태가 되는 순간, 낡은 문서는 다시 안전해진다.**

**달성 기여**: [목표 §3.3](../00-goals.md#33-낡음이-표시된-상태다)과 목표 1(큐레이션). 이 기능이 곧 제품이다.

## 2. 5상태

```rust
pub enum BindingState {
    Live,        // 좌표 존재 + 감시 집합 전체의 digest 불변
    Stale { triggered_by: NonEmpty<SymbolId> },   // 무엇이 켰는지 함께
    Pending,     // 좌표가 아직 없다 (신생 프로젝트 / 계획 항목)
    Orphaned,    // 좌표가 사라졌다 (심볼 삭제·이동)
    Superseded { by: EntityId },   // 이 의도가 다른 의도로 대체됨
}
```

| 왜 이 다섯인가 | |
|---|---|
| `Pending` ≠ `Stale` | **"아직 안 만들었다"와 "만든 뒤 어긋났다"는 다르다.** 뭉개면 신생 프로젝트에서 전부 낡음으로 보인다 |
| `Orphaned` ≠ `Stale` | 구현 제거는 코드 변경과 다른 사건이다. 사람의 판단을 부른다 |
| `Superseded` | **대체된 결정이 "살아 있음"으로 적극 보증되는 것이 낡음보다 강한 거짓 신호다** |
| `Stale`이 `triggered_by`를 갖는 이유 | "본체가 변해서"와 "호출자가 변해서"는 사람이 다르게 처리한다 |

`Superseded`는 코드에서 나오지 않는다 — 계보 엣지에서 온다. 의도층의 사건이므로 사람 또는 승인된 추론이 만든다.

## 3. 결박 반경 — 닫히지 않는 문제를 선언으로 다룬다

**거짓 음성은 원리적으로 닫히지 않는다.** 좌표 바깥(호출자·설정·스키마)이 변해 결정이 무효가 돼도 `live`로 남는다. "이 결정과 관련 있는 코드 전부"는 결정 불가능하다. **그러므로 닫지 않고 선언한다.**

| 반경 | 감시 집합 | 판정 비용 | 켜는 방법 |
|---|---|---|---|
| `symbol` (기본) | 결박된 심볼의 digest | 상수 | 기본값 |
| `callers` | + 직접 호출자 | 인접 조회 1회 | 결박 시 선택 |
| `closure(k)` | + k-홉 의존 폐포 | 폐포 크기 비례 | **명시적 승인. 예산 초과 시 저장 시점에 거부** |
| `files` | + 나열된 파일(설정·스키마·마이그레이션) | 열거 길이 | 사람이 지정 |

**반경이 판정 결과에 함께 출력된다.** *"이 결정은 `symbol` 반경에서 live"* 는 *"이 결정은 유효하다"* 와 다른 문장이고, 그 차이가 산출에 남는 것이 이 설계의 요구다.

**`closure(k)`는 런타임에 조용히 느려지는 대신 설정 시점에 실패한다** — `결박 수 × 폐포 크기 ≤ 10⁶`를 넘으면 저장을 거부한다.

## 4. 구현

### 4.1 감시 집합과 상태 계산

```rust
pub struct Binding {
    id: BindingId,
    subject: EntityId,            // 결정·라벨·계획항목 — 비코드 개체 (§4.3)
    target: SymbolId,
    radius: Radius,
    watch_snapshot: BlakeMap,     // 결박 시점의 (심볼 → body_digest)
    created_at: Snapshot,
}

fn state_of(b: &Binding, proj: &Projection) -> Result<BindingState> {
    let Some(target) = proj.symbol(b.target)? else { return Ok(Orphaned) };  // 좌표 소멸
    let watch = expand_radius(b.target, b.radius, proj)?;                    // 감시 집합
    let changed: Vec<_> = watch.iter()
        .filter(|s| proj.digest(s)? != b.watch_snapshot.get(s))
        .collect();
    Ok(if changed.is_empty() { Live } else { Stale { triggered_by: changed.into() } })
}
```

**`watch_snapshot`을 저장하는 이유**: 결박 시점의 digest를 기억해야 "그 이후 변했는가"를 답할 수 있다. 매번 커밋 이력을 거슬러 계산하면 비싸다. 저장 비용은 반경 크기에 비례하고, 그래서 반경에 예산이 걸린다.

**증분 갱신**: 재추출 시 digest가 바뀐 심볼 집합을 알고 있으므로(F04), `WATCH` 테이블의 역방향 조회로 영향받는 결박만 재계산한다. 전체 재계산이 아니다.

### 4.2 상태 계산은 상수 시간이 아니다

투영 신선도 검사(HEAD 비교)는 상수 시간이지만 **결박 상태 계산은 반경 크기의 비용을 진다.** 둘을 혼동하지 않는다. `touch` 질의(F11)는 결박 상태를 계산하므로 그 비용을 진다 — 그래서 반경 예산이 있다.

### 4.3 비코드 개체 식별자 — 지금 정한다

`Coord`는 코드 전용이다(`repo_id, commit, extractor, symbol_id`). 그런데 **결정·계획·잔여·라벨은 자기 식별자가 필요하다.** 설계에 이 규정이 없다.

```rust
pub struct EntityId {
    kind: EntityKind,     // Decision | Plan | Label | Residual | ScopeReduction | Concept
    // 안정 식별자. 원본 문서의 (경로, 앵커) 또는 명시적 ID.
    // 문서가 이동해도 유지되어야 하므로 경로 해시가 아니다.
    id: Ulid,
    origin: EntityOrigin, // 어느 문서·어느 섹션에서 왔나 (추적용, 정체성 아님)
}
```

**지금 정하지 않으면 나중엔 마이그레이션이다.** 의도층 개체가 쌓인 뒤에 식별 체계를 바꾸면 전부 다시 결박해야 한다. 비용이 지금은 0이다.

같은 이유로 **노드·엣지 타입을 닫힌 열거로 하드코딩하지 않는다** — 코어는 타입의 *구조*를 알고 타입의 *목록*은 데이터로 둔다. 나중에 개념 노드(F18)를 추가할 때 코어 개정이 필요 없게.

## 5. 이슈와 대응

| 이슈 | 왜 | 대응 | 안 되면 |
|---|---|---|---|
| **거짓 양성** [R-07](../00-risks.md#r-07) | 정규화 부족 | F03이 이미 방어. **추가로 코퍼스의 포매팅 커밋에서 `stale` 0건을 게이트로** | 제품이 성립하지 않는다 |
| **거짓 음성** | 반경 밖 변경 | 원리적으로 안 닫힌다. **선언된 반경을 산출에 노출**하는 것이 대응 | 반경 기본값을 `callers`로 올리는 것을 실측으로 검토 |
| **`watch_snapshot` 부피** | 반경 × 결박 수 | `closure(k)` 예산 + 대부분은 `symbol`(원소 1) | 압축 |
| **낡음 감지기가 낡는다** | 마지막 재추출이 3주 전 | 감지기 상태를 대장에 — 마지막 재추출 Snapshot·추출기 버전·이후 커밋 수. **상수 시간 검사이므로 무한 후퇴하지 않는다** | — |
| **`Orphaned` 폭발** [R-08](../00-risks.md#r-08) | 디렉터리 이동 | 같은 `body_digest`의 새 심볼로 **재결박 제안**(자동 아님) + 같은 경로 접두사 변경은 일괄 승인 | 제안 정확도를 실측 |
| **사람이 표시를 무시** | 노이즈 | `stale` 출력에 `triggered_by`와 반경을 항상 붙여 **행동 가능하게** 만든다 | [목표 G1](../00-goals.md#5-성공실패의-판정-형태) 반증 — 제품 재론 |

## 6. 고려한 대안

| 대안 | 기각 이유 |
|---|---|
| **3상태(live/stale/pending)** | `orphaned`와 `superseded`가 뭉개진다. 특히 대체된 결정이 "유효"로 보이는 것은 낡음보다 나쁘다 |
| **반경 없이 심볼만** | 거짓 음성이 크고, 사용자가 그 사실을 모른다. **선언은 해결이 아니지만 은폐보다 낫다** |
| **반경 무제한 허용** | 폐포 계산이 설치 비용 제약을 깬다. 저장 시점 거부가 런타임 지연보다 낫다 |
| **커밋 이력을 매번 거슬러 계산** | 비싸고, 캐시가 없으면 계보 질의마다 전량 추출 |
| **낡음을 자동으로 해소(재결박)** | 의미가 다른 코드에 잘못 붙는다. 사람의 판단을 부르는 것이 설계 의도 |
| **`EntityId`를 나중에 정한다** | 마이그레이션 비용. 지금은 0 |

## 7. 검증

| 측정 | 게이트 |
|---|---|
| **포매팅 전용 커밋이 켜는 `stale`** | **0** ← 통과 못 하면 진행 불가 |
| 의미 변경 커밋에서 `stale` 검출률 | 높을수록 좋음. 표본 검토 |
| 대규모 이동에서 `orphaned` + 재결박 제안 정확도 | ≥ 90% |
| 상태 계산 비용 | 반경별 · 결박 수별 벤치 |
| 증분 상태 갱신 정확도 | 전체 재계산과 일치 |

**반증 게이트**: 거짓 양성률이 높아 사람이 표시를 무시한다 → [목표 G1](../00-goals.md#5-성공실패의-판정-형태) 반증.
