# F08 — 미해소 참조: 공백을 1급 사실로

| 우선순위 | 의존 | 규모 | 크레이트 |
|---|---|---|---|
| **P1** | F07 | M | `pal-core::graph` |

---

## 1. 왜 — 이 기능이 이 제품의 정체성이다

빌드하지 않으면 생성 코드·DI 바인딩·서드파티 계층은 **노드 자체가 파일 시스템에 없다.** 이것은 정밀도 손실이 아니라 완전성 손실이다.

대부분의 코드 그래프 도구는 못 푼 참조를 조용히 버린다. 그러면 그래프는 깨끗해 보이고, **"닿는 경로 없음"이라는 답이 "가는 참조 12건이 미해소"와 구별되지 않는다.** 그것이 거짓 안전이다.

> **답은 없는 것을 만들어내는 것이 아니라, 없음을 노드로 만드는 것이다.**

**달성 기여**: [목표 §3.1](../00-goals.md#31-모르는-것을-안다고-하지-않는다) — 이 기능이 그 주장의 전부다.

---

## 2. 데이터

```rust
pub struct UnresolvedRef {
    name: RefName,                    // 참조된 이름
    site: Site,                       // 참조 지점 — span 필수
    reason: UnresolvedReason,
    attempts: NonEmpty<ResolveAttempt>,   // 무엇을 시도했고 왜 실패했나
}

pub enum UnresolvedReason {
    NoDefinition,        // 정의를 못 찾음 (생성 코드·DI·외부)
    TooManyCandidates,   // 후보 K 초과 → 나열 대신 강등
    LanguageGradeBelow,  // 그 언어의 등급이 이 해소를 못 받침
    OutOfScope,          // 범위 밖 (node_modules 등)
    DynamicDispatch,     // 수신자를 정적으로 모름
    StringBased,         // 문자열로 지정된 대상
}
```

**`attempts`가 필수인 이유**: "왜 못 풀었나"가 없으면 사용자는 도구를 못 믿고, 우리는 무엇을 고칠지 모른다. 시도 기록이 곧 개선 지도다.

**해소돼도 지우지 않는다.** 나중에 실행 관측(F16)이 해소해도 `UnresolvedRef`는 남고 `observed` 엣지가 그것을 **가리키며 붙는다.** 재현 보증이 없으므로 다른 환경에서 그 지점은 다시 미해소이고, **정적 하한과 관측된 해소를 겹쳐 보여주는 것이 정직한 형태다.**

## 3. 이것이 만드는 것 셋

### 3.1 거짓 안전이 관측 가능해진다

```
$ pal refs callees OrderService.cancel
호출 12  (exact 9 · candidate 1 · 미해소 2)
미해소:
  PaymentGateway.refund   동적 디스패치    cancel.ts:88   시도: 스코프체인 → 없음, 임포트 → 인터페이스만
  handler                 문자열 기반      registry.ts:14 시도: 리터럴 아님
```

### 3.2 공백이 순위를 갖는다 — 로드맵을 자동 생성한다

미해소 참조가 몰린 파일·사유가 곧 **다음에 무엇을 만들지**다.

```
$ pal refs unresolved --by reason
문자열 기반      412   ← 라우트 레지스트리 패턴. 프레임워크 인식기(F14)를 만들면 대부분 해소
동적 디스패치    287   ← 실행 관측(F16)의 1순위 표적
정의 없음        156   ← 그중 89건이 DI 컨테이너. 팩 규칙(F18) 후보
후보 과다         44   ← L2c(수신자 타입)가 있으면 줄어든다
언어 등급 미달    31   ← SQL 파일. SCIP 수용 또는 추출기 추가
```

**이 표가 이 프로젝트의 백로그다.** 사람이 우선순위를 정하지 않는다 — 밀도가 정한다.

### 3.3 외부 사실의 수용 지점이 생긴다

F16의 관측 수용이 **`UnresolvedRef`를 해소하는 형태로** 들어온다. 실행 조달은 전수가 아니라 이 지도를 따라 좁게 일어난다 — 그래서 설치 비용 제약과 충돌하지 않는다.

| 실패 사유 | 실행 관측이 해소하는가 |
|---|---|
| 동적 디스패치 · 문자열 기반 | **예** — 트레이스가 실제 대상을 준다 |
| 정의 없음(생성 코드·DI) | **예** — 빌드 산출물·컨테이너 덤프가 노드를 준다 |
| 후보 과다 | 부분 — 관측된 것만 확정, 나머지는 `candidate` |
| 언어 등급 미달 | 부분 — 실행으로는 안 되지만 **그 언어의 빌드 통합 인덱서가 만든 SCIP/LSIF로는 된다** |
| 범위 밖 | 아니오 — 범위의 문제 |

## 4. 이슈와 대응

| 이슈 | 왜 | 대응 | 안 되면 |
|---|---|---|---|
| **미해소가 압도적으로 많다** | L2c 부재 등 | ① 사유별로 나눠 보면 대부분이 소수 패턴에 집중된다 ② 그 패턴을 인식기/팩으로 처리 ③ **비율 자체를 대장에 공개** | 미해소 비율이 높은 프로젝트는 등급을 낮춰 표시. 숨기지 않는다 |
| **`UnresolvedRef` 부피** | 참조 지점마다 노드 | 같은 (이름, 사유, 파일) 조합은 **집계**하고 `site` 목록을 상한(예: 10)까지만. 초과는 건수로 | — |
| **노이즈로 인식됨** | 사용자가 "쓸데없는 경고"로 봄 | 기본 출력은 **사유별 집계 한 줄**. 상세는 요청 시 | 기본을 더 접는다 |
| **보존 정책** | 지우지 않으므로 단조 증가 | **좌표가 살아 있는 동안만 유지.** 좌표가 `orphaned`면 함께 축출 | — |
| **`attempts` 기록 비용** | 모든 실패마다 문자열 | 시도를 열거형으로(문자열 아님). 부피가 작다 | — |

## 5. 고려한 대안

| 대안 | 기각 이유 |
|---|---|
| **미해소를 로그로만 남긴다** | 질의할 수 없고, 순위를 못 매기고, 관측 수용의 표적이 될 수 없다 |
| **미해소를 "unknown" 심볼 노드로 만든다** | 존재하지 않는 심볼이 그래프에 생긴다. 경로 탐색이 가짜 노드를 지난다 |
| **사유를 자유 문자열로** | 집계·순위·수용 표적화가 전부 불가능해진다 |
| **해소되면 삭제** | 다른 환경에서 다시 미해소다. 정적 하한과 관측 해소를 겹쳐 보이는 것이 정직 |
| **미해소 비율을 숨기고 깨끗한 그래프만 보여준다** | 이 제품의 정반대 |

---

## 6. 검증

- **하한 정직성 테스트** — 코퍼스에 의도적으로 동적 디스패치를 넣고, 그것이 `UnresolvedRef`로 잡히는가(엣지가 없거나 조용히 사라지지 않는가).
- **사유 분류 정확도** — 표본 100건을 손으로 검토해 사유가 맞는가.
- **집계 일관성** — 사유별 합 = 전체.
- **밀도 지도의 유용성** — 상위 사유 3개를 처리하면 미해소가 몇 % 줄어드는지 예측하고, 실제로 처리 후 검증.
