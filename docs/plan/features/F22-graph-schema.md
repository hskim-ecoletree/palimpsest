# F22 — 그래프 스키마와 무결성 (KG의 뼈대)

| 우선순위 | 의존 | 규모 | 크레이트 |
|---|---|---|---|
| **P0** | P0-preflight | M | `schema/graph.toml` · `pal-core::schema` · `xtask` |

> **의존이 `—`에서 `P0-preflight`로 바뀐 이유 (2026-08-11)**: 이 기능은 `pal-core::schema`와 `xtask`를 요구하므로 코드다. [P0-preflight](P0-preflight.md)는 "**이것 전에 코드를 쓰지 않는다**"이고 그것은 전역 선행조건이다. 기능 간 의존이 없다는 것과 선행조건이 없다는 것은 다르다.

> 근거: [DESIGN §1.1·§1.2](../../DESIGN.md) (D25·D26) · [§3.4](../../DESIGN.md) (D27) · [§6.4·§12.7](../../DESIGN.md) (D29) · [지시 U13~U15](../../instructions/2026-08-10-owner-direction.md)

---

## 1. 왜

**설계에 타입 표는 있었고 그래프 스키마는 없었다.** 노드 라벨의 집합, 엣지 타입의 집합, 각 엣지의 도메인·레인지·카디널리티, 속성별 생성 주체 — 어디에도 없다. [U10](../../instructions/2026-08-04-owner-direction.md)이 온톨로지를 목표로 세웠는데 그 실질이 비어 있던 자리이고, 그래서 "엔티티가 잘 설계되었는가"라는 질문에 **대조할 대상이 없었다.**

그리고 없으면 이렇게 된다 — 기능 20개가 각자 노드를 만들고, 어느 것이 어디에 붙는지가 코드에만 있고, `pal export`가 무엇을 내보내야 하는지 매번 새로 정한다.

**이 기능이 P0인 이유**: F01이 첫 노드를 만드는 순간 스키마가 있어야 한다. 나중에 만들면 그것은 스키마가 아니라 **이미 만들어진 것의 목록**이다.

**달성 기여**: 모든 기능의 형태. 그리고 [goals §0.1](../00-goals.md)의 (c)(d)가 요구하는 노드 넷이 여기서 자리를 얻는다.

## 2. 산출 둘

### 2.1 `schema/graph.toml` — 단일 진실

`surface/queries.toml`이 질의에 대해 하는 일을 노드·엣지에 대해 한다. **다섯이 여기서 파생된다**: ① Rust 타입의 검사 ② JSON 스키마 ③ 문서 표 ④ `pal export`의 매핑 ⑤ `doctor`의 불변식 1·2.

```toml
schema_version = 1

[node.Symbol]
provenance = "extracted"
key        = ["coord"]
attrs = [
  { name = "name",           type = "string", producer = "extractor", required = true },
  { name = "body_digest",    type = "digest", producer = "extractor", required = true },
  { name = "identity_grade", type = "enum:IdentityGrade", producer = "extractor", required = true },
]

[edge.CALLS]
from        = "Symbol"
to          = ["Symbol", "UnresolvedRef"]
cardinality = "many-to-many"
provenance  = ["extracted", "observed"]
grade       = true          # 해소 등급 필수
```

**모든 엣지가 공통으로 지는 넷**: 해소 등급(F07) · 출처 · 근거(`inferred`일 때 필수) · 발생 `Snapshot`. 넷이 없는 엣지 타입은 등록되지 않는다.

### 2.2 id 산출 규칙 — 출처는 정체성의 성분이다 ([R14](../../evidence-map.md))

**선행 구현이 정확히 이 자리에서 자기 설계를 unsound로 판정했다**([G §2](../../research/2026-08-11-legacy-freshness-anchor-observation.md)). 파생물 id가 `제목 + 대상 커밋 + 대상 집합`만 해시하고 생산자를 제외해서, **정적 엔진의 판정과 에이전트의 판정이 같은 노드로 붕괴하고 last-writer-wins로 생산자 표시가 덮어써졌다.** 마커는 저장됐으나 정체성을 지지 않았고 그래서 소멸했다.

> **파생 노드의 id = hash(네임스페이스, 대상 좌표, 출처, 생산자, 재현 입력).**

| 규칙 | 왜 |
|---|---|
| 출처·생산자가 성분 | 두 엔진의 같은 판정이 **나란히 선다.** 없으면 [F16 §1.2](F16-observation-intake.md)의 다섯째 몫(엔진 간 불일치)이 성립하지 않는다 — **붕괴한 것은 어긋날 수 없다** |
| 재현 입력이 성분 | 다른 시점·다른 범위의 산출이 덮어쓰지 않고 쌓인다. **SAST의 다중 taint 흐름을 가르는 것도 여기다**([F16 §4.2-3](F16-observation-intake.md)) |
| 네임스페이스 접두어 | 파생 노드 id가 코드 좌표와 우연히 같아질 수 없다 |
| **본문은 성분이 아니다** | 같은 근거로 다시 만든 요약이 문장만 달라졌다고 새 노드가 되면 계보가 소음이 된다([DESIGN §15-43](../../DESIGN.md)) |

**병합 규칙**: id가 같으면 갱신, 다르면 새 노드. **id가 같은데 출처가 다르면 스키마 위반**이고 불변식 3이 잡는다.

### 2.2 노드 넷 신설 — `Change` · `Defect` · `Journey` · `Actor`

**새 요구가 아니다. 다른 문서가 이미 반환한다고 적었는데 타입이 없던 것이다.**

| 노드 | 어디가 이미 전제하는가 | 없으면 |
|---|---|---|
| `Change` (커밋·PR) | [DESIGN §12.6](../../DESIGN.md)이 "변경의 1급화 — 수입" | [F23](F23-git-integration.md)의 git 결합이 설 자리가 없고 [F20](F20-conformance-governance.md)의 델타에 기준선이 없다 |
| `Defect` | [DESIGN §11.3](../../DESIGN.md)의 `touch`가 "결함 계보"를 반환한다고 적음 | **재발과 나비효과를 셀 수 없다** — [F11](F11-touch.md)의 유일한 효능 측정과 [G7](../00-goals.md)이 여기 걸린다 |
| `Journey` | 백서 §7 사슬의 `여정` | [goals §0.1](../00-goals.md)의 (c)가 성립하지 않는다 |
| `Actor` | [DESIGN §9.2](../../DESIGN.md)의 생산자 분리 검사 | 주체 비교가 문자열 비교로 내려앉고 "누가 승인했나"가 질의가 아니다 |

- **`Journey`·`Defect`는 저작 노동이다.** 이 기능은 **자리만 만든다.** 필수가 아니며 없으면 관련 산출이 `Capable::NotBuilt`다 — 빈 목록이 아니다.
- **`Actor`는 최소 형태**(`human|agent|tool` + 안정 식별자 + 표시 이름). 조직도·권한·평가의 어휘를 들이지 않는다.

## 3. 구현

### 3.1 속성 출처 동질성 ([DESIGN §3.4](../../DESIGN.md))

> **한 노드·엣지의 모든 속성은 같은 출처를 갖는다. 섞으려면 노드를 쪼개고 엣지로 잇는다.**

`Symbol{name, summary, owner}`가 아니라 `Symbol{name}` ← `DESCRIBES` ← `Synthesis{summary}`. 그래야 **코드가 변했을 때 요약만 낡는다.**

`producer` 여섯: `extractor`(결정론적 계산) · `rule(좌표)`(결정론적 추론) · `provider(id)` · `agent`(에이전트 추론) · `human` · `machine-record`.

### 3.2 `pal doctor` — 불변식 여덟

[DESIGN §12.7](../../DESIGN.md)의 여덟을 돌린다. **결과가 `Envelope`이고 자기 자신에게도 3분할이 걸린다** — 표본만 봤으면 "이상 없음"이 아니라 검사하지 못한 범위가 `Residual`이다.

| 언제 도나 | 기본 |
|---|---|
| 2층 재구축 후 · 스키마 버전 상승 후 첫 질의 · 사용자 호출 · CI | **표본.** 전수는 명시적 호출 |

매 질의마다 돌리지 않는다 — 그것이 P12 위반이다.

### 3.3 낡음 전파 ([DESIGN §6.4](../../DESIGN.md))

`stale`(자기 감시 집합이 변함)과 `stale-derived{경유 좌표[]}`(입력이 낡음)를 가른다. **처분이 다르기 때문이다** — 앞의 것은 사람의 재판정 큐이고 뒤의 것은 대개 기계가 입력을 갱신하면 닫힌다. 합치면 [R-10](../00-risks.md#r-10)의 승인 노동이 부풀어 오른다.

전파에도 예산이 붙고, 걸리면 멈추는 것이 아니라 `Residual{사유=낡음 전파 예산 초과}`다.

### 3.4 스냅샷 격리

질의는 열린 시점의 2층을 보고, 갱신은 원자적으로 커밋된다. 부분 갱신이 보이는 창이 없다. 재구축 중에는 `ProjectionFreshness::Rebuilding`이 값으로 실린다. `redb`의 MVCC가 이것을 준다 — 새로 만들 것이 없고 **쓰지 않으면 안 되는 것**이다.

## 4. 이슈와 대응

| 이슈 | 왜 | 대응 | 안 되면 |
|---|---|---|---|
| **스키마 팽창** | 노드·엣지 타입이 늘어도 아무것도 깨지지 않고 비용만 는다(저작·검사·내보내기·문서) | 타입 수를 대장에 싣는다. 추가 커밋은 `vocab.toml` 증가와 같은 자격으로 검토 | 상한을 도입한다(지금은 두지 않는다 — 근거 없는 숫자) |
| **스키마가 코드보다 늦게 자란다** | 급할 때 코드에만 노드를 만든다 | CI: 코드에 있고 스키마에 없으면 실패 | — |
| **동질성 규칙이 노드 수를 늘린다** | 속성 하나에 노드 하나가 되면 그래프가 부푼다 | **속성 단위가 아니라 출처 단위로 쪼갠다.** 같은 출처의 속성은 한 노드에 모인다 | 실측에서 노드 수가 목표를 넘으면 §3.1을 재론 |
| **`doctor` 전수 비용** | 10⁷ 엣지 | 표본 기본 + 표본임을 산출에 표시 | 검사 항목별로 샘플링 비율 조정 |
| **`Journey`·`Defect`가 저작되지 않는다** | 사슬 A의 뿌리가 늘어난다([DESIGN §15-34](../../DESIGN.md)) | P0-preflight가 잰다. **자리만 만들고 필수로 두지 않는다** | 두 노드를 내리고 `Change`·`Actor`만 남긴다 — 둘은 git에서 결정론적으로 나온다 |
| **전파 폭발** | 파생 폐포가 크면 대부분이 `stale-derived` | 예산 + `Residual` | 전파 깊이를 1홉으로 낮추고 그 사실을 산출에 표시 |

## 5. 고려한 대안

| 대안 | 기각 이유 |
|---|---|
| **스키마를 Rust 타입 정의로만 둔다** | 문서·내보내기·검사가 각자 자란다. 그리고 프로젝트가 스키마를 읽을 수 없다 |
| **RDF/OWL·SHACL 채택** | 표현력은 충분하고도 남지만 이 설계가 매 질의에 요구하는 것(`Envelope`·등급·출처)을 얹는 비용이 다르다. 그리고 추론기를 들이면 §3 파티션이 다시 열린다 |
| **스키마 없이 자유 속성** | "엔티티가 잘 설계되었는가"에 대조할 대상이 없다. U13이 물은 것이 정확히 이것 |
| **`doctor`를 매 질의에 실행** | P12 위반 |
| **`stale` 하나로 통합** | 사람의 재판정 큐에 기계가 닫을 것이 섞인다 |
| **노드 넷을 P2로 미룬다** | `Change`·`Actor`는 P1의 F23·F12가 요구하고, `Defect`는 G7의 저울이다. 미루면 채점 수단 없이 P1을 닫게 된다 |

## 6. 검증

- **스키마 ↔ 코드 동기 CI** — 양방향.
- **`producer` ↔ `provenance` 정합** — 스키마 로딩 시점 거부.
- **불변식 여덟의 자기 검사** — 의도적으로 깨뜨린 그래프를 만들어 각 불변식이 실제로 잡는지. **여덟 개 각각에 깨진 픽스처가 있어야 한다.**
- **동질성 위반 탐지** — 서로 다른 `producer`의 속성을 한 노드에 넣으면 컴파일 또는 CI에서 실패.
- **전파 정합** — `live` 노드의 입력에 `stale`이 없는가(불변식 8)를 코퍼스에서.
- **격리** — 재구축 중 질의를 동시에 던져 부분 갱신이 보이는지(반복 실행).
- **스키마 규모 기록** — 노드 라벨 수·엣지 타입 수를 각 게이트에 기록. **자라는 것 자체가 관측 대상.**
