# F23 — git 워크플로와의 결합

| 우선순위 | 의존 | 규모 | 크레이트 |
|---|---|---|---|
| **P1** | F09 · F22 | M | `pal-intent` · `pal-git` · `pal-cli` |

> 근거: [DESIGN §12.8](../../DESIGN.md) (D31) · [지시 U18](../../instructions/2026-08-10-owner-direction.md) · [R-21](../00-risks.md#r-21)

---

## 1. 왜

설계는 git을 **읽는다** — blob·트리·커밋이 사실층의 원본이다. 그러나 **사람과 팀이 실제로 일하는 단위**(브랜치·PR·리뷰·머지)와는 결합하지 않는다. 그 결과 둘이 일어난다.

1. **의도층이 한 사람의 로컬 파일에만 산다.** 승인 노동이 [R-10](../00-risks.md#r-10)이 말한 대로 이 프로젝트에서 가장 비싼 것인데, 그 산물을 팀이 공유할 방법이 `pal intent export`를 손으로 돌리는 것뿐이다.
2. **델타의 기준선이 없다.** [F20](F20-conformance-governance.md)이 *"평가는 절대값이 아니라 델타"*라 정했는데 **무엇 대비 델타인지**가 정해진 적 없다. git이 그 답을 이미 갖고 있다 — `main` 대비, 브랜치 시작점 대비, 이전 PR 대비.

**달성 기여**: 승인 노동이 한 사람에게서 팀으로 옮겨가는 유일한 경로. 그리고 [goals §0.1](../00-goals.md)의 (a)가 리뷰 시점에 도달하는 경로.

## 2. 세 결합

### 2.1 의도의 정본을 텍스트로 — **[스택 §2.2](../00-stack.md)의 방향을 뒤집는다**

| | 현재 계획 | 이 기능 이후 |
|---|---|---|
| 원본 | `intent.redb` | **`.palimpsest/intent/*.jsonl`** (git에 커밋) |
| 파생 | JSONL 내보내기 | `intent.redb` (색인. 지워도 재구축) |

**[R-21](../00-risks.md#r-21)이 한 겹 더 닫힌다.** 지금 대응은 "지우는 코드가 존재하지 않는다"인데, 사용자가 `.palimpsest/`를 통째로 지우는 것은 막을 수 없다고 그 항목 자신이 인정한다. 정본이 git에 있으면 **그 경우에도 복구된다.**

### 2.2 결박을 커밋에 남긴다

```
feat(order): 취소를 멱등으로

Palimpsest-Binds: ADR-0042@order-svc:OrderService.cancel
Palimpsest-Binds: PLAN-2026-08#4-2@order-svc:OrderService.cancel
```

- 결박이 **변경과 같은 리뷰를 받는다.** 지금은 결박이 어디에서도 검토되지 않는다.
- `Change` 노드([F22](F22-graph-schema.md))가 git에서 결정론적으로 선다 — 트레일러는 그 노드에 붙는 엣지다.
- **트레일러는 편의이지 정본이 아니다.** 없어도 §2.1의 JSONL로 전부 성립한다.

### 2.3 판정의 단위는 브랜치·PR

```
pal briefing    --base main          # 이 브랜치가 만질 것
pal conformance --base main          # 이 브랜치가 만든 순증
pal deviation   --base main --plan PLAN-2026-08
pal touch <coord> --tree worktree    # 커밋 전 (R-06의 TreeRef)
```

**`--base` 하나가 [F19](F19-briefing-view.md)·[F20](F20-conformance-governance.md)·[F12](F12-plan-binding.md)의 기준선을 동시에 정한다.**

## 3. 구현

### 3.1 텍스트 정본이 성립하려면 — 머지가 되어야 한다

방향을 뒤집으면 두 사람이 같은 파일을 고친다. 충돌이 일상이면 이것은 이득이 아니라 비용이다.

| 규칙 | 왜 |
|---|---|
| **추가 전용** — 승인·거부·재결박은 새 레코드, 기존 줄은 고치지 않는다 | [DESIGN §3.1](../../DESIGN.md)의 "승격은 새 노드 생성"과 같은 형태. 새 규칙이 아니다 |
| **한 줄 한 레코드 + 결정론적 정렬** | 충돌이 라인 단위로 해결되고 대개 양쪽을 다 취하는 것이 정답이다 |
| **레코드에 스키마 버전과 발행 `Actor`** | 누가 언제 승인했는지가 git blame이 아니라 데이터로 남는다 |
| **파일 분할** — 종류별·월별로 쪼갠다 | 한 파일이 커지면 충돌 확률이 오른다 |

### 3.2 `Change` 노드

```
Change { 종류(commit|pull-request|changeset), vcs 식별자, 대상 좌표 집합,
         발생 Snapshot, 저자 Actor, 부모 }        // 출처: extracted
```

- 커밋은 git에서 결정론적으로 나온다(`ReproInput = History(base..head)` — [DESIGN §3](../../DESIGN.md)).
- **PR은 git에 없다.** 호스팅 서비스에서 오므로 `observed`이고 조달자는 [F21](F21-provider-ports.md)의 포트 6이다. **PR 없이도 커밋만으로 전부 성립한다** — 특정 호스팅에 묶이지 않는 것이 P7이다.

### 3.3 P11에 닿는 지점 — 정직하게

결합 2.2는 **대상 저장소의 커밋 메시지에 줄을 더한다.** P11(*"대상을 변형하지 않는다"*)은 코어가 코드를 고치는 것을 금지하며 사람이 쓰는 커밋 메시지는 그 대상이 아니다. 그러나 경계가 얇다.

- 트레일러는 **사람 또는 호스트가 쓰고 코어는 읽기만 한다.** `pal-git`의 접촉면 다섯에 쓰기가 없다([R-15](../00-risks.md#r-15)) — 이 기능이 그것을 늘리지 않는다.
- 코어가 제공하는 것은 **트레일러 문자열을 만들어 주는 것까지**다(`pal bind --print-trailer`). 커밋하는 것은 사람이다.

### 3.4 palimpsest 자신의 개발 방법론

U18은 이 저장소에도 걸린다. [계획 §7](../README.md)의 진행 규칙이 이미 절반이고 — 게이트 기록, ADR은 종료 시점 발행, 기준의 사전 등록 — 여기서 더하는 것은 셋이다.

| | 내용 |
|---|---|
| **작은 브랜치** | 기능 하나가 여러 커밋이어도 게이트 하나가 한 브랜치. 게이트 기록이 머지 커밋에 붙는다 |
| **Conventional Commits** | 이미 쓰고 있다(`docs:` · `chore:`). `Palimpsest-Binds:` 트레일러가 여기 얹힌다 |
| **자기적용** | 이 저장소에 먼저 설치한다. **[R-19](../00-risks.md#r-19)의 편향(문서 대 코드 비율이 극단적)을 게이트 기록에 명시한 채로** — 자기적용은 피드백 루프이지 증거가 아니다 |

## 4. 이슈와 대응

| 이슈 | 왜 | 대응 | 안 되면 |
|---|---|---|---|
| **아무도 트레일러를 안 쓴다** | 규율에 기댄다. R6·R7이 두 번 관측한 실패 양식([DESIGN §15-41](../../DESIGN.md)) | 정본이 JSONL이므로 **트레일러가 비어도 결박은 산다.** 그리고 `pal bind`가 트레일러를 만들어 준다 | 트레일러를 내리고 JSONL만 남긴다 |
| **JSONL 충돌** | 팀이 커지면 잦아진다 | 추가 전용 + 한 줄 한 레코드 + 파일 분할 | 머지 드라이버 제공(`.gitattributes`) — 하지만 그것도 설치 비용 |
| **정본을 커밋 안 한다** | gitignore에 넣어 버린다 | 첫 승인 시점에 커밋을 권고 + `doctor`가 미커밋 의도를 보고 | — |
| **비밀 유출** | 결박 서술에 사내 정보가 들어가고 그것이 커밋된다 | 의도 파일은 **대상 저장소 안**이므로 이미 그 저장소의 공개 범위를 따른다. 그 사실을 설치 시 알린다 | — |
| **PR 조달이 호스팅에 묶인다** | GitHub/GitLab 각각 다름 | **PR은 `observed` + provider 포트 6.** 코어는 커밋만 안다 | PR 노드를 내리고 커밋만 |
| **`--base` 계산 비용** | 두 스냅샷의 판정을 각각 계산 | 1층 캐시가 대부분 적중(콘텐츠 주소) | 델타 대상을 변경 파일의 결박 반경으로 좁힌다 |

## 5. 고려한 대안

| 대안 | 기각 이유 |
|---|---|
| **의도를 별도 저장소·서버에** | 상주 프로세스·계정·동기화. P12 위반이고 설치 실패율이 오른다 |
| **git notes 사용** | 커밋 후 부착이 가능하고 히스토리를 안 바꾸지만, **기본 설정에서 push/fetch되지 않아** 공유가 조용히 실패한다. 그리고 도구 지원이 얇다 |
| **`redb`를 그대로 정본으로** | 바이너리는 머지되지 않고 리뷰되지 않는다. R-21이 완전히 닫히지 않는다 |
| **커밋 메시지를 코어가 고쳐 쓴다** | P11 정면 위반. 이력 재작성은 대상 저장소의 가장 위험한 연산이다 |
| **PR을 1급 전제로** | git만 쓰고 PR을 안 쓰는 프로젝트에서 능력이 죽는다. U(균일성)의 같은 형태 |
| **트레일러를 필수로** | 규율 의존 장치를 필수로 두면 실제로 일어나는 일은 이탈이다 |

## 6. 검증

- **정본 왕복** — JSONL → redb 재구축 → JSONL 재출력이 **바이트 동일**한가.
- **`.palimpsest/` 전체 삭제 후 복구** — git에서 clone만으로 결박·승인이 전부 돌아오는가. **이것이 R-21의 최종 검사다.**
- **동시 편집** — 두 브랜치에서 각각 승인 후 머지. 충돌 발생률과 해결 가능성을 코퍼스에서 잰다.
- **트레일러 왕복** — `pal bind --print-trailer` → 커밋 → 재추출에서 같은 결박이 서는가.
- **`--base` 델타 정확도** — 브랜치의 실제 변경과 델타 산출이 일치하는가.
- **트레일러 0건에서 전건 통과** — 규율 의존이 능력의 전제가 아님을 검사.
- **PR 조달 없이 전건 통과** — 호스팅 비의존 검사.
