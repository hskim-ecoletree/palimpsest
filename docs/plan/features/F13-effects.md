# F13 — 효과 집합 (E): 이 코드가 무엇을 바꾸는가

| 우선순위 | 의존 | 규모 | 크레이트 |
|---|---|---|---|
| **P2 — 가장 비싼 미지** | F07 · F12 | **XL** | `pal-extract::dataflow` |

---

## 1. 왜

실측된 최대 결함 군집이 **"두 경로가 같은 상태를 다르게 쓴다"** 형태다. 이것은 호출 그래프로 안 보인다 — 두 경로 다 정상적으로 존재하기 때문이다.

그리고 이것이 **하한 위에서 `Finding`을 세울 수 있는 첫 술어**다:

> `writes(P1) ⊋ writes(P2)` — 경로 P1이 쓰는 것이 P2보다 진부분집합으로 크다

**포함 관계는 존재 주장이므로 하한 위에서 성립한다.** 우리가 못 본 쓰기가 더 있어도 "P1이 이것을 쓰는데 P2는 안 쓴다"는 사실은 유지된다. 부재 주장이 아니라서 완전성이 없어도 참일 수 있는 드문 술어다.

---

## 2. 위험 — 선례가 경고한다 ([R-13](../00-risks.md#r-13))

같은 기반(tree-sitter) 위에서 이름 해소를 프로덕션 규모로 돌린 stack-graphs조차 **데이터플로우는 미해결로 남겼다.** 이 기능이 이 계획에서 가장 비싼 단일 항목이며, **실패 시 내리는 경로를 미리 만들어 둔다.**

---

## 3. 구현 — 야심을 줄이는 세 결정

### 3.1 경로 곱이 아니라 **합집합**

"진입점에서 이 지점까지의 모든 경로"는 후보 폭발에 지수적이다. 하지만 **"이 심볼이 도달 가능한 쓰기의 합집합"** 은 도달 가능 집합 크기에 선형이다.

```rust
// 역위상 순서로 한 번 훑으면 끝. 재귀 없음.
fn effect_sets(g: &Graph) -> Map<SymbolId, EffectSet> {
    let mut out = Map::new();
    for sym in reverse_topo(g) {                    // 순환은 SCC로 축약
        let mut e = local_effects(sym);             // 이 심볼이 직접 쓰는 것
        for callee in g.callees(sym) {
            e.union_with(&out[callee]);             // 피호출자의 효과를 흡수
        }
        out.insert(sym, e);
    }
    out
}
```

판정 술어를 포함 관계로 잡은 것이 이 성질을 쓰기 위해서다.

### 3.2 별칭 분석을 하지 않는다 — **선언된 효과 어휘**만 센다

임의 표현식의 포인터/별칭 분석은 컴파일러 영역이고 빌드 없이는 불가능하다. 대신 **인식 가능한 형태만** 효과로 센다:

| 효과 종류 | 인식 형태 (TypeScript) |
|---|---|
| 필드 쓰기 | `this.x = …`, `obj.field = …` (수신자가 해소된 경우만) |
| 컬렉션 변형 | `arr.push/splice`, `map.set/delete` |
| 저장소 | ORM 호출(`repo.save`, `db.update`) — **프레임워크 인식기가 정의**(F14·F18) |
| 외부 발신 | HTTP 클라이언트·큐 발행 |
| 전역/모듈 상태 | 모듈 스코프 변수 대입 |

**나머지는 전부 `UnresolvedRef{동적 디스패치 \| 문자열 기반}`로 환원한다.** 못 센 것을 못 셌다고 적는 자리가 이미 있다(F08).

### 3.3 정규화

같은 것을 가리키는 서로 다른 표기를 하나로 모은다: `this.status` / `order.status` / `Order.status` → `Order.status`. 수신자 타입 해소(L2c)가 없으면 이것이 부분적으로만 된다 — **그 사실이 효과 집합의 등급으로 표시된다.**

## 4. 이슈와 대응

| 이슈 | 왜 | 대응 | 안 되면 |
|---|---|---|---|
| **L3(정의-사용)가 안 선다** | 빌드 없음 | §3.2 — 인식 가능한 형태만. 나머지는 미해소 | 이 능력을 내린다(§6) |
| **수신자 타입 미상** | L2c 부재(F07) | 같은 파일/임포트된 클래스면 해소. 아니면 필드명만으로 약한 정규화 + 등급 하락 표시 | 효과 집합 정밀도가 낮다고 선언 |
| **순환 호출** | 재귀·상호재귀 | SCC로 축약 후 역위상 | — |
| **부피** | 심볼 10⁶ × 효과 집합 | 효과 항목을 인터닝(u32 ID) + 비트셋. 상위 심볼은 집합이 크지만 공유가 많다 | 상한 + `elision` |
| **프레임워크 의존** | ORM·HTTP 인식은 프레임워크마다 다름 | 인식기를 데이터로(F14·F18). 코어는 형태만 안다 | 인식기 없는 프레임워크는 공백으로 표시 |
| **거짓 효과** | 잘못 인식 | 증거(`Site`)를 항상 첨부. 검증 가능하게 | 표본 검토로 정밀도 측정 |

## 5. 고려한 대안

| 대안 | 기각 이유 |
|---|---|
| **완전한 데이터플로우 분석(SSA·포인터 분석)** | 빌드 필요. 1인 프로젝트 범위 밖. stack-graphs도 못 했다 |
| **경로별 효과 열거** | 후보 폭발에 지수적. 합집합으로 충분하다 |
| **LLM에게 "이 함수가 뭘 바꾸나" 묻기** | `inferred`다. 사실층에 못 들어간다. 다만 라벨 제안으로는 가능(승인 필요) |
| **테스트 실행 트레이스로만** | `observed`이고 부재 주장에 못 쓴다. 보조로는 유효(F16) |
| **효과를 세지 않고 감사만** | 감사(F15)의 술어가 없어진다. 효과가 감사의 전제층 |

## 6. 검증 — 반증되면 내린다

| 측정 | 게이트 |
|---|---|
| **과거 결함 재현 검출** — 코퍼스의 실제 결함(같은 상태를 다르게 쓰는 두 경로)을 이 술어가 잡는가 | **못 잡으면 이 능력을 내린다.** 되돌리는 비용은 문서 한 행 |
| 효과 정밀도 | 표본 100건 손 검토 |
| 효과 집합 크기 분포 | 상위 심볼이 전체를 삼키지 않는가 |
| 계산 비용 | 10⁶ 심볼에서 전체 효과 집합 계산 시간 |

**내리는 방법**: 효과 집합을 독립 능력에서 빼고 감사의 전제층으로만 둔다. 능력 번호를 옮기지 않았으므로 문서 한 행이면 된다.
