# F16 — 관측 수용 (O): 코어가 실행하지 않고 받는 문

| 우선순위 | 의존 | 규모 | 크레이트 |
|---|---|---|---|
| **P1** | F22 | M | `pal-intake` |

> 근거: [DESIGN §7.2](../../DESIGN.md) (출처 넷) · [DESIGN §0.4-6](../../DESIGN.md) (절차 기록)

> ### 이 문서는 2026-08-11에 둘로 쪼개졌다
>
> 원래 F16은 **수용 API**와 **외부 엔진 조달**을 한 문서에 담고 있었다.
> [T9](../../gates/preflight.md#t9--조달-가능성-실측)가 조달원 부재를 실측해 조달이 P2로 내려갔는데,
> **[F21](F21-provider-ports.md)(P1)이 필요로 하는 것은 조달이 아니라 수용 API였다** —
> F21 §3.1 규칙 1(*"코어는 F16의 수용 API로 받는다"*)과 §7 체크리스트(*"F16의 intake로 합류"*).
> 한 문서 안에 P1이 필요로 하는 절과 P2로 내려간 절이 같이 있으면 그것이 곧 숨은 모순이다.
>
> | | 무엇 | 우선순위 |
> |---|---|---|
> | **F16** (이 문서) | 수용 계약 · 출처 배정 · `observed` 무효화 · 좌표 결박 | **P1** |
> | **[F16b](F16b-engine-procurement.md)** | 외부 엔진 조달 — SAST·린터·SCIP, 그리고 palimpsest의 다섯 몫 | **P2** |
>
> **경계는 "무엇을 받느냐"가 아니라 "받는 장치냐 받을 것을 고르는 일이냐"다.**

---

## 1. 왜

정적 추출만으로는 DI 바인딩·리플렉션·동적 디스패치·생성 코드가 안 보인다. 그런데 그것들은 **실행 중에는 보인다.**

**그리고 코어는 실행하지 않는다.** 코어는 실행 환경을 갖지 않는다(빌드하지 않기로 했으므로). 대신 **수용 API**를 열고, 실행은 호스트·CI·사람이 한다.

이 문서는 **그 문**이다. 문 너머에서 무엇이 오는지는 [F21](F21-provider-ports.md)(프로젝트가 코드로 채우는 자리)과 [F16b](F16b-engine-procurement.md)(외부 분석 엔진)가 정한다.

### 1.1 왜 P1인가 — **[F21](F21-provider-ports.md)이 들어올 문이 이것뿐이다**

[F21](F21-provider-ports.md)은 P1이고 포트 일곱을 연다. 그중 **여섯은 조달원과 무관하다** — 언어 추출기·진입점 인식기·경계 계약 추출기·효과 어휘 매퍼·모듈 경로 규약·개념 팩. 그리고 F21의 규칙 1이 못 박는다:

> **코어는 provider를 실행하지 않는다.** 호출은 CLI 배치 경로나 호스트가 하고, **코어는 F16의 수용 API로 받는다.**

즉 **provider 산물이 `observed`로 들어오는 유일한 경로가 이 문**이고, 그것이 P1에 있어야 [goals §6](../00-goals.md)의 *"대상 전제 없음"* 이 문장이 아니라 인터페이스가 된다. [F02](F02-parse-extract.md)의 언어 목록이 유한하다는 사실이 치명적이지 않게 되는 것도 여기서다.

**P1에서 이 문으로 들어오는 것은 provider 산물이다. SAST alert가 아니다** — 그것은 [F16b](F16b-engine-procurement.md)이고 P2다.

## 2. 수용 계약

```rust
pub struct ObservationSubmission {
    kind: ObservationKind,        // CallTrace | DiBinding | RouteProbe | TestResult | ScipIndex
    coords: NonEmpty<Coord>,      // 무엇에 대한 관측인가
    env_fingerprint: EnvFingerprint,   // OS·런타임·의존 버전·설정 해시
    procedure: ProcedureRecord,   // 무엇을 어떤 절차로 실행했나 — 필수
    evidence: NonEmpty<Evidence>,
    observed_at: Timestamp,
}
// 절차 기록 없는 값을 타입으로 만들 수 없다 → 사칭이 입력 시점에 막힌다
```

**조달자의 정체는 묻지 않되 조달 절차는 요구한다.** 그것을 만든 것이 Claude Code인지 CI인지 사람이 붙여넣은 트레이스인지는 **출처 배정을 바꾸지 않는다.** 이것이 "호스트를 통해 실행에 닿는다"가 "호스트에 의존한다"로 미끄러지지 않게 막는 유일한 장치다.

**출처 배정은 조달자가 아니라 순서로 결정된다:**

> 1. `(커밋, 추출기 버전)`만으로 재현되는가 → `extracted`
> 2. 아니면 환경 의존 절차가 실제로 산출한 것인가(누가 조달했든) → **`observed`**
> 3. 아니면 사람이 승인해 고정한 것인가 → `asserted`
> 4. 아니면 → `inferred`

| 경계 사례 | 배정 | 왜 |
|---|---|---|
| 사람이 손으로 붙여넣은 트레이스 | `observed` | 사람이 **만든** 게 아니라 **운반**했다 |
| 빌드 의존 정밀 엔진(SCIP)의 산물 | `observed` | 결정론적이지만 빌드 환경이 좌표에 필요하다 |
| 에이전트가 수행한 "정확한" 정적 분석 | `inferred` | 재현 보증이 없다. 정확할 수 있다는 것은 배정 근거가 아니다 |
| [provider](F21-provider-ports.md)가 `deterministic = true`를 선언 | `observed` | 코어가 재현을 검사할 수 없다. 선언이 하는 일은 **재조달 시 대조**이지 배정 변경이 아니다 |

## 3. `observed`도 낡는다 — 무효화 계약

`observed`는 네 출처 중 **가장 빨리 낡는다.** 재계산으로 갱신되지 않기 때문이다 — `extracted`는 코드가 바뀌면 다음 추출에서 새 값이 되지만 **3주 전 트레이스는 그대로 남는다.**

그리고 `observed`는 `Finding`을 세울 수 있는 유일한 비-`extracted` 출처다. 낡은 관측이 그 권한을 유지하면 **"낡은 서술이 거짓 신호가 된다"가 사실층 안에서 재생산된다.**

> **규칙**: 모든 `observed` 사실은 자기가 가리키는 좌표 집합에 결박된다. 그 좌표 중 하나라도 `body_digest`가 변하면 `stale-observation`이다.

1. **지워지지 않는다** — 정적 하한과 과거의 관측된 해소를 겹쳐 보여주는 것이 정직한 형태다.
2. **판정 입력에서 자동 배제된다** — 그것에 기대던 `Finding`은 `Residual{관측 낡음}`으로 떨어진다. 표시로만 두지 않는 이유는 사람이 표시를 무시하기 때문이다.
3. **재조달 큐에 들어간다** — 낡은 관측의 좌표 밀도가 "여기서 한 번 더 돌리면 가장 많이 회복된다"는 지도다.

**보존 정책이 이 규칙을 대신하지 못한다.** 보존은 "좌표별 최근 M개"라는 **개수** 기준이고 낡음은 **신선도** 기준이다. 코드가 열 번 바뀌는 동안 관측이 한 번도 없었으면 그 하나짜리 관측은 M에 안 걸리고 영원히 산다. **두 장치 다 필요하다.**

**제출자의 신고를 신선도 앵커로 쓰지 않는다.** 제출물이 *"이 관측은 커밋 X 기준"*이라 말해도 앵커는 결박된 좌표의 현재 digest에서 온다 — 아니면 **제출자가 자기 산출물의 유효기간을 정하게 된다**([F09](F09-grounding.md) · [DESIGN §6.5](../../DESIGN.md)).

## 4. P1에서 이 문으로 들어오는 것

| 입력 | 무엇을 준다 | 어디서 |
|---|---|---|
| **provider 산물** | 언어 추출·진입점·경계 계약·효과 어휘·경로 규약 | [F21](F21-provider-ports.md) 포트 1~5·7 |
| 실행 트레이스 | 동적 디스패치·문자열 기반 대상 | 표적 실행 |
| DI 컨테이너 덤프 | `정의 없음`(DI 바인딩) | |
| 라우트 프로브 | 실제 노출된 진입점 | [F14](F14-entrypoints-boundaries.md) 대조 |
| 테스트 결과 | 경로 실행 여부 | |

**SAST · 린터·타입체커 진단 · SCIP/LSIF · 의존 취약점 스캔은 [F16b](F16b-engine-procurement.md)(P2)다.** 계약은 같지만 그것을 고르고 붙이는 일이 별도의 값이고, [T9](../../gates/preflight.md#t9--조달-가능성-실측)가 그 값의 전제를 반증했다.

**코어는 아무것도 실행하지 않는다** — 실행 팩도 [provider](F21-provider-ports.md)도 호스트·CI가 돌리고 결과는 이 수용 API로 들어온다. CI가 이 경계를 검사한다.

## 5. 좌표 결박 — 이 문 안쪽에서 일어나야 하는 것 셋

선행 구현체가 같은 자리에서 **코드 0줄로 재유예했다**([R15](../../evidence-map.md) · [G §3](../../research/2026-08-11-legacy-freshness-anchor-observation.md)). 미작성의 이유가 값지다 — *happy-path fixture가 hard case를 전부 우회하므로 테스트가 green이어도 실효 증거가 못 된다.* 아래 셋은 **입력 종류와 무관하게** 이 문의 착수 조건이다.

| # | 조건 | 처분 |
|---|---|---|
| 1 | **실패와 침묵은 다르다** — exit code를 안 보면 실행 실패가 "0건"으로 위장한다 | **`observed` 사실이 아니라 조달 자체의 부재로 받는다.** 침묵(`Residual`)과 처분이 다르다 — 재조달 큐로 가고 대장에 "조달 실패 N건"으로 선다. **가장 무거운 하나** — 실패가 침묵으로, 침묵이 안전으로 두 번 미끄러진다 |
| 2 | **위치 → 좌표 resolver가 어디 사는가** | **provider 안이 아니라 수용 경계**([F21](F21-provider-ports.md)의 caller-side). provider 안에 두면 프로젝트마다 다시 구현되고 정확도가 코어 계약에서 사라진다. **resolver 실패와 정당한 미결박을 구별하는 픽스처가 필요하다** |
| 3 | **산출이 환경마다 다르다** — 실행 시각·도구 버전·절대 경로·스레드 순서 | 수용 시점 정규화. 무엇을 정규화했는지가 절차 기록에 남는다. 안 하면 재조달 대조가 **거짓 불일치**를 낸다 |

파일:라인 → 심볼 매핑은 [F02](F02-parse-extract.md)의 `Site`가 준다. 매핑 실패는 `UnresolvedRef{사유=좌표 해소 실패}`이며, **엔진의 입도가 우리보다 잔 경우의 처분은 [F16b §3.2](F16b-engine-procurement.md)** 에 있다(SARIF 고유).

## 6. 이슈와 대응

| 이슈 | 왜 | 대응 | 안 되면 |
|---|---|---|---|
| **절차 기록 위조 가능** | 우리가 실행을 안 했으니 검증할 수 없다 | 기록을 요구하는 것은 **감사 가능성**이지 위조 방지가 아니다. 이 한계를 명시한다. 환경 지문 + 조달 시각 + 증거 원문 보존으로 사후 대조는 가능 | 영구 잔여로 기록 |
| **`observed` 단조 증가** | 지우지 않음 | 좌표별 최근 M=10 + 환경 지문별 최소 1개. **접는 것과 지우는 것을 구별**(접힌 것은 "여기 관측이 있었다"를 여전히 말한다) | 예산 초과 시 경고 |
| **아무도 안 켠다** | 실행 계약(승인·부작용)이 실무에서 부담 | 실행 허용 범위를 `asserted` 설정으로 + **승인 없는 실행 경로 부재를 CI로 검사** | 이 능력이 빈다. "아무도 안 한다"가 판정 |
| **관측이 `extracted`와 어긋남** | 정적 추론이 틀렸거나 관측이 다른 환경 | **덮어쓰지 않고 나란히 저장 + 불일치 보고** | — |
| **부재 주장 오용** | "트레이스에 없으니 없다" | **`observed`는 존재 주장에만 강하다.** 침묵은 `Residual`이지 `clean`이 아니다 — 타입으로 강제 | — |

## 7. 고려한 대안

| 대안 | 기각 이유 |
|---|---|
| **코어가 직접 실행** | 빌드 없음 원칙 위반. 임의 커밋에서 균일하지 않다. 그리고 남의 머신에서 임의 코드 실행은 신뢰 문제 |
| **조달자 정체를 검증** | 호스트 결합. 정체 중립이 P7의 실질 |
| **절차 기록을 선택 필드로** | 선택 필드는 비게 된다. 필수이거나 없거나 |
| **`observed`를 `extracted`에 합치기** | `extracted`의 결정론 계약이 거짓이 된다 |
| **낡은 관측을 표시만 하고 판정에 계속 사용** | 사람이 표시를 무시한다. 자동 배제가 옳다 |
| **수용 API를 F16b와 한 문서에 유지** | P1이 필요로 하는 절과 P2 절이 한 문서에 섞인다 — 2026-08-11에 실제로 모순이 됐다 |

## 8. 검증

- **`stale-observation` 전이** — 좌표 digest 변경 시 자동 배제되는가.
- **불일치 보고 경로** — `extracted`와 어긋나는 관측이 실제로 보고되는가.
- **절차 기록 없는 제출 거부** — 타입 수준에서 막히는가.
- **출처 배정** — 제출자가 무엇을 선언하든 `observed`로 고정되는가. `extracted`로 새는 경로가 있으면 실패.
- **조달 실패 ↔ 침묵 구별** — exit code가 0이 아닌 제출이 "0건 관측"으로 들어오지 않는가.
- **좌표 매핑률** — 제출된 위치 중 몇 %가 심볼 좌표로 결박되는가.
- **승인 없는 실행 경로 부재** — CI 검사.
- **`clean` 누출 검사** — 0건 제출이 "이상 없음"을 말하지 않는가. **골든 JSON으로 상시.**

**이 기능의 게이트는 [F21](F21-provider-ports.md)의 `provider 0개 통과`와 짝이다** — 문이 있어야 provider가 들어오고, provider가 없어도 전 질의가 답해야 한다.

## 9. 완료 체크리스트

- [ ] `ObservationSubmission` — 절차 기록 없이 생성 불가(타입 강제)
- [ ] 출처 배정 4단계 (조달자 정체와 무관 · `deterministic` 선언이 배정을 바꾸지 않음)
- [ ] `stale-observation` 자동 배제 + `Residual{관측 낡음}` 강등
- [ ] 재조달 큐 (낡은 관측 좌표 밀도)
- [ ] **제출자의 신고를 신선도 앵커로 쓰지 않는다** ([F09](F09-grounding.md) · [DESIGN §6.5](../../DESIGN.md))
- [ ] **조달 실패를 침묵과 구별** — exit code 검사 · "조달 실패 N건" 대장 표시 · 재조달 큐 (§5-1)
- [ ] **위치 → 심볼 좌표 매핑** — 위치는 **수용 경계**(provider 안 아님) + 실패 시 `UnresolvedRef` + resolver 결함/정당한 미결박 구별 픽스처 (§5-2)
- [ ] **수용 시점 정규화** — 시각·버전·절대 경로·순서. 정규화 내역이 절차 기록에 (§5-3)
- [ ] 재조달 대조 — 불일치 보고, 덮어쓰지 않음
- [ ] 실행 허용 범위 `asserted` 설정 + 승인 없는 실행 경로 부재 CI 검사
- [ ] 보존 정책 M=10 + 환경 지문별 최소 1 + 접기/지우기 구별
- [ ] `observation.intake` 질의 (direction=provide)
- [ ] 매핑률 · `clean` 누출 검사 기록
