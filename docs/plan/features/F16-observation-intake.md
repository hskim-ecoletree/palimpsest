## 1. 왜

정적 추출만으로는 DI 바인딩·리플렉션·동적 디스패치·생성 코드가 안 보인다. 그런데 그것들은 **실행 중에는 보인다.**

**핵심은 전수가 아니라 표적이다.** `UnresolvedRef` 밀도(F08)가 **"여기서 한 번 돌려보면 가장 많이 밝혀진다"** 는 지도를 이미 그려 준다. 조달은 그 지도를 따라 좁게 일어나므로 설치 비용 제약과 충돌하지 않는다.

**그리고 코어는 실행하지 않는다.** 코어는 실행 환경을 갖지 않는다(빌드하지 않기로 했으므로). 대신 **수용 API**를 열고, 실행은 호스트·CI·사람이 한다.

### 1.1 왜 P1로 올라왔나 — 그리고 왜 다시 내려갔나

[goals §0.1](../00-goals.md)이 상위 가치로 올린 (b)*(단편적으로 안 보이는 결함·취약점·잘못된 추상화를 거시적으로)*는 이 설계에서 [F13](F13-effects.md)(효과 집합)과 [F15](F15-judgment.md)(지배관계)가 지고 **둘 다 XL**이며 [R-13](../00-risks.md#r-13)이 "가장 비싼 미지"라 적었다. [R-17](../00-risks.md#r-17)(1인 대역폭) 아래에서 그 둘을 앞당길 수는 없다.

| 경로 | 규모 | 사슬 A(라벨 저작)에 매달리나 |
|---|---|---|
| 직접 만든다 (F13 → F15) | **XL 둘** | **예.** 라벨이 없으면 전부 `Residual` |
| **조달한다 (이 기능)** | **L 하나** | **아니오** — 외부 엔진의 alert는 라벨 없이 `Finding`을 세운다 |

그래서 이 기능은 배관이 아니라 **P1에서 감사 산출이 서는 유일한 방법**이다. 그리고 이것이 [DESIGN §15.1](../../DESIGN.md)의 사슬 A에 새로 적힌 우회로다.

**여기까지가 2026-08-10의 논거이고, 이 표는 지금도 참이다.** 무너진 것은 표가 아니라
표 오른쪽 열이 조용히 깔고 있던 전제다 — **"외부 엔진의 alert"가 실제로 존재한다.**

| 전제 | T9 실측 (2026-08-11) |
|---|---|
| 대상 프로젝트가 SAST를 돌린다 | **0 / 4 코퍼스.** GitHub 코드 스캐닝도 4개 저장소 전부 비활성 |
| 돌린 산물이 좌표를 갖는다 | 1 / 4 (ditto). 그것도 실행 로그뿐 — SARIF 0 · 아티팩트 0 |
| 감사의 판정 대상에 그것이 있다 | **없다.** boxwood Kotlin 백엔드는 분석 CI가 0이다 |

**"L 하나로 선다"는 여전히 맞다. 세울 재료가 없을 뿐이다.**
조달은 우리가 만드는 것이 아니라 남이 이미 하고 있어야 성립하는 것이고([R-25](../00-risks.md#r-25)),
실측은 아무도 하고 있지 않다고 답했다. 그래서 **P2로 되돌린다** — 기능을 내리지는 않는다.
성질이 반증된 것이 아니라 환경이 비어 있는 것이므로, 환경이 바뀌면 이 표가 다시 선다.

### 1.2 그러면 palimpsest의 몫은 무엇인가 — 다섯

조달만으로는 이 제품일 이유가 없다. **SAST를 그냥 돌리면 된다.** 이기는 자리는 정밀도가 아니라 아래 다섯이고, **다섯 중 어느 것도 성립하지 않으면 이 기능은 내린다**(§7의 반증).

| # | 몫 | 기존 도구가 못 하는 이유 |
|---|---|---|
| 1 | **결박** — alert가 좌표에 걸리고 그 좌표를 다시 만질 때 나타난다([F11](F11-touch.md)) | alert는 실행마다 새로 나고 어디에도 결박되지 않는다 |
| 2 | **낡음** — "이 alert가 아직 유효한가"에 답한다(§3) | 재실행이 유일한 답이고 재실행은 빌드를 요구한다 |
| 3 | **3분할 재분류** — alert 목록을 `{Finding, Residual, OutOfScope}`로 옮긴다. 엔진이 **보지 못한 범위**가 `Residual`로 선다 | 엔진은 자기가 못 본 것을 산출하지 않는다 |
| 4 | **억제의 이력** — `nosemgrep`·baseline·예외 목록이 **언제 왜 누가** 붙었는지가 `asserted`로 결박되고 만료를 갖는다 | 억제는 주석으로 흩어지고 근거가 남지 않는다. **[F20](F20-conformance-governance.md)의 손잡이가 하나 더 있는 자리이며 지금 아무도 세지 않는다** |
| 5 | **엔진 간 불일치** — 두 엔진이 어긋나면 그것이 신호다 | 각 엔진은 자기 답만 안다 |

## 2. 수용 계약

```rust
pub struct ObservationSubmission {
    kind: ObservationKind,        // CallTrace | DiBinding | RouteProbe | TestResult | ScipIndex
    coords: NonEmpty<Coord>,      // 무엇에 대한 관측인가
    env_fingerprint: EnvFingerprint,   // OS·런타임·의존 버전·설정 해시
    procedure: ProcedureRecord,   // 무엇을 어떤 절차로 실행했나 — 필수
    evidence: NonEmpty<Evidence>,
    observed_at: Timestamp,
}
// 절차 기록 없는 값을 타입으로 만들 수 없다 → 사칭이 입력 시점에 막힌다
```

**조달자의 정체는 묻지 않되 조달 절차는 요구한다.** 그것을 만든 것이 Claude Code인지 CI인지 사람이 붙여넣은 트레이스인지는 **출처 배정을 바꾸지 않는다.** 이것이 "호스트를 통해 실행에 닿는다"가 "호스트에 의존한다"로 미끄러지지 않게 막는 유일한 장치다.

**출처 배정은 조달자가 아니라 순서로 결정된다:**

> 1. `(커밋, 추출기 버전)`만으로 재현되는가 → `extracted`
> 2. 아니면 환경 의존 절차가 실제로 산출한 것인가(누가 조달했든) → **`observed`**
> 3. 아니면 사람이 승인해 고정한 것인가 → `asserted`
> 4. 아니면 → `inferred`

| 경계 사례 | 배정 | 왜 |
|---|---|---|
| 사람이 손으로 붙여넣은 트레이스 | `observed` | 사람이 **만든** 게 아니라 **운반**했다 |
| 빌드 의존 정밀 엔진(SCIP)의 산물 | `observed` | 결정론적이지만 빌드 환경이 좌표에 필요하다 |
| 에이전트가 수행한 "정확한" 정적 분석 | `inferred` | 재현 보증이 없다. 정확할 수 있다는 것은 배정 근거가 아니다 |

## 3. `observed`도 낡는다 — 무효화 계약

`observed`는 네 출처 중 **가장 빨리 낡는다.** 재계산으로 갱신되지 않기 때문이다 — `extracted`는 코드가 바뀌면 다음 추출에서 새 값이 되지만 **3주 전 트레이스는 그대로 남는다.**

그리고 `observed`는 `Finding`을 세울 수 있는 유일한 비-`extracted` 출처다. 낡은 관측이 그 권한을 유지하면 **"낡은 서술이 거짓 신호가 된다"가 사실층 안에서 재생산된다.**

> **규칙**: 모든 `observed` 사실은 자기가 가리키는 좌표 집합에 결박된다. 그 좌표 중 하나라도 `body_digest`가 변하면 `stale-observation`이다.

1. **지워지지 않는다** — 정적 하한과 과거의 관측된 해소를 겹쳐 보여주는 것이 정직한 형태다.
2. **판정 입력에서 자동 배제된다** — 그것에 기대던 `Finding`은 `Residual{관측 낡음}`으로 떨어진다. 표시로만 두지 않는 이유는 사람이 표시를 무시하기 때문이다.
3. **재조달 큐에 들어간다** — 낡은 관측의 좌표 밀도가 "여기서 한 번 더 돌리면 가장 많이 회복된다"는 지도다.

**보존 정책이 이 규칙을 대신하지 못한다.** 보존은 "좌표별 최근 M개"라는 **개수** 기준이고 낡음은 **신선도** 기준이다. 코드가 열 번 바뀌는 동안 관측이 한 번도 없었으면 그 하나짜리 관측은 M에 안 걸리고 영원히 산다. **두 장치 다 필요하다.**

## 4. 조달원

| 조달원 | 무엇을 준다 | 비고 |
|---|---|---|
| **SAST (CodeQL·Semgrep 계열)** | alert · **taint 경로** · 룰 식별자 | **§1.1의 승격 근거.** taint 경로가 [F13](F13-effects.md)의 효과 집합과 같은 자리를 다른 방법으로 채운다. Semgrep 계열은 빌드가 필요 없어 U에 덜 부딪히고, CodeQL 계열은 정밀하나 빌드를 요구하므로 적용 범위가 좁게 붙는다 |
| **린터·타입체커 진단** | 미사용·불일치·타입 오류 | 대부분의 프로젝트가 **이미 CI에서 돌리고 있다** — 조달 비용이 가장 낮은 입력 |
| **표준 코드 인덱스 (SCIP/LSIF)** | 빌드 통합 인덱서의 정밀 심볼·참조 | 프로덕션 선례가 있다. **`언어 등급 미달` 사유를 여는 유일한 경로** |
| 의존 취약점 스캔 | 외부 패키지의 알려진 취약점 | 좌표는 매니페스트 파일. **코드 심볼이 아니므로 결박 반경이 다르다** |
| 실행 트레이스 | 동적 디스패치·문자열 기반 대상 | 표적 실행 |
| DI 컨테이너 덤프 | `정의 없음`(DI 바인딩) | |
| 라우트 프로브 | 실제 노출된 진입점 | F14 대조 |
| 테스트 결과 | 경로 실행 여부 | |

**코어는 아무것도 실행하지 않는다** — SAST도 실행 팩도 [provider](F21-provider-ports.md)도 호스트·CI가 돌리고, 결과는 이 수용 API로 들어온다. CI가 이 경계를 검사한다.

### 4.1 SAST 수용의 추가 요구 — **범위를 안 주면 받지 않는다**

`observed`는 **존재 주장에만 강하고 부재 주장에는 쓸 수 없다.** 이 규칙이 SAST에서 가장 무겁게 걸린다 — **alert 0건의 리포트는 부재 주장처럼 생겼고 사람은 그렇게 읽는다.**

| 요구 | 왜 |
|---|---|
| **적용 범위 필수** — 스캔한 경로·룰셋 지문·대상 언어 | 범위 밖은 `OutOfScope`로 대장에 적힌다. 범위 없는 산출은 수용하지 않는다 |
| **침묵은 `Residual`** | `audit.judge`가 SAST를 근거로 세우는 것은 `Finding`뿐이다. 타입 수준에서 `clean` 경로가 없다([F15](F15-judgment.md)) |
| **룰셋 변경은 `ScopeReduction`** | 룰을 끄면 alert가 사라진다. 고쳐서 사라진 것과 다르다 — [F20](F20-conformance-governance.md)의 손잡이 일곱째 |
| **억제는 `asserted` + 만료** | 근거 없는 억제는 저장되지 않는다. 소유권과 같은 처리([DESIGN §11.6](../../DESIGN.md)) |

### 4.2 이 조달은 이미 한 번 시도됐다 — 선행 시도가 남긴 다섯 ([R15](../../evidence-map.md))

선행 palimpsest 구현체가 같은 조달을 설계하다 **코드 0줄에서 재유예했다**([G §3](../../research/2026-08-11-legacy-freshness-anchor-observation.md)). 미작성의 이유가 값지다 — *happy-path fixture가 hard case를 전부 우회하므로 테스트가 green이어도 실효 증거가 못 된다.* **아래 다섯은 이 기능의 착수 조건이며, 하나라도 미정인 채로 첫 코드를 쓰면 같은 자리에서 멈춘다.**

| # | 조건 | 처분 |
|---|---|---|
| 1 | **실패와 침묵은 다르다** — exit code를 안 보면 빌드 실패가 "0 findings"로 위장한다 | **`observed` 사실이 아니라 조달 자체의 부재로 받는다.** 침묵(`Residual`)과 처분이 다르다 — 재조달 큐로 가고 대장에 "조달 실패 N건"으로 선다. **가장 무거운 하나** — 실패가 침묵으로, 침묵이 안전으로 두 번 미끄러진다 |
| 2 | **위치 → 좌표 resolver가 어디 사는가** | **provider 안이 아니라 수용 경계**([F21](F21-provider-ports.md)의 caller-side). provider 안에 두면 프로젝트마다 다시 구현되고 정확도가 코어 계약에서 사라진다. **resolver 실패와 정당한 미결박을 구별하는 픽스처가 필요하다** |
| 3 | **한 지점의 여러 흐름** — 같은 sink·같은 룰의 다른 taint 경로가 하나로 접히면 조용한 과소 계상 | 흐름 식별자가 **id의 성분**([F22](F22-graph-schema.md)의 재현 입력) |
| 4 | **엔진의 입도가 더 잘다** — SARIF는 식 단위, 우리 최소 단위는 심볼 | 셋 중 하나를 **미리 정한다**: 감싸는 심볼로 올림 / 파일로 올림(정밀도 상실 표시) / 거부(`UnresolvedRef`) |
| 5 | **산출이 환경마다 다르다** — 실행 시각·도구 버전·절대 경로·스레드 순서 | 수용 시점 정규화. 무엇을 정규화했는지가 조달 절차 기록에 남는다. 안 하면 재조달 대조가 **거짓 불일치**를 낸다 |

## 5. 이슈와 대응

| 이슈 | 왜 | 대응 | 안 되면 |
|---|---|---|---|
| **절차 기록 위조 가능** | 우리가 실행을 안 했으니 검증할 수 없다 | 기록을 요구하는 것은 **감사 가능성**이지 위조 방지가 아니다. 이 한계를 명시한다. 환경 지문 + 조달 시각 + 증거 원문 보존으로 사후 대조는 가능 | 영구 잔여로 기록 |
| **`observed` 단조 증가** | 지우지 않음 | 좌표별 최근 M=10 + 환경 지문별 최소 1개. **접는 것과 지우는 것을 구별**(접힌 것은 "여기 관측이 있었다"를 여전히 말한다) | 예산 초과 시 경고 |
| **아무도 안 켠다** | 실행 계약(승인·부작용)이 실무에서 부담 | 실행 허용 범위를 `asserted` 설정으로 + **승인 없는 실행 경로 부재를 CI로 검사** | 이 능력이 빈다. "아무도 안 한다"가 판정 |
| **관측이 `extracted`와 어긋남** | 정적 추론이 틀렸거나 관측이 다른 환경 | **덮어쓰지 않고 나란히 저장 + 불일치 보고** | — |
| **부재 주장 오용** | "트레이스에 없으니 없다" | **`observed`는 존재 주장에만 강하다.** 침묵은 `Residual`이지 `clean`이 아니다 — 타입으로 강제 | — |
| **조달이 아예 없다** | 대상에 CI도 SAST도 없다([G8](../00-goals.md) · [R-25](../00-risks.md#r-25)) | P0-preflight에서 코퍼스의 조달 가능성을 먼저 잰다. 그리고 **린터·타입체커는 SAST보다 훨씬 흔하다** — 가장 낮은 문턱부터 지원 | (b)가 다시 F13·F15에 매달린다. P1의 약속을 (a)(d)로 줄인다 |
| **alert 폭발** | 성숙 프로젝트의 첫 스캔은 수천 건 | **첫날 전량을 `Finding`으로 세우지 않는다** — [F20](F20-conformance-governance.md)의 델타와 같은 규칙으로 기존분은 baseline이 되고 그 baseline 자체가 `asserted`이며 결박된다 | 표시가 읽히지 않는다([DESIGN §15-9](../../DESIGN.md)) |
| **엔진 좌표 ↔ 우리 좌표 매핑 실패** | SAST는 파일:라인으로 말하고 우리는 심볼로 말한다 | 라인 → 심볼 매핑은 [F02](F02-parse-extract.md)의 `Site`가 이미 준다. 매핑 실패는 `UnresolvedRef{사유=좌표 해소 실패}` | 파일 단위로 낮춰 결박(반경이 커지고 그 사실이 표시된다) |

## 6. 고려한 대안

| 대안 | 기각 이유 |
|---|---|
| **코어가 직접 실행** | 빌드 없음 원칙 위반. 임의 커밋에서 균일하지 않다. 그리고 남의 머신에서 임의 코드 실행은 신뢰 문제 |
| **조달자 정체를 검증** | 호스트 결합. 정체 중립이 P7의 실질 |
| **절차 기록을 선택 필드로** | 선택 필드는 비게 된다. 필수이거나 없거나 |
| **`observed`를 `extracted`에 합치기** | `extracted`의 결정론 계약이 거짓이 된다 |
| **낡은 관측을 표시만 하고 판정에 계속 사용** | 사람이 표시를 무시한다. 자동 배제가 옳다 |

## 7. 검증

- **미해소 참조 해소율** — 표적 조달이 `UnresolvedRef`를 유의미하게 줄이는가. **못 줄이면 이 능력의 전제가 틀렸다.**
- **불일치 보고 경로** — `extracted`와 어긋나는 관측이 실제로 보고되는가.
- **`stale-observation` 전이** — 좌표 digest 변경 시 자동 배제되는가.
- **승인 없는 실행 경로 부재** — CI 검사.
- **좌표 매핑률** — SAST의 파일:라인 중 몇 %가 심볼 좌표로 결박되는가. **낮으면 다섯 몫의 1·2가 함께 무너진다.**
- **`clean` 누출 검사** — alert 0건 리포트를 넣었을 때 산출이 "이상 없음"을 말하지 않는가. **골든 JSON으로 상시.**
- **다섯 몫의 반증 (§1.2)** — 이것이 이 기능의 진짜 게이트다.

| 몫 | 반증 형태 |
|---|---|
| 결박 | `touch`가 alert를 띄우지 못하거나, 띄워도 사람의 다음 행동이 같다 |
| 낡음 | `stale`이 켜져야 할 때 안 켜지거나, 거짓 양성이 많아 무시된다 |
| 3분할 | 엔진의 목록을 그대로 옮길 뿐 `Residual`이 아무것도 더하지 않는다 |
| 억제 이력 | 코퍼스에 억제가 거의 없거나, 있어도 근거를 아무도 안 적는다 |
| 불일치 | 두 엔진이 실질적으로 어긋나지 않아 신호가 없다 |

**다섯이 다 반증되면 이 기능을 내리고 (b)를 F13·F15로 되돌린다** — 그때는 P1의 약속이 (a)(d)로 줄어든다.
