# P0-preflight — 코드를 쓰기 전에 손으로 재는 것

| 우선순위 | 의존 | 규모 | 산출 |
|---|---|---|---|
| **P0 — 맨 앞. 이것 전에 코드를 쓰지 않는다** | 없음 | M | `corpus/` · `docs/gates/preflight.md` |

---

## 1. 왜 — 이 프로젝트에서 가장 비싼 것을 가장 먼저 검사한다

이 설계에는 **사람의 노동을 요구하는 뿌리가 셋**이고, 뿌리가 무너지면 그 위의 기능 전부가 빈 껍데기가 된다.

```
        ① 라벨 승인 노동        ② 규칙 팩 저작        ③ 개념 저작
              │                       │                     │
              └───────────┬───────────┴──────────┬──────────┘
                          ▼                      ▼
              감사(F15) · 효과 판정(F13) · 구조 평가(F20) · 팩(F18)
              — 뿌리가 각각 절반씩만 일어나면 잎에 남는 것은 8분의 1
```

이 셋을 마지막에 검사하면 **F13·F15·F18·F20의 비용이 이미 지불된 뒤다.** 그래서 맨 앞에 둔다.

**그리고 성공 기준을 사후에 고르지 않기 위해서다.** 과제와 채점 절차를 코드 이전에 커밋해야 그 커밋 해시가 등록 증거가 된다([R-18](../00-risks.md#r-18)). 다만 **수치 합격선까지 전부 지금 정할 수는 없다** — 아무도 재본 적 없는 값에 미리 선을 그으면 그것은 근거가 아니라 소원이다. 등록 시점 규칙은 §5.1에 있고, 요점은 **"코드 이전"이 아니라 "결과 이전"** 이다.

**"코드 0줄"의 실제 의미도 §2에서 좁힌다.** T2·T4·T6은 도구가 있어야 성립하는 작업을 도구 없이 재는 것이라, 무엇을 재고 무엇을 안 재는지를 먼저 못 박지 않으면 잰 값이 실제 단가를 대표하지 못한다([R-23](../00-risks.md#r-23)).

---

## 2. 무엇을 재는 것이고 무엇을 재는 것이 아닌가 — 먼저 못 박는다 ([R-23](../00-risks.md#r-23))

T2·T4·T6은 전부 **도구가 있어야 성립하는 작업**을 도구 없이 재려는 것이다. 그대로 두면 잰 값이 실제 단가와 다른 양이 되고, 편향의 방향조차 모른다(후보 찾기가 들어가면 과대추정, 애매한 후보를 건너뛰면 과소추정).

**그래서 재는 것을 성분으로 가른다.**

| 성분 | 도구가 줄여주나 | preflight에서 |
|---|---|---|
| **후보 제시** — 무엇을 판정할지 찾기 | **예, 거의 전부** | **재지 않는다.** 준비 작업으로 하고 시간에 안 넣는다 |
| **사람의 판단** — 이것이 가드인가 / 이 개념이 저 코드인가 | **아니오. 도구가 줄여줄 수 없다** | **이것만 잰다** |
| **재질문** — 같은 것을 또 묻게 되는가 | 예(거부 기록으로) | 표본에 의도적 중복을 넣어 발생률만 |

**그러므로 절차는 항상 두 단계다** — ① 후보를 먼저 다 만들어 목록으로 고정하고(시간 측정 밖) ② 그 목록을 판정하는 시간만 잰다.

그리고 **게이트 기록에 편향 방향을 적는다**: *"이 측정은 판단 성분만 잰 것이고 후보 제시 비용은 도구가 흡수한다고 가정했다. 가정이 틀리면 F15·F18의 판정은 낙관적이다."*

## 3. 작업

| # | 작업 | 산출 | 왜 |
|---|---|---|---|
| **T1** | **boxwood 작업본 복원** — zip 백업에서 git 이력 포함 복원 | 복원된 저장소 또는 실패 보고 | 실패하면 나머지가 대체 코퍼스로 재설계된다. 그래서 첫 작업 ([R-20](../00-risks.md#r-20)) |
| **T2** | **라벨 판정 30건** — ⓐ `rg`로 데코레이터·인터셉터·`check*`/`validate*`/`assert*` 함수를 뽑아 **후보 목록 30건을 먼저 고정**(시간 밖) → ⓑ 각각에 "이것이 인가 가드인가 · 근거 좌표는 어디인가"를 판정하는 **시간만** 측정. 표본에 중복 3건을 몰래 섞어 재질문율 측정 | `docs/gates/preflight.md` 측정표 + **편향 방향 명시** | [R-10](../00-risks.md#r-10)의 1차 판정 · [R-23](../00-risks.md#r-23) |
| **T3** | **단가 절감 장치 넷을 분리 측정** — ① 이미 지불되는 승인에 올라타기 ② 일괄 승인 ③ 진척 가시화 ④ 거부도 기록 | 어느 것이 단가를 내리는가 | 넷 다 만들면 비싸다. 무엇을 만들지 정한다 |
| **T4** | **규칙 팩을 손으로 써 보기** — boxwood에 규칙 5~10개를 종이 위에서 쓰고, `rg`로 그 규칙이 매칭하는 건수를 세어 **파생 비율**을 낸다. "줄어들 미해소 참조 수"는 미해소 목록이 없으므로 **재지 않는다**(F07 이후로 넘긴다) | 규칙당 파생 라벨 수 | 팩이 값을 못 내면 F18을 강등 |
| **T5** | **평가 코퍼스·과제·합격선 사전 등록** | `corpus/` 커밋 | §5 |
| **T6** | **온톨로지 저작 가능성** — 도메인 개념 20개와 관계를 손으로 적고, 각각에 **"이 개념을 담는 코드가 어디인가"를 경로/이름 수준으로 지목할 수 있는지**를 판정한다. 심볼 인덱스가 없으므로 좌표 정확도가 아니라 **지목 가능 여부**를 센다 | 지목 가능률 + 저작 시간 | 개념이 코드에 안 붙으면 온톨로지 층은 결박 없는 덩어리가 된다 |
| **T7** | **Kotlin 파싱 사전 측정** — **`tree-sitter` CLI로 한다**(`tree-sitter parse --quiet --stat`). 코드를 쓰지 않는다. boxwood 전 파일의 성공/ERROR 노드 비율 + 표본 20파일에서 최상위 선언 추출 정확도 | 숫자 | [R-03](../00-risks.md#r-03). 30분이면 되고, 안 하면 F07 한복판에서 안다 |
| **T8** | **재발 사례 5건 확보** — ditto 이력에서 같은 종류의 실수가 반복된 지점을 찾아 **(커밋, 파일, 심볼명, 어떤 규칙이 떴어야 하나)** 를 표로 고정한다 | `corpus/tasks/recurrence.toml` | **[F11](F11-touch.md)의 유일한 직접 효능 측정이 이 데이터에 걸려 있다.** 없으면 제품 전체의 게이트가 측정 불가 |

**T8이 여기 있는 이유**: F11의 반증 게이트가 "재발 5회 지점에서 `touch`가 관련 결정을 띄우는가"인데, 그 5건이 무엇인지 아무 데도 적혀 있지 않았다. 나중에 고르면 **결과를 보고 사례를 고르는 것**이 되어 게이트가 무효가 된다([R-18](../00-risks.md#r-18)).

## 4. 반증 게이트 — 무엇이 나오면 계획이 바뀌는가

| 관측 | 처분 |
|---|---|
| 라벨 판정 30건이 감당 불가한 시간을 먹는다 | **감사(F15)·구조 평가(F20)를 산출 목록에서 내린다.** 큐레이션·컨설팅만 남긴다 |
| 손으로 쓴 팩이 라벨을 유의미하게 파생시키지 못한다 | F18(선언 팩)을 "있으면 좋은 것"으로 강등 |
| 과제·합격선을 사전 등록할 수 없다 | **이후 모든 게이트가 자기 판정이 된다.** 이 사실을 명시하고 진행하거나, 등록 가능한 형태로 과제를 다시 짠다 |
| 개념 20개 중 코드를 지목할 수 있는 것이 소수 | 온톨로지 층은 결박 없는 덩어리다. 자리만 비워 두고 층은 만들지 않는다 |
| Kotlin 파싱 성공률이 낮다 | 판정 코퍼스를 TypeScript 프로젝트로 교체 |
| boxwood 복원 실패 | 대체 코퍼스 선정 후 T2~T4 재실행 |
| **재발 사례 5건을 식별할 수 없다** | **[F11](F11-touch.md)의 직접 효능 측정이 성립하지 않는다.** 대리 측정(계획 이탈률, F12)만 남는다는 것을 명시하고 진행 — 숨기지 않는다 |

> **취소는 실패가 아니라 이 계획이 작동한 것이다.** preflight이 반증되면 기능 20개 중 여섯이 착수 전에 취소된다 — 그것이 이 단계를 맨 앞에 둔 이유다.

## 5. `corpus/` 레이아웃 — 사전 등록의 실물

```
corpus/
├── manifest.toml         # 저장소·커밋·언어 구성·규모 (+ 합성 코퍼스면 그 사실)
├── tasks/
│   ├── *.toml            # 과제 5건 이상. 각각: 질문 / 기대 산출의 형태 / 채점 절차
│   └── recurrence.toml   # T8 — 재발 5건의 (커밋, 파일, 심볼, 떴어야 할 규칙)
├── arms.toml             # 대조군 — ① 문서 한 장 ② 기성 코드그래프 MCP 도구 ③ 기존 정적 분석 도구
└── criteria.toml         # 합격선. 이 파일의 커밋 시각이 등록 증거
```

**규칙 넷**

1. **사후에 과제를 고르지 않는다.** 과제를 기능 구현 도중에 바꾸면 그것이 곧 게이트 오염이다.
2. **n ≥ 5.** 사례 하나로 "되더라"를 결론 삼지 않는다.
3. **기권을 명시한다.** 대조가 성립하지 않는 기능(예: 팩 — 팩 자체가 문서다)은 "대조 불가"를 적는다. 생략하고 통과로 처리하는 것이 가장 조용한 실패 경로다.
4. **`criteria.toml`이 합격선의 단일 진실이다.** 기능 문서의 검증 표는 *무엇을 재는가*를 적고 *숫자*는 여기서 온다 — 같은 숫자를 두 곳에 적으면 그것이 곧 drift다([README §7](../README.md#7-진행-규칙)).

### 5.1 언제까지 등록하나 — **전부 지금은 불가능하다**

지금 확정할 수 없는 합격선이 있다(예: F07의 `exact|scoped` 비율 — 아무도 측정한 적이 없는 값에 미리 선을 그으면 그것은 근거가 아니라 소원이다). 그래서 등록 시점을 둘로 나눈다.

| | 무엇 | 언제 |
|---|---|---|
| **지금 (T5)** | 과제·대조군·채점 절차·재발 사례. 그리고 **판정 형태**("비율을 기록하고 그 값이 컨설팅 신뢰도의 상한임을 선언한다") | 코드 첫 줄 이전 |
| **기능 착수 직전** | 그 기능의 수치 합격선 | **그 기능의 첫 코드 커밋 이전.** 커밋 순서가 등록 증거 |

**핵심은 "코드 이전"이 아니라 "결과 이전"이다.** 결과를 보고 선을 옮기는 것만 막으면 [R-18](../00-risks.md#r-18)의 완화는 성립한다.

### 5.2 코퍼스 후보와 규모 코퍼스의 처분 ([R-24](../00-risks.md#r-24))

| 저장소 | 스택 | 무엇의 판정 대상인가 |
|---|---|---|
| boxwood | Kotlin/Spring/Exposed + Svelte | 효과 집합(F13)·감사(F15)·다언어 |
| ditto | TypeScript | 적시 제시(F11)·계획 결박(F12)·**재발 사례(T8)** |
| palimpsest 자신 | 문서 위주 | 서술물 인입(F10) — **편의 표본임을 명시**([R-19](../00-risks.md#r-19)) |
| 규모 코퍼스 (여기서 선정) | TypeScript | [목표 G5](../00-goals.md#5-성공실패의-판정-형태) — **P1 종료 시점의 게이트이지 P0의 완료 조건이 아니다** |

**규모 코퍼스 선정 규칙**: 단일 저장소로 10⁵ 파일은 희귀하다. ① 모노레포 ② 여러 저장소 합산(매니페스트가 이미 집합이다) ③ 실 저장소의 N배 복제 중 무엇을 썼는지 `manifest.toml`에 적는다. **복제 코퍼스는 캐시 적중률과 이름 충돌 분포를 왜곡하므로 그 사실을 함께 적는다.**
