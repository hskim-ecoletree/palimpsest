# F21 — `provider` 포트: 프로젝트가 코드로 채우는 자리

| 우선순위 | 의존 | 규모 | 크레이트 |
|---|---|---|---|
| **P1** | F16 | M | `pal-intake::provider` · `schema/provider.toml` |

> 근거: [DESIGN §7.4](../../DESIGN.md) (D28) · [지시 U16](../../instructions/2026-08-10-owner-direction.md) · [U1](../../instructions/2026-08-03-owner-direction.md)

---

## 1. 왜

**대상 프로젝트가 무엇인지 코어는 알 수 없다.** MSA인지 모놀리스인지, 이벤트 기반인지 요청/응답인지, 모노레포인지 단일 저장소인지, 라이브러리인지 CLI인지 웹 서버인지, 어떤 언어와 프레임워크인지 — 아무것도 가정할 수 없다. 그런데 **프로젝트 자신은 그것을 안다.**

[F18](F18-packs-concepts.md)의 선언 팩이 그 절반을 받는다(데이터로 표현되는 것). 나머지 절반 — **코드로만 표현되는 것** — 을 받을 자리가 지금 비어 있다. [DESIGN §7.3](../../DESIGN.md)은 *"코어는 팩을 실행하지 않고 호스트가 실행한다"*고만 적었고 **무엇을 주고받는지가 없다.**

**달성 기여**: [goals §6](../00-goals.md)의 "대상 전제 없음"이 문장이 아니라 인터페이스가 되는 지점. 그리고 [F02](F02-parse-extract.md)의 언어 목록이 유한하다는 사실이 치명적이지 않게 되는 지점.

## 2. 포트 일곱 — **절반 이상은 코드가 필요 없다**

| # | 포트 | 프로젝트가 아는 것 | 선언으로 되나 | 산물의 출처 |
|---|---|---|---|---|
| 1 | **언어 추출기** | 코어가 모르는 언어·DSL | 아니오 | `observed` |
| 2 | **진입점 인식기** | 자기 프레임워크의 라우팅·핸들러 규약 | **대개 예** | 예이면 `asserted_via=rule` |
| 3 | **경계 계약 추출기** | 자기 IDL·스키마 위치와 방언 | 부분 | 위와 같음 |
| 4 | **효과 어휘 매퍼** | 자기 ORM·큐·캐시 호출이 무엇을 쓰는가 | **대개 예** | 위와 같음 |
| 5 | **모듈·경로 규약** | 모노레포 레이아웃·생성 디렉터리·별칭 | **예** | `asserted` |
| 6 | **관측 조달자** | 자기 CI·테스트·SAST를 어떻게 돌리는가 | 아니오 | `observed` ([F16](F16-observation-intake.md)) |
| 7 | **개념·규칙 팩** | 자기 도메인 어휘 | **예** | `asserted_via=rule` ([F18](F18-packs-concepts.md)) |

> **확장점을 많이 여는 것이 목표가 아니다.** 확장점 하나는 저작 노동 하나이고 [사슬 A](../../DESIGN.md)의 뿌리 후보다. **코드가 필요한 자리를 최소로 유지하는 것**이 이 설계의 목표이며, 실제로 코드가 필요한 것은 1·6과 2·3의 잔여뿐이다.

## 3. 계약 — 프로세스 경계

```
palimpsest → provider :  stdin  JSON  { kind, schema_version, snapshot, inputs, budget }
provider   → palimpsest: stdout JSON  { schema_version, capability, facts[], unresolved[], elision }
                         stderr       진단(수용되지 않음)
                         exit code    0 = 산출 있음 · 그 외 = 조달 실패(그 사실이 대장에 남는다)
```

### 3.1 다섯 규칙

1. **코어는 provider를 실행하지 않는다.** 호출은 CLI 배치 경로나 호스트가 하고, 코어는 [F16](F16-observation-intake.md)의 수용 API로 받는다. 인프로세스 플러그인(동적 라이브러리·임베디드 런타임)을 **열지 않는다** — [DESIGN §7.3](../../DESIGN.md)이 기각한 "코어가 프로젝트 분석기를 실행한다"가 뒷문으로 들어오는 형태이기 때문이고, 부수적으로 **어떤 언어로 짜든 된다**는 이득을 얻는다.
2. **산물은 `observed`다.** `deterministic = true`를 선언해도 배정은 바뀌지 않는다 — 코어가 재현을 검사할 수 없다. 선언이 하는 일은 **재조달 시 대조**이고 불일치는 지워지지 않고 보고된다.
3. **능력을 선언하지 않으면 거부된다.** 무엇을 산출하는지(`capability`)와 어디까지 유효한지(적용 범위)가 매 응답에 실린다. 없으면 [DESIGN §0.4-6](../../DESIGN.md)의 절차 기록 요구에 걸린다.
4. **없어도 모든 질의가 답한다.** provider 0개에서 코어 하한으로 전부 선다. 부재는 대장에 `(provider N개 · 미설정 포트 M개)`로 적힌다.
5. **예산과 절단이 걸린다.** 응답의 `elision`이 필수이고, 시간·크기 상한을 넘으면 끊되 그 사실이 `Residual`이 된다. **남의 코드가 무한히 도는 것을 조용히 기다리지 않는다.**

### 3.2 언어 추출기도 포트인 이유

언어 목록을 늘리는 것으로는 스택 불가지에 도달하지 못한다 — 목록은 언제나 유한하고 대상은 그 밖에 있을 수 있다. 포트 1을 열되 선 하나를 지킨다.

> **코어 내장 추출기의 산물만 `extracted`다.** 외부 추출기의 산물은 `observed`이고 대장에 그 사실이 적힌다.

지키지 않으면 `extracted`의 결정론 계약이 프로젝트 코드로 넘어가고 P2가 프로젝트 단위로 무효화된다.

### 3.3 선언 → 코드의 승급 경로

포트 2·3·4는 대개 선언으로 되고 안 될 때만 코드가 된다. **같은 포트에 두 형태가 공존하며 출처가 다르다.**

| 형태 | 어디 | 출처 | 언제 |
|---|---|---|---|
| 선언 (TOML 패턴·애노테이션 목록) | `packs/` | `asserted_via=rule` | 기본 |
| 코드 (provider 실행 파일) | 프로젝트가 정한 곳 | `observed` | 선언으로 표현되지 않을 때 |

**둘이 같은 사실을 만들면 나란히 서고 불일치가 보고된다** — [DESIGN §7.2](../../DESIGN.md)의 "덮어쓰지 않는다"와 같은 규칙이다.

## 4. 이슈와 대응

| 이슈 | 왜 | 대응 | 안 되면 |
|---|---|---|---|
| **provider가 저작되지 않는다** | 팩 저작과 같은 실패 양식 | 절반 이상이 선언으로 되게 설계한 것이 대응. P0-preflight T4가 1차 판정 | 포트 1·6만 남기고 나머지는 선언 전용으로 |
| **임의 코드 실행의 안전** | 사용자 머신에서 남의 코드가 돈다 | 코어가 실행하지 않는 것이 방어. **그러나 책임을 호스트로 옮긴 것이지 없앤 것이 아니다**([DESIGN §15-37](../../DESIGN.md)) | 실행 경로에 명시적 승인 + 실행 범위 `asserted` |
| **프로세스 기동 비용** | 파일마다 프로세스를 띄우면 10⁵에서 죽는다 | **배치 단위 호출**(파일 목록을 한 번에 넘기고 한 번에 받는다). 스트리밍 JSON Lines | 장기 프로세스 모드를 옵션으로 (기본 아님 — P12) |
| **스키마 드리프트** | provider가 옛 스키마로 답한다 | `schema_version` 필수 + 불일치 시 거부 | 하위 호환 어댑터 |
| **provider가 거짓을 신고한다** | 코어는 검사할 수 없다 | `deterministic` 선언 시 재조달 대조. [DESIGN §15-31](../../DESIGN.md)의 잔여가 그대로 걸린다 | 닫지 않는다 |
| **부분 실패** | 파일 일부만 처리하고 죽는다 | 응답의 `elision`으로 남고 나머지는 `UnresolvedRef` | — |

## 5. 고려한 대안

| 대안 | 기각 이유 |
|---|---|
| **인프로세스 플러그인**(동적 라이브러리·WASM·임베디드 스크립트) | 코어가 임의 코드를 실행하게 된다([DESIGN §7.3](../../DESIGN.md) 기각 항목). WASM은 격리를 주지만 파일·프로세스 접근이 필요한 포트 1·6이 그 안에서 성립하지 않는다 |
| **LSP를 표준 포트로** | 대상 프로젝트의 의존성 설치를 요구하고 과거 커밋에서 안 된다. 다만 **포트 6의 조달원으로는 좋다** |
| **팩만으로 전부 표현** | 언어 추출기와 조달자가 데이터로 표현되지 않는다 |
| **provider 산물을 `extracted`로** | 재현을 코어가 검사할 수 없다. `extracted`의 계약이 남의 코드로 넘어간다 |
| **포트를 필요할 때마다 늘린다** | 확장점 하나가 저작 노동 하나다. 일곱을 못 박고 늘릴 때 근거를 남긴다 |

## 6. 검증

- **provider 0개 통과** — 전 질의가 답한다(`P7` 상시 검사에 포함).
- **참조 provider 둘** — ① 간단한 언어 추출기(포트 1) ② SAST 조달자(포트 6). 실물이 없으면 계약이 검증되지 않는다.
- **출처 배정** — provider 산물이 전부 `observed`인가. `extracted`로 새는 경로가 있으면 실패.
- **능력 미선언 거부** · **스키마 버전 불일치 거부**.
- **예산 절단** — 응답을 지연시키는 provider를 만들어 `Residual`이 나오는가.
- **선언 ↔ 코드 불일치 보고** — 같은 사실을 다르게 말하면 양쪽이 남고 보고되는가.
- **배치 비용** — 10⁴ 파일에서 프로세스 기동이 전체 시간의 몇 %인가.
