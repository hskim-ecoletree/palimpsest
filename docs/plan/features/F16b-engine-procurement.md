## 1. 왜 P1로 올라왔나 — 그리고 왜 다시 내려갔나

[goals §0.1](../00-goals.md)이 상위 가치로 올린 (b)*(단편적으로 안 보이는 결함·취약점·잘못된 추상화를 거시적으로)*는 이 설계에서 [F13](F13-effects.md)(효과 집합)과 [F15](F15-judgment.md)(지배관계)가 지고 **둘 다 XL**이며 [R-13](../00-risks.md#r-13)이 "가장 비싼 미지"라 적었다. [R-17](../00-risks.md#r-17)(1인 대역폭) 아래에서 그 둘을 앞당길 수는 없다.

| 경로 | 규모 | 사슬 A(라벨 저작)에 매달리나 |
|---|---|---|
| 직접 만든다 (F13 → F15) | **XL 둘** | **예.** 라벨이 없으면 전부 `Residual` |
| **조달한다 (이 기능)** | **L 하나** | **아니오** — 외부 엔진의 alert는 라벨 없이 `Finding`을 세운다 |

그래서 이 기능은 배관이 아니라 **감사 산출이 XL 없이 서는 유일한 방법**이다. 그리고 이것이 [DESIGN §15.1](../../DESIGN.md)의 사슬 A에 새로 적힌 우회로다.

**여기까지가 2026-08-10의 논거이고, 이 표는 지금도 참이다.** 무너진 것은 표가 아니라
표 오른쪽 열이 조용히 깔고 있던 전제다 — **"외부 엔진의 alert"가 실제로 존재한다.**

| 전제 | T9 실측 (2026-08-11) |
|---|---|
| 대상 프로젝트가 SAST를 돌린다 | **0 / 4 코퍼스.** GitHub 코드 스캐닝도 4개 저장소 전부 비활성 |
| 돌린 산물이 좌표를 갖는다 | 1 / 4 (ditto). 그것도 실행 로그뿐 — SARIF 0 · 아티팩트 0 |
| 감사의 판정 대상에 그것이 있다 | **없다.** boxwood Kotlin 백엔드는 분석 CI가 0이다 |

**"L 하나로 선다"는 여전히 맞다. 세울 재료가 없을 뿐이다.**
조달은 우리가 만드는 것이 아니라 남이 이미 하고 있어야 성립하는 것이고([R-25](../00-risks.md#r-25)),
실측은 아무도 하고 있지 않다고 답했다. 그래서 **P2로 되돌린다** — 기능을 내리지는 않는다.
성질이 반증된 것이 아니라 환경이 비어 있는 것이므로, 환경이 바뀌면 이 표가 다시 선다.

**되돌릴 조건은 [게이트 기록의 "뒤집을 수 있는 관측 셋"](../../gates/preflight.md#t9--조달-가능성-실측)에 있다.**
다만 셋 다 *우리가 대상 저장소를 고쳐야* 성립하고, 그것은 조달의 전제를 무너뜨린다.

## 2. 그러면 palimpsest의 몫은 무엇인가 — 다섯

조달만으로는 이 제품일 이유가 없다. **SAST를 그냥 돌리면 된다.** 이기는 자리는 정밀도가 아니라 아래 다섯이고, **다섯 중 어느 것도 성립하지 않으면 이 기능은 내린다**(§5의 반증).

| # | 몫 | 기존 도구가 못 하는 이유 |
|---|---|---|
| 1 | **결박** — alert가 좌표에 걸리고 그 좌표를 다시 만질 때 나타난다([F11](F11-touch.md)) | alert는 실행마다 새로 나고 어디에도 결박되지 않는다 |
| 2 | **낡음** — "이 alert가 아직 유효한가"에 답한다([F16 §3](F16-observation-intake.md#3-observed도-낡는다--무효화-계약)) | 재실행이 유일한 답이고 재실행은 빌드를 요구한다 |
| 3 | **3분할 재분류** — alert 목록을 `{Finding, Residual, OutOfScope}`로 옮긴다. 엔진이 **보지 못한 범위**가 `Residual`로 선다 | 엔진은 자기가 못 본 것을 산출하지 않는다 |
| 4 | **억제의 이력** — `nosemgrep`·baseline·예외 목록이 **언제 왜 누가** 붙었는지가 `asserted`로 결박되고 만료를 갖는다 | 억제는 주석으로 흩어지고 근거가 남지 않는다. **[F20](F20-conformance-governance.md)의 손잡이가 하나 더 있는 자리이며 지금 아무도 세지 않는다** |
| 5 | **엔진 간 불일치** — 두 엔진이 어긋나면 그것이 신호다 | 각 엔진은 자기 답만 안다 |

**몫 1·2는 [F16](F16-observation-intake.md)의 장치를 alert에 적용한 것이다.** 장치가 P1에 서 있으므로 이 기능이 P2에서 착수해도 그 부분은 이미 있다 — 그것이 쪼갠 이득이다.

## 3. 조달원

| 조달원 | 무엇을 준다 | 비고 |
|---|---|---|
| **SAST (CodeQL·Semgrep 계열)** | alert · **taint 경로** · 룰 식별자 | **§1의 승격 근거.** taint 경로가 [F13](F13-effects.md)의 효과 집합과 같은 자리를 다른 방법으로 채운다. Semgrep 계열은 빌드가 필요 없어 U에 덜 부딪히고, CodeQL 계열은 정밀하나 빌드를 요구하므로 적용 범위가 좁게 붙는다 |
| **린터·타입체커 진단** | 미사용·불일치·타입 오류 | 대부분의 프로젝트가 **이미 CI에서 돌리고 있다** — 조달 비용이 가장 낮은 입력. **다만 [T9](../../gates/preflight.md#t9--조달-가능성-실측)에서 "훨씬 흔하다"는 가정이 확인되지 않았다** — 코퍼스 넷 중 실효적으로 도는 곳은 하나였다 |
| **표준 코드 인덱스 (SCIP/LSIF)** | 빌드 통합 인덱서의 정밀 심볼·참조 | 프로덕션 선례가 있다. **`언어 등급 미달` 사유를 여는 유일한 경로** |
| 의존 취약점 스캔 | 외부 패키지의 알려진 취약점 | 좌표는 매니페스트 파일. **코드 심볼이 아니므로 결박 반경이 다르다** |

**코어는 아무것도 실행하지 않는다** — SAST도 호스트·CI가 돌리고 결과는 [F16의 수용 API](F16-observation-intake.md#2-수용-계약)로 들어온다. CI가 이 경계를 검사한다.

### 3.1 SAST 수용의 추가 요구 — **범위를 안 주면 받지 않는다**

`observed`는 **존재 주장에만 강하고 부재 주장에는 쓸 수 없다.** 이 규칙이 SAST에서 가장 무겁게 걸린다 — **alert 0건의 리포트는 부재 주장처럼 생겼고 사람은 그렇게 읽는다.**

| 요구 | 왜 |
|---|---|
| **적용 범위 필수** — 스캔한 경로·룰셋 지문·대상 언어 | 범위 밖은 `OutOfScope`로 대장에 적힌다. 범위 없는 산출은 수용하지 않는다 |
| **침묵은 `Residual`** | `audit.judge`가 SAST를 근거로 세우는 것은 `Finding`뿐이다. 타입 수준에서 `clean` 경로가 없다([F15](F15-judgment.md)) |
| **룰셋 변경은 `ScopeReduction`** | 룰을 끄면 alert가 사라진다. 고쳐서 사라진 것과 다르다 — [F20](F20-conformance-governance.md)의 손잡이 일곱째 |
| **억제는 `asserted` + 만료** | 근거 없는 억제는 저장되지 않는다. 소유권과 같은 처리([DESIGN §11.6](../../DESIGN.md)) |

### 3.2 엔진 고유의 착수 조건 둘 ([R15](../../evidence-map.md))

선행 구현체가 남긴 다섯 중 **셋은 입력 종류와 무관해 [F16 §5](F16-observation-intake.md#5-좌표-결박--이-문-안쪽에서-일어나야-하는-것-셋)로 갔다.** 아래 둘은 SAST·SARIF 고유다.

| # | 조건 | 처분 |
|---|---|---|
| 1 | **한 지점의 여러 흐름** — 같은 sink·같은 룰의 다른 taint 경로가 하나로 접히면 조용한 과소 계상 | 흐름 식별자가 **id의 성분**([F22](F22-graph-schema.md)의 재현 입력) |
| 2 | **엔진의 입도가 더 잘다** — SARIF는 식 단위, 우리 최소 단위는 심볼 | 셋 중 하나를 **미리 정한다**: 감싸는 심볼로 올림 / 파일로 올림(정밀도 상실 표시) / 거부(`UnresolvedRef`) |

## 5. 검증

- **미해소 참조 해소율** — 표적 조달이 `UnresolvedRef`를 유의미하게 줄이는가. **못 줄이면 이 능력의 전제가 틀렸다.**
- **좌표 매핑률** — SAST의 파일:라인 중 몇 %가 심볼 좌표로 결박되는가. **낮으면 다섯 몫의 1·2가 함께 무너진다.**
- **`clean` 누출 검사** — alert 0건 리포트를 넣었을 때 산출이 "이상 없음"을 말하지 않는가. **골든 JSON으로 상시.**
- **다섯 몫의 반증 (§2)** — 이것이 이 기능의 진짜 게이트다.

| 몫 | 반증 형태 |
|---|---|
| 결박 | `touch`가 alert를 띄우지 못하거나, 띄워도 사람의 다음 행동이 같다 |
| 낡음 | `stale`이 켜져야 할 때 안 켜지거나, 거짓 양성이 많아 무시된다 |
| 3분할 | 엔진의 목록을 그대로 옮길 뿐 `Residual`이 아무것도 더하지 않는다 |
| 억제 이력 | 코퍼스에 억제가 거의 없거나, 있어도 근거를 아무도 안 적는다 |
| 불일치 | 두 엔진이 실질적으로 어긋나지 않아 신호가 없다 |

**다섯이 다 반증되면 이 기능을 내리고 (b)를 F13·F15로 되돌린다.**

**착수 전에 조달원부터 다시 잰다.** [T9](../../gates/preflight.md#t9--조달-가능성-실측)가 0/4를 실측한 상태이므로, 조달원이 없는 코퍼스에서 위 검증은 전부 `대조 불가`가 된다. **재측정 없이 착수하면 그 사실을 모른 채 L을 쓴다.**

- [ ] **SAST 수용** — alert · taint 경로 · 룰셋 지문 · **적용 범위 필수**
- [ ] **린터·타입체커 진단 수용** (문턱이 가장 낮은 입력)
- [ ] SCIP/LSIF 수용 경로
- [ ] 의존 취약점 스캔 수용 (좌표 = 매니페스트, 결박 반경이 다르다는 표시)
- [ ] **흐름 식별자를 id 성분으로** ([F22](F22-graph-schema.md) · §3.2-1)
- [ ] **입도 매핑 규칙 확정** — 감싸는 심볼 / 파일 / 거부 중 하나 (§3.2-2)
- [ ] **억제 수용** — `asserted` + 근거 + 만료. 만료 없으면 저장 거부
- [ ] **룰셋 변경 → `ScopeReduction`** 연결
- [ ] **baseline 처리** — 첫 스캔 전량을 `Finding`으로 세우지 않는다
- [ ] 해소율 · 매핑률 · `clean` 누출 검사 · **다섯 몫의 대조 기록**
