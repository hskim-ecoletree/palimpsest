# F10 — 서술물 인입: 문서를 코드 좌표에 건다

| 우선순위 | 의존 | 규모 | 크레이트 |
|---|---|---|---|
| **P1** | F09 | L | `pal-extract::narrative` |

---

## 1. 왜 — 의도층의 콜드스타트

결박 장치(F09)가 있어도 **결박할 것이 없으면 `touch`는 빈 답을 낸다.** 성숙 프로젝트에 설치한 첫날, 사실층은 즉시 서지만 의도층은 비어 있다.

그런데 그 프로젝트에는 이미 문서가 있다 — ADR, 설계 문서, README, 주석, 위키. **그것들을 좌표에 거는 것이 의도층을 채우는 가장 싼 경로다.**

**그리고 여기에 가장 위험한 유혹이 있다.** 에이전트가 이력을 읽고 "이 결정은 아마 X였을 것"을 채워 의도층을 즉시 그럴듯하게 만드는 것. **그것이 세탁이다.** 과거 의도의 발굴은 유용하지만 그 산물은 `inferred`에 들어가고 **사람의 승인으로만** `asserted`로 승격된다. 이 규칙이 없으면 설치 첫날에 시스템 전체가 오염되고, 그 뒤로는 어디까지가 기록이고 어디부터가 재구성인지 아무도 모른다.

---

## 2. 입력 → 출력

```
입력:  마크다운(ADR·설계·README) · 코드 주석 · 커밋 메시지
출력:  NarrativeItem[] — 각각 {본문 조각, EntityId, 좌표 후보[], 해소 신호, 3분류}
```

**3분류**

| 분류 | 뜻 | 처분 |
|---|---|---|
| **결박됨** | 강한 신호로 좌표가 해소됨 | 제안 → 승인 → `asserted` 결박 |
| **후보 있음** | 약한 신호로 후보 N개 | `inferred` 제안. 승인 대기 |
| **미결박** | 신호 없음 | `narrative.unbound`에 남는다 — **이것이 사람의 작업 목록** |

---

## 3. 구현

### 3.1 문서 파싱

`pulldown-cmark`로 마크다운을 순회하며 **섹션 단위**로 조각낸다(헤딩이 경계). 조각 하나가 `EntityId` 하나.

- 프론트매터(YAML)에 명시적 좌표가 있으면 최우선.
- 코드 블록·인라인 코드 스팬을 별도로 수집(해소 신호).
- 문서 경로와 헤딩 앵커가 `EntityOrigin`이 된다(추적용이지 정체성이 아님 — 문서가 이동해도 `EntityId`는 유지).

### 3.2 좌표 해소 — 신호를 강한 것부터 ([R-09](../00-risks.md#r-09))

| 신호 | 강도 | 구현 |
|---|---|---|
| 프론트매터의 명시적 좌표 | **확정** | `grounds: ["src/order/cancel.ts#OrderService.cancel"]` |
| 코드 블록 안의 경로 | 강 | 경로가 대장에 존재하는가 |
| 인라인 코드 스팬의 식별자가 **심볼 인덱스에 유일** | 강 | `` `OrderService.cancel` `` → 정확히 1건이면 확정 후보 |
| 같은 커밋에서 함께 변경된 파일 | 중 | git 이력에서 계산. 문서와 코드가 같은 커밋에 있으면 관련 가능성 |
| 문서 경로의 디렉터리 근접성 | 약 | `docs/order/` ↔ `src/order/` |
| **본문 자연어의 이름 유사도** | **쓰지 않는다** | 거짓 결박을 만든다. "주문 취소 로직"이 `cancelOrder`인지 `OrderCanceller`인지 기계가 모른다 |

**같은 강도의 후보가 여럿이면 확정하지 않는다.** 후보 목록을 제안하고 승인을 요구한다.

### 3.3 승인 경로

```
문서 조각  →  좌표 후보 산출(inferred)  →  승인 큐  →  사람이 승인  →  asserted 결박
                                              │
                                              └─ 거부해도 기록된다 ← 재질문 제거가 승인 비용 절감의 대부분
```

**승격은 필드를 고쳐 쓰는 것이 아니다.** `inferred` 노드를 승인하면 그것을 가리키는 새 `asserted` 노드가 생기고 원본은 `promoted_by`와 함께 남는다. ① 되돌릴 수 있어야 하고 ② "원래 누구의 추론이었는가"가 계보에 남아야 한다.

### 3.4 코드 주석

주석은 **가장 정확한 좌표를 이미 갖고 있다** — 붙어 있는 심볼. 다만 주석이 결정인지 설명인지는 모른다.

- 표식이 있는 주석만 인입한다: `// @decision:`, `// ADR-0042`, `// TODO(ADR-…)`.
- 표식 없는 일반 주석은 인입하지 않는다(부피만 늘고 신호가 없다).
- 주석은 `body_digest` 정규화에서 **제거되므로**(F03), 주석 수정이 결박을 stale로 만들지 않는다. 의도한 동작이다.

### 3.5 첫 소비자는 이 저장소 자신이다

`docs/DESIGN.md`의 결정들과 이 계획 문서들을 코드 좌표에 걸어 본다. 설치 첫날의 산출을 자기 위에서 먼저 관측한다.

**단, 이것은 개발용 피드백 루프이지 증거가 아니다** — palimpsest 저장소는 문서 대 코드 비율이 극단적이라 성적이 실제 프로젝트와 다를 것이 거의 확실하다([R-19](../00-risks.md#r-19)). 게이트 기록에 편의 표본임을 명시한다.

## 4. 이슈와 대응

| 이슈 | 왜 | 대응 | 안 되면 |
|---|---|---|---|
| **해소율이 낮다** [R-09](../00-risks.md#r-09) | 사람이 쓴 문서는 심볼을 정확히 안 가리킨다 | ① 신호 계단식 ② 미결박을 작업 목록으로 노출 ③ **앞으로 쓰는 문서에는 좌표를 요구**(F12) | **F12의 비중을 올린다** — 계획 문서는 쓰는 시점에 좌표를 요구할 수 있어 정확도가 높다. 과거 인입이 실패해도 앞으로는 성립한다 |
| **거짓 결박** | 약한 신호로 확정 | 자연어 유사도 사용 금지 + 동점 후보는 확정 안 함 + 승인 필수 | 신호 강도 임계를 올린다 |
| **세탁** | 에이전트가 과거 의도를 지어냄 | `inferred` 파티션 + 승인으로만 승격 + 원본 보존 | 타입으로 강제(승격이 새 노드 반환) |
| **승인 노동** [R-10](../00-risks.md#r-10) | 문서가 수백 개 | 일괄 승인(같은 파일의 조각들) + 거부도 기록 + 진척 가시화 | P0-preflight가 이미 1차 판정 |
| **문서 이동** | 경로 기반 추적이 끊김 | `EntityId`가 경로 해시가 아님(§F09-4.3) | — |
| **대용량 문서** | 위키 수천 페이지 | 섹션 단위 조각 + 인입 대상 경로를 매니페스트로 제한 | 점진 인입 |

## 5. 고려한 대안

| 대안 | 기각 이유 |
|---|---|
| **임베딩/의미 유사도로 좌표 해소** | 거짓 결박을 대량 생산한다. 그리고 결박은 **정확해야** 값이 있다 — 틀린 결박은 없는 결박보다 나쁘다 |
| **LLM에게 좌표를 물어보고 그대로 저장** | 세탁. `inferred`로는 가능하되 승인 없이 `asserted`가 될 수 없다 |
| **모든 주석을 인입** | 부피만 늘고 신호가 없다. 표식 있는 것만 |
| **문서를 통째로 하나의 결박 단위로** | 문서 하나가 여러 코드에 걸린다. 섹션 단위가 실용적 최소 |
| **인입 없이 앞으로 쓰는 문서만** | 성숙 프로젝트의 콜드스타트를 포기한다. 첫날 값이 0이 된다 |

## 6. 검증

| 측정 | 목표 |
|---|---|
| **좌표 해소율** (결박됨 / 전체 조각) | 코퍼스별 기록. 이 숫자가 의도층 콜드스타트의 실효성이다 |
| **거짓 결박률** | 결박된 것 중 표본 50건을 손으로 검토. 목표 < 5% |
| 미결박 목록의 유용성 | 사람이 그 목록을 보고 실제로 붙이는가 |
| 자기 저장소 인입 결과 | 수동 검토. **편의 표본임을 명시** |

## 7. 완료 체크리스트

- [ ] 마크다운 섹션 조각화 + 프론트매터
- [ ] 해소 신호 계단식 (자연어 유사도 **제외**)
- [ ] 3분류 + 동점 후보 미확정 규칙
- [ ] `inferred` → 승인 → `asserted` 승격(원본 보존 + `promoted_by`)
- [ ] 표식 있는 주석 인입
- [ ] 승인 큐 + 일괄 승인 + 거부 기록
- [ ] `narrative.unbound` 질의
- [ ] 자기 저장소 인입 + 수동 검토 기록(편의 표본 명시)
- [ ] 거짓 결박률 표본 검토
