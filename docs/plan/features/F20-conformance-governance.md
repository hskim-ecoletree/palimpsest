# F20 — 구조 평가 델타와 거버넌스 경계

| 우선순위 | 의존 | 규모 | 크레이트 |
|---|---|---|---|
| **P3** | F15 · F18 | M | `pal-query::conformance` |

---

## 1. 왜

F19가 변경 **전**이라면 이것은 변경 **후**다. "이 변경이 구조를 좋게 했나 나쁘게 했나".

**절대값이 아니라 델타다.** "이 프로젝트의 아키텍처 점수 72점"은 근거가 없다. **"이 변경으로 위반 2개가 해소되고 1개가 새로 생겼으며, 판정 범위가 파일 30개만큼 줄었다"** 는 근거가 있다.

그리고 **범위 변동이 델타의 필수 성분**이다. 이것이 빠지면 게이트 오염에 무방비다.

---

## 2. 델타 5성분

```rust
pub struct Conformance {   // 판정(after) ⊖ 판정(before)
    new_findings: Vec<Finding>,
    resolved_findings: Vec<Finding>,
    new_residuals: Vec<Residual>,
    resolved_residuals: Vec<Residual>,
    scope_change: Vec<ScopeReduction>,   // ← 이것이 빠지면 나머지 넷이 거짓말을 한다
}
```

**왜**: 규칙을 지우거나 제외 범위를 넓히면 위반이 사라진다. 그것은 "해소"가 아니라 "범위 축소"다. 다섯째 성분 없이는 둘이 구별되지 않는다.

### 2.1 손잡이 여섯 — 범위가 줄어드는 경로

| 손잡이 | 감지 방법 |
|---|---|
| 제외 규칙 확대 | 대장 diff (규칙 ID별) |
| 언어 등급 하락 | 언어 등급 표 diff |
| 팩 규칙 삭제 | 팩 지문 diff |
| 라벨 삭제 | 라벨 삭제 이벤트 |
| 범위 설정 변경 | 매니페스트 diff |
| 예산 축소 | 예산 상수 diff |

각각이 `ScopeReduction`을 만들고, **사라진 좌표에 결박되어 `touch`로 사람이 있는 곳으로 온다.**

### 2.2 평가 축 넷

효과 집합(F13) · 호출 흐름(F07) · 의존 방향 · **소유권**.

**소유권 — 만료 규칙 없는 주장은 저장을 거부한다.** "이 모듈은 A팀 소유"는 코드 밖에서 낡는 첫 사실이다. 재확인 주기 없이 저장하면 그것이 곧 낡은 문서의 재생산이다.

## 3. 거버넌스 경계 — 이 층 위에 서되 이 층이 아니다

**개념은 수입하고 집행은 수입하지 않는다.**

| 수입한다 | 수입하지 않는다 |
|---|---|
| 변경을 1급 개체로 다룬다는 개념 | **게이트 집행** — 머지 차단·승인 강제 |
| 지속적 적합성이라는 개념 | **fail-closed 차단** — 입력 없으면 막기 |
| — | 위험 등급·완료 판정 어휘 |

**fail-closed는 형태를 바꿔서 수입한다**: 입력이 부재할 때 `Finding`도 `clean`도 아닌 **`Residual`** 을 낸다. 차단하지 않고 "판정할 수 없었다"를 말한다.

**이 기능은 소비 계약을 만들고 게이트를 만들지 않는다.**

```rust
// 거버넌스 층이 읽는 산출의 스키마
pub struct GovernanceFeed {
    judgments: Vec<Judgment>,
    delta: Conformance,
    scope_reductions: NonEmpty<ScopeReduction>,   // 동반 강제 — 오염의 역류 방어
    residuals: Vec<Residual>,
}
```

**코어 어휘 금지 목록**(`gate`, `risk_level`, `block`, `approve_and_merge`, `completion`, `change_contract`)이 이 경계의 실물이고 **CI가 상시 검사한다.**

## 4. 이슈와 대응

| 이슈 | 왜 | 대응 | 안 되면 |
|---|---|---|---|
| **거버넌스 어휘 역류** | 편의를 위해 코어에 들어옴 | 어휘 금지 CI (F01부터 켜져 있음) | 허용 목록 증가 자체가 관측 대상 |
| **기존 아키텍처 lint와 겹침** | 의존 방향 검사는 이미 있다 | **이길 지점은 셋** — 결박된 기준 / 3분할 / 적시 제시 | 셋 다 행동을 안 바꾸면 **이 산출을 내린다** |
| **델타 계산 비용** | 두 Snapshot 판정 | 증분 재추출 + 판정 캐시 | 대화 흐름을 끊으면 비동기로 |
| **소유권 주장의 낡음** | 코드 밖 사실 | 만료 규칙 필수(없으면 저장 거부) | — |
| **범위 축소가 무시됨** | 목록에만 있으면 안 본다 | `touch` 대상으로 만들어 사람이 있는 곳으로 | — |

---

## 5. 고려한 대안

| 대안 | 기각 이유 |
|---|---|
| **절대 점수(아키텍처 건강도)** | 근거가 없다. 델타는 근거가 있다 |
| **범위 변동을 별도 보고서로** | 아무도 안 본다. 동반 필수 |
| **머지 게이트 제공** | 거버넌스는 이 층 위에 선다. 집행을 수입하면 이 층이 정치적 도구가 되고 그 순간 사실층의 중립성이 훼손된다 |
| **fail-closed 차단 그대로 수입** | 입력 부재로 개발을 막으면 아무도 안 쓴다. 형태를 `Residual`로 바꾼다 |
| **소유권을 선택 필드로** | 선택 필드는 비게 된다 |

---

## 6. 검증

- **소급 검출** — 코퍼스의 과거 범위 축소 커밋(제외 규칙 확대 등)을 실제로 잡는가.
- **거버넌스 없는 코어 검사(CI 상시, F01부터)** — 거버넌스 층이 하나도 연결되지 않은 환경에서 코어 테스트 전건 통과 + 코어 어휘에 변경 계약·위험 등급·완료 판정 개념 없음.
- **fail-closed 형태 변환** — 입력 부재 시 `Residual`이 나오는가.
- **기성 lint 대비 행동 변화**.
