# F03 — 심볼 정체성과 정규화

| 우선순위 | 의존 | 규모 | 크레이트 |
|---|---|---|---|
| **P0** | F02 | M | `pal-core::coord` · `pal-extract::normalize` |

---

## 1. 왜 — 이 기능이 제품의 성패를 가른다

**결박은 좌표 위에 서고, 좌표는 정체성 위에 선다.** 그리고 낡음 판정은 "이 코드가 변했는가"인데, 그 판단이 틀리면:

- **거짓 양성** — 포매팅 커밋 하나에 결박 300개가 `stale`로 켜진다 → 사람이 표시를 무시한다 → **제품이 죽는다**([R-07](../00-risks.md#r-07), [목표 G1](../00-goals.md#5-성공실패의-판정-형태))
- **거짓 음성** — 의미가 변했는데 안 켜진다 → 낡은 결정이 `live`로 적극 보증된다 → 백서가 고발한 문제를 재생산한다

**달성 기여**: [목표 §3.3](../00-goals.md#33-낡음이-표시된-상태다). 이 기능의 품질이 곧 그 주장의 진위다.

## 2. 세 값

```
symbol_id      = blake3(repo_id ‖ 정규화 경로 ‖ 컨테이너 체인 ‖ 이름 ‖ 판별자)
body_digest    = blake3(구문 트리에서 주석·공백·포매팅을 제거한 정규형)
identity_grade = 판별자가 어느 언어 능력 등급에서 계산됐는가
```

| 값 | 답하는 질문 | 바뀌면 |
|---|---|---|
| `symbol_id` | **같은 심볼인가** | 정체성이 끊긴다 → `orphaned` |
| `body_digest` | **변했는가** | 결박이 `stale` |
| `identity_grade` | **이 답을 얼마나 믿을 수 있나** | 응답에 함께 실린다 |

**둘을 분리한 것이 핵심이다.** 파일을 옮기면 `symbol_id`가 바뀌지만 `body_digest`는 그대로다 — 그래서 재결박 제안이 가능하다([R-08](../00-risks.md#r-08)). 포매팅만 바꾸면 `body_digest`가 그대로다 — 그래서 거짓 양성이 죽는다.

---

## 3. 구현

### 3.1 `body_digest` 정규화 — 무엇을 지우는가

```rust
pub fn body_digest(node: Node, src: &[u8], caps: LangCaps) -> Blake3 {
    let mut h = Hasher::new();
    normalize_into(&mut h, node, src, caps);
    h.finalize()
}
```

| 지우는 것 | 왜 | 조건 |
|---|---|---|
| **공백·줄바꿈·들여쓰기** | 포매터가 매일 바꾼다 | 항상 |
| **주석** | 문서 수정이 코드 변경이 아니다 | 항상 |
| **후행 쉼표·선택적 세미콜론** | 스타일 | 항상 |
| **리터럴 따옴표 종류** (`'x'` ↔ `"x"`) | 스타일 | 항상 |
| **지역 변수명** | 리네임이 의미를 안 바꾼다 | **스코프 해소가 되는 언어에서만**(L2+) — 못 하면 서로 다른 코드가 같은 digest를 갖는다 |
| **파라미터명** | 위와 같음 | L2+ |

| 지우지 **않는** 것 | 왜 |
|---|---|
| 리터럴 값 | `TIMEOUT = 30` → `300`은 의미 변경 |
| 연산자·제어 구조 | 당연 |
| 호출 대상 이름 | 다른 함수를 부르는 것은 변경 |
| 필드·메서드 이름(멤버 접근) | 외부에서 보이는 계약 |
| 타입 주석 | 계약 |

**구현 방식**: 구문 트리를 순회하며 **정규화된 토큰 스트림을 해셔에 직접 흘려보낸다.** 정규형 문자열을 만들어 저장하지 않는다(메모리·시간 낭비). 지역 변수명은 스코프 해소가 되면 `#0`, `#1`처럼 **선언 순서 기반 De Bruijn 유사 색인**으로 치환한다 — 이름을 지우되 서로 다른 변수는 구별된다.

```
원본:   function add(a: number, b: number) { const s = a + b; return s }
정규형: function add(#0: number, #1: number){const #2=#0+#1;return #2}
```

### 3.2 `symbol_id`의 성분

| 성분 | 예 | 주의 |
|---|---|---|
| `repo_id` | `"order-svc"` | 매니페스트가 발급하는 **안정 식별자**. 경로도 원격 URL도 아니다 |
| 정규화 경로 | `src/order/cancel.ts` | 저장소 루트 기준. 구분자 통일, 대소문자 보존 |
| 컨테이너 체인 | `["OrderService"]` | 파일→클래스→(중첩)클래스 |
| 이름 | `cancel` | |
| **판별자** | 아래 표 | **여기가 언어 등급에 의존한다** |

### 3.3 판별자와 `identity_grade` — 감추지 않는 형태

| 언어 등급 | 판별자 | `identity_grade` | 귀결 |
|---|---|---|---|
| **L2+** | 정규화 시그니처(해소된 파라미터 타입) | `exact` | 오버로드가 정확히 구별된다 |
| **L1** | 파라미터 개수 + 컨테이너 내 선언 순서 | `ordinal` | 같은 개수의 오버로드는 **순서에 의존** |
| **L0** | 없음 — **심볼을 만들지 않는다** | 없음 | 좌표가 없다. 결박·적시 제시가 성립하지 않는다 |

```rust
// L0 에서 결박을 시도하는 코드는 컴파일되지 않는다
pub enum SymbolIdentity { Exact(SymbolId), Ordinal(SymbolId), Unavailable }

impl Binding {
    // SymbolIdentity 가 아니라 SymbolId 를 요구 → Unavailable 에서는 만들 수 없다
    pub fn new(target: SymbolId, radius: Radius, ..) -> Self;
}
```

**대장이 이것을 노출한다** — 언어별 표에 `identity_grade` 열이 서고, L0 언어가 있으면 머리에 "결박 불가 언어 N개"가 적힌다.

### 3.4 정체성 규칙

| 대상 | 규칙 |
|---|---|
| 오버로드 | §3.3의 판별자 |
| 익명 함수·클로저·람다 | 독립 심볼이 아니다. 가장 가까운 이름 있는 조상에 귀속되고 그 `body_digest`에 **포함된다** |
| 제네릭 | 선언 하나가 심볼 하나. 인스턴스화는 심볼이 아니다 |
| 매크로·애노테이션 프로세서 생성 심볼 | 파일 시스템에 없다 → 심볼이 아니라 `UnresolvedRef`(F08). 실행 관측(F16)의 표적 |
| 재선언·조건부 컴파일 | 같은 좌표에 둘 이상이면 후보 집합으로 저장 |

## 4. 이슈와 대응

### 4.1 [R-16] L1의 오버로드 재정렬 — 조용한 재결박

**이것이 이 기능의 가장 교활한 실패 양식이다.** L1에서 같은 파라미터 개수의 오버로드 둘이 선언 순서를 바꾸면:

- 정체성이 **끊기지 않는다** (`symbol_id`가 여전히 유효)
- 그런데 각 좌표가 **상대 심볼을 가리킨다**
- `body_digest`가 달라 `stale`이 켜진다 — 하지만 그 뜻은 "결박한 코드가 변했다"가 아니라 **"이제 다른 함수를 가리킨다"**
- 산출에서 둘이 구별되지 않는다 → 사람은 재확인하러 가서 **엉뚱한 함수를 읽는다**

거짓 `orphaned`는 관측 가능하지만 이것은 평범한 낡음으로 위장한다.

**대응** — 컨테이너 내 오버로드 집합의 **집합 digest**를 함께 감시해 순서 변경을 별도 사건(`identity-shift`)으로 띄운다.
**단 스키마로 먼저 고정하지 않는다** — L1 언어에서 오버로드 재정렬이 실제로 얼마나 일어나는지 아무도 세어본 적이 없다. **이 기능에서 코퍼스로 세고, 유의미하면 넣는다.** 그것이 이 항목의 완료 조건 중 하나다.

### 4.2 그 밖

| 이슈 | 왜 | 대응 | 안 되면 |
|---|---|---|---|
| **`repo_id`가 해시 성분** | 저장소 분할·병합 시 전 심볼 정체성이 한 번에 끊긴다 | 안정 식별자 + **별칭 테이블**이 재배치를 흡수. 흡수 안 된 재배치는 전 심볼 `orphaned`라는 **관측 가능한 사건**이 된다 | 조용한 정체성 유실보다 낫다 |
| **파일 이동** | 경로가 해시 성분 | `orphaned` + 같은 `body_digest`의 새 심볼을 찾아 **재결박 제안**(자동 아님, 승인 필요) | 일괄 재결박(같은 경로 접두사 변경 N건 → 승인 1회) |
| **정규화가 의미를 삼킴** | 지역 변수명을 지웠는데 그 이름이 계약인 경우(구조분해·객체 리터럴 키) | 객체 리터럴 키·구조분해 이름은 **지우지 않는다**(외부에서 보이는 형태) | 속성 테스트로 검출 |
| **digest는 같은데 의미가 변함** | `foo(CONST)` 에서 `CONST` 값만 변경 | **이 기능이 보증하지 않는다.** "텍스트만 변했다"를 걸러낼 뿐. 이것은 결박 반경(F09)의 문제로 넘긴다 | 명시적 한계로 문서화 |
| **해시 충돌** | blake3 128비트 절단 시 | 256비트 전부 저장. 저장 비용보다 정체성 오류가 비싸다 | — |

## 5. 고려한 대안

| 대안 | 기각 이유 |
|---|---|
| **라인 번호에 결박** | 공백 한 줄에 stale이 켜진다. 이 제품이 성립하지 않는다 |
| **파일 전체에 결박** | 거짓 양성이 심볼 결박보다 훨씬 심하다. 큰 파일에서 무의미 |
| **AST 전체 해시(정규화 없이)** | 포매터 한 번에 전부 켜진다 |
| **의미 기반 해시(타입 해소 후 IR)** | 빌드가 필요하다. 균일성 포기 |
| **경로를 `symbol_id`에서 빼고 이름만** | 동명 심볼이 전부 하나가 된다. 대형 저장소에서 무의미 |
| **파일 이동 시 자동 재결박** | 의미가 다른 동일 코드에 잘못 붙는다. 제안까지만 하고 승인을 요구 |
| **`identity_grade`를 숨기고 항상 `exact`인 척** | L1/L0 언어에서 설계 절반이 조용히 죽는다. 이 제품의 반대 |

## 6. 검증 — 이 기능은 검증이 곧 기능이다

### 6.1 속성 기반 검사 (`proptest`) — 양방향

```rust
proptest! {
    // ① 포매팅 변형에 digest 불변
    #[test]
    fn digest_stable_under_formatting(src in ts_source(), fmt in formatting_mutation()) {
        prop_assert_eq!(digest(&src), digest(&fmt.apply(&src)));
    }
    // ② 의미 변경에 digest 변동  ← 한쪽만 검사하면 "항상 같은 값 반환"도 통과한다
    #[test]
    fn digest_changes_on_semantic_edit(src in ts_source(), edit in semantic_mutation()) {
        prop_assert_ne!(digest(&src), digest(&edit.apply(&src)));
    }
}
```

`formatting_mutation`: 들여쓰기 변경, 줄바꿈 삽입/삭제, 주석 삽입, 따옴표 교체, 후행 쉼표, 지역 변수 리네임(L2+에서만).
`semantic_mutation`: 리터럴 값 변경, 연산자 교체, 호출 대상 변경, 분기 추가/삭제, 타입 주석 변경.

### 6.2 코퍼스 실측 — **숫자가 게이트다**

| 측정 | 목표 | 못 넘기면 |
|---|---|---|
| **포매팅 전용 커밋이 켜는 `stale` 수** | **0** | 정규화 결함. 고칠 때까지 진행 불가 |
| 대규모 이동 커밋에서 재결박 제안 정확도 | ≥ 90% | 제안 신호를 늘린다(`body_digest` + 이름 + 컨테이너) |
| L1 언어에서 오버로드 재정렬 발생 빈도 | 측정만 | 유의미하면 §4.1의 집합 digest 감시를 넣는다 |
| 같은 커밋 두 번 추출 시 `symbol_id` 일치 | 100% | 비결정성 버그 |

### 6.3 골든

코퍼스별 `(symbol_id, body_digest)` 목록 스냅샷. 추출기 버전을 올릴 때 얼마나 움직이는지가 보인다 — **좌표가 움직이는 것 자체는 정상이지만(그래서 `extractor_version`이 좌표 축이다), 얼마나 움직이는지는 알아야 한다.**
