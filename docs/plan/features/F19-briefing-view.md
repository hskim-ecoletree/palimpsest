# F19 — 사전 브리핑과 뷰 모델

| 우선순위 | 의존 | 규모 | 크레이트 |
|---|---|---|---|
| **P3** | F07 · F08 · F11 · F12 | L | `pal-query::briefing` · `pal-core::narrative` |

> **의존을 본문에 맞춰 고쳤다 (2026-08-12).** 선언은 `F12 · F15`였는데 **F15는 이 문서 본문
> 어디에도 쓰이지 않는다** — 구조체·검증·체크리스트 전부에 없다. 반대로 본문이 명시적으로
> 부르는 **F11**(`candidates`: *"touch 재사용"*)과 **F17**(`proposal`)이 선언에 없었다.
>
> **오독의 출처**: `Reach`가 `{Finding, Residual, OutOfScope}`를 쓰는데 F15의 제목이
> *"지배관계·**3분할 판정**"*이라 그 타입의 소유자로 읽힌 것으로 보인다. **그 3분할은
> [D9](../../DESIGN.md)가 정한 공용 어휘(§8)지 F15의 산출이 아니다.** F15는
> `pal-core::judgment`·`pal-query::audit`에 살고 의존이 F13·F14인 **감사 경로**이고,
> 브리핑의 `reach`는 감사 판정이 아니라 **도달**이다 — [DESIGN §11.5](../../DESIGN.md)가 그 출처를
> `extracted`(+팩이면 `asserted`)로 못 박았다.
>
> **F17은 의존에 넣지 않는다.** `proposal`은 `Capable<Synthesis>`로 두면 나머지 셋으로
> 브리핑이 성립한다 — 강제 규칙 일곱째(*능력 부재를 값으로*)의 형태이고, 이 문서 §2가
> *"입력이 없을 때 빈 `reach`가 아니라 `Residual`"*로 같은 원리를 이미 쓴다.
>
> **바뀌는 것**: 이 기능 앞에 서 있던 것이 **미판정 XL(F15)**에서 **P1 사슬**로 바뀐다.
> [T3가 이월한 질문](../../gates/preflight.md#t3--단가-절감-장치-넷의-분리-측정)(*리뷰가 대조로 바뀌나*)의
> 자리가 여기다. **다만 F07이 XL이라 가까워진 것이지 열린 것은 아니다**([R-17](../00-risks.md#r-17)).

---

## 1. 왜

`touch`(F11)는 **좌표 하나**에 대해 답한다. 브리핑은 **변경하려는 것 전체**에 대해 변경 **전에** 답한다.

**이름이 이 기능의 절반이다.** "영향 범위"가 아니라 **"영향 하한과 그 잔여"** 다. 전자는 완전성을 함의하고 우리는 그것을 보증할 수 없다.

---

## 2. 브리핑도 3분할이다

```rust
pub struct Briefing {
    targets: NonEmpty<Coord>,
    at: Snapshot,
    reach: Reach,                 // 사실 — 도달 확정 / 잔여 / 범위 밖
    candidates: Vec<BoundItem>,   // 후보 — touch 재사용 (F11)
    proposal: Synthesis,          // 제안 — inferred, evidence_refs 필수 (F17)
    narration: NarrationFields,   // coverage · unresolved · basis · direct_reads
}
pub struct Reach { findings: Vec<Finding>, residuals: Vec<Residual>, out_of_scope: Vec<OutOfScope> }
```

**세 부분의 출처가 갈린다** — 사실(`extracted`)·후보(결박물)·제안(`inferred`). **섞으면 세탁이다.** 에이전트가 만든 제안이 기계가 계산한 사실과 같은 자리에 있으면 독자는 구별할 수 없다.

**입력이 없을 때 빈 `reach`가 아니라 `Residual`을 낸다.** "영향 없음"과 "계산할 수 없었음"은 다르다.

---

## 3. 뷰 모델 — 코어는 데이터까지, 픽셀은 어댑터

```rust
pub struct ViewModel {
    nodes: Vec<ViewNode>,   // 해소 등급과 출처를 실어서
    edges: Vec<ViewEdge>,   // 어댑터가 구별 없이 그릴 수 없게
    frame: Frame,
    elision: Elision,       // 잘린 수 · 사유별 분해 · 초과 상한 — 비면 저장 거부
}
```

**노드·엣지에 등급과 출처가 실리는 이유**: 어댑터가 `exact` 엣지와 `candidate` 엣지를 같은 실선으로 그리면 시각화가 거짓말을 한다. 데이터에 실어 보내면 어댑터가 **구별하지 않을 수 없다.**

**절단은 그림이 아니라 데이터로 남는다.** 뷰 노드 상한 500. 잘린 것은 `elision`에 건수와 사유로.

---

## 4. 이슈와 대응

| 이슈 | 왜 | 대응 | 안 되면 |
|---|---|---|---|
| **`reach`가 잔여에 압도됨** | 미해소·라벨 부재 | 사유별 분해를 앞에 놓아 **무엇을 고치면 줄어드는지** 보인다 | 읽을 수 없으면 이 기능의 값이 낮다 |
| **제안이 사실로 오독됨** | 한 화면에 섞임 | 출처 파티션 + 시각적 분리를 어댑터에 요구(데이터에 출처가 있으므로 강제됨) | — |
| **탐색 깊이 비용** | 3홉 × 후보 | 예산(3홉, `candidate` 경유 1홉) + `Residual{탐색 예산 초과}` | 깊이 2 |
| **뷰가 이해의 착각을 만든다** | 그림은 설득력이 있다 | `elision`을 그림에 **반드시 표시**하도록 뷰 모델이 요구 | 효능 측정에서 드러난다 |
| **효능을 못 잰다** | "브리핑이 도움이 됐나" | **F12의 이탈률 전후 대조** — 브리핑을 본 뒤의 변경이 계획에서 덜 벗어나는가 | 대리 측정만 |

---

## 5. 고려한 대안

| 대안 | 기각 이유 |
|---|---|
| **"영향 범위"로 이름 짓기** | 완전성을 함의한다. 우리는 하한만 보증한다 |
| **사실·제안을 한 목록으로** | 세탁 |
| **코어가 SVG/이미지를 그린다** | 호스트 결합 + 절단이 그림 안에 숨는다 |
| **입력 없을 때 빈 결과 반환** | "영향 없음"으로 읽힌다. fail-closed의 형태 변환이 `Residual` |
| **뷰 상한 없이 전부 그리기** | 500 노드 넘으면 사람이 못 읽는다. 접되 기록한다 |
