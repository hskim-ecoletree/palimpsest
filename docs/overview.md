# palimpsest 개요 — 처음 보는 사람을 위한 안내

> 이 문서는 **이 저장소를 처음 여는 사람**을 위한 것이다. 사전 지식을 전제하지 않는다.
>
> 이 문서는 **소개**이고 결정의 정본이 아니다. 결정은 [`docs/adr/`](adr/), 목표는
> [`docs/plan/00-goals.md`](plan/00-goals.md), 스택은
> [`docs/plan/00-stack.md`](plan/00-stack.md), 회차 절차는 `/round` 스킬이 진다.
> 여기 적힌 것과 저기 적힌 것이 다르면 **저쪽이 맞다.**

---

## 1. 한 문장으로

**코드에서 사실을 뽑아 그래프로 만들고, 사람이 쓴 결정·설계·계획을 그 코드 위치에 못 박아,
누군가 그 코드를 고치려는 순간에 "여기에 무엇이 걸려 있고 그중 무엇이 낡았는지"를 알려 주는
도구.**

`palimpsest`는 양피지를 긁어내고 그 위에 다시 쓴 문서를 가리키는 말이다. 지워진 옛 글씨가
아래에 남아 비쳐 보이는 그 상태가 이 프로젝트가 다루는 대상이다 — 코드에는 지금의 모습만
남지만, 그렇게 된 이유와 그때의 판단은 아래에 깔려 보이지 않는다.

---

## 2. 어떤 문제를 푸는가

### 2.1 상황

어떤 팀이 2년 전에 이런 결정을 내렸다고 하자.

> "주문 취소는 **여러 번 호출돼도 결과가 같아야 한다**. 결제 취소가 두 번 일어나면 안 되니까."

이 결정은 회의록에, 위키에, ADR 문서에, 슬랙 스레드에 적힌다. 그리고 코드는 `OrderService.cancel()`
안에 구현된다.

1년 뒤 신입 개발자가 `OrderService.cancel()`을 고친다. 그는 그 결정을 모른다.
문서를 찾아보려 해도 **어느 문서가 이 함수에 관한 것인지 알 방법이 없다.** 문서는 함수
이름을 적어 두지 않았고, 적어 뒀더라도 그 사이에 함수 이름이 바뀌었을 수 있다.

그래서 세 가지가 일어난다.

| 무엇 | 왜 |
|---|---|
| **같은 버그가 다시 난다** | 예전에 왜 그렇게 고쳤는지 아무도 모른다 |
| **고치면 엉뚱한 데가 깨진다** | 무엇이 이 코드에 의존하는지 안 보인다 |
| **문서가 조용히 거짓말을 한다** | 코드는 바뀌었는데 문서는 그대로다. 낡았다는 표시가 없다 |

세 번째가 가장 나쁘다. **낡은 문서는 없는 문서보다 위험하다** — 없으면 사람이 코드를 읽지만,
낡은 문서가 있으면 사람이 그것을 믿는다.

### 2.2 그래서 무엇을 하나

두 가지를 한다.

**첫째, 코드를 읽어서 "무엇이 어디에 있고 무엇이 무엇을 부르는지"를 기계가 아는 형태로
만든다.** 이것을 **그래프**라고 부른다 — 점(함수·클래스·파일)과 선(호출·참조)의 모음이다.

**둘째, 사람이 쓴 글을 그 그래프의 점에 묶어 둔다.** "이 결정은 `OrderService.cancel` 에
관한 것이다"를 기계가 아는 형태로 기록한다. 이 묶는 행위를 이 프로젝트는 **결박**이라고 부른다.

그러면 세 번째 문제가 기계적으로 풀린다. `OrderService.cancel` 의 코드가 바뀌면, 거기 묶여
있던 결정에 **`stale`(낡음) 표시**가 자동으로 켜진다. 사람이 문서를 갱신하는 것은 못 시키지만,
**낡았다는 사실을 알려 주는 것은 기계가 할 수 있다.**

### 2.3 그러면 무엇이 달라지나

이 프로젝트가 스스로 정한 채점 기준이 있다([`00-goals.md §0.1`](plan/00-goals.md)):

> **역사·결정을 알게 하는 것은 목적이 아니라 수단이다. 상위 가치는 그 결과로 더 나은 코드가
> 나오는 것이다.**

즉 "산출이 정확하다"는 합격 사유가 아니다. **그 산출을 본 뒤의 코드가 실제로 달라져야** 한다.
재발이 줄고, 고칠 때 엉뚱한 데가 안 깨져야 한다.

## 3. 다 만들면 어떻게 쓰이나

에이전트(또는 사람)가 `OrderService.cancel()`을 고치려 한다. 손대기 **전에** 이 화면이 뜬다.
([`00-goals.md §1`](plan/00-goals.md)에서 가져왔다. 아직 전부 만들어지지 않았다.)

```
$ pal touch order-svc:OrderService.cancel

■ 이 좌표에 걸린 것 (3)
  ADR-0042  취소는 멱등해야 한다              live      symbol 반경
  ADR-0031  정산 경계 밖으로 나가지 않는다     stale     ← 감시 집합 중 SettlementGate.check 가 12커밋 전 변경
  PLAN §4-2 재고 복원은 이번 범위 아님         pending   ← 예상 좌표에 아직 코드가 없음

■ 이 심볼이 하는 것
  writes  order.status · inventory.reserved · outbox.event
  호출자  7  (exact 5 · scoped 0 · candidate 2)

■ 여기서 났던 일 (2)
  Defect  #218  중복 취소로 재고가 두 번 복원됨      도입 4a91f2 → 해소 c7d033

■ 내가 모르는 것 (2)
  UnresolvedRef  PaymentGateway.refund   사유=동적 디스패치   at cancel.ts:88

■ 판정
  Residual  2  (사유=미해소 참조 경유 — 위 두 건이 해소되면 재판정)
  ※ "이상 없음"이라고 말하지 않습니다. 위 2건은 보지 않은 것입니다.
```

읽는 법:

- **`live`** — 이 결정이 걸린 코드는 결박한 이후로 안 변했다.
- **`stale`** — 변했다. 그러니 이 결정이 아직 유효한지 **사람이 확인해야 한다.**
- **`내가 모르는 것`** — 기계가 못 푼 참조를 숨기지 않고 낸다.
- **`판정`에 "이상 없음"이 없다** — 못 본 것을 "괜찮다"로 바꾸지 않는다.

마지막 두 줄이 이 프로젝트의 성격을 가장 잘 보여 준다. **모르는 것을 안다고 말하지 않는다.**

## 4. 왜 기존 도구로는 안 되나

| 기존 도구 | 왜 부족한가 |
|---|---|
| `grep` · 코드 검색 | 문자열을 맞힐 뿐 관계를 모른다. 이름이 안 걸리면 없는 것이 된다 |
| 위키 · ADR 문서 | 코드와 연결이 없다. 낡아도 낡았다는 표시가 없다 |
| 코드 그래프 도구 (LSP, SCIP 등) | 관계는 알지만 **사람의 결정을 담지 않는다.** 그리고 대개 빌드를 요구한다 |
| 정적 분석기 (SAST, 린터) | 규칙 위반은 잡지만 "이 팀이 왜 이렇게 정했는지"는 모른다 |

이 프로젝트가 다른 지점 넷([`00-goals.md §3`](plan/00-goals.md)):

1. **모르는 것을 안다고 하지 않는다** — 못 푼 참조가 1급 데이터로 남는다.
2. **`clean`(이상 없음)을 출력하지 않는다** — 판정 결과에 그런 값이 아예 없다.
3. **낡음이 표시된 상태다** — 그것도 줄 번호가 아니라 **의미 단위**로. 코드 포매팅만 바꿔서는
   낡음이 안 켜진다.
4. **대상 프로젝트를 빌드하지 않는다** — 남의 프로젝트의 툴체인·비밀키·환경변수를 가질 수
   없고, 3년 전 커밋이 지금 빌드된다는 보장도 없다.

## 5. 전체 구조

### 5.1 두 층으로 되어 있다

```
┌─────────────────────────────────────────────────────────┐
│  하네스 (harness)   — 에이전트가 일하는 절차              │
│  · 회차를 어떻게 도는가 (스킬)                            │
│  · 역할·경계 (에이전트 정의)                              │
│  · 우회하면 피해가 큰 경계 (훅)                            │
└─────────────────────────────────────────────────────────┘
                        ↕  그래프에 묻고, 결정을 결박한다
┌─────────────────────────────────────────────────────────┐
│  코어 (core)        — `pal` 이라는 CLI 실행 파일 하나      │
│  · 코드를 읽어 그래프를 만든다                             │
│  · 사람의 글을 좌표에 결박한다                             │
│  · 물으면 봉투에 담아 답한다                               │
└─────────────────────────────────────────────────────────┘
```

**코어는 대화하지 않는다.** JSON을 받고 JSON을 낸다. 스크립트에서도 CI에서도 그대로 돈다.

**하네스는 Claude Code 전용이다.** 원래는 어느 도구에서든 쓸 수 있게 만들려 했는데,
2026-08-18에 뒤집었다([ADR-0025](adr/0025-the-harness-that-reads-the-graph-is-the-same-product.md)).
이유는 표현력이다 — 하네스의 본체는 **절차**인데, MCP 같은 프로토콜은 도구만 줄 수 있고
스킬은 절차를 줄 수 있다. 다만 **코어는 여전히 하네스 없이 혼자 선다**
(`crates/pal-cli/tests/host_free.rs`가 그것을 잰다).

### 5.2 데이터가 사는 곳은 셋

이 구분이 이 설계에서 가장 중요한 것 하나다.

```
git (코드의 진실)                     사람의 승인 (의도의 진실)
   │                                          │
   ▼                                          ▼
┌─ 1층 · 추출 캐시 ──────────┐       ┌─ 의도 저장소 ────────────┐
│ 파일 하나 → 파싱한 결과     │       │ 결박 · 승인/거부 이력     │
│ 지워도 됨 (다시 파싱)       │       │ 지우면 **영영 잃는다**    │
└────────────────────────────┘       └──────────────────────────┘
   │                                          │ 읽기만
   ▼                                          ▼
┌─ 2층 · 질의 투영 ───────────────────────────────────────────┐
│ 심볼 색인 · 인접 리스트 · 역방향 색인                          │
│ 통째로 지워도 1층 + 의도 저장소에서 다시 만들어진다             │
└─────────────────────────────────────────────────────────────┘
```

왜 이렇게 나누나:

- **1층이 있으면 "3년 전 커밋을 여는 비용"이 바뀐 파일 수에 비례한다.** 캐시 열쇠에 커밋이
  들어가지 않기 때문이다 — 열쇠는 `(파일 내용 해시, 추출기 버전, 경로, 언어, 능력 축)`이다.
  브랜치를 바꿔도 내용이 같은 파일은 이미 캐시에 있다.
- **의도 저장소를 따로 두지 않으면 "캐시를 지우고 다시 만든다"가 사람의 승인 노동을 지우는
  명령이 된다.** 그래서 이 크레이트에는 **지우는 API가 아예 없고**, 그 사실을 CI가 검사한다.
- **의도의 정본은 `.palimpsest/intent/*.jsonl` 텍스트 파일이고 git에 커밋된다.** 그래서
  `git clone` 만으로 돌아오고, 팀에 공유되고, 결박이 코드 변경과 같은 리뷰를 받는다.

### 5.3 크레이트 구성

Rust 워크스페이스이고 크레이트가 일곱이다.

| 크레이트 | 하는 일 | 의존 |
|---|---|---|
| `pal-core` | 도메인 타입·불변식·판정. **이 프로젝트의 어휘가 전부 여기 산다** | 워크스페이스 내부 의존 **0** |
| `pal-git` | git 접근. `gix` 크레이트를 이 안에 가둔다 | `pal-core` |
| `pal-extract` | tree-sitter로 소스를 파싱해 심볼을 뽑는다 | `pal-core` |
| `pal-store` | 1층 캐시 + 2층 투영. **지우는 API를 가진 유일한 크레이트** | `pal-core` |
| `pal-intent` | 의도 저장소. **지우는 API가 없다** | `pal-core` |
| `pal-query` | 이름 붙은 질의 실행. 예산 절단과 봉투 조립 | `pal-core`, `pal-store` |
| `pal-cli` | `pal` 실행 파일. 사람이 보는 화면과 설치·훅·회차 | 위 전부 |

의존 방향은 **CI가 기계로 검사한다**(`xtask/src/main.rs`의 검사 1):

- `pal-core`는 워크스페이스의 **어떤** 크레이트에도 의존하지 않는다 — 도메인이 저장 기술을
  내부화하는 것을 막는다.
- `pal-core`는 `tree-sitter`·`redb`·`gix`에 의존하지 않는다 — 파서와 저장 기술이 좌표계에
  새는 것을 막는다.
- `pal-store`는 `pal-intent`에 쓰기 의존하지 않는다 — 캐시 폐기 경로가 사람의 노동에 닿는
  것을 막는다.

## 6. 주제별로 — 개념 · 코드 · 흐름

여기부터가 본론이다. 주제마다 **① 개념이 무엇이고 ② 코드 어디에 있고 ③ 어떻게 도는지**를
적는다.

---

### 6.1 좌표 — "같은 심볼인가"와 "변했는가"를 가른다

#### 개념

문서를 코드에 묶으려면 코드의 한 지점을 가리키는 **주소**가 필요하다. 줄 번호는 안 된다 —
위에 한 줄만 추가돼도 전부 밀린다.

그래서 값을 **둘** 계산한다.

| 값 | 묻는 것 | 바뀌면 |
|---|---|---|
| `symbol_id` | **같은 심볼인가** | 정체성이 끊긴다 (`orphaned`) |
| `body_digest` | **내용이 변했는가** | 결박이 `stale` 이 된다 |

이 둘을 나눈 것이 핵심이다.

- 파일을 옮기면 `symbol_id`는 바뀌지만 `body_digest`는 그대로다 → **"이 함수가 여기로
  옮겨 온 것 같다"는 재결박 제안이 가능하다.**
- 코드 포매팅만 바꾸면 `body_digest`가 그대로다 → **포매팅 커밋에 낡음이 안 켜진다.**

하나로 합치면 둘 중 하나를 잃는다.

`symbol_id`의 재료는 `(저장소, 파일 경로, 컨테이너 체인, 이름, 구분자)`다. **컨테이너 체인**은
`파일 → 클래스 → 중첩 클래스` 같은 담김 관계다. 이게 없으면 같은 파일의
`class A { m() {} }` 와 `class B { m() {} }` 가 선언 순서로만 갈리고, 순서를 바꾸는 것만으로
정체성이 맞바뀐다.

#### 코드

`crates/pal-core/src/coord.rs`

```rust
pub enum SymbolIdentity {
    Exact(SymbolId),      // 스코프 해소로 유일하다
    Ordinal(SymbolId),    // 선언 순서에 의존한다 — 조금 덜 믿을 만하다
    Unavailable,          // 좌표가 성립하지 않는다 (텍스트만 읽은 언어)
}
```

**여기서 "타입으로 강제한다"가 무슨 뜻인지 볼 수 있다.** `Unavailable` 변형에는 값을 실을
자리가 없다. 그래서 거기서 `SymbolId`를 **꺼낼 수 없다.** 결박을 만드는 `Binding::new`는
`SymbolId`를 요구하므로, **좌표가 없는 심볼에 결박을 거는 코드는 컴파일 자체가 안 된다.**

문서에 "이러면 안 된다"고 적는 대신 언어가 막는다. 이 방식이 이 저장소 전체에 깔려 있고,
Rust를 고른 첫 번째 이유이기도 하다.

---

### 6.2 대장 — "무엇을 보았고 무엇을 보지 않았는가"

#### 개념

"전부 검사했다"는 주장은 검사할 수 없다. 그래서 이 프로젝트는 그것을 다음처럼 바꾼다.

> 기계는 **선언된 관측 범위 안에서** 전수임을 보증한다.
> 범위 밖은 "없음"이 아니라 **"보지 않음"** 으로 산출된다.

이 선언이 **대장(ledger)** 이다. 모든 답에 따라붙는다.

파일 하나의 상태가 3값(성공/건너뜀/실패)이 아니라 **일곱**인 것이 이 태도의 실물이다.

| 상태 | 뜻 | 사용자가 할 일 |
|---|---|---|
| `Parsed` | 파싱 성공 | 없음 |
| `Partial` | 파싱했는데 일부 구문에서 회복 | 문법 개선 대상 |
| `Unsupported` | 언어는 알아봤는데 이 빌드가 못 읽었다 (사유 포함) | 로드맵을 본다 |
| `Unrecognized` | 무슨 언어인지 모른다 | **설정을 고친다** |
| `Excluded` | 설정으로 제외됨 (규칙 ID 필수) | 의도한 것인지 확인 |
| `Binary` | 대상이 아니다 | 없음 |
| `Generated` | 생성된 파일이다 (증거 둘과 함께) | 없음 |

`Unrecognized`와 `Unsupported`를 뭉개면 대장이 거짓말을 한다 — 전자는 **설정 문제**이고
후자는 **로드맵 문제**인데, 사용자가 고칠 자리를 엉뚱한 데서 찾게 된다.

**언어별 능력 등급**도 따로 있다. `L0`(텍스트만) · `L1`(구조) · `L2`(스코프 해소된 참조) ·
`L3`(읽기/쓰기 집합) · `L4`(제어흐름). 하한이 전역이 아니라 **언어마다 다르다**는 사실이
데이터로 실린다.

#### 코드

- `crates/pal-core/src/ledger.rs` — `FileState` 7값, `ExtractGrade` L0~L4, `IdentityGrade`
- `crates/pal-cli/src/ledger.rs` — `pal ledger` 화면
- `crates/pal-extract/src/recognize.rs` — 확장자 → 언어 인식

#### 흐름

```
pal ledger
  → pal-git 이 HEAD 트리의 파일 목록을 낸다
  → 파일마다 언어를 인식한다 (recognize)
  → 인식된 언어에 추출기가 있으면 파싱, 없으면 Unsupported
  → 파싱 결과를 1층 캐시에 넣는다 (열쇠에 커밋이 없다)
  → 상태 일곱으로 집계해서 대장을 낸다
```

### 6.3 결박 — 이 프로젝트의 심장

#### 개념

**결박(binding)** 은 "사람이 쓴 글 한 조각"과 "코드 좌표 하나"를 묶는 기록이다.

```
결박 = { 무엇이(subject) · 내용(note) · 어디에(target) · 언제(bound_at)
        · 무엇까지 지켜보나(radius) · 감시 집합(watch) · 어떻게 섰나(promoted_by) }
```

여기서 **반경(radius)** 이 흥미롭다. 이런 문제가 있다.

> `OrderService.cancel` 에 걸린 결정이 있다. `cancel` 자체는 안 변했는데, 그것을 부르는
> `checkout` 이 변해서 결정이 무효가 됐다. 기계는 이것을 알 수 있나?

**원리적으로 알 수 없다.** "이 결정과 관련 있는 코드 전부"는 결정 불가능한 문제다.
그래서 이 프로젝트는 **닫으려 하지 않고 선언하게 한다.**

| 반경 | 무엇까지 지켜보나 | 판정 비용 |
|---|---|---|
| `symbol` (기본) | 대상 하나 | 상수 |
| `callers` | + 직접 호출자 | 인접 조회 1회 |
| `closure:k` | + k홉 호출자 폐포 | 폐포 크기 비례 |
| `files:a,b` | + 나열한 파일의 심볼 전부 | 열거 길이 |

그리고 **선언한 반경이 판정 결과에 함께 출력된다.**

> "이 결정은 `symbol` 반경에서 `live` 다"

이 문장은 "이 결정은 유효하다"와 **다른 문장**이다. 그 차이가 화면에 남는 것이 이 설계의
요구다. 선언은 문제를 해결하지 않지만 **은폐하지는 않는다.**

#### 상태는 넷이다

`crates/pal-core/src/binding.rs`의 `CodeFreshness`:

| 값 | 뜻 |
|---|---|
| `Live` | 좌표가 있고 감시 집합 전체가 그대로다 |
| `Stale { triggered_by }` | 감시 집합의 무언가가 변했다. **무엇이 켰는지 함께 싣는다** |
| `Orphaned { missing }` | 좌표가 사라졌다. `Stale`과 **다른 사건이다** — 구현 제거는 사람의 판단을 부른다 |
| `Undeterminable { reason, at }` | **판정할 수 없다.** `Live`로 접지 않는다 |

넷째가 이 열거의 요점이다. 판정 불가를 `Live`로 접으면 **"못 봤다"가 "괜찮다"로 둔갑한다.**
사유는 넷이다 — 정체성 등급 부족 · 부분 파싱 · 감시 원소가 사라짐 · 투영이 낡음.

#### 코드

- `crates/pal-core/src/binding.rs` — `Binding`, `CodeFreshness`, `BindingStatus::evaluate`
- `crates/pal-core/src/radius.rs` — 반경 넷과 확장
- `crates/pal-intent/src/store.rs` — 결박의 실제 저장
- `crates/pal-cli/src/bind.rs` — `pal bind`

#### 흐름

```
pal bind OrderService.cancel --note "취소는 멱등해야 한다" --radius callers
  → 이름을 심볼로 해소한다. 후보가 여럿이면 **거부한다** (기계가 안 고른다)
  → 반경을 펼쳐 감시 집합을 만든다 (지금의 body_digest 를 함께 저장)
  → 의도 저장소에 결박을 쓴다

pal touch OrderService.cancel   (나중에)
  → 의도 저장소에서 이 좌표에 걸린 결박을 꺼낸다
  → 결박마다 감시 집합의 지금 digest 와 저장된 digest 를 댄다
  → 다르면 Stale, 좌표가 없으면 Orphaned, 못 보면 Undeterminable, 아니면 Live
```

### 6.4 정직함을 타입으로 만드는 장치 셋

이 프로젝트의 성격을 가장 잘 보여 주는 부분이다. **"모르는 것을 안다고 하지 않는다"를
문서에 적는 대신 타입으로 만든다.**

#### 장치 ① `Capable<T>` — "없음"과 "아직 안 만듦"을 가른다

기능을 점진적으로 만들면 문제가 생긴다. 감사 기능을 아직 안 만들었을 때 화면에 뭐라고
쓸 것인가?

| 후보 | 왜 안 되나 |
|---|---|
| `Option<T>`의 `None` | "값이 없다"인지 "안 만들었다"인지 구별이 안 된다 |
| 빈 목록 | **거짓 안전.** `Finding 0`(위반 없음)과 "감사를 안 만들었음"이 같은 화면이 된다 |

```rust
// crates/pal-core/src/capable.rs
pub enum Capable<T> {
    Present(T),
    NotBuilt { capability: CapabilityId },
}
```

출력은 이렇게 된다.

```
■ 판정
  (이 빌드에는 감사 능력이 없습니다 — F15 미구축)
```

`Finding 0`이라고 말하지 않는다.

#### 장치 ② `Judgment` — `clean`이 타입에 없다

```rust
pub enum Judgment { Finding(Finding), Residual(Residual), OutOfScope(OutOfScope) }
//                  위반 확정          판정 불가            범위 밖
```

**넷째 변형이 없다.** "이상 없음"이라는 값이 타입에 존재하지 않으므로, 그렇게 출력하고
싶어도 낼 방법이 없다.

`Residual`(잔여)에는 **왜 판정 못 했는지**와 **무엇이 있으면 판정 가능한지**가 실린다.
그리고 잔여는 목록이 아니라 **좌표에 결박된다** — 그 좌표를 다시 만지는 순간 잔여가 사람이
있는 곳으로 온다. 선행 하네스가 잔여 개념을 갖고도 실패한 이유가 여기 있었다:
*표시는 목록으로 존재했고, 목록은 아무도 다시 열지 않았다.*

#### 장치 ③ `Envelope<T>` — 벌거벗은 답을 낼 방법이 없다

```rust
// crates/pal-core/src/envelope.rs
pub struct Envelope<T> {
    answer: T,
    snapshot: Snapshot,                // 어느 커밋 기준인가
    projection: ProjectionFreshness,   // 이 색인이 워킹트리와 일치하나
    coverage: Coverage,                // 미해소 N · 범위 밖 N · 경유한 언어 등급
    capabilities: CapabilitySet,       // 이 빌드가 실제로 답할 수 있는 것
    ledger: LedgerRef,                 // 관측 범위
    elision: Elision,                  // 예산에 걸려 잘린 것
}
```

질의 실행기(`pal-query`)의 진입점이 **`Envelope`만 반환한다.** 그래서 "답만 돌려주는
경로"가 타입 수준에 존재하지 않는다.

`elision`(절단)이 특히 중요하다. 탐색이 예산에 걸려 중간에 잘렸으면 **얼마나 무슨 이유로
잘랐는지가 답에 실린다.** 이것이 그래프 DB를 안 쓴 결정적 이유이기도 하다 — SQL에도
Cypher에도 `LIMIT`은 있지만 *"한도에 걸린 지점의 사유별 분해를 돌려달라"* 는 표현이 없다.

### 6.5 출처 — 이 값을 무엇으로 믿을 수 있나

#### 개념

그래프의 모든 값은 **어디서 왔는지**를 지고 다닌다.

| 출처 | 뜻 | 성질 |
|---|---|---|
| `extracted` | 코드에서 결정론적으로 계산됨 | 같은 입력 → 같은 답 |
| `observed` | 실행·빌드·계측에서 얻음 | **재현 보증이 없다.** 존재 주장에만 강하고 부재 주장에는 못 쓴다 |
| `asserted` | 사람이 승인해 고정함 | 결박 필수 |
| `inferred` | 합성·추론의 산물 | **근거·공백·확신도가 필수** |

**이 값은 불변이다.** 추론을 승인해서 확정으로 만드는 것은 값을 고쳐 쓰는 게 아니라
**새 노드를 만드는 것**이다. 원본은 `promoted_by`와 함께 남는다.

```rust
impl Inferred {
    // self 를 소비하지 않는다 — 원본이 남아야 한다
    pub fn promote(&self, approval: Approval) -> (AssertedNode, PromotedByEdge);
}
```

setter가 없고 고쳐 쓰는 경로가 없다. **그것 자체가 "세탁 방지"의 구현 형태다** —
에이전트가 추측한 것이 조용히 사실로 승격되는 길이 없다.

#### 코드

`crates/pal-core/src/graph.rs` — `Provenance`, `Producer`, `ResolutionGrade`

**해소 등급**도 같은 자리에 있다. 참조를 얼마나 확실하게 풀었는지다.

| 등급 | 뜻 |
|---|---|
| `exact` | 임포트·정의가 해소되어 대상이 유일 |
| `scoped` | 스코프 해소로 후보가 유일 |
| `candidate` | 후보가 여럿. **엣지 N개가 아니라 후보 집합 하나로 저장된다** |
| `contract` | 경계를 넘는 계약 매칭. 증거 필수 |

셋째가 중요하다. 이름이 같은 것 전부에 선을 그으면 그래프는 차고 신호는 죽는다.
**거짓 엣지는 없는 엣지보다 나쁘다.**

### 6.6 단일 진실 파일 둘 — 데이터가 코드를 검사한다

#### 개념

이 저장소에는 **코드가 아니라 데이터인데 코드보다 위에 있는 파일**이 둘 있다.

| 파일 | 정하는 것 |
|---|---|
| `schema/graph.toml` | **무엇이 존재하는가** — 노드·엣지·속성·생산자 |
| `surface/queries.toml` | **무엇을 물을 수 있는가** — 질의 목록 |

규칙은 양방향이다. **코드에만 있고 파일에 없으면 CI 실패. 파일에만 있고 코드에 없어도 CI 실패.**

이게 왜 필요한가. 예를 들어 스키마에는 `UnresolvedRef` 노드가 있는데 상태가
`not_built`(아직 안 만듦)로 적혀 있다. 이게 허용되는 이유는 **코드에 짝이 있고 그 타입이
값을 만들 수 없기** 때문이다(`uninhabited` — 거주 불가 타입). 자리만 두고 값을 만들 수
있으면 그것은 *"있는데 안 나오는"* 상태가 된다.

반대편도 실제로 걸렸다. `pal touch`는 오래 서 있었는데 `surface/queries.toml`에 줄이
없었다. 그러면 양방향 대조가 그 이름에 대해 **꺼진 채로** 돈다. **꺼진 검사는 `–`가 아니라
실패다.**

#### 코드

- `crates/pal-core/src/schema.rs` — 스키마를 읽는 **유일한** 경로
- `xtask/src/main.rs` 검사 7 — 스키마 정합
- `xtask/src/main.rs` 검사 11 — 카탈로그 정합

검사가 자기 파서를 들면 **CI를 통과한 스키마가 실행 시점에 거부될 수 있다.** 그래서
`xtask`는 자기 파서를 안 만들고 `pal-core::schema`를 부른다.

### 6.7 CI 검사 — 규율 대신 기계

`cargo xtask check` 하나가 스무 개 남짓의 검사를 돈다. 몇 개만 보면 성격이 보인다.

| 검사 | 무엇을 막나 |
|---|---|
| 의존 방향 | 도메인이 저장 기술을 내부화하는 것 |
| **코어 어휘 금지** | `pal-core` 소스에 `claude`·`mcp`·`redb`·`cypher`·`gate` 같은 말이 나오면 실패 |
| 의도 저장소 폐기 경로 부재 | 캐시 지우는 코드가 사람의 승인 노동에 닿는 것 |
| `gix` 격리 | git 라이브러리가 여러 크레이트로 퍼지는 것 |
| 선택 필드 금지 | 응답에 실리는 타입에 `Option<T>`가 생기는 것 |
| **예산 상수 단일 위치** | 상한값이 코드 여기저기 리터럴로 흩어지는 것 |
| 재구축 등가성 | 2층을 지우고 다시 만들었을 때 답이 달라지는 것 |

**예산 상수**는 이런 것들이다 — 후보 집합 상한 32, 경로 곱 예산 10⁴, 탐색 깊이 3,
화면 노드 500. 이 숫자들 중 **실측에서 나온 것은 하나도 없다.** 그래서 이름에
`PROVISIONAL_`(잠정) 접두어를 달고, 각각 "어느 측정이 이 값을 확정하는가"를 주석으로
단다. 그리고 어느 상한에 걸렸는지가 답의 `elision`에 실린다.

허용 목록(`xtask/vocab.toml`)에 줄이 느는 것 자체가 관측 대상이다.

### 6.8 하네스 — 에이전트가 일하는 절차

#### 개념

원래 이건 목표가 아니었다. 2026-08-18에 목표로 옮겼다
([ADR-0025](adr/0025-the-harness-that-reads-the-graph-is-the-same-product.md)).

옮긴 이유는 이 저장소 자신이 겪은 세 가지다.

1. **사전부검이 영향 범위를 상상했다** — 조회할 그래프가 안 붙어 있으면 모델 추정이 유일한 수단이다.
2. **회차가 끝날 때마다 잔여가 남았다** — 완료 항목 넷을 닫고 「다음으로 넘기는 것」 열 개를 낳았다.
3. **결정이 그래프로 안 들어갔다** — 회차가 만든 판정이 문서로 12,818줄 쌓였다. 읽어야
   꺼내지고, 조용히 낡고, 결박이 없어 낡음이 표시되지 않는다.

세 번째가 특히 아프다. 이 제품이 고발한 문제를 **자기 저장소의 판정 기록이 그대로 저지르고
있었다.**

#### 표면은 넷이고 그 이상 없다

| 표면 | 하는 일 |
|---|---|
| 스킬 | 회차를 어떻게 도는가 |
| 에이전트 정의 | 역할·경계·반환 형식 |
| 훅 | 우회하면 피해가 큰 경계 |
| `pal` CLI | 상태 관리자 — **대화하지 않는다** |

#### 역할은 다섯이고 단계에 묶이지 않는다

| 역할 | 하는 일 |
|---|---|
| **사관** | 결정·의도를 코드 좌표에 결박해 남긴다 |
| **사서** | 물으면 찾아 준다 — 영향 범위 · 낡음 · 걸린 결정 |
| **큐레이터** | 전부 내놓지 않고 지금 필요한 것을 고른다 |
| **서사자** | 흩어진 사실을 읽히는 이야기로 엮는다 |
| **동료** | 같이 판단한다 |

**"사서는 착수 단계, 서사자는 종료 단계" 같은 배치를 하지 않는다.** 그렇게 묶으면 정의된
곳에서만 쓰게 된다. 가장 자주 걸리는 자리는 회차 밖에 있다 — **`grep`을 집으려는 순간에
그래프에 먼저 묻는다.** `grep`은 문자열을 맞히고 그래프는 관계를 안다.

#### 코드

- `crates/pal-cli/src/install.rs` — `pal install`. **대상 프로젝트 바깥을 안 건드린다**
  (`$HOME` 읽기·`~` 전개가 소스에 하나도 없고, CI가 그것을 센다)
- `crates/pal-cli/src/install/layout.rs` — 설치되는 리소스 목록 (스킬·에이전트 정의)
- `crates/pal-cli/src/hook.rs` — 훅이 부르는 자리
- `crates/pal-cli/src/round/` — 회차 상태 관리
- `.claude/skills/round/SKILL.md` — 회차 절차의 정본 (853줄)

### 6.9 회차 — 일을 시작하고 끝내는 단위

#### 개념

**회차(round)** 는 이 프로젝트에서 작업의 단위다. 디렉터리 하나가 회차 하나다 —
`.palimpsest/rounds/<이름>/`에 `intent.md`(잠긴 의도)와 `state.md`(교대용 상태)가 산다.
둘 다 커밋한다.

```
인터뷰 → 사전부검 → 완수 조건 → 승인 → 루프 → 종료·막힘·접힘
```

- **인터뷰** — 소유자가 무엇을 하려는지, **말하지 않은 것과 모호한 것**을 질문으로 꺼낸다.
- **사전부검** — 실패를 미리 찾는다. 원 의도와 계획만 주고 대화 기록은 안 준다(독립성).
- **완수 조건** — 체크 가능한 것만 적는다. 각 조건에 **RED**(시작할 때 실제로 빨간지 관측)와
  **음성 대조**(검사가 고장이면 드러나는 조건)를 단다.
- **루프** — 실행 → 검증 → 처분. 처분은 넷이다: 정정 · 확대 · 축소 · 전환.
- **나가는 문은 셋** — 종료(다 했다) · 막힘(하려는데 안 된다) · 접힘(안 하기로 했다).

핵심 규칙 하나: **회차가 끝날 때 「나중에」가 0이다.** 회차 중에 나온 발견은 그 회차에서
없어진다. 다만 **접힘은 「나중에」가 아니다** — 「나중에」는 하겠다고 해 놓고 안 하는 것이고,
접힘은 안 하기로 정하고 **왜인지를 적는 것**이다.

왜 사유를 강제하나. 선행 하네스는 접는 문을 갖고 **열일곱 번 접었는데 사유 필드가 없어
왜 접었는지 하나도 못 읽는다.** 같은 저장소가 반론 하나를 기각하는 데는 근거를 요구했다.
**반론은 근거 필수, 일 통째는 근거 불필요** — 그 비대칭이 실패의 자리였다.

#### 정반합 — 판정을 혼자 하지 않는다

결정론적인 조건(CI가 빨강/초록으로 답하는 것)은 기계가 판정한다. **해석이 들어가는
조건**에만 세 역할을 쓴다.

| 역할 | 누가 | 받는 것 |
|---|---|---|
| **정(正)** | 메인 에이전트 | 전부 |
| **반(反)** | `pal-decision-opponent` | **초안과 근거만** — 대화 기록도 사고 과정도 안 받는다 |
| **합(合)** | `pal-decision-synthesizer` | 초안 + 반론 |

**합을 메인이 겸하지 않는다.** 초안을 쓴 쪽이 판정하면 자기 확신이 안 깨진다.

그리고 게이트는 판정값이 아니라 **해악도**로 가른다. 측정에서 선행 하네스의 판정값이
15건 전부 같은 값이었다 — 그 필드는 정보를 안 냈다. 실제 변별력은 심각도에 있었다.

#### 코드

- `crates/pal-intent/src/round_condition.rs` — `intent.md`의 완수 조건 파싱
- `crates/pal-cli/src/round/status.rs` — 검증 상태 읽기 (실행하지 않는다)
- `crates/pal-cli/src/round/approval.rs` — 명령 오라클 승인
- `crates/pal-cli/src/round/verify.rs` — 승인된 명령 실행 + 추가 전용 증거 기록
- `crates/pal-cli/src/round/stop.rs` — Stop 훅 정책

**승인과 실행이 갈려 있다.** `pal round approve`는 실행하지 않고 승인만 남기고,
`pal round verify`만 실제로 돌려서 증거를 덧붙인다. 원장은 **추가 전용**이라 지난 기록을
고칠 수 없다.

## 7. 실제로 어떻게 도는가 — 두 흐름

### 7.1 코어: 설치부터 조회까지

```
① pal install --target ../their-project
     └ .claude/ 아래에 스킬·에이전트 정의를 놓는다
     └ settings.json 에 훅을 exec form 으로 등록한다
     └ 매니페스트(sha256)를 남긴다 — 나중에 사람이 고친 것을 밟지 않으려고
     └ ★ 검증이 끝나기 전에는 한 바이트도 안 쓴다 (부분 설치 금지)

② pal ledger
     git HEAD 트리 → 파일 목록
       → 언어 인식 → 추출기 있으면 tree-sitter 파싱
       → 파일 부분 그래프를 1층 캐시에 저장 (열쇠에 커밋 없음)
       → 상태 일곱으로 집계

③ pal bind <심볼> --note "..." --radius callers
     이름 → 심볼 해소 (여럿이면 거부)
       → 반경 펼쳐 감시 집합 + 지금의 digest 기록
       → 의도 저장소(재생 불가)에 쓴다
       → 정본은 .palimpsest/intent/*.jsonl 이고 git 에 커밋된다

④ pal touch <심볼>
     1층 캐시 → 스티칭 → 2층 투영
       → 2층에서 심볼·참조를 읽는다
       → 의도 저장소에서 걸린 결박과 지켜보는 결박을 읽는다
       → 결박마다 신선도 판정 (Live/Stale/Orphaned/Undeterminable)
       → 못 만든 능력은 Capable::NotBuilt 로 자리를 채운다
       → 전부 Envelope 에 담아 낸다

⑤ pal doctor
     저장된 그래프가 자기 규칙(불변식 여덟)을 지키는지 본다
       → 모집단이 없는 불변식은 "위반 0" 이 아니라 Residual 이다
```

⑤의 마지막 줄이 이 프로젝트의 태도를 압축한다. 검사할 대상이 하나도 없었으면
"통과"가 아니라 **"못 쟀다"** 다([ADR-0002](adr/0002-empty-population-is-not-zero-violations.md)).

### 7.2 하네스: 회차 한 바퀴

```
/round 를 연다
  ① 인터뷰      — 안 물은 것을 먼저 발굴한다. 끝은 상한이 정한다
  ② 사전부검    — pal-premortem-sweeper 가 실패 시나리오를 낸다
                  영향 범위는 상상하지 말고 그래프에 묻는다
  ③ 완수 조건   — intent.md 에 체크 가능한 것만. RED · 음성 대조 · 퇴로를 단다
  ④ 승인        — 소유자가 잠긴 의도를 승인한다
  ⑤ 루프        — 실행 → 검증 → 처분
                  · 의도를 향해 가는 변경은 자유
                  · 의도에서 멀어지는 변경은 승인 (승격)
                  · 해석이 필요한 판정은 정반합 셋으로
  ⑥ 종료        — pal round verify --all 로 승인된 명령을 전부 재실행
                  독립 리뷰가 라운드를 돈다 (대화 기록 없이 산출물만 본다)
                  회차 보고를 쓰고 결정을 결박한다
```

## 8. 용어집

> **이 절이 사용자와 합의할 어휘의 초안이다.** 같은 개념을 다른 이름으로 부르면 대화가
> 갈리므로, 이 저장소가 실제로 쓰는 말을 그대로 적는다.

### 8.1 가장 자주 쓰는 열 개

| 말 | 뜻 | 왜 이 말이 필요한가 |
|---|---|---|
| **결박** (binding) | 사람이 쓴 글 조각을 코드 좌표에 묶은 기록 | 이 제품이 파는 것 자체다. 문서와 코드를 잇는 유일한 연결 |
| **좌표** (coord) | 코드의 한 지점을 가리키는 주소 `(저장소, 트리, 추출기 버전, 심볼)` | 줄 번호는 밀린다. 안 밀리는 주소가 있어야 결박이 산다 |
| **낡음** (stale) | 결박이 걸린 코드가 결박 이후로 변했다는 상태 | 문서가 낡는 건 못 막지만 **낡았다는 사실의 감지**는 기계가 한다 |
| **대장** (ledger) | "무엇을 보았고 무엇을 보지 않았는가"의 선언 | "전부 검사했다"는 검사할 수 없다. 범위를 선언해야 전수 주장이 성립한다 |
| **봉투** (envelope) | 모든 답에 붙는 껍데기 — 스냅샷·커버리지·능력·절단 | 답만 돌려주는 경로가 **타입에 존재하지 않게** 만든다 |
| **출처** (provenance) | 그 값을 무엇으로 믿을 수 있나 — 4값 | 추측이 조용히 사실이 되는 것을 막는다 |
| **잔여** (residual) | 판정하지 못한 것 + 사유 + 무엇이 있으면 판정 가능한지 | "이상 없음"이라고 말하지 않기 위한 자리 |
| **능력 부재** (`Capable::NotBuilt`) | 이 빌드가 그것을 답하지 않는다 | "없음"과 "안 만듦"이 같은 화면이 되는 것을 막는다 |
| **절단** (elision) | 예산에 걸려 잘린 것 + 얼마나 · 왜 | 조용한 절단 금지가 이 제품의 정체성이다 |
| **회차** (round) | 일을 여는 단위. 의도를 잠그고 끝날 때까지 돈다 | 「나중에」를 0으로 만드는 장치 |

### 8.2 좌표와 정체성

| 말 | 뜻 |
|---|---|
| **`symbol_id`** | "같은 심볼인가"에 답하는 값. `(저장소, 경로, 컨테이너 체인, 이름, 구분자)`에서 계산 |
| **`body_digest`** | "내용이 변했는가"에 답하는 값. `symbol_id`와 **다른 축이다** |
| **컨테이너 체인** | `파일 → 클래스 → 중첩 클래스` 같은 담김 관계. `symbol_id`의 성분 |
| **정체성 등급** | `exact`(스코프로 유일) · `ordinal`(선언 순서 의존) · `unavailable`(좌표 불가) |
| **스냅샷** (snapshot) | 이 답이 어느 `(저장소, 커밋)` 기준인가 |
| **트리 참조** (`TreeRef`) | 커밋 또는 워킹트리. 둘 다 1급이다 |
| **추출기 버전** | `(문법 버전, 추출기 코드 버전)`. 좌표의 성분이고 캐시 열쇠의 성분 |

### 8.3 관측 범위

| 말 | 뜻 |
|---|---|
| **파일 상태 일곱** | `Parsed`·`Partial`·`Unsupported`·`Unrecognized`·`Excluded`·`Binary`·`Generated` |
| **추출 등급** | `L0`(텍스트) · `L1`(구조) · `L2`(스코프 참조) · `L3`(읽기/쓰기) · `L4`(제어흐름) |
| **커버리지** (coverage) | 미해소 몇 · 범위 밖 몇 · 어느 언어 등급을 경유했나 |
| **미해소 참조** (`UnresolvedRef`) | 기계가 못 푼 참조. **버리지 않고 1급 데이터로 남긴다** |

### 8.4 결박과 낡음

| 말 | 뜻 |
|---|---|
| **반경** (radius) | 무엇까지 지켜보나. `symbol` · `callers` · `closure:k` · `files:...` |
| **감시 집합** (watch) | 반경을 펼친 결과 + 그때의 digest. **결박 자신의 내용이다** |
| **`live`** | 감시 집합이 그대로다 |
| **`stale`** | 감시 집합의 무언가가 변했다. **무엇이 켰는지 함께 실린다** |
| **`orphaned`** | 좌표가 사라졌다. `stale`과 다른 사건이다 |
| **`undeterminable`** | 판정할 수 없다. **`live`로 접지 않는다** |
| **승격** (`promoted_by`) | 결박이 선 길 — 손으로 걸었나(`hand`), 제안을 승인해서 섰나(`proposal`) |

### 8.5 출처와 등급

| 말 | 뜻 |
|---|---|
| **`extracted`** | 코드에서 결정론적으로 계산됨 |
| **`observed`** | 실행·빌드·계측에서 얻음. 재현 보증이 없어 **부재 주장에 못 쓴다** |
| **`asserted`** | 사람이 승인해 고정함 |
| **`inferred`** | 합성·추론의 산물. 근거·공백·확신도 필수 |
| **해소 등급** | `exact` · `scoped` · `candidate` · `contract` |
| **생산자** (producer) | 그 속성을 채운 주체. 노드의 출처와 정합해야 로딩을 통과한다 |

### 8.6 판정

| 말 | 뜻 |
|---|---|
| **`Finding`** | 위반이 확정된 것. 반례가 첨부된다 |
| **`Residual`** | 판정할 수 없는 것. **좌표에 결박된다** |
| **`OutOfScope`** | 범위 밖. 대장을 참조한다 |
| **불변식 여덟** | `pal doctor`가 그래프에 대해 검사하는 규칙. 스키마에서 파생되며 손으로 세지 않는다 |
| **빈 모집단** | 검사할 대상이 하나도 없었던 상태. **"위반 0"이 아니라 잔여다** |
| **음성 대조** | "검사가 고장이면 드러나는 조건". 합격선에 미리 등록한다 |

### 8.7 저장

| 말 | 뜻 |
|---|---|
| **1층 · 추출 캐시** | 파일 하나의 파싱 결과. 콘텐츠 주소. **지워도 된다** |
| **2층 · 질의 투영** | 심볼 색인·인접 리스트·역방향 색인. **지워도 된다** |
| **의도 저장소** | 결박·승인·거부의 원본. **지우면 영영 잃는다.** 지우는 API가 없다 |
| **스티칭** (stitching) | 파일별 부분 그래프를 질의 시점에 이어 붙이는 것 |
| **역방향 색인** | "이것을 가리키는 것들". `touch`의 근간 |
| **재구축 등가성** | 2층을 지우고 다시 만들었을 때 모든 자리에서 같은 값이 나오는가 |

### 8.8 하네스와 회차

| 말 | 뜻 |
|---|---|
| **하네스** (harness) | 그래프를 읽어 회차를 도는 층. Claude Code 전용 |
| **코어** (core) | `pal` CLI. 하네스 없이도 혼자 선다 |
| **표면** (surface) | 사용자·에이전트가 닿는 자리. **넷이고 그 이상 없다** |
| **역할 다섯** | 사관 · 사서 · 큐레이터 · 서사자 · 동료. **단계에 배치되지 않는다** |
| **의도** (intent) | 회차가 잠근 것. 원문은 소유자 문장 그대로이고 요약하지 않는다 |
| **완수 조건** | 체크 가능한 것만. 상자가 켜졌다는 것은 "됐다"가 아니라 **"쟀다"** 다 |
| **RED** | 시작할 때 실제로 빨간 것을 관측하는 것. 0개를 훑고 통과하는 검사는 아무것도 안 잰다 |
| **퇴로** | "X가 안 되면 약하게 선언하고 Y에 집중한다". 미리 등록하면 나중에 쓰는 데 승인이 필요 없다 |
| **처분 넷** | 정정 · 확대 · 축소 · 전환. 앞 둘은 자유, 뒤 둘은 승인 |
| **승격** (promotion) | 의도에서 멀어지는 변경을 소유자에게 올리는 것 |
| **막힘** | 하려는데 안 된다. 같은 실패 3회 또는 원인을 못 대는 상태 |
| **접힘** | 안 하기로 정하는 것. **사유를 적어야 접힘이다** |
| **정반합** | 판정을 셋으로 나눈 것. **합을 메인이 겸하지 않는다** |
| **오라클** (oracle) | 완수 조건을 판정하는 명령. 승인과 실행이 갈려 있다 |
| **원장** (ledger, 회차 쪽) | 검증 증거의 기록. **추가 전용** |

> ⚠ **"대장"과 "원장"은 다른 것이다.** 앞은 코어의 관측 범위(`Ledger`)이고 뒤는 회차의
> 검증 증거 기록이다. 영어로는 둘 다 ledger라 헷갈리기 쉽다.

### 8.9 목표·원리 기호

| 기호 | 뜻 | 어디 있나 |

## 9. 지금 어디까지 서 있는가

**상태는 문서가 아니라 이슈에 산다.** 어디까지 왔는지는 이렇게 확인한다.

```bash
./scripts/frontier.sh
```

지금 시점에서 확실히 말할 수 있는 것만 적는다.

| | 상태 |
|---|---|
| 서 있는 것 | 대장 · 좌표 · 1층 캐시 · 2층 투영 · 결박과 낡음 판정 · `touch` · 설치 · 회차 상태 관리 |
| 1급 언어 | 다섯 (Kotlin·Java·JavaScript·TypeScript·Rust) — 그러나 **추출기는 셋**(Kotlin·TypeScript·Rust). 나머지 둘은 `NotBuilt` |
| 답하는 질의 | `surface/queries.toml`에 적힌 것 — 열 |
| 엣지 | 스키마에 선언된 것 여덟 (노드는 열). **파일 경계를 넘는 참조는 아직 없다** |
| 안 선 것 | 미해소 참조(`UnresolvedRef`) 값 생성 · 판정(`Finding`) · 여정(`Journey`) · 외부 분석기 조달 |
| Windows | **지원 대상이고 CI가 잰다.** 다만 `core.autocrlf=true`가 매니페스트 대조를 깨는 문제가 열려 있다 |
