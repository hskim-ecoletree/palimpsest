# ADR-0005 — 부재는 **종류를 싣는다**. 상태를 늘리는 대신 이유를 값으로 둔다

**상태**: 채택 (2026-08-13) · [F02](../gates/F02.md) 종료 시점에 발행 ·
근거 [F02-2 게이트](../gates/F02-2-partial.md)

## 맥락

이 저장소는 *"안 만들었음"* 과 *"없음"* 을 가르는 장치를 이미 셋 갖고 있다 —
[`Capable`](../../crates/pal-core/src/capable.rs)(빌드가 그 능력을 안 만들었다) ·
`Residual`(검사하지 못한 것) · `Uncapturable`(담기지 않은 변경). 셋 다 같은 문장에서
나왔다: **못 본 것을 못 봤다고 적지 않으면 0 과 구별되지 않는다.**

그런데 그 규율이 **부재의 종류**에는 적용되지 않고 있었다.

`FileState::Unsupported { language }` 의 문서는 *"언어는 인식됐고 **추출기가 없다.
로드맵의 자리다**"* 였다. `.sql` 에 대해 참이다. 그런데 F02-2 가 `ERROR` 비율 임계 강등을
세우면서 **같은 칸에 다른 것**이 들어오게 됐다 — 추출기는 **있는데** 문법이 그 파일을
통째로 못 읽은 Kotlin 파일 **27 건**이다.

두 이유를 한 칸에 뭉개면 대장 머리가 이렇게 적는다:

```
  unsupported        339    언어 인식됨, 추출기 없음
```

**그 27 건에 대해 거짓이고, 거짓의 방향이 나쁘다** — 사용자는 고칠 자리를 **로드맵에서
찾는다.** 실제로 고칠 자리는 문법이다.

**선택지는 둘이었다.** 상태를 여덟으로 늘리거나, 한 칸 안에 이유를 값으로 싣거나.

## 결정

**부재를 나타내는 값은 그 부재의 *종류*를 함께 싣는다. 상태(칸)를 늘려서 가르지 않는다.**

```rust
Unsupported { language: LanguageId, reason: UnsupportedReason }

enum UnsupportedReason {
    NoExtractor,                                     // 로드맵의 자리
    GrammarDefeated { error_ratio_percent, recovery_sites },  // 문법의 자리
}
```

두 규칙이 함께 간다:

1. **칸은 사용자가 세는 단위다.** *"파일 997 개가 일곱 칸 중 하나에 정확히 하나씩"* 이
   대장의 성립 조건이고([DESIGN §4](../DESIGN.md)), 칸이 늘면 그 문장을 읽는 사람이
   매번 다시 배워야 한다. **칸을 늘리는 것은 비싸다.**
2. **이유는 행동을 가른다.** *"로드맵을 기다린다"* 와 *"문법을 바꾼다"* 는 사용자가
   **다르게 처리하는** 것이고, 다르게 처리하는 것을 같은 출력으로 내면 대장이 거짓말을
   한다. **이유가 행동을 가르지 않으면 그것은 값이 아니라 장식이다** — 그때는 싣지 않는다.

판별식: **칸을 늘릴지 이유를 늘릴지는 *"집계 표에서 따로 세어야 하는가"* 로 정한다.**
따로 세어야 하면 칸이고, 같은 칸 안에서 다르게 **행동**해야 하면 이유다.

## 결과

- **일곱 칸이 유지된다.** `Bucket` · `Envelope` · 스키마 문서 · `doctor` 의 불변식이
  전부 그 수 위에 서 있고 하나도 안 움직였다
- 대장 머리가 이렇게 적는다:
  ```
    unsupported        339    추출기 없음(로드맵) 312 · 문법이 못 읽음 27
  ```
- **골든이 움직인다.** 이유 필드가 붙으면 기존 `unsupported` 항목 전부의 모양이 바뀐다
  (312 건). **회귀가 아니라 산출이고**, 그 사실이 게이트에 목록으로 적혔다
- **값을 치른다.** 이유를 읽는 쪽이 `match` 를 하나 더 쓴다. 그 대가로 *"어디를 고쳐야
  하는가"* 가 산출에 남는다

### 이 결정이 적용되지 **않는** 자리

**부재가 아닌 것에는 쓰지 않는다.** F02-2 가 「입자 부재」(조상 없는 익명 함수의 변경)를
`recovery_sites` 에 담을지 판단하면서 **안 담기로** 했다 — 회복 지점은 *"문법이 이 바이트를
못 읽었다"* 이고 입자 부재는 **바이트를 완벽히 읽었는데 담을 심볼이 없는 것**이다.
종류가 다른 부재를 한 목록에 담으면 이 ADR 이 막으려는 것을 그대로 저지른다.

**이유의 수가 늘어나는 것 자체가 관측 대상이다.** 셋째 이유가 필요해지면 그때 *"칸이어야
하는 것 아닌가"* 를 다시 묻는다.
