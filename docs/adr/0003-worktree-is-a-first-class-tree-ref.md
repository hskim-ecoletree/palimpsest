# ADR-0003 — 워킹트리는 커밋과 같은 자격의 좌표이고, 그 좌표는 git 의 blob 이름 위에 선다

**상태**: 채택 (2026-08-13) · [F01](../gates/F01.md) 종료 시점에 발행 ·
근거 [F01 게이트](../gates/F01.md) · [R-06](../plan/00-risks.md#r-06)

## 맥락

[DESIGN §2.1](../DESIGN.md)은 좌표의 시간축을 커밋으로 잡았고, [F01 §3.2](../plan/features/F01-repo-ledger.md)는
그것이 이 제품의 1순위 사용 장면과 어긋난다고 적었다 — **적시 제시는 커밋 전 순간에
일어난다.** 그래서 `TreeRef` 에 `Worktree` 변형을 두었다.

**S1 이 그 타입을 세우고 값을 만들지 않았다.** 열 달 뒤가 아니라 다음 기능까지의
공백이었지만, 그동안 `Envelope.projection.matches_worktree` 는 `NotBuilt{F01}` 로
서 있었다 — *"이 빌드는 워킹트리 상태를 모른다."* 그것은 참인 선언이었고, 동시에
**이 제품의 1순위 장면이 아직 안 켜졌다는 뜻**이었다.

F01 이 그 자리를 채우면서 두 가지가 드러났다.

1. **워킹트리를 "커밋의 변형" 으로 다루면 조용히 커밋 좌표로 바뀐다.** `list_tree` 의
   초안은 `TreeRef` 를 받아 `base()` 만 보고 커밋 트리를 냈다 — 워킹트리를 물어도
   커밋을 답한 것이다. 타입에 변형이 있다는 것과 그 변형이 값을 갖는다는 것은 다르다.
2. **워킹트리 파일의 바이트는 blob 의 바이트가 아니다.** `.gitattributes` 에 `text` 가
   걸린 파일은 체크아웃에서 CRLF 가 들어가고 저장소의 blob 은 LF 다. 읽은 그대로
   해시하면 **아무것도 안 고친 워킹트리가 dirty 로 보인다.**

## 결정

**워킹트리는 커밋과 같은 자격의 `TreeRef` 다.** `--at` 을 주지 않으면 그것이 기본이고,
커밋 축은 명시적으로 고르는 것이다.

**그리고 워킹트리 좌표는 우리가 만든 요약이 아니라 git 의 blob 이름 위에 선다.**

| 층 | 무엇 |
|---|---|
| **blob 이름** | git 이 정한 정체성. `(경로, blob)` 목록의 각 성분이 **git 의 것과 한 건도 달라서는 안 된다** |
| **`tree_digest`** | 그 목록의 우리 요약. 외부 정본이 없으므로 **불변식**으로만 판정한다 — 같은 목록 → 같은 요약, 다른 목록 → 다른 요약 |

**blob 이름을 계산하는 경로는 하나이고, 그 경로가 git 의 clean 필터를 적용한다.**
`.gitattributes` 의 `text` 속성(그리고 미지정일 때 `core.autocrlf`)을 읽어 CRLF→LF 를
되돌린 **뒤에** 해시한다. NUL 이 있으면 손대지 않는다 — git 도 그렇다.

**`TreeRef::Worktree` 를 받은 함수는 워킹트리를 답한다.** `base()` 로 넘겨 커밋을
답하는 구현은 R-06 이 겨냥한 자리를 스스로 지우는 것이다.

## 결과

- **1층 캐시 키가 커밋을 모른다는 설계가 실제로 성립한다.** 캐시 키는
  `(blob 이름, 추출기 버전, 분류 맥락)` 이고 blob 이름이 git 의 것과 같으므로, 워킹트리
  파일과 커밋된 같은 내용은 **같은 캐시 항목**을 쓴다. F01 §3.2 가 *"공짜로 성립한다"* 고
  적은 근거가 이것이고, 그 등가성은 blob 이름의 일치에 통째로 걸려 있다.
- **`matches_worktree` 는 어느 트리를 보든 답에 실린다.** 커밋을 보고 있으면
  *"그 커밋이 HEAD 이고 고친 것이 없는가"*, 워킹트리를 보고 있으면 *"내가 잰 그
  워킹트리인가"* 다. 뒤의 것도 자명하지 않다 — 계산하는 동안 사용자가 파일을 고칠 수 있다.
- **인덱스 stat 을 믿는 것은 최적화이지 정의가 아니다.** 믿은 것과 다시 잰 것이 **같은
  답을 내야** 하고, 그것을 `[f01.pass]` ③ 의 다섯째 변이(mtime 만 갱신)가 센다.
  회계(`trusted_from_index` · `rehashed`)가 산출에 실리는 이유도 같다.
- **`.gitattributes` 를 읽는 소비자가 셋이 됐다** — clean 필터 · 언어 인식 ③ ·
  (같은 매처를 쓰는) 매니페스트 제외 규칙. **파서는 하나다**(`pal-core::attributes`).
  [ADR-0001](0001-one-read-path-two-check-layers.md)의 *"읽는 경로가 하나"* 와 같은 규칙이
  스키마가 아닌 파일에 걸린 형태다.

## 무엇이 이 결정을 뒤집는가

- **git 의 필터가 eol 을 넘어서면.** `filter` 드라이버(clean/smudge 스크립트)나 `ident`
  가 걸린 저장소에서는 우리가 계산한 blob 이름이 git 의 것과 다시 어긋난다. 그때는
  필터를 재현할지, 인덱스의 값만 믿고 **재해시를 포기할지**를 다시 정해야 한다.
- **워킹트리가 없는 소비자가 생기면.** bare 저장소나 원격만 있는 환경에서는 이 결정이
  *"기본이 워킹트리"* 부터 성립하지 않는다. 지금은 그런 저장소를 **오류로 낸다** —
  없는 워킹트리를 0 으로 흉내 내지 않는다.
- **`tree_digest` 를 부분 갱신해야 할 만큼 규모가 커지면.** 순차 요약은 파일 하나가
  바뀌어도 전체를 다시 접는다. 10⁵ 에서 그 비용이 문제가 되면 그때 진짜 머클 트리가
  필요하고, 그것은 F05 의 증분과 같은 자리에서 결정된다.
