# ADR-0032 — **코드 좌표를 못 담는 어휘는 우리 온톨로지가 아니다.** OpenMetadata 를 세 층 어디에서도 채택하지 않는다

**상태**: 채택 (2026-09-05) · 회차 `2026-09-05-openmetadata-decision` 종료 시점에 발행 ·
근거 [게이트](../gates/openmetadata-decision.md) · [이슈 #104](https://github.com/hskim-ecoletree/palimpsest/issues/104)

## 맥락

소유자가 물었다 (2026-09-05):

> 향후 palimpsest 에 설계/기획/산출물 등의 문서나, 프로젝트 참여자들의 slack 이나 메신저의
> 채팅등을 전부 연결하여 관리하는 종합 온톨로지까지 고려한다면 여러 유형의 데이터(지금의
> 소스코드를 그래프로 만들때의 엔티티 설계 등)를 일관된 방법으로 관리하는게 낫잖아?

그리고 범위를 좁혔다 — *"이것에 대해 구체화하거나 설계를 할 필요는 없어. openmetadata 를
적용하는 것은 어떨지 결정하고 싶은거야"*.

[OpenMetadata](https://open-metadata.org) 2.0.1 은 `ontologyAxiom`(OWL 공리 여섯) ·
`conversationSource` · `contextFile` · `article` 을 1급 엔티티로 진다. 문서와 대화까지
담는 종합 온톨로지를 겨냥한다면 그 확장은 정확히 우리가 필요로 하는 방향이다.

**그래서 문제는 「그 제품이 좋은가」가 아니라 「그 어휘가 우리 데이터를 담는가」였다.**

## 결정

**세 층 어디에서도 채택하지 않는다** — 런타임으로도, 어휘 차용으로도, 내보내기 대상으로도.

| 층 | 왜 안 하나 |
|---|---|
| **런타임 채택** | 로컬 배포가 Docker 에 **6 GiB · 4 vCPU** 를 요구하고 MySQL/PostgreSQL · Elasticsearch · Airflow · 서버 · 인제스션이 상시로 떠야 한다. `P12`(*"설치·운영 비용이 1급 제약이다. palimpsest 는 사용자의 머신에서 돌고 그 비용은 사용자가 낸다"*)와 정면으로 부딪힌다 |
| **어휘만 차용** | 실물을 넣어 재 봤다 — 엣지 **1/8** · 출처 **1/4** · 파일 속성은 버려야 들어가고 **코드 심볼은 담을 자리가 없다.** 차용하려면 대부분을 버리거나 확장으로 메워야 하는데, **확장으로 메운 어휘는 더 이상 그 표준이 아니다** |
| **내보내기 대상으로만** | 기술적으로 선다(`pal export` 가 이미 있다). 그러나 **읽는 자가 0 이다.** [ADR-0012](0012-a-single-truth-file-declares-only-what-has-a-counterpart-in-code.md) 가 *"짝이 없으면 적지 않는다"* 로 금지한 자리다. 소비자가 생기면 그때 연다 |

## 근거 — 어휘가 안 맞는 자리

이 회차가 쓴 검증 스크립트가 `pal export` 로 뽑은 **실제 노드**를 OpenMetadata 의 JSON
Schema 에 넣어 돌렸다. 실행 출력과 매핑 표는 [게이트](../gates/openmetadata-decision.md)에 있다
(**이 ADR 은 매핑 표를 싣지 않는다** — 갈릴 수 있는 매핑을 동결되는 자리에 두면
[ADR-0024](0024-an-adapter-that-can-diverge-is-a-second-core.md) 가 이름 붙인 그것이 된다).

가르는 관측 하나: **통과한 판정 대상 둘이 전부 「속성을 버리고 이름만 남긴 것」이었다.**
들어가긴 하는데, 들어가려면 palimpsest 가 담는 것을 버려야 한다.

**까닭은 제품의 결함이 아니라 대상의 차이다.** OpenMetadata 는 데이터베이스 테이블 ·
대시보드 · 파이프라인을 담는 카탈로그이고, palimpsest 는 **코드 심볼과 그것에 결박된
사람이 쓴 글**을 담는다. 2.0 의 온톨로지 확장이 대상을 넓혔지만 **코드 좌표를 담는 축은
그 확장에 없다.**

## 이 결정이 뒤집지 않는 것

[00-goals.md](../plan/00-goals.md) §4 의 비목표 두 행 — *"범용 지식 그래프"* 와
*"자기 자신의 온톨로지를 만드는 도구"* — 을 **뒤집지 않는다.** 오히려 첫 행이 이 결정의
근거다: 노드 타입이 *"코드 좌표에 결박 가능한 것과, 그것에 결박되는 것뿐"* 이라는 제약과
OpenMetadata 의 어휘가 안 맞는다.

소유자가 말한 문서·채팅 온톨로지는 **로드맵이지 확정 설계가 아니다**(원문: *"확정된
설계라기보다 로드맵으로 생각만"*). 그것을 실제로 담을 때 이 두 행을 뒤집을지는 그 회차가 판정한다.

## 이 결정의 경계 — **어디까지 유효한가**

★ **이 판정은 데이터 카탈로그와 어휘 표준 안에서만 유효하다.**

정반합이 잡았다. 비교 모집단 열다섯에서 카탈로그 다섯이 **전부 데이터 카탈로그**였고,
palimpsest 가 실제로 서 있는 층 — 소프트웨어 산출물 + 코드 좌표 + 사람이 쓴 글 — 의 표본이
**0** 이었다. **SARIF**(`graph`·`node`·`edge` + `physicalLocation`·`region` + `message` +
`logicalLocation` + `versionControlDetails`)와 **Backstage** 는 후보 자격을 갖는데
비교하지 않았다.

**그러므로 이 ADR 은 「OpenMetadata 를 안 쓴다」를 말하고 「우리 스키마가 최선이다」는 말하지 않는다.**

## 이 결정을 뒤집을 조건

- OpenMetadata 가 코드 좌표(파일 · 범위 · 심볼 정체성)를 1급으로 담는 엔티티를 낸다
- 또는 서버 없이 어휘만 쓰는 배포 형태가 공식으로 선다
- 또는 우리 쪽에 그 형식을 **읽는 소비자**가 생긴다 (내보내기 층에 한정)
