# palimpsest — 이 저장소에서 코드를 이해하는 방법

이 파일은 `pal install` 이 놓았다. **지시의 단일 진실은 여기 하나다** —
`CLAUDE.md` 가 `@.claude/pal/INSTRUCTIONS.md` 한 줄로 이것을 끌어온다.

⚠ 손으로 고치지 마라. `pal update` 가 **고친 파일을 밟지 않고 보고만 한다** —
그래서 고치면 갱신이 여기서 멈춘다.

★ **프로젝트 고유의 것은 어디에 적나 — `.claude/pal/policy.toml` 이다.**
그 파일은 **우리가 안 놓고 안 지운다.** 없으면 만들어라.

`pal install` 이 놓은 나머지(`.claude/pal/` · `.claude/commands/pal/` ·
`.claude/agents/pal-*` · `.claude/skills/pal-round/`)는 **우리 것**이다 —
`update` 가 갈아 끼우고 `uninstall` 이 걷어낸다. 거기 적은 것은 **제거할 때 사라진다.**
회차의 금지역 · 프로젝트 규율 · 판정 기준은 전부 `policy.toml` 로 간다.

## 무엇을 먼저 묻는가

코드를 고치기 전에 **그 자리에 무엇이 결박돼 있는지** 묻는다.

```
pal touch <심볼 이름>
```

빈 답도 답이다 — *"결박이 없다"* 와 *"못 봤다"* 는 다르고, `pal` 은 그 둘을
다르게 낸다.

## 무엇을 믿는가

- **`Residual` 은 「이상 없음」이 아니다.** 검사하지 못한 것이다.
- **모집단 0 은 통과가 아니다.** 셀 것이 없었다는 뜻이다.
- 답은 **봉투**를 지고 나온다 — 어느 스냅샷에서, 무엇을 접고, 무엇을 잘랐는지.
  봉투를 벗겨 답만 인용하지 마라.

## 무엇을 하지 않는가

- **결박을 기계가 만들지 않는다.** 후보를 내고 사람이 승인한다.
- **낡은 것을 자동으로 다시 만들지 않는다.** 낡음은 탐지만 한다.
- 이름이 비슷하다는 이유로 좌표를 고르지 않는다.

## 설치 상태를 의심할 때

```
pal doctor --install
```

다섯 검사가 나온다 — 설정 파일의 JSON · 매니페스트 대조 · 설치 루트 · `pal` 실행
파일 · `.gitignore` 등재. **정상이면 다섯이 전부 초록이고, 아니면 어느 것이
왜인지 말한다.**
