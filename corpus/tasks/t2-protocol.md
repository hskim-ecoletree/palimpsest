# T2 측정 프로토콜 — 대화형 제시 (사전 등록)

**측정을 시작하기 전에 등록한다.** 어떻게 쟀는지가 수보다 먼저 고정되어야 한다.

## 어떻게 재나

에이전트가 `t2-items/NN.md`를 **한 건씩 그대로 제시**하고, 소유자가 답하면
그 왕복의 **벽시계 초**를 기록한다.

| | |
|---|---|
| 시작 | 에이전트가 그 건을 제시한 시각 |
| 끝 | 소유자의 답이 도착한 시각 |
| 기록 | `t2-timing-log.tsv` (원자료) → `label-judgment-sheet.md` (판정표) |

**후보 제시는 여전히 측정 밖이다** — 후보는 `7a0eaff`에 고정되어 있고 에이전트는 그것을
읽어 옮길 뿐 고르지 않는다. 이 프로토콜은 [R-23](../../docs/plan/00-risks.md#r-23)의
*"도구가 흡수하는 성분"* 을 실제로 도구가 흡수하게 만든 것이다.

## 프로토콜 개정 — 코드를 함께 제시한다 (2026-08-12)

**1회차는 좌표만 주고 코드를 주지 않았다. 판정자가 답할 수 없었다.**
코퍼스를 직접 열어야 한다는 말조차 하지 않았고, '인가 가드'의 작동 정의도 주지 않았다.

**이것은 설계 실수였다.** [R-23](../../docs/plan/00-risks.md#r-23)은 *후보 제시는 도구가
흡수한다*고 적었는데, 좌표만 던지는 것은 **제시 비용을 판정자에게 떠넘기는 것**이다.
코드를 함께 주는 쪽이 등록된 전제에 **더 충실하다.**

| | |
|---|---|
| 무엇을 바꿨나 | `t2-items/NN.md`에 고정 SHA의 **코드 스니펫**(후보 줄 앞 8행·뒤 16행)을 박았다 |
| 판정 선택지 | `예` / `아니오` / **`모름`** — 애매해서 결론을 못 내리는 것도 1급 데이터다 |
| 생성 스크립트 | `scripts/t2-build-items.py` (고정 SHA에서 뽑는다. 작업본을 쓰지 않는다) |

**편향 방향**: 코드를 함께 주면 판정이 빨라진다 — **과소추정** 쪽이다.
그러나 좌표만 주는 쪽은 *도구가 흡수한다*는 전제 자체를 깨므로 **다른 양을 재게 된다.**
등록된 전제를 지키는 쪽을 택하고 방향을 적는다.

**1·2건은 시간 측정에서 뺀다** — 개정 전 프로토콜에서 이미 노출됐다.
판정은 다시 받되 그 두 수는 쓰지 않는다. 유효 표본은 **31건**이고 `n≥5`를 넘는다.

## 편향 방향 — 이 수는 순수 판단 시간이 아니다

> **왕복 시간은 판단 시간보다 크다. 이 측정은 과대추정 방향이다.**

들어가 있는 것:

| 성분 | 방향 |
|---|---|
| 코드를 읽고 판단하는 시간 | **재려던 것** |
| 답을 타이핑하는 시간 | 과대추정 |
| 에이전트의 응답 지연(제시 메시지 생성) | 과대추정 |
| 소유자가 자리를 뜬 시간 | **오염** — 아래 규칙 3 |

**T4가 낸 값과 직접 비교하지 않는다.** 그쪽은 다른 방식으로 쟀다.
합격선 판정에는 **중앙값**을 쓴다 — 한 건이 길면 평균이 끌려간다.

## 규칙

1. **한 번에 한 건.** 앞 건으로 돌아가지 않는다.
2. 답은 짧게. `예 / 근거좌표` 또는 `아니오 / 없음` 이면 충분하다.
3. **자리를 뜨면 답에 `[중단]`을 붙인다.** 그 건은 시간 측정에서 빼고 그 사실을 기록한다.
   빼는 것이 지우는 것보다 정직하다.
4. **앞에서 본 것 같아 확인했으면 답에 `[다시]`를 붙인다.** 이것이 재질문율의 분자다.
   에이전트는 이후 그것을 **다시 묻지 않는다** — 물으면 그 자체가 단서가 된다.
5. 에이전트는 **모든 건을 같은 형식으로** 제시한다. 문구를 바꾸면 그것이 신호가 된다.
6. 에이전트는 `label-answer-key.toml`을 열지 않는다. 중복의 자리를 모른 채 진행한다.

## 절감 장치는 켜지 않는다

**T2는 순수 기준선이다**([소유자 판단 §3](../../docs/instructions/2026-08-11-owner-direction.md#3--t2는-순수-기준선으로만)).
일괄 승인·진척 가시화를 쓰지 않는다. 진척은 `n / 33`만 표시한다 — 그것은 장치가 아니라
프로토콜 규칙 1(한 번에 한 건)을 지키기 위한 최소 표시다.
