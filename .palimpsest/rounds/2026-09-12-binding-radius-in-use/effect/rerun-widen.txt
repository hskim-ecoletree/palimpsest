# 재현 — 착수 상태에서 보존 경로를 다시 돌리면 정본이 바이트까지 같나  ⟨조건 `A5`⟩

> 회차 `2026-09-12-binding-radius-in-use` · 2026-09-13
>
> ⚠ 앞 판의 `A5` 는 *"정본 JSONL 을 손으로 고쳐 import 한 행이 0 이다"* 였고 **그것을 답할
> 기계가 원리상 없다**(`CA1-09`) — `import_jsonl` 이 출처를 안 검사하므로 손으로 고친 행과
> 명령이 만든 행을 가르는 표지가 산출에 없다. **재현성이 「전부 코드 경로를 지났다」의 기계
> 형태다.**

## 무엇을 했나

```
① pal intent import <fd176a8 의 bindings.jsonl> --intent <새 임시 저장소>
   → { "schema_version": 2, "bindings": 37, "aliases": 0, "already_present": 0 }
     (새 저장소이므로 already_present 가 0 이다 — 사본이 아니라 처음부터 세웠다)

② 넓힐 18 건에 대해
   pal radius <결박> --to callers --intent <그 임시 저장소>
   → 18 / 18 성공

③ pal intent export --intent <그 임시 저장소>  →  repro.jsonl

④ cmp -s repro.jsonl .palimpsest/intent/bindings.jsonl
```

## 결과

```
★ 바이트까지 같다 — A5 통과
```

## 이것이 무엇을 재나

**넓힘 전량이 코드 경로를 지났다.** 손으로 고친 행이 하나라도 섞였다면 그 행은 이 재현에서
나오지 않으므로 `cmp` 가 갈린다. 그리고 재현이 서는 것은 `Binding::with_radius` 가 감시
집합을 **정렬해서** 내기 때문이다 — 입력 순서가 산출을 바꾸면 같은 일을 두 번 해도 다른
파일이 나오고, 단위 시험 `with_radius_의_감시_순서가_결정론적이다` 가 그것을 붙든다.

⚠ **이 대조는 「위조한 감시 원소가 통과한다」를 고치지 않는다.** `import_jsonl` 이 좌표
실재성도 digest 출처도 안 검사하는 것은 그대로다(`PM2-03`) — 이 회차는 그 문을 **안 썼다**
는 것을 재현으로 보일 뿐이고, 문을 닫는 것은 범위 밖이다.
