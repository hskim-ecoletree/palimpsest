# `G5` — push 는 섰고 CI 가 안 떴다

> 회차 `2026-09-12-binding-radius-in-use` · 2026-09-13

## 무엇을 했나

```
$ git rev-parse HEAD
a7e5a0563b2ffe6acf5559226d7ecc2d79ad4456

$ git push origin main
To https://github.com/hskim-ecoletree/palimpsest.git
   1276b8f..a7e5a05  main -> main

$ git rev-list --count origin/main..HEAD
0
```

**한 번에 몰아서 밀었다** — 커밋 49. 규약이 그것을 요구하는 까닭은 워크플로가
`concurrency.cancel-in-progress: true` 라 앞 런이 취소되기 때문이다.

## 무엇이 관측됐나 — **런이 0 건이다**

| 무엇 | 값 |
|---|---|
| GitHub 이 push 를 본 시각 | **2026-09-13T08:52:48Z** (`repos/.../events` 의 `PushEvent` · `head=a7e5a05`) |
| `origin/main` | `a7e5a05` — 그 SHA 다 |
| `gh run list --commit a7e5a05` | **0 건** (08:53 부터 09:10 까지 열네 번 물었다) |
| `commits/a7e5a05/check-runs` | `total_count = 0` |
| 워크플로 상태 | `CI  state=active  path=.github/workflows/ci.yml` |
| 트리거 | `on: push: branches: [main]` — **경로 필터가 없다** |
| 저장소의 Actions 권한 | `enabled=true · allowed=all` |
| 이 회차가 `.github/` 를 만졌나 | **아니다** (`git diff --stat 1276b8f..HEAD -- .github/` 가 비었다) |
| githubstatus.com | `Actions: operational` · `Webhooks: operational` |

★ **앞 push 들은 2 초 만에 떴다** — `d9f3954` 는 `08:...`이 아니라 2026-09-12T12:12:**18**Z 에
push 되고 12:12:**20**Z 에 런이 생겼다. 그러므로 이것은 **지연이 아니라 미발화**로 보인다.

## `G5` 의 판정 — **미측정으로 둔다**

`G5` 의 오라클은 *"회차의 마지막 커밋 SHA 에 `conclusion=success`"* 다.

- **통과가 아니다** — `success` 가 없다.
- **반증도 아니다** — 실패한 런도 없다. 잴 대상이 안 생겼다.
- **대조불가로 안 적는다** — 그 값은 *"재는 도구가 원리상 못 잰다"* 는 뜻인데, 이 워크플로는
  어제까지 같은 저장소에서 **정상으로 돌았다.** 원리의 문제가 아니다.
- **그래서 미측정이다** — 「안 쟀다」이고, 그 까닭이 내 쪽이 아니라 **CI 가 발화하지 않은
  것**이라는 사실을 이 파일이 진다.

## 내가 할 수 있었던 것과 안 한 것

- **워크플로에 `workflow_dispatch` 가 없다** — 수동으로 띄울 문이 없다. 그것을 더하는 것은
  이 회차의 축이 아니고, 종료 직전에 CI 정의를 고치는 것은 **판정 도구를 판정 중에 바꾸는
  것**이다.
- **빈 커밋으로 재시도하지 않았다.** 대신 **실제로 필요한 갱신**(`state.md` 에 push 를
  기록하는 것)을 커밋해 그것이 재시도를 겸하게 했다. 빈 커밋은 회차의 마지막 커밋을
  아무 내용 없는 것으로 만들고, 그러면 `G5` 의 판정 대상이 이 회차가 한 일을 안 담는다.
- ⚠ **push 가 두 번이 된다.** 규약의 「한 번」은 `cancel-in-progress` 때문인데 **취소할 런이
  0 건**이므로 그 까닭이 이 자리에 없다. 그 사실을 여기 적는다.
