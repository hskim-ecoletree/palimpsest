# K9 — CI 관측 · 2026-08-23

⚠ **K9 는 「회차의 **마지막** 커밋 SHA」를 잰다.** 이 파일은 그 도중의 관측이고,
회차가 커밋을 더 내면 **그 SHA 에 대해 다시 재야 한다.** SHA 를 게이트에 박지 않는 까닭이다.

## `round/*` 는 push 로는 안 돈다

```
on:
  push:
    branches: [main]
  pull_request:

```

트리거가 `push: branches: [main]` 과 `pull_request` 둘뿐이라 이 브랜치는
**push 해도 런이 안 생긴다** — 실측: 원격에 `0ae2402` 가 있는데 런 0 이었다.
**PR 이 유일한 길이고, 소유자가 그것을 골랐다**(2026-08-23).

## PR #91 의 런 — **회차 전체**

⚠ **이 목록은 한 시점의 스냅숏이다.** 회차가 커밋을 더 내면 늘어난다 —
지금 상태는 `gh run list --branch round/agent-laziness` 가 낸다.

```
  a18377b  pull_request  success
  d0eb554  pull_request  success
  8935971  pull_request  success
  f601091  pull_request  success
  fcf4417  pull_request  success
  672f76a  pull_request  success
```

**이 회차가 낸 모든 커밋에서 초록이다.** 마지막 커밋 `a18377b` 을 포함한다.

### 마지막 런의 잡

```
  macos-latest  success
  놓는다 · windows-latest  success
  놓는다 · ubuntu-latest  success
  windows-latest  success
  ubuntu-latest  success
  받는다 · ubuntu-latest → windows-latest  success
  받는다 · windows-latest → ubuntu-latest  success
```

★ **세 OS 와 설치 왕복 둘이 전부 초록이다.** 이 회차는 `record.py` 를 크게 고쳤고,
앞 회차에서 그 파일의 인코딩 결함을 **잡은 것은 `windows-latest` 하나뿐**이었다 —
이 기계에 Windows 가 없으므로 **CI 가 유일한 관측자**인 축이다.

## ⚠ 그래도 `K9` 는 「대조 불가」다

조건은 *"CI 가 **회차의 마지막 커밋 SHA** 에 `conclusion=success` 를 붙였다"* 이고,
**이 파일을 커밋하는 것 자체가 새 마지막 커밋을 만든다.** 위 목록은 그 커밋 **이전**의
관측이다. `cancel-in-progress: true` 라 나눠 push 해서 앞의 초록을 남기는 길도 없다.

★ **이 회차가 정확히 그 모양을 금지역으로 한 번 잡았다** — *"빨간 커밋이 자기를
「통과」로 적었다."* 그래서 **켜지 않는다.** 구조를 고치는 것은
[#95](https://github.com/hskim-ecoletree/palimpsest/issues/95) 가 진다.

**재는 법**: `gh run list --branch round/agent-laziness --limit 5 --json headSha,conclusion`
— 그 목록의 맨 위 SHA 가 `git rev-parse HEAD` 와 같고 `conclusion` 이 `success` 면 통과다.
