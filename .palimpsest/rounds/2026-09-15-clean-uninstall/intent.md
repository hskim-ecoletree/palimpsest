# 잠긴 의도 — 제거하면 설치한 적 없던 것처럼

> 회차 `2026-09-15-clean-uninstall` · 착수 커밋 `acd7e82` · 2026-09-15

## 원문

소유자가 2026-09-15 에 쓴 것 — **압축하지 않는다.** 전문과 계기(물음 여섯)는
[`docs/instructions/2026-09-15-owner-direction.md`](../../../docs/instructions/2026-09-15-owner-direction.md) `U28`.

> uninstall 했을 때 정말 깔끔하게 원래 설치된 것이 없었던 것처럼 하고 싶어

인터뷰에서 소유자가 고른 칸(물음 문장과 칸의 설명문은 에이전트가 쓴 것 — 전문은 위 문서):

> 정본(승인한 결박 · 회차 기록)을 지워야 하나 → **기본 보존, 플래그로만 삭제**
> 사용자가 원래 가진 `.claude/settings.json` → **원래 포맷 유지 최소 편집**
> 손으로 고친 pal 블록 → **거부 유지 + 미리 알림** — 칸의 설명문에 `--force`(마커 사이를 걷고 지운 줄을 출력)가 들어 있었다
> 프로젝트 밖 승인 저장소 → **이 프로젝트 몫만 걷기**
> 승인·봉인 파일을 프로젝트별로 못 가른다 → **기록에 프로젝트 식별자 추가** — ⚠ `## 승격` 2 가 바꿨다

사전부검 R1 뒤 소유자가 고른 칸(`## 승격` 1~3):

> 종료 봉인·명령 승인 기록을 기본 uninstall 에서 → **정본으로 보고 `--purge` 에서만 걷기**
> 승인 기록을 가르는 방식 → **v1 그대로 + 옆에 표시 파일**
> 같은 원격의 클론·worktree 가 나눠 쓰는 외부 기록 → **worktree 있으면 거부, 클론은 경고** — 칸의 설명문: 「외부 기록 삭제를 거부하고 이유를 출력합니다(프로젝트 안 정본은 지움)」

에이전트가 기본값으로 적고 소유자가 이견을 달지 않은 것:

> 설치 **뒤에** 사용자가 스스로 고친 것은 남기고 우리 몫만 걷는다.
> 증인 — 설치 → 실제 사용 → uninstall 뒤 **프로젝트 워킹트리와 HOME 스냅샷이 설치 전과 바이트로 같은가**. 세 OS CI 시험으로 건다.
> 범위 밖 — 사용자가 `PATH` 에 둔 `pal` 바이너리 · Claude Code 가 스스로 만든 파일 · git 이력.
> 확대 — `narrative-pending.json` 을 `.gitignore` 블록에 넣는다.

## 목적 기여

[`00-goals.md` §2](../../../docs/plan/00-goals.md) 의 **첫 릴리스 정의** — *"1(큐레이션)과 2(컨설팅)가 실사용에서 값을 내면 제품이다."*
실사용의 앞 조건은 **남의 저장소에 설치해 보는 것**이고, 사용 기록 기간(`U27` · #160)이 바로 그것을 **남의 저장소 몇 건에서 설치부터** 채우라고 정했다.
설치해 본 사람이 **흔적 없이 거둘 수 있어야** 남의 저장소에 설치를 허락받는다. 지금은 거두면 `git status` 에 `M .claude/settings.json` 과
추적 안 된 파일이 남고, 사용자 HOME 에 승인 기록이 남는다(착수 관측 R1·R2·R5).

**왜 지금 이것이 먼저인가** — `AGENTS.md` 의 순서에서 지금 서 있는 자리는 「효과를 본다」(#160)이고, 그 기록의 절반(남의 저장소)이 **설치 허락**에
매달려 있다. 프론티어의 다른 착수 가능 이슈(#161~#166 · 언어 확장)는 설치된 뒤의 품질이라 이것보다 소비 지점에서 멀다.

## 계획

순서는 **데이터를 잃게 할 수 있는 자리 → 흔적 → 알림**이다.

1. **분류를 한 자리에 세운다**(`install/layout.rs`). `.gitignore` 블록 · uninstall · `--purge` 가 **같은 목록**을 읽는다.

   | 부류 | 자리 | 기본 uninstall | `--purge` |
   |---|---|---|---|
   | install 이 놓은 것 | `.claude/…` · 블록 · 설정 키 · 설치가 적은 `manifest.toml` | 걷는다(지금 그대로 · 사용자가 고친 pal 파일도 지우고 경고) | 걷는다 |
   | 파생물 | `.palimpsest/cache/` · `index.redb` · `narrative-pending.json` · `radius-base-*.redb` | **걷는다** — 설치 전부터 있었어도(다시 만들어진다) · 지운 목록을 출력 | 걷는다 |
   | 조건부 | `.palimpsest/intent.redb` — **결박 또는 거부가 하나라도 있으면 정본**, 둘 다 없으면 파생물(개체 ID 만 든 것) | 정본이면 남기고 수 · `pal intent export` · `--purge` 를 출력한다. 사용자 `.gitignore` 블록은 걷고, **자기 자신과 `intent.redb` 만 무시하는 `.palimpsest/.gitignore`** 를 둔다 | 걷는다 |
   | 정본(안) | `.palimpsest/intent/` · `.palimpsest/rounds/` · 설치가 안 적은 `manifest.toml` | **바이트 그대로 남기고** 출력 | **git 이 추적하지 않는 것만** 걷는다 · 추적 중인 것은 남기고 출력(고쳐졌으면 그 사실도) |
   | 운영 상태(밖) | 이 프로젝트의 Stop 활성화 · 진행 파일 · `.lock` | **걷는다** · 같은 원격의 다른 체크아웃도 Stop 정책이 비활성화된다는 사실을 출력 | 걷는다 |
   | 정본(밖) | 이 프로젝트의 명령 승인 · 종료 봉인 | 남기고 수와 경로를 출력 | 걷는다 — ★ **추적 중인 회차 원장에 적힌 봉인은 남긴다**(그 회차가 워킹트리에 남으므로) |
   | 가를 수 없는 것(밖) | 표시 파일 없는 `<digest>.json` 중 이 체크아웃의 원장에 없는 것 · 표시 파일 없는 진행 파일 중 이 체크아웃의 slug 에 안 맞는 것 | 안 지우고 수 · 경로 · **들여다본 저장소 자리**를 출력 | 같다 |

   ★ **같은 저장소의 다른 git worktree 가 있으면** 기본 uninstall 도 `--purge` 도 **밖의 기록(운영 상태 · 정본)을 하나도 건드리지 않고** worktree 경로와 까닭을 출력한다 —
   기본 uninstall 은 rc=0(밖을 남기는 것이 그 명령의 약속 안이다), `--purge` 는 안을 걷은 뒤 rc=1(요청한 것을 다 못 했다).
   **따로 받은 클론**은 가를 수 없어 밖을 걷고 「같은 원격의 다른 클론의 기록도 함께 지웠다」를 출력한다(rc=0).

2. **`settings.json` 위치 보존 편집** — install 이 재직렬화하지 않는다. 최상위 멤버(`agent`)와 `hooks.<사건>` 배열의 **새 묶음 원소**를
   텍스트 자리로 더하고, uninstall 이 그 자리만 뺀다. 들여쓰기·줄바꿈(LF/CRLF)·끝 개행 유무를 그 파일에서 읽는다. 남의 키 순서·이스케이프·수 표기는 **바이트로 건드리지 않는다.**
   **사건 키·`hooks` 키는 우리가 만든 것만 지운다** — 사용자가 미리 둔 빈 배열 `[]` 은 남는다(사전부검 R1 7). `serde_json` 은 검증과 값 대조에만 쓴다.
   **사용자가 `agent` 값을 바꿨으면 그 키를 남긴다** — 설치 뒤 사용자가 스스로 고친 것이다(조건 설계 평가 R1 · 착수 동작은 지운다).
   **v0.1.1 이하가 설치한 방**(매니페스트에 편집 자리 기록이 없다): 값으로 우리 몫을 뺀 뒤, 파일이 git 에 추적 중이고 `HEAD` 의 그 파일이
   **pal 키·훅이 없고 결과와 같은 JSON 값**이면 `HEAD` 바이트로 되쓴다. 아니면 값만 되돌렸다고 출력한다(사전부검 R1 6).
3. **손으로 고친 블록** — 블록 대조는 **줄바꿈을 맞춘 공간**에서 한다(기존 `blocks.rs` 규율 · 사전부검 R1 12). `doctor --install` 에
   검사 「pal 블록이 넣은 그대로인가」를 더해 고친 블록이면 Failed 로 두고, `update` 가 파일 경로를 출력한다.
   `uninstall --force` 는 **여는 마커와 닫는 마커가 각각 한 번씩 순서대로** 있을 때만 그 사이를 걷고 지운 줄을 출력한다.
   아니면 rc=1 로 한 바이트도 안 쓴다(사전부검 R1 13). **`update` 가 블록을 새 목록으로 갈아 끼울 때 매니페스트의 `inserted` 도 함께 갈아 끼운다**(R13).
4. **외부 기록의 귀속** — 명령 승인 · 종료 봉인 `<digest>.json` 의 형식은 **v1 그대로**(옛 바이너리가 계속 읽는다). 쓸 때 옆에
   `<digest>.project`(프로젝트 식별자)를 쓴다. 진행 파일도 옆에 `.project` 를 쓴다. 봉인은 이 체크아웃의 `rounds/*/verification.log` checkpoint 에서도
   digest 를 모아 표시 파일이 사라진 봉인까지 가른다 — `--purge` 는 **원장을 지우기 전에** 모은다.
5. **저장소 디렉터리** — 기록을 처음 쓸 때 `create_dir_all` 이 **새로 만든 조상**을 `palimpsest/` 안에 적어 둔다. 걷은 뒤 비면
   `approvals` · `palimpsest` 와 적힌 조상만 지운다(사전부검 R1 9 — Linux `~/.local/share` 등).
6. **흐름 시험** — 증인을 세 OS CI 의 한 시험으로 건다(조건 G1). 스냅샷 함수는 시험 공용 모듈 한 자리에 둔다.
7. **효과** — 커밋한 스크립트 `effect/f1-run.sh` 로, 이 저장소가 아닌 실제 저장소의 새 클론에서 **이 회차가 빌드한 바이너리**로 흐름(F1)을 밟고
   워킹트리·HOME 스냅샷 diff 를 붙인다. 같은 스크립트를 착수 바이너리로 한 번 돌려 RED 로 붙인다.

## 완수 조건

전부 **결정론적**(시험·CI·커밋된 스크립트)이다. 새 시험은 `crates/pal-cli/tests/clean_uninstall_*.rs` 에 두고 세 OS CI 가 돈다.
**모든 스냅샷 시험은 대상이 실제로 생겼음을 uninstall 전에 단언한다** — 안 생긴 것을 안 남았다고 세지 않는다(사전부검 R1 3·8).
**`doctor` 를 보는 시험은 `PATH` 에 시험 대상 `pal` 을 둔다.**

**스냅샷의 정의** — 스냅샷 함수 하나를 모든 조건이 쓴다.
- **워킹트리**: 저장소 루트 아래 모든 파일·디렉터리의 경로·바이트·모드. `.git/` 은 빼되 **`.git/config` · `.git/info/exclude` 는 바이트로 넣는다**(시험이 부른 git 이 `.git/index` 를 고쳐 쓰므로 나머지는 뺀다).
- **HOME**: macOS·Linux 는 **격리 `HOME` 전체**(그 안의 `XDG_DATA_HOME` · 캐시 포함). Windows 는 실제 사용자 자리라 전체를 못 격리하므로 **`%LOCALAPPDATA%\palimpsest` 하위 트리**.

**허용 목록 `L`**(기본 uninstall 뒤 **남아도 되는** 자리 — B3 · B7 · F1 · G1 이 쓴다. ★ **`L` 의 자리가 남으면 uninstall 직전 바이트와 같아야 한다**):

## 차선책

- **A1 모집단 중 위치 보존 편집이 못 덮는 형태가 나오면**(예: 하네스가 받는데 `serde_json` 이 못 읽는 형태) — 그 형태에서만 **설치 전 바이트를
  매니페스트에 보관하고, uninstall 때 파일이 설치 직후 바이트 그대로면 원본으로 복원**한다. 그 형태를 게이트에 적는다.
- **D2 · G1 의 Windows 기본 저장소 걸음이 CI 러너에서 설 수 없으면**(`%LOCALAPPDATA%\palimpsest` 가 이미 있는 러너 등) — Windows 는
  `PAL_APPROVAL_DIR` 로 같은 걸음을 돌리고, 기본 자리 해석은 `default_store` 의 단위 시험으로 잰다. 그 사실을 게이트 `## 판정` 에 적는다.

## 범위 밖

- 사용자가 `PATH` 에 둔 `pal` 바이너리 자체
- Claude Code 가 스스로 만든 파일(`.claude/settings.local.json` 등)과 세션 기록
- git 이력 — 이미 커밋된 설치 흔적은 워킹트리만 되돌린다
- 승인을 `bindings.jsonl` 로 자동으로 내보내는 것(#166) — B3 은 **알리기만** 한다
- 하위 디렉터리에서 install 하면 거기가 루트가 되는 동작 — 제거와 무관하다
- 프로젝트 식별자의 정의(origin · 루트 커밋) — 클론을 가르도록 바꾸지 않는다
- 승인 때 `--approval-dir` · `PAL_APPROVAL_DIR` 로 다른 자리에 쓴 기록 · origin 이 바뀌기 전 식별자의 기록 — uninstall 은 **들여다본 자리를 출력**할 뿐 찾아가지 않는다(사전부검 R1 10)
- **설치 전부터 pal 파생물이 있던 방의 파생물 바이트** — 사용이 `index.redb` · `cache/` 의 바이트를 바꾸므로 원리상 설치 전으로 못 돌린다(사전부검 R1 5 실측). 다시 만들어지는 것이라 지우고 출력한다. 증인의 「설치 전과 바이트로 같다」는 **pal 을 처음 들인 방**에서 잰다(B1 · G1)
- **pal 이 놓은 파일의 사용자 편집** — 그 파일은 pal 몫이라 uninstall 이 지우고 경고한다(착수 동작 · B6). 프로젝트 고유의 규율 자리는 pal 이 안 놓고 안 지우는 `.claude/pal/policy.toml` 이다. 「사용자가 스스로 고친 것은 남긴다」는 **사용자 파일**(`settings.json` · `CLAUDE.md` · `.gitignore`)과 사용자가 바꾼 설정 값에 건다 — 소유자가 「지우고 경고」로 판정했다(`## 승격` 4)
- **git 이 추적 중인 정본** — `--purge` 도 지우지 않는다. 팀이 커밋한 기록을 워킹트리에서 날리는 일은 사용자의 `git rm` 이다(B4)
- **Windows 의 HOME 전체 스냅샷** — 실제 사용자 자리라 격리할 수 없어 `%LOCALAPPDATA%\palimpsest` 하위만 잰다(스냅샷의 정의)
