# IR2-06 — `e1-count.py` 가 끝나지 않은 런에서 「셀 수 없었다(rc=2)」로 멈춘다
# 2026-09-17 · 독립 리뷰 R2 발견 #6 의 음성 대조

## 무엇이 문제였나

계약은 머리 주석에 적혀 있다 — `rc: 0 전부 같다 · 1 어긋났다 · 2 셀 수 없었다(짐작하지 않고 멈춘다)`.
그런데 끝나지 않은 런에 걸면 `gh run view --job … --log` 가 비0 으로 죽고,
`subprocess.check_output` 의 `CalledProcessError` 가 그대로 튀어 **rc=1(어긋났다)** 로 보였다.
「어긋났다」와 「못 쟀다」는 다른 값이다 — 앞엣것은 판정이고 뒤엣것은 판정 없음이다.

## 어떻게 고쳤나

`_gh()` 를 두어 `gh` 가 비0 이면 `셀수없다` 로 올리고, 런 상태가 `completed` 가 아니면
로그를 받기 전에 먼저 멈춘다.

## 대조 셋 (실측)

### ① 없는 런 — rc=2
  $ python3 e1-count.py --run 999999999999
  셀 수 없었다: `gh run view 999999999999 …` 가 rc=1 로 죽었다: failed to get run: HTTP 404: Not Found
  rc=2

### ② 아직 도는 런 — rc=2   ★ 이 대조가 IR2-06 의 자리다
  $ python3 e1-count.py --run 35133536368        # 마지막 SHA aa6e137 의 런, push 직후
  셀 수 없었다: 런 35133536368 이 아직 안 끝났다(status=in_progress) — 끝난 런에서만 센다
  rc=2

### ③ 끝난 런 — rc=0 (양성 대조)
  $ python3 e1-count.py --run 35120132604
  파일 5 · OS 3 · 어긋남 0
  rc=0

## 왜 이 대조를 미뤄 뒀나

②는 **도는 런이 실재할 때만** 걸 수 있다. 고친 시점에는 모든 런이 끝나 있어서
그 자리를 못 쟀고, 종료 push 직후에 잡았다. 그 사실을 여기 적어 둔다 —
「대조를 걸 기회가 시간에 묶여 있다」는 것 자체가 이 장치의 성질이다.
