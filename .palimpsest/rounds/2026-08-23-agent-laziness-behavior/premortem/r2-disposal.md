# 사전부검 R2 — 처분표

> 원 반환문: [`r2-raw.md`](r2-raw.md) · **남기지 않는다.**
> 세는 자리는 `record.py count` 이지 이 문서가 아니다.

⚠ **R2 의 시나리오 대부분이 「계획자신」**이다 — R1 을 고치면서 세운 장치가 새 표면이 됐다.
§11③ 이 실측한 *"장치를 고칠 때마다 새 선언면이 생긴다"* 가 사전부검 단계에서 일어났다.
**그래서 상한이 셋인 것이고, R3 이 마지막이다.**

## 기각 여덟에 대하여

**전부 사전부검이 스스로 적었다가 돌려 보고 걷어낸 것**이다 —
`SKILL.md` 의 상대 링크 0 개 · 서브에이전트 전사는 분리 저장 · `.py`·`.tsv`·venv 는 검사를
안 깬다 · 조건 ID 순서 무관 · `pytest`/`python3` 판본 일치 · `SendMessage` 는 동작한다.
레코드에 **유효성 `거짓`** 으로 그대로 싣는다.

⚠ **그중 하나가 이 회차의 규칙을 바꿨다** — `.tsv` 는 심어서 돌렸더니 **세면서 초록**이었다.
계획 v2 의 「`.tsv` 금지」는 **근거 없이 넓었고**, v3 에서 걷었다(R2-t).

## 남은 열림

**승격 1 하나**다(R1 에서 올린 것). R2 는 새 승격을 안 냈다.
