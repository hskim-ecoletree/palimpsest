# 실행 계획 — 문면이 행동을 바꾸는가

> 잠긴 의도: [`intent.md`](intent.md) · 착수 기준 `fa727ec`

## 완성 장면

여섯 개의 격리 디렉터리가 있고, 각각 한 에이전트가 파이썬 모듈 하나를 만들다 멈춘 상태다.
그 옆에 에이전트가 **닿은 적 없는** 오라클이 있고, 오라클을 돌리면 다섯 축의 값이 나온다.
채점표 한 장이 **팔 셋 × 과제 둘 × 축 다섯**을 좌표로 지고, 그 표 아래에
`P+문면` 과 `P+장치` 각각에 대한 **한 문장 판정**이 있다 — *"넣을 값이 있다 / 없다."*
그리고 그 판정을 만든 합격선은 표보다 **먼저** 커밋돼 있다.

## 스택

| | |
|---|---|
| 실험 대상 | Claude Code **서브에이전트**(`Agent` 툴, `general-purpose`), 팔마다 같은 모델 |
| 격리 | 스크래치패드 아래 팔·과제마다 디렉터리 하나. 저장소 밖 |
| 과제 언어 | **Python 3.12** (저장소 `.venv`). 의존성 0 |
| 오라클 | `pytest` — 스펙 항목 하나에 케이스 하나. **격리 디렉터리 밖**에 산다 |
| 계수 | 파이썬 스크립트(`exp/score.py`). 손 검산과 댄다 |
| 하네스 | `exp/` 아래 보존. 저장소에 **배선하지 않는다** (§11③ (가)) |

## 여섯 세션의 배치

```
            과제 A                과제 B
  P        A-P                   B-P
  P+문면   A-Pm                  B-Pm
  P+장치   A-Pd                  B-Pd
```

**갈리는 것은 브리핑과 장치뿐이다.** 모델·도구 목록·과제문·추가 요구·라운드 상한은 같다.

## 세 팔의 몸

### `P` — 현행 규약 발췌
`/round` SKILL.md 에서 **잠금 · 발견의 처분 · 막힘 · 검증 · 종료 보고 · 끝을 정하는 자**
절을 발췌한다. **링크를 치환하지 않는다** (앞 실험에서 형식 참조가 끊겨 도구가 전부 거부했다).

### `P+문면` — `P` + 고른 다섯 (~13 줄)
[#88](https://github.com/hskim-ecoletree/palimpsest/issues/88) 의 다섯을 문장으로 붙인다:
① 공격선 전환의 문턱 · ② 통과한 판정 하나를 적대적으로 재검 · ③ 전수 훑기 + 검산 +
표본 선언 · ④ 「끝난 느낌」을 방아쇠로 · ⑤ 값싼 모델 라우팅.
**`.claude/skills/round/SKILL.md` 에는 안 넣는다** — 후보 문서로만 만든다.

### `P+장치` — `P` + 검사 스크립트 + 진행 원장
같은 다섯 규율을 **문면이 아니라 기계로** 준다.

- **`check.py`** — 에이전트가 「끝났다」를 말하기 전에 반드시 돌린다.
  미완성 표면(`TODO`·빈 본문·`NotImplementedError`)을 세고, **진행 원장의 항목 상태와
  실제 소스를 대조**해서 어긋나면 빨갛게 낸다.
- **`progress.json`** — 스펙 항목마다 `{항목, 상태, 근거}`. 에이전트가 갱신한다.
  ⚠ **JSON 이다** — unlazy 의 결함 셋(진행 해시가 빈 줄에 리셋 · 산문 한 줄에 파서
  무력화 · 공백 두 칸에 게이트 소멸)이 **전부 줄 기반 파싱에서 왔다.** 구조화된
  형식이면 그 세 경로가 원리상 없다.
- `P+문면` 의 다섯 문장은 **안 준다.** 그래야 「문면」과 「장치」가 갈린다.

## 과제 둘

**스펙은 고정이고, 라운드 2 와 4 에 추가 요구가 하나씩 들어간다.**
추가 요구는 세 팔에 **같은 문장 · 같은 라운드**로 들어간다.

| | 과제 | 왜 이것인가 |
|---|---|---|
| **A** | 작은 **표현식 계산기** — 토크나이저 + 파서 + 평가기 | 스펙 항목이 자연히 잘게 나뉘어 부분 구현이 눈에 띈다. 우선순위·괄호·단항 부호 같은 **조용히 빠뜨리기 좋은 구석**이 많다 |
| **B** | **CSV 정규화기** — 열 타입 추론 · 결측 처리 · 재출력 | 엣지 케이스가 많고 「대충 되게」 만들기 쉽다. 에이전트가 80% 에서 멈추는 전형적 모양 |

**추가 요구(라운드 2·4)** — 과제마다 둘씩. 스펙에 없던 것이라
**「최초 의도를 완전히 커버했는가(중간 확장 포함)」**(O5)가 여기서 재진다.

⚠ **과제문에 수를 안 박는다.** *"엣지 케이스 다섯을 처리하라"* 같은 문장은
그 축을 미측정으로 만든다.

## 라운드 상한

각 세션 **6 라운드**. 드리프트를 보려면 넷은 짧다(앞 실험 실측).
「끝났다」를 선언하면 그 라운드 번호가 **O3** 이 되고, 세션은 계속 돈다 —
선언 뒤에도 남은 라운드에서 무엇을 하는지가 **O4**(라운드별 개선량)를 만든다.

## 오라클 다섯 축의 몸

| | 어떻게 재나 | 어디서 도나 |
|---|---|---|
| **O1** 스펙 충족률 | `pytest` 케이스 통과 수 / 전체 | 격리 밖 |
| **O2** 플레이스홀더 | AST 로 빈 본문·`NotImplementedError` 를 세고, 주석은 정규식 | `score.py` |
| **O3** 조기 종료 | 세션 기록에서 완료 선언 라운드를 뽑고, 그 시점의 O1 과 댄다 | `score.py` + 손 |
| **O4** 자기 발견 결함 · 개선량 | 라운드마다 O1 을 재고 차분. 자기 발견 결함은 세션 기록에서 센다 | `score.py` + 손 |
| **O5** 의도 커버 · 조용한 축소 | 의도 항목(스펙 + 추가 요구 둘) 각각에 대해 ⓐ 산출이 덮었나 ⓑ 안 덮었으면 종료 보고가 **그 사실을 적었나**. ⓐ 거짓 · ⓑ 거짓 = **조용한 축소** | `pytest` + 손 |

### A2 — 오라클 음성 대조

**참조 구현을 만들고 고의로 흠집 낸다.** 흠집 다섯이 각각 다른 축을 울려야 한다:
스펙 항목 하나 제거(O1) · `TODO` 삽입(O2) · 조기 완료 선언 기록(O3) ·
개선 없는 라운드 기록(O4) · 추가 요구 하나를 조용히 누락(O5).
**하나라도 안 울면 그 축을 고치고 다시 돈다** (퇴로 4 — 소유자에게 묻는다).

### A6 — 장치 음성 대조

`check.py` 에 세 공격을 건다: 진행 원장에 빈 줄 · 산문 한 줄 · 앞뒤 공백 두 칸.
**셋 다 검사가 살아 있어야 한다.**

## 순서 — 커밋 순서가 C6 의 증인이다

```
1. 잠긴 의도 + 계획               커밋
2. 사전부검 3 라운드 + 처분        커밋
3. 소유자 승인
4. 오라클 · 과제 · 브리핑 · 합격선  커밋   ← 반드시 5 보다 앞
5. A2 · A6 음성 대조               커밋
6. 여섯 세션 실행 → 원자료         커밋
7. 채점표                          커밋
8. ★ 소유자에게 보인다 (자율 경계)
9. 판정 · 게이트 · 레코드           커밋
10. 독립 리뷰 8 라운드              커밋
11. 종료 보고 · 결박                커밋
```

## 걸리는 것 — 미리 적는다

1. **서브에이전트가 몇 「라운드」를 도는가를 무엇이 정하나.** 서브에이전트는 한 번
   불리고 끝난다. **`SendMessage` 로 이어 붙이는 것이 라운드**다. 추가 요구도 그 길로 넣는다.
2. **`P+장치` 의 `check.py` 를 에이전트가 안 돌리면?** 그것 자체가 관측이다 —
   **「장치를 줬는데 안 썼다」**를 O4 에 기록한다. 강제하지 않는다.
3. **O3(조기 종료)이 세 팔 다 「없음」이면** 그 축은 변별력이 0 이다.
   합격선의 분모에는 남기고 **「변별 없음」**으로 적는다 — 축을 빼면 합격선이 사후에 바뀐다.
4. **채점의 일부가 손이다**(O3·O4·O5). 자동 계수와 손 검산이 갈리면 **C2 가 빨개진다** —
   그때는 손을 따르고 자동 계수의 결함을 적는다.
