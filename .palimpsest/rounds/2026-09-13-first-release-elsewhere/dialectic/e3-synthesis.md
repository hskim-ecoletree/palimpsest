### ⑷ `E4` 산출이 쓰인 행

- **K1.** P∖(C∪D) = {`src/core/hosts/index.ts`}(`oracle/E4-breakage.txt:9`)이고, 오류 자리가 최상위 import 하나다(`:12`). 그래서 「덜 말했나 — 한계 안」으로 가른다. `index.ts` 는 어느 C 로 읽어도 C 밖이라, 이 행은 C 의 출처와 무관하게 선다.
- **K2 · K3.** P∩C(`:8`)는 호출자 파일 두 개가 파손 파일과 맞는다는 근거다.
- **D2 · D3.** P(`:5`)에 `shared.ts` 도 ADR 파일도 없다. `tsc` 반사실이 두 행에 닿지 않는다는 근거다.
- ⚠ **C 의 출처가 두 갈래다(반론 7).**
  - 오라클은 C 를 `pal query symbol.callers` 에서 뽑는다(`oracle/E4-breakage.mjs:5` · `:42`).
  - 조건문 `intent.md:363` 은 C 를 *"`touch` 가 호출자로 낸 파일 집합"* 이라 적는다. `touch` 화면은 수만 싣는다.
  - 조건문대로 C = ∅ 으로 두면 P∖(C∪D) = P 가 된다(`E4-breakage.mjs:61`). 그러면 `setup.ts` 의 262 행 50 열이 `export async function discoverCodexAgents(`(`5ec95eb:src/cli/commands/setup.ts:258`) 안에 들어 `isDecl`(`:48`)에 걸리고, 「선언 안」이 1 이 된다. 오라클을 다시 돌리지는 않았다. 스크립트의 논리와 원문 줄에서 도출했다.
  - 이것은 **`E4` 판정의 몫**이라 여기서 판정하지 않는다.
  - `E3` 쪽 결론은 둘로 적는다. 질의로 뽑은 C 로는 「한계 밖으로 덜 말한 행 0」이다. `touch` 가 댄 수로는 「수 2 = 파손 호출자 함수 2」라서, 수 수준에서 덜 말하지 않았다.

### ⑸ `E3` 판정값

**통과 — 조건이 하나 붙는다.**
- 여섯 행 모두 두 끝이 풀린다. D1 · D2 · D3 은 변경 헝크, K1 · K2 는 변경 헝크, K3 은 D1 의 헝크다.
- 세 물음의 답이 선다. 사전 앎과 `E4` 가 소비된 칸이 있다.
- 금지역 꼴 ⑶ 을 지운 뒤, 사전 앎의 몫을 화면의 몫으로 센 칸은 0 이다.

**조건.** D2 · D3 의 「안 닿았나 — 아니다」는 봉인 §5(`effect/00-seal.md:57-65`)를 잠근 기준선으로 받는 데 기댄다. 소유자가 이 기준선을 받지 않으면 D2 · D3 에서 화면의 몫과 노출의 몫을 가를 좌표가 없다(잠그기 전 실험의 원 출력이 `baseline/` 에 없다). 그러면 `E3` 는 **대조 불가**다. **반증**으로 갈 행은 없다. 끝이 답을 담지 않는 행이 0 이기 때문이다.

판정과 따로 남기는 기록이 넷 있다.
- 효과가 가장 큰 두 행(D2 · D3)은 「셋 밖 — 걸음을 더했다」다. 세 물음의 틀에는 「봉인이 빠뜨린 걸음을 잡았다」가 없다.

## 소유자에게

**올린다.**

**왜.** 살아남은 반론 중 가장 무거운 것이 **금지역**(반론 1)이다. 초안의 근거 행은 사전 앎의 몫을 화면의 몫으로 셌다. 그 꼴을 지우면 효과가 가장 큰 두 행(D2 · D3)이 봉인 §5 한 장에 기댄다. 그런데 그 봉인을 쓴 자가 잠그기 전에 같은 ADR-0003 결정 본문에 노출됐다(`intent.md:119`). 사전부검은 그 오염을 금지역으로 적었다(`intent.md:176`). 이 기준선을 믿을지를 봉인과 읽은 줄 기록을 쓴 메인이 스스로 정하면, 자기 기준선을 자기가 판정하는 셈이 된다.

**소유자가 정할 것 (한 문장).** 잠그기 전 실험에서 같은 ADR-0003 결정 본문을 본 사람이 쓴 봉인 §5 를 D2 · D3 의 기준선으로 받아, `shared.ts` wrapper 제거와 ADR-0003 상태 줄 편집을 이번 `pal touch` 화면의 효과로 적고 `E3` 를 **통과**로 닫을지, 아니면 노출의 몫이 기록으로 안 갈린다고 보아 `E3` 를 **대조 불가**로 둘지.
