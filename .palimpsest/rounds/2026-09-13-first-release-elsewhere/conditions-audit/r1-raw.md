## 발견

### A3·A5 는 선 엣지가 맞는지만 잰다. TS 가 푸는 저장소 안 임포트를 `pal` 이 몇이나 놓쳤는지는 어느 조건도 안 잰다
- 모집단: 원의도
- 유효성: 참
- 해악도: 거짓신호
- 어디가 걸리나: `A5` ⑴~⑶, `A3`, `E2` ⑵. `A5` ⑴ 은 엣지 하나로 닫힌다(「> 0」). ⑶ 은 **선 엣지 전량**의 대상 파일 불일치 0, 곧 정밀도다. ⑵ 는 `outside_repo` 로 남은 상대·별칭 지정자만 0 을 요구하므로, 그 몫이 `no_target_file`·「파일로 못 폈다」·`ambiguous` 같은 다른 까닭으로 옮겨 가도 닫힌다. ditto 복제본에서 `from` 지정자를 세면 상대 922 줄, `~/` 별칭 763 줄이다(원의도가 말한 저장소 안 1,701 과 같은 규모). 이 중 1 건만 서고 나머지가 전부 다른 까닭으로 남아도 A5 는 셋 다 닫힌다. `A3` 도 가지마다 표본 ≥ 1 만 요구하고 「TS 가 푼 지정자 중 `pal` 이 엣지를 안 세운 수」는 안 센다. 원문의 장면은 「`호출자` 가 파일 경계를 넘은 **실제 수**로 나온다」이고, `E2` ⑵ 도 ≥ 1 만 본다.

### E1 의 조상 판정 넷은 다섯 산출이 한 커밋에 들어가도 전부 참이다
- 모집단: 자기장치
- 유효성: 참
- 해악도: 거짓신호
- 어디가 걸리나: `E1` 오라클. `git merge-base --is-ancestor X X` 는 rc 0 이다(HEAD `d4a7361` 에서 실측 `same-commit rc=0`). 봉인·`touch` 출력·읽은 줄·변경 SHA·차이 문서를 한 커밋에 넣어도 넷이 다 초록이므로, 이 조건이 지키려는 「봉인이 화면을 보기 전에 섰다」가 음성 대조 없이 항등식이 된다. 커밋이 서로 달라야 한다는 요구가 문면에 없다.

### B4 가 「표본 규칙 그대로」라고 적었는데, 적힌 규칙이 등록된 규칙과 다르다
- 모집단: 저장소
- 유효성: 참
- 해악도: 거짓신호
- 어디가 걸리나: `B4`, `corpus/criteria.toml:10026-10027`(표본 규칙은 `[f09.4].sample_selection` 규칙 4), `corpus/criteria.toml:7304-7305`(규칙 4 = **`symbol_id` 사전순** 균등 간격). `B4` 는 「**심볼 이름**을 사전순으로」라고 적었다. 이름으로 뽑으면 ditto 의 동명 심볼(`baseline/04-touch-claim.txt` · `baseline/04-touch-localDir.txt`: 후보 2건)에서 `touch` 가 후보 화면으로 끝난다. 그러면 새로 붙는 승인 대기 구역을 조립하지 않은 호출이 표본에 섞여 p95 가 낮게 나올 수 있다(추정. 후보 화면에서도 `elapsed_micros` 가 찍히는지는 안 쟀다). 등록 문구의 고장 대응(「결박이 실린 좌표의 수를 함께 낸다」)도 `B4` 에 옮겨지지 않았다.

- 어디가 걸리나: `F3`, `## 범위 밖` 마지막 항. 원문의 범위 규칙은 「위 장면을 막는 것만」이고, 범위 밖 절 스스로 스킬·에이전트 정의가 「장면(`touch`)을 안 막는다」고 적었다. 인터뷰 마지막 결론은 「이것이 전부인가 → 없다」다. 이슈를 하나 세우는 일이 싸기는 하지만, 완수 조건에 들면 이 회차를 닫는 요건이 된다.

## 조건의 합이 의도를 덮나

덮이지 않는 대목은 셋이다.

첫째, 원문의 장면 줄이다.

> `호출자` 가 파일 경계를 넘은 실제 수로 나온다(목표 2 · (d))

`A3`·`A5` 는 선 엣지의 정밀도를 재고, `E2` ⑵ 는 ≥ 1 을 본다. 「실제 수」, 곧 TypeScript 가 푸는 저장소 안 임포트 중 몇이 엣지가 됐는지는 조건 전부가 닫혀도 안 닫힌다. 원문이 이 회차에 맡긴 물음(「`outside_repo` 11010 이 TS 상대 경로 임포트를 해소기가 못 읽어서 생긴 것인지는 **안 쟀다.** 회차가 잰다」)의 절반도 여기에 걸린다. 까닭이 옮겨 가기만 해도 `A5` ⑵ 는 닫힌다.

둘째, 같은 장면의 첫 줄이다.

> `■ 이 좌표에 걸린 것` ≥ 1 — ditto 의 ADR·문서가 결박돼 `live`/`stale` 로 나온다(목표 1 · (a))

`E2` ⑴ 은 수만 본다. 결박된 것이 ditto 의 결정 문서인지, `live`/`stale` 판정을 싣는지는 안 닫힌다.

셋째, 착수 첫 걸음 1 이다.

> `gh run list -L 3` 으로 앞 회차 `G5`(CI 미발화)를 본다. 런이 떴으면 `conclusion` 으로 판정해 게이트와 상자를 고치고 커밋한다. 여전히 0 이면 Actions 설정·사용량을 한 번 본다. 그래도 막히면 소유자가 어디를 봐야 하는지 한 줄로 알리고 회차는 계속한다.

앞 회차 `G5` 를 판정하거나 소유자에게 알리는 일을 지는 조건이 없다. `F2` 는 이 회차 마지막 커밋의 CI 만 본다. 착수 첫 걸음 3(기준선을 박는 것)은 `A5` RED 가 `baseline/04-touch-resolveRepoRootForCreate.txt` 를 가리키고 `D1` RED 가 착수 바이너리를 부르는 것으로 간접적으로만 걸린다.
