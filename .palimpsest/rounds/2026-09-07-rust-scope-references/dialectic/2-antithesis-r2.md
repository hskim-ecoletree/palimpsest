## 초안이 서는 자리 — 내가 무너뜨리지 못한 것

**초안의 사실 바닥은 내 손에서 전부 살아남았다.** 산문으로 뒤집지 않고 다시 돌렸다.

1. **`F1`·`F2` 의 열넷 개 값과 「계측기가 산출물과 하나도 안 틀린다」** — 내가 장치를
   직접 돌렸고 산출물과 **바이트 동일**이다.

       $ cargo run -q --release -p pal-extract --example scope_variants -- . > run.txt ; echo "EXIT=$?"
       EXIT=0
       $ diff run.txt .palimpsest/rounds/2026-09-07-rust-scope-references/observations/v-variants.txt
       (무출력)

   기준 `선언 13517 · 엣지 6639 · 지역 25782 · 최상위 251 · 미해소 11889 · 선언전 0 · 모호 47`,
   `V9` `14971 · 6639 · 25786 · 323 · 12280 · 0 · 52`. 델타 합 `1454+0+4+72+391+5 = 1926`
   도 산출물에서 곧장 나온다. **`EXIT=0` 도 내가 재현했다.**

2. **`G1` 의 계약(「일곱 칸의 합 = `refs` 길이」)** — `crates/pal-core/src/projection.rs:245-282`
   의 팔을 읽었다. 다섯 팔이 `counts.* += 1` 뒤 `continue` 하거나 `counts.edges += 1;
   edges.push(...)` 로 끝나고 **두 칸을 올리는 팔도 아무 칸도 안 올리는 팔도 없다.**
   게다가 그 항등식은 **시험이 지킨다** — `crates/pal-cli/tests/rust_references.rs:86-96`
   이 `c.total()` 과 일곱 칸의 합을 `assert_eq!` 로 묶는다(*"갈래 하나가 샜다"*).
   초안의 `W1` 은 내 손에서 안 열렸다.

3. **`G4` 의 `77 = 72 + 5`** — tree-sitter 를 **안 쓰고** 정규식만으로 독립 재현했다.

       $ python3 <스크래치패드>/regex_probe.py     # `mod X` 와 뿌리가 X 인 use 절을 센다
       use-clauses whose root == same-file mod name: 77
       $ python3 <스크래치패드>/regex_collide.py   # 그중 중괄호 목록이 X 를 되담는 것
       5
       ('crates/pal-core/src/lib.rs', 72, 'cascade::{Cascade, NodeFreshness, cascade}')
       ('crates/pal-core/src/lib.rs', 78, 'doctor::{… run as doctor}')
       ('crates/pal-core/src/lib.rs', 134, 'traverse::{Step, traverse}')
       ('crates/pal-extract/src/lib.rs', 27, 'classify::{Extraction, FileOutcome, classify, grade_of}')
       ('crates/pal-extract/src/lib.rs', 34, 'recognize::{Recognition, recognize}')

   **수도 줄 번호도 초안과 같다.** 초안의 `W4`(계측기가 같은 오독을 공유한다)와
   `W5`(`77` 이 다른 모집단이다)는 적어도 이 두 수에서는 **닫혔다** — 완전히 다른
   기계가 같은 답을 냈다.

4. **`G5` 의 「둘뿐」** — `crates/pal-extract/src/rust.rs` 의 `mod tests` 를 전수로 훑어
   `use_절_배제` 를 재는 셋째 자리를 찾으려 했고 **못 찾았다.** `a11`(`:815-844`)은
   `ImportSet` 을 재지 참조를 안 재고, `b3`(`:971-981`)은 `use a::b; …` 를 쓰지만
   `assert!(sc.scopes.len() > 1 && !sc.refs.is_empty())` 라 참조가 **늘어도** 안 빨개진다.

5. **`G3` 의 「소비자가 미해소 하나뿐」** — 내가 우회로를 찾으려 했다. `RefCounts` 는
   `Serialize`/`Deserialize` 를 달아(`projection.rs:65`) 직렬화로 새 나갈 수 있는데,
   `FileRow` 를 사람 화면으로 내는 경로가 저장소에 없다(`FileRow` 의 비시험 소비자는
   `pal-store/src/projection.rs:470·483` 과 `pal-cli/src/ledger.rs:392` 뿐이고
   `pal-query/src/lib.rs:506` 의 `dump()` 는 `nodes`·`edges` 만 낸다). **초안이 맞다.**

6. **`F4` 의 좌표 넷** — `pal-query/src/lib.rs:628·634·639` · `pal-cli/src/query.rs:322` ·
   `pal-cli/src/touch.rs:265` · `pal-core/src/touch.rs:293`(`Capable<Vec<UnresolvedRef>>` ·
   `pub enum UnresolvedRef {}` 가 `:256`). **넷 다 HEAD 에서 그 줄이 맞다.**

7. **원장 칸의 형식** — `.claude/skills/round/bin/record.py:128` 의 대응표가
   *"`완화`: 처분=축소 + 조건변경=완화"* 이고 `:679` 가 그 조합을 검사한다. `:126` 이
   *"축소: 승격됨=예/아니오 (등록된 차선책이면 아니오)"* 이므로 `V` 절에 등록된 차선책이
   없다는 초안의 관측(`intent.md:154-170`)에서 `승격됨=예` 가 형식으로 따라 나온다.
   **칸 셋의 내부 정합은 안 깨진다.**

   장치와 **시험 밖**에서"* 라고 **범위를 스스로 밝혔다.** 오독이었다. **물린다.**
