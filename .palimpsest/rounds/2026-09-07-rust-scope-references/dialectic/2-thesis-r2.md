## 근거 — 좌표와 함께

### 0. 내가 쓴 계측기 — **저장소 장치를 안 고치고 독립으로 다시 쟀다**

설계문이 요구한 「돌린 명령과 출력」을 대되, `scope_variants.rs` 한 대에 기대면 그 장치가
스스로 판정 대상이라 순환이 된다. 그래서 **파이썬 tree-sitter 로 `rust_scopes.rs` ·
`scopes.rs` · `pal_core::file_edges` 의 규칙을 독립 재구현**해서 같은 저장소를 돌렸다.
저장소 파일은 한 글자도 안 고쳤다(스크래치패드에만 썼다).

    $ python3 <스크래치패드>/probe.py /Users/incognito/dev/projects/palimpsest
    파일 138
    기준 : declarations 13517 · edges 6639 · locals 25782 · top_level 251 · unresolved 11889 · before_declaration 0 · ambiguous 47
    V9   : declarations 14971 · edges 6639 · locals 25786 · top_level 323 · unresolved 12280 · before_declaration 0 · ambiguous 52
    델타 : declarations +1454 · edges +0 · locals +4 · top_level +72 · unresolved +391 · before_declaration +0 · ambiguous +5

**일곱 갈래 열넷 개 값이 `v-variants.txt` 와 하나도 안 틀리고 같다.** 그러므로 아래에서
이 계측기가 내는 분해는 장치의 산출과 같은 것을 재고 있다. ⚠ 이것은 **두 계측기가
같은 오독을 공유하지 않는다**는 보증은 아니다(§내가 확인 못 한 것).

저장소 장치도 다시 돌렸다 — 종료 코드를 직접 보려고:

    $ cargo run -q -p pal-extract --example scope_variants -- .   ; echo "EXIT=$?"
    EXIT=0
    V9    use 절 배제를 끈다                          4255       0       0  같다         다르다 ✓
      ⚠ V9 은 **엣지 축이 아니라 참조 갈래 축**에서만 갈린다 — 선언 14971 · 엣지 6639 · 지역 25786 · 최상위 323 · 미해소 12280 · 선언전 0 · 모호 52
    △ 변형 1 개는 **엣지 집합에서 안 갈렸다** — 갈린 것은 참조 갈래 축뿐이다: V9
       등록된 축이 엣지 집합이므로 **이 줄을 통과로 읽지 마라.**

★ **`EXIT=0` 이다.** 장치가 화면에는 *"통과로 읽지 마라"* 를 찍으면서 **종료 코드로는
통과를 낸다.** 이 갈라짐이 이 판의 물질이다.

### `G1` — 넓힌 축은 `V5`~`V9` 다섯 행에서 **원리상 빨개질 수 없다**

`crates/pal-extract/examples/scope_variants.rs:441-448` 이 판정을 이렇게 낸다:

    let 엣지가_다른가 = 가짜 + 누락 > 0;
    let 갈래가_다른가 = 합 != 기준_합;
    if !엣지가_다른가 && !갈래가_다른가 { 실패 += 1; }

`갈래가_다른가` 가 언제 거짓이 될 수 있나. `crates/pal-core/src/projection.rs:245-282` 의
`file_edges` 는 `scopes.refs` 의 **모든 항목을 정확히 한 칸에** 넣는다(각 팔이 `+= 1`
뒤에 `continue` 하거나 `edges.push` 한다). 그러므로 **일곱 칸의 합 = `refs` 의 길이**다
(그 계약을 `crates/pal-core/src/projection.rs:56` 이 *"갈래의 합이 `refs` 의 길이와 같아야
한다"* 로 적어 놓았다).

`V5`~`V9` 다섯은 전부 `skips`(`crates/pal-extract/src/rust_scopes.rs:262-288`)의 토글이고,
끄면 **참조가 늘기만 한다.** 늘어난 수를 재면:

    $ python3 <스크래치패드>/probe5.py /Users/incognito/dev/projects/palimpsest
    skips 토글 하나를 끌 때 새로 참조가 되는 마디 수 (다른 배제는 켠 채)
      V5 속성                  4317
      V6 매크로 앞형제             5026
      V7 경로 꼬리               8059
      V8 field_identifier    17486
      V9 use 절               1926

다섯 다 0 이 아니다 → `refs` 길이가 는다 → 일곱 칸의 합이 는다 → `합 != 기준_합` 이
**항상 참**이다. 곧 **`V5`·`V6`·`V7`·`V8`·`V9` 는 이 저장소에서 `실패` 를 원리상 못
올린다.** 넓히기 전에는 이 다섯 중 넷(`V5` 가짜 13 · `V6` 34 · `V7` 87 · `V8` 253)이
**제 힘으로** 초록이었고 하나(`V9`)가 빨갰다. 넓힌 뒤에는 다섯 다 **무조건** 초록이다.

★ **이것이 §5 의 자에 걸리는 지점이다.** 재는 의도의 양이 **한 행에서** 준 것이 아니라
**다섯 행에서** 줄었다. `V9` 를 통과시킨 것은 그중 눈에 띈 하나일 뿐이다.

### `G2` — 등록된 축은 엣지 집합이다. 장치가 **자기 안에서** 그렇게 적는다

- 잠긴 의도 `intent.md:92` — `V1` 만 축을 명시한다: *"엣지 집합이 기준과 **다르다**"*.
- 잠긴 의도 `intent.md:90` — `V` 절 머리말: *"각 행은 「그 규칙을 끈 변형에서 이 저장소를
  돌렸을 때 무엇이 달라져야 하는가」다. 달라지지 않으면 그 조건은 아무것도 안 재고 있다."*
- 장치 모듈 주석 `crates/pal-extract/examples/scope_variants.rs:3` — *"규칙을 하나씩 끈
  판으로 저장소를 통째로 돌려 **엣지 집합이 달라지는지**를 잰다."*
- 장치 스스로 `:472-478` — *"등록된 축이 엣지 집합이므로 **이 줄을 통과로 읽지 마라.**"*
- 게이트 `docs/gates/rust-scope-references.md:264-265` — *"⚠ **`V9` 는 덮개에서 뺀다** —
  그 변형은 엣지 집합에서 안 갈리고 (…) 증인 하나가 미판정인 채로 덮개에 서면 안 된다."*

**같은 저장소가 네 자리에서 「등록된 축은 엣지 집합」이라고 적고, 한 자리(판정 로직)에서만
다른 축을 쓴다.** 그 한 자리가 종료 코드를 진다.

### `G3` — 넓힌 축이 재는 여섯 칸 중 **다섯은 아무 데도 안 닿는다**

`RefCounts` 의 일곱 칸이 `projection.rs` 와 변형 대조 장치와 시험 밖에서 읽히는지 전수로
훑었다:

    $ for f in declarations locals top_level before_declaration ambiguous unresolved; do
        grep -rn "\.$f" crates --include='*.rs' | grep -v projection.rs | grep -v examples/ | grep -v '/tests/'
      done
    # declarations · locals · top_level · before_declaration · ambiguous → 출력 0 행
    # unresolved → crates/pal-query/src/lib.rs:634 · crates/pal-cli/src/query.rs:323

`FileStitch.refs` 자체의 소비자도 하나뿐이다 — `crates/pal-query/src/lib.rs:633-634` 의
`if let Slot::Built(c) = f.refs { unresolved += c.unresolved; }`.

`V9` 가 움직인 다섯 칸(선언·지역·최상위·미해소·모호) 중 **소비자가 있는 것은 미해소
하나**다. 그리고 그 하나가 보여 주는 것은 *"규칙이 무언가를 재고 있다"* 가 아니라
*"규칙을 끄면 화면의 「범위 미해소」가 391 늘어 나빠진다"* 다. 나빠짐을 「갈렸다 ✓」로
세는 것은 조건이 재려던 것이 아니다.

⚠ **장치가 이 축을 세운 사유가 그 사이 무너졌다.** 도입 커밋 `11b6162` 의 갈래합 주석은
*"어떤 규칙은 엣지를 안 만들면서 **화면에 나가는 수**만 움직인다(`RefCounts::unresolved`
가 `pal touch` 의 「내가 모르는 것」이다)"* 였고, **그 괄호 안이 거짓**이었다. 지금
`crates/pal-extract/examples/scope_variants.rs:100-104` 가 그 사실을 스스로 적는다.
사유가 반증된 뒤에도 그 사유로 세운 판정 축은 그대로 서 있다.

### `G4` — **`최상위 +72` 와 `77` 은 같은 수가 아니다** (라운드 1 이 못 정한 것)

받은 금지역은 *"`use <같은 파일 mod>::` 자리 **77 곳이 전부 파일 최상위**"* 라 적었고,
`최상위 +72` 와 그 `77` 이 같은지는 아무도 안 쟀다고 했다. 장치를 안 고치고 쟀다.

    $ python3 <스크래치패드>/probe6.py /Users/incognito/dev/projects/palimpsest

    그것을 담는 서로 다른 use_declaration: 77 · 한 절에 둘 이상: 0

    $ python3 <스크래치패드>/probe2.py /Users/incognito/dev/projects/palimpsest
    use 절이 낳은 참조 총계: 1926 {'unresolved': 391, 'declarations': 1454, 'top_level': 72, 'locals': 4, 'ambiguous': 5}
    ── top_level 72 건 ─ 묶인 선언 마디 종류 분포: {'mod_item': 72}
    ── edges 0 건 ─ 묶인 선언 마디 종류 분포: {}
    == ambiguous 5 건 ==
      crates/pal-core/src/lib.rs:72  cascade(Value)

**답: `77 = 72 + 5` 다.** 모집단은 77 이 맞고 전부 파일 최상위인 것도 맞다(심볼 안 0).
그중 **72 만 `top_level` 에 떨어지고 5 는 `Ambiguous` 로 샌다.** 새는 까닭은 자리가
아니라 **이름 충돌**이다 — `crates/pal-core/src/lib.rs:18` 의 `mod cascade;` 와
`crates/pal-core/src/lib.rs:72` 의 `pub use cascade::{Cascade, NodeFreshness, cascade};`
가 같은 스코프에 `cascade` 라는 **호이스팅된 값 바인딩 둘**을 세우고,
`crates/pal-core/src/scope.rs:395-398` 의 `if hoisted && 아이템_수 > 1 { return
RefResolution::Ambiguous }` 가 발화한다. 다섯 다 「모듈과 같은 이름을 재수출하는」
같은 형태다(`cascade`·`doctor`·`traverse`·`classify`·`recognize`).

### `G5` — **`use_절_배제` 를 지키는 증인이 둘 다 눈이 멀었다**

설계문은 *"`use` 절 배제 규칙이 옳은가"* 를 이 판 밖에 두면서 *"`A8` 이 결정론적으로
답한다"* 를 사유로 들었다. **`A8` 은 이 규칙을 안 잰다.**

`crates/pal-extract/src/rust.rs:795-801`:

    fn a8_use_절_안의_이름은_참조가_아니다() {
        let src = "mod t { use super::*; fn f(){} }";
        assert!(!참조에_있나(src, "super"));
        assert!(!참조에_있나("use x::f; fn g(){}", "f"));
    }

두 단언에 `use_절_배제` 를 끄고 같은 것을 물었다:

    use_절_배제=True  'mod t { use super::*; fn f(){} }'   참조 = ['f', 't']
    use_절_배제=False 'mod t { use super::*; fn f(){} }'   참조 = ['f', 't']
    use_절_배제=True  'use x::f; fn g(){}'                  참조 = ['g']
    use_절_배제=False 'use x::f; fn g(){}'                  참조 = ['g', 'x']

까닭도 읽어서 확인했다 — `super` 는 `identifier` 가 아니라 `super` 마디라
`reference_namespace`(`crates/pal-extract/src/rust_scopes.rs:262-272`)가 애초에 안 받고,
`use x::f` 의 `f` 는 `scoped_identifier` 의 `name` 필드라 **경로 꼬리 배제**
(`crates/pal-extract/src/rust_scopes.rs:117-121` · `:279`)가 먼저 지운다. 규칙을 통째로
지워도 `A8` 은 초록이다. 늘어나는 이름은 `x` 하나인데 `A8` 은 `x` 를 안 묻는다.

★ **그러므로 `use_절_배제` 를 지키는 자리는 `A8`(눈멀었다)과 `V9`(넓힌 축에서 무조건
초록) 둘뿐이고 둘 다 발화하지 않는다.** 이것이 §11 ② 기본 다섯 중
**`측정이_죽은_가지`**(*"검사·시험이 있는데 실제로는 아무것도 재지 않는다. 통과가 거짓이
된다"* · `.claude/skills/round/SKILL.md:875`)의 정확한 형태다. 축을 넓힌 것이 그 두 자리
중 하나를 닫아 버렸다.

### `G6` — 받은 금지역의 문면 하나를 **부분 반증**한다

받은 금지역은 *"`V9` 변형의 엣지 축은 이 저장소에서 **규칙이 만든 상수 0** 이지 코퍼스의
우연이 아니다"* 라 적었다. **「규칙이 만든」이 과하다.**

    $ python3 <스크래치패드>/probe3.py …
    use 절 참조 1926 중 — 심볼 밖(최상위) 1719 · 심볼 안 207
    use_declaration 마디 중 심볼 안에 있는 것: 195

    $ python3 <스크래치패드>/probe4.py …
    심볼 안에 있는 use 절 참조 207 의 갈래: {'declarations': 153, 'unresolved': 51, 'locals': 3}
    그중 미해소(=파일 밖 뿌리) 이름 상위: [('std', 37), ('pal_core', 5), ('serde_json', 4), …]

**`use` 절 195 개는 이미 심볼 **안**에 있다**(`mod tests { … }` · 함수 본문). 그것들이
엣지를 안 낳는 까닭은 규칙이 막아서가 아니라, 그 51 개의 뿌리 이름이 **전부 외부
크레이트**(`std`·`pal_core`·`serde_json`…)라서 `OutsideFile` 로 떨어지기 때문이다. 규칙은
엣지를 허용한다 — 내 계측기로 격리 확인했다:

    # <스크래치패드>/case_top/a.rs      # <스크래치패드>/case_fn/a.rs
    mod m { pub fn f() {} }             mod m { pub fn f() {} }
    use m::f;                           fn g() { use m::f; f(); }
    fn g() { f(); }
    델타 : … edges +0 … top_level +1     델타 : … edges +1 … top_level +0

곧 **`0` 은 규칙(`innermost`)과 이 코퍼스의 `use` 배치가 **함께** 만든 값**이다. 결정론적이고
재현되지만 「규칙 단독」은 아니다. ⚠ 이 반증은 내 판정을 **약하게 만들지 않고 강하게
만든다** — 엣지 축이 `V9` 에 대해 구조적으로 텅 빈 자였다면 그 자를 버리는 것이 정정일
수 있는데, 텅 빈 자가 아니라 **`V9` 가 실제로 떨어지는 살아 있는 자**이기 때문이다.

### `G7` — §5 의 자를 직접 댄다 (설계문 요구 3)

- **변경 전에 `V9` 가 재던 의도의 양**: *"`use` 절 배제를 끄면 이 저장소의 **REFERENCES
  엣지 집합**이 달라지는가."* 이 회차의 목적 기여가 역방향 참조 색인
  (`intent.md:32-34`)이고 완수의 대상이 엣지이므로, 이 물음은 회차의 완수 대상을 곧장
  겨눈다. 측정된 답은 **아니다**(가짜 0 · 누락 0) — 그것은 **정보**이고 **빨강**이다.
- **변경 뒤에 `V9` 가 재는 의도의 양**: *"`use` 절 배제를 끄면 엣지 집합이 달라지거나,
  아니면 참조 일곱 갈래의 저장소 합이 달라지는가."* 뒤 항은 `G1` 에 의해 **끄면 항상
  참**이다. 그러므로 이 물음의 답은 규칙이 무엇을 하든 **언제나 「달라진다」**다.
  물음이 답을 미리 갖고 있으면 그것은 재는 것이 아니다.

**늘어난 것은 정보(갈래 다섯의 이동)이고 줄어든 것은 재는 의도의 양(다섯 행의 발화
가능성)이다.** 설계문 §금지 둘이 갈라 놓으라 한 그 둘이고, §5 의 자는 뒤엣것을 잰다 —
*"고친 뒤 그 검사가 **재는 의도의 양**이 늘었으면 정정, 줄었으면 완화다"*
(`.claude/skills/round/SKILL.md:329`).
