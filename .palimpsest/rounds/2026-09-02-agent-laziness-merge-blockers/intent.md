## 인터뷰에서 잠근 결정

- **경계** — #101 본문과 사용자 원문의 병합 차단 항목 전부를 한 모집단으로 삼는다.
  접힌 평가 회차는 수정하지 않는다.
- **의도** — 과거 성공 기록이나 빈 종료문이 완료로 소비되지 않고, 종료 직전 현재 코드와
  전체 판단 원장을 다시 재어야만 complete가 되는 단일 경로를 만든다.
- **자율** — 로컬 구현·시험·이슈 처분·브랜치 push·PR 병합은 선행조건이 모두 실제로
  충족된 경우까지 수행한다. 네이티브 차단 관계는 바꾸거나 우회하지 않는다.
- **종료** — 정상·음성 대조, 전체 정책 검사·시험, 구조적 doctor 전수 판정, 독립 검토,
  최종 SHA의 CI 작업 7개 성공, PR 병합과 origin/main 포함 확인이 모두 증인이다.
- **재고** — schema 2 approve/verify와 Stop reducer는 재사용한다. schema 1은 읽기 호환만
  유지하고 종료 승인 근거에서는 제외한다. #96은 진행 원장이 이미 verification event
  ledger로 흡수됐는지 실제 계약과 효과를 대조해 처분한다.

질문의 경계·의도·자율·종료·재고 범주를 모두 열었다. 사용자가 결함 모집단, 시험 방식,
외부 종료선과 실패 시 출구를 모두 지정했으므로 추가 선택을 요구하지 않는다.

## 개정

- 사전부검 PM1-01에 따라 schema 호환 상태와 Stop 종료 자격을 분리한다. schema 1의 status
  읽기 호환은 보존하지만 새 완료 체크포인트 없이는 Stop을 통과하지 못한다.
- PM1-03·PM1-04에 따라 새 원장은 command와 dialectic 조건을 명시적으로 가르고, 최종화
  명령은 한 canonical profile의 exact 승인을 다시 확인해 이미 met인 command도 전부 재실행한다.
- PM1-05에 따라 열림 축이 없는 구형 findings는 열린 해악 0이 아니라 종료 자격 없음이다.
- PM1-06·PM1-07에 따라 shallow fixture는 실제 shallow임을 먼저 증명하고 clone 깊이와
  무관한 origin identity를 우선한다.
- PM1-09에 따라 #96은 verification ledger에 흡수됐다고 간주하지 않는다. #95와 #101이
  소비 가능한 종료 경계에 더 가까우므로 그 근거를 적어 명시적 접힘 처분한다.
- PM1-10에 따라 최종 CI·병합·origin/main 확인은 추적 파일을 다시 쓰지 않는 외부 종료
  절차로 둔다. G2가 재는 것은 그 절차를 우회할 자기 CI 주장 부재다.
- 독립리뷰 R1-01·R1-04에 따라 schema 3 command profile을 canonical 값 하나로 고정하고,
  checkpoint는 외부 private store의 exact finalization seal 없이는 complete가 아니다.
- R1-02에 따라 report의 본문 유효성과 bytes digest를 status aggregate 자체에 넣는다.
- R1-03에 따라 completion reader도 finding 정본의 필수 축과 enum을 fail-closed한다.
- R1-05에 따라 판정문은 잠긴 intent를 직접 가리키고 범위 밖 절을 가진다.
- R1-06에 따라 doctor는 checked와 명시적 `not_built` 능력 부재를 전부 분류하고 malformed
  outcome을 거부하며, 그 단일 명령을 세 OS CI가 실행한다.
- CI1-01에 따라 fake checkpoint 공격 쓰기는 판정 전에 writer를 명시적으로 닫는다. Unix의
  열린 파일 rename 허용에 기대지 않고 Windows에서도 같은 완료 상태를 재는 fixture로 맞췄다.
