## 남지 않은 것

**완수 조건 아홉을 다 판정했다** — 통과 일곱 · **반증 둘**. 상자와 게이트 표준 표가
양방향으로 같고 `cargo xtask check` 의 「원장 둘 대조」가 그것을 댄다.

**반증 둘은 실패가 아니다.** A2(`--schema` 출력만으로 정본과 비정본의 지위가 구별된다)와
B2(소비되는 정본 키를 바꾸면 검사가 실패한다)가 반증됐고, **그 반증이 이 회차의 산출이다.**
원인이 잠긴 경계(두 파서 사전) 밖에 있어 최소 수정으로 못 닫으므로
[#102](https://github.com/hskim-ecoletree/palimpsest/issues/102) 로 **분할**했다.

**상한과 해악 게이트.** 사전부검 2 라운드(상한) · 독립 리뷰 2 라운드(상한)를 다 썼다.
두 리뷰 라운드가 각각 *"끝내도 되는가 — **안 된다**"* 로 닫았고 **두 번 다 그 판정이
옳았다.** 라운드 1 이 연 금지역 둘(지어낸 좌표 · 면제된 쪽만 고친 정정)과 실패 하나
(`.gitignore` 된 좌표가 CI 를 빨갛게 만든다)를 닫았고, 라운드 2 가 연 금지역 셋
(대조 장치가 스스로 어긋남 · 효과 전사가 낡음 · 게이트의 B2 근거가 실측과 반대)과
실패 하나(중단되면 변이가 남는다)를 닫았다. **지금 열린 금지역·실패는 0 이다.**

**효과.** 테스트도 CI 도 아닌 것이 돌린 출력이 `effect/observation.md` 에 있다. 물음은
*"이 선언 하나가 정본인가를 `--schema` 출력만으로 답할 수 있나"* 이고 답은 **아니오**다.
착수할 때 A2 가 전제한 *"`설명` 경계만 바로 세우면 구별된다"* 가 **틀렸다는 것**이 이
회차가 얻은 가장 값진 것이다.

## 다음 회차가 받는 것

**분할이지 넘김이 아니다** — 이슈로 서서 프론티어에 올랐다.

[**#102** `--schema` 의 부재가 안 보인다 — `unwrap_or` 가 같은 값을 하드코딩해 둔 자리 일곱](https://github.com/hskim-ecoletree/palimpsest/issues/102)

A2·B2 반증의 뿌리다. 같은 키가 **값을 바꾸면 빨갛고 지우면 초록**이라 「소비되는가」의 답이
고른 변이 연산자에 좌우된다. 그리고 세 라운드가 실제로 낸 결함은 전부 **항 누락**인데
지금 장치는 그 축을 원리상 못 잡는다. 이슈가 답해야 할 것 넷을 본문에 적었다.

## 범위 밖

착수 때 정한 것 셋에, 잠금 뒤 개정이 진 다섯이 더해졌다. 전부 `intent.md` 의
`## 범위 밖` 에 있고 개정이 그 추가를 진다.

- #94 와 관계없는 회차 검사 개선 · 다른 열린 이슈의 구현 · `--schema` 전체를 새 공개 API 로
  설계하는 일 (착수 때)
- `unwrap_or` 로 받쳐져 키 부재가 안 보이는 자리 · `extract.py` 만 읽는 키에 검사가 없는
  것 · `xtask` 의 `판정인절` 죽은 매개변수와 반대인 두 주석 · `_검산` 이 `판정값` 을 손으로
  다시 열거한 이중 정본 (개정이 더했다 — #102 가 진다)
- 닫힌 게이트 둘의 본문. `docs/gates/` 는 동결이라 안 고치고 사유 정정을 `README.md` 에
  적었다 — MCP 선례와 같은 자리다.
- 레코드 `출처` enum 에 정반합 자리가 없는 것. 이 회차의 판정을 둘 뒤집은 반론이 원장 밖에
  산다. 규약 층이라 #94 가 답할 물음이 아니다.

## 원리상 못 잰 것

**세 OS 의 `cargo xtask check`·`cargo xtask test`.** 이 기계는 darwin 하나뿐이고
`zstd-sys` 와 tree-sitter 문법이 C 컴파일러를 요구해 크로스 빌드도 안 선다
(`.github/workflows/ci.yml` 머리가 그 사유를 적는다). **무엇이 갖춰지면 잴 수 있나** —
CI 가 잰다. 마지막 커밋 SHA 의 세 OS 결론이 그 조건이고, 아래 「원장」이 그것을 진다.

**그래프가 Python 선언에서 Rust 검사로 이어지는 소비 관계를 못 답한다.**

이고 가까운 이름도 0 이다. `pal query --list` 가 그 능력을 **`F07 cross-file-resolution`**
으로 이름 붙여 「아직 못 만든 능력」에 싣는다.

**그래서 이 회차의 소비 관계는 전부 코드 판독과 변이 실측이 냈다.** 그래프가 답한 것은
`check_ledger_pair` 의 좌표 하나뿐이고(`xtask/src/main.rs`), 역방향 호출자는 `(없음)`
이었다. ★ **모델 추정이 그 자리를 메운 것이 아니라 변이가 메웠다** — 그 차이를 적어 둔다.
