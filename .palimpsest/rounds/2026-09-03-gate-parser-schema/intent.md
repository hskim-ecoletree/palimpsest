도달할 가능성이 크므로 지금 먼저 판정한다.

## 인터뷰에서 잠글 결정

- **경계** — #94 본문과 소유자 후속 댓글이 지정한 `게이트파서`·`조건파서` 둘을 다룬다.
  관련 없는 회차 검사나 다른 열린 이슈는 범위에 넣지 않는다.
- **의도** — 두 파서 설명이 기계가 소비하는 정본인지 사람이 읽는 비정본 요약인지 한 가지
  지위만 갖게 하고, 코드와 갈려도 거짓 정본이 되지 않도록 한다.
- **자율** — 기존 `feat(#94)` 커밋을 먼저 검증한다. 조건을 이미 충족하면 새 제품 코드를
  만들지 않고 판정 기록만 완성한다. 반증되면 #94가 제시한 대조 장치·제거·요약 격하 중
  하나를 근거로 고르고 최소 수정한다.
- **종료** — 재현 가능한 정상·음성 대조, 전체 검사, 독립 검토, 효과 관측, 최종 커밋의 CI
  성공과 #94 종료가 증인이다.
- **재고** — `origin/main`에 `8af2240 feat(#94)`가 있고, 현재 `record.py --schema`는 두
  설명을 `설명.정본아님` 아래에 둔다. 이 구현을 새로 쓰지 말고 먼저 검증한다.

## 완수 조건

- [ ] A1 #94의 `게이트파서`와 후속 댓글의 `조건파서`가 모두 판정 대상에 든다.
- [ ] A2 `--schema` 출력만으로 기계가 소비하는 정본과 사람이 읽는 비정본 설명의 지위가 구별된다.
- [ ] B1 두 비정본 설명을 각각 독립적으로 바꿔도 정책 검사는 같은 결과를 내며, 바꾼 값이 실제 `--schema` 출력에 도달했음을 함께 확인한다.
- [ ] B2 소비되는 정본 키를 유효한 구조 안에서 바꾸면 그 키를 읽는 경로의 고유 진단으로 검사가 실패한다.
- [ ] B3 검사나 문서에 두 파서의 코드 갈래를 다시 손으로 열거한 두 번째 정본을 만들지 않는다.
- [ ] C1 정상·음성 대조의 명령, 입력, 실제 종료값과 출력을 재실행 가능한 산출물로 남긴다.
- [ ] C2 `cargo xtask check`와 관련 시험이 현재 작업 트리에서 성공한다.
- [ ] D1 독립 검토에 열린 금지역·실패가 없고, 테스트가 아닌 실제 `--schema` 출력으로 효과를 확인한다.
- [ ] D2 회차 기록과 게이트를 커밋하고 최종 커밋의 지원 플랫폼 CI가 성공한 뒤 #94를 닫는다.

**RED 관측**: 아직 미측정이다. 다음 세션의 첫 실행은 `8af2240`의 부모 또는 격리된 변이에서
비소비 선언이 실제 검사 결과를 바꾸지 않는데도 정본처럼 노출되던 결함을 재현한다.

**음성 대조**: 비정본 설명의 독립 변이는 검사 결과를 바꾸지 않아야 하고, 소비되는 정본
키의 독립 변이는 해당 소비 경로를 반드시 실패시켜야 한다. 두 변이 모두 새 출력에
도달했음을 먼저 확인한다.

명시하고, 공개 계약 증거가 하나라도 나오면 호환성 조건을 추가한다.
